Week 07 / Organise observations

Look a reading up by name

Attach a name to each value so a reader can find it without counting positions.

Last week we kept readings in a list, so order and position stayed available. A position answers "when?". This week the question is "which sensor?". A position is the wrong tool for that.

A test rig applies a calibration factor to each raw reading. The factors are known for T1, T2 and P1. A new humidity sensor H1 also sends readings, but nobody has calibrated it yet.

Start with the problem

Try this first.

Three sensors have calibration factors; a fourth sensor, H1, has none. On paper, find the factor for P1 in a list of pairs and then in a dictionary. Decide what the program should do for H1.

Why this week's tool?

A dictionary stores each value under a key. Reading by key needs no loop. A missing key is visible: [] raises KeyError, while .get() returns a default you choose.

By the end: Correct the readings of the calibrated sensors. Report the uncalibrated sensor by name. Explain why the program must not silently use a factor of 1 for it.

The idea behind the program

A key describes the meaning of a value

factors['P1'] asks for the value that belongs to the name P1. In a list of pairs the same question needs a loop that compares names. The dictionary keeps each key once and remembers the order in which keys were added.

A missing key is information, not zero

factors['H1'] stops the program with KeyError when H1 is absent. factors.get('H1') returns None instead. Both tell you that no factor exists; neither invents one. Choosing a default such as 1.0 is an engineering decision that must be written down.

A tuple keeps a small record together

A pair such as ('T1', 21.5) is a fixed record: it cannot be changed after creation. Unpacking it as sensor, value = pair gives readable names. Because it is immutable, a tuple can also serve as a dictionary key, for example a (row, col) position.

A short Python example

Read the example alongside the explanation. Run it in a new notebook cell and change one input to see how it behaves.

factors = {'T1': 1.02, 'T2': 0.98, 'P1': 1.10}
raw = {'T1': 21.5, 'P1': 101.3, 'H1': 40.0}
for sensor, value in raw.items():
    factor = factors.get(sensor)
    if factor is None:
        print(sensor, 'has no calibration factor')
    else:
        print(sensor, 'corrected:', round(value * factor, 2))
print('Known sensors:', list(factors))

Example output

T1 corrected: 21.93
P1 corrected: 111.43
H1 has no calibration factor
Known sensors: ['T1', 'T2', 'P1']

A key finds a value; a missing key is an event

A dictionary maps each key to one value. Reading d[key] finds the value without a loop. Keys keep the order in which they were added. A key that was never added does not give zero or an empty value. d[key] raises KeyError, and d.get(key) returns None unless you give a default.

Draw or trace

Draw factors = {'T1': 1.02, 'P1': 1.10} as two labelled boxes. Write the requests factors['P1'], factors['H1'] and factors.get('H1', 1.0) beside them and mark which one finds a box.

Predict before running. After factors['T2'] = 0.98 is added, in what order does for key in factors visit the keys? What does factors['H1'] do?

Trace and explanation — after your prediction
  1. factors['P1'] finds the box labelled P1 and gives 1.10; no comparison loop runs.
  2. Adding T2 appends it after P1, so the loop visits T1, P1, T2 in insertion order.
  3. factors['H1'] finds no box and raises KeyError. factors.get('H1', 1.0) returns 1.0 and does not add H1 to the dictionary.

The order is T1, P1, T2, and factors['H1'] stops the program. A default from get() is a decision you made, not data the dictionary had. A tuple such as ('T1', 21.5) is a fixed record. It can be unpacked into names. Because it cannot change, it can also be a key.

Examples and variations

Each example changes something about the same problem. Open the ones you want to explore and follow the worked explanation.

01Calibrated sensor

factors = {'T1': 1.02, 'T2': 0.98, 'P1': 1.10}; raw P1 = 101.3

Question: What does factors.get('P1') return, and what is the corrected value?

  1. Key 'P1' exists → 1.10
  2. 101.3 × 1.10 = 111.43
  3. Print P1 corrected: 111.43

P1 corrected: 111.43

The lookup needs no loop. The key P1 names the value directly, and the corrected reading is printed with its sensor name.

02Uncalibrated sensor

same factors; raw H1 = 40.0

Question: What happens with factors['H1'] and with factors.get('H1')?

  1. 'H1' in factors → False
  2. factors['H1'] → KeyError: 'H1'
  3. factors.get('H1') → None

H1 has no calibration factor

The [] form stops the program; get() lets the program report the missing factor by name. Neither form pretends that a factor exists.

03Silent default fault

same factors; get('H1', 1.0) used for every sensor

Question: What would the report show for H1, and what is wrong with it?

  1. get('H1', 1.0) → 1.0
  2. 40.0 × 1.0 = 40.0
  3. H1 is printed like a calibrated sensor

H1 corrected: 40.0 (misleading)

The output looks correct but the reading was never calibrated. A default hides the missing entry. Use a default only when the decision is written down and visible in the report.
