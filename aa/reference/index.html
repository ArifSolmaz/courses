What is an algorithm?

An algorithm is a finite sequence of clear instructions for solving a problem. Think of a robot that must find the closest obstacle from a list of sensor readings. It can read each distance, keep the smallest one, and return it. The algorithm is the method; Python is the programming language we use to express it.

The input is the information given to an algorithm. The output is the answer it produces. A correct algorithm must produce the required answer for every valid input and must terminate. Algorithm analysis studies the work and memory required.

Python: variables, lists and control structures

A variable is a named place for storing a value; x = 7 stores 7 in an integer variable named x. A list stores multiple values in order: a = [12, 7, 19, 4]. An index is the zero-based position of an element.

a[2] reads the element at index 2, which is the third element (19). = assigns a value, == tests equality and < tests whether a value is smaller. if runs an instruction only if its condition is true. return ends a function and returns its result. Python uses indentation (spaces at the start of a line) to show which instructions belong to a loop or condition. A colon : starts a new indented block. Four spaces are conventional.

for i in range(3): is a loop: i takes the values 0, 1, 2 in order. range(3) starts at zero and excludes 3. range(1, 4) produces 1, 2, 3; range(0, 8, 3) produces 0, 3, 6. len(a) gives the list length. A function is defined with def; minimum(a) passes the list to it.

while i < 3: runs while its condition is true. Write i = 0 before the loop and use i += 1 each time. This means i = i + 1. Likewise i *= 2 means i = i * 2.

Algorithm (Python)

def minimum(a):
    n = len(a)
    smallest = a[0]
    for i in range(1, n):
        if a[i] < smallest:
            smallest = a[i]
    return smallest

The function assumes n ≥ 1 because it reads a[0]. Starting the loop at 1 avoids comparing the first element with itself.

Understanding input size

What is n?

Input size is not necessarily the value of a number. If you receive an array of five temperatures, n=5 even if the largest temperature is 100. If a picture has width w and height h, there are w×h pixels.

The value of an integer is not its representation length

In our everyday decimal system, 235 has three digits: 2×100 + 3×10 + 5×1. Binary (base 2) uses only 0 and 1. Each binary digit is called a bit. From right to left, the place values double: 1, 2, 4, 8, 16, … . So binary 1101 means 8+4+0+1=13.

One bit can represent 0 and 1; two bits can represent 0 through 3; three bits can represent 0 through 7. In general b bits have 2b different patterns. The largest unsigned value is 2b−1. Without leading zeroes, a positive integer requiring b bits satisfies 2b−1 ≤ x < 2b.

A power tells us how many times to multiply a number by itself: 2³=2×2×2=8; 2⁴=16. A logarithm asks the reverse question: log₂8=3. Since 13 lies between 8 and 16, log₂13 lies between 3 and 4. The brackets ⌊ ⌋ mean round down, for example ⌊3.70⌋=3.

take base-2 logarithms of 2b−1 ≤ x < 2b to get b−1 ≤ log₂x < b. The logarithm is an increasing function, so the inequality directions stay the same. Rounding log₂x down gives b−1; add 1 to obtain the number of bits.

b = ⌊log₂ x⌋ + 1   (x ≥ 1)

For x=13, log₂13≈3.70, so b=3+1=4. Zero is outside this formula; its binary representation is 0, one digit. This is the shortest unsigned representation; Python's int is not limited to a fixed 32-bit width; larger integers can require more memory. (13).bit_length() returns 4. The full Python object's memory usage is larger than those four bits.

Why does this matter for algorithms? A program that counts from 1 to x takes x steps. This is linear growth. But if we measure input length in bits b, x can be between 2b−1 and 2b. The same program therefore grows exponentially in the bit length. For example, x=8 needs 4 bits and 8 steps; x=16 needs 5 bits and 16 steps. One extra bit doubled the work in this example.

More than one input size

Two arrays can have different lengths n and m. If a robot compares 5 distance readings with 8 reference values, n=5 and m=8. A graph is a model of points (vertices) connected by lines (edges). For example, a network with three stations joined by two roads has V=3 and E=2. Choose an input size that matches the problem.

Why not simply measure seconds?

Running time in seconds depends on the processor, language, compiler and data. Imagine algorithm A uses n² operations and B uses 10n operations. At n=5, A uses 25 and B uses 50; at n=100, A uses 10,000 and B uses 1,000. The better choice can change as n grows. Counting operations helps us understand this without depending on one computer.

Operation cost and T(n)

An instruction may contain several elementary operations. For example, sum += a[i] is shorthand for sum = sum + a[i]: read an array element, add it and store the result. In this model, each execution of the line costs one unit. A unit-cost model is an agreement on which operations we count and what weight each receives.

T(n) is a mathematical function giving the total work under that model for an input of n elements. T(3)=12 means that substituting 3 for n gives 12 operations, not 12 seconds. Here a function is a rule that maps an input to a result.

05 / BASIC CONCEPTS

What are we measuring?

Why measure time and memory separately?

Imagine a robot that must read its sensors 100 times per second. It can spend about 10 milliseconds on each cycle. One method may do little work but use a lot of memory; another may use less memory but do more work. That is why we measure both time and space.

To sum all numbers in an array, keep the running total in one variable. Four elements require four additions; 100 elements require 100 additions. Yet one running-total variable is enough in both cases. The work grew but the extra memory did not. Growth classes describe this difference.

Algorithm analysis studies how the resources required by a solution change as the input size grows. n usually denotes the number of elements. For two arrays, n and m may be separate sizes; for a graph, V and E may count vertices and edges.

Time complexity

T(n): the amount of work in a chosen cost model. Instead of measuring seconds, we can count comparisons, assignments or arithmetic operations.

Space complexity

S(n): how the amount of memory used at any one time grows. Input, output and auxiliary memory may be reported separately.

Example: finding the maximum of an array requires n−1 comparisons for n ≥ 1. If the input is already in memory, only an index and the current maximum are needed: Θ(n) time and Θ(1) auxiliary space.

Assumption: basic operations on fixed-width numbers and array indexing have constant cost. Large integers, I/O and caching may require different cost models. Source: algorithm analysis (Turkish).

What do O, Ω and Θ mean?

Growth, upper and lower bounds

Suppose two programs have operation counts A(n)=3n+3 and B(n)=n². At n=10, A=33 and B=100; at n=100, A=303 and B=10,000. It is not enough to look at which is faster at the beginning. We want to know which grows faster as n becomes large.

n3n+3n²(3n+3)/n

100303100003.03
1000300310000003.003

Asymptotic means behaviour as n grows large. An upper bound (Big-O) gives a ceiling on growth; a lower bound (Omega) gives a floor; a tight bound (Theta) has both bounds of the same growth class. A bound need not be equal to the original function; a constant multiple is allowed.

For n≥1, 3n+3 is at least 3n and at most 6n, because 3≤3n. Therefore 3n ≤ 3n+3 ≤ 6n. Both the floor and ceiling are proportional to n. The result is Θ(n). O(n²) can also be an upper bound, but it is looser.

In the definitions below, f(n) is the actual cost being studied, and g(n) is the growth function we compare it with. c, c₁ and c₂ are suitable positive constants; n₀ is the threshold beyond which the inequalities hold. The symbol ∈ means 'belongs to a set'. T(n)∈Θ(n) means T(n) belongs to the class of linearly growing functions.

What is a limit? Little-o and little-omega

A limit describes what a value approaches as the input grows. For 1/n, when n=10,100,1000 the values are 0.1, 0.01, 0.001. They approach zero, although they never equal zero for finite positive n. The limit is zero.

nn/n² = 1/nn²/n = n

n/n² approaches zero, so n grows strictly slower than n²: n∈o(n²). n²/n grows without bound, so n²∈ω(n). Big O and little o are different: n∈O(n) is true, but n∈o(n) is false because n/n=1.

From exact counts to growth rates

Suppose our cost model gives T(n)=3n+3. If n doubles from 100 to 200, the cost changes from 303 to 603, almost twice as much. The constant 3 and the extra +3 affect actual cost but not its long-term growth class. The tight bound is Θ(n).

Big-O is like saying “the cost eventually stays below a constant multiple of this function.” Omega says it stays above a constant multiple; Theta says both are true. For T(n)=3n+3 and n≥1, 3n ≤ T(n) ≤ 6n. That proves Θ(n). A looser upper bound O(n²) is also true but less informative.

Exercise: Is 8n+2 in O(n²)? Is it in Θ(n²)?

Yes to O(n²), no to Θ(n²). Its tight growth rate is linear; (8n+2)/n² tends to zero.

Example: proving a tight bound

T(n) = 3n² + 2n + 5

For n ≥ 1, we have 2n ≤ 2n² and 5 ≤ 5n². Therefore:

3n² ≤ T(n) ≤ 10n²

Choose c₁=3, c₂=10 and n₀=1 to obtain T(n) ∈ Θ(n²). O(n³) is also a valid upper bound, but it is not tight.

Actual function values for n=1…10: T(n) stays between two constant multiples of n².

Common mistake: O does not mean worst case, Ω does not mean best case, and Θ does not mean average case. First choose which input case to analyse (best, worst or average); then give an asymptotic bound on that cost function.

How do we analyse loops?

Algorithm (Python)

i = 0 runs once; i<4 is tested before each iteration; i += 1 adds 1 to i after each body execution. work() is a placeholder function for a job. In real programs its contents must also be analysed. Unless stated otherwise, we assume that it performs a constant amount of work.

In nested loops, the inner counter starts over for each outer iteration. With three outer and two inner iterations, the (i,j) pairs are (0,0),(0,1),(1,0),(1,1),(2,0),(2,1): 3×2=6. If the inner loop depends on i, count each outer iteration separately and add the counts.

Why can shrinking inner work be linear?

At n=16, the outer counter takes values 16,8,4,2,1. Inner calls total 16+8+4+2+1=31. Double the sum to get 32+16+8+4+2=62; subtract the original sum, leaving 32−1=31. For n a power of two, the sum is 2n−1. For every positive integer n, integer halving gives a total at least n and less than 2n. Therefore Θ(n). A logarithmic outer loop alone does not imply n log n work.

09 / COMPARING ALGORITHMS

Linear search or binary search?

What is a search problem? Why are best and worst cases different?

We want to know whether a particular value exists in an array, or find its position. To search for 12 in [8,3,12,5,9], inspect 8, then 3, then 12. Three elements were examined; the result is index 2. If the target is absent, the example Python function returns −1. This is not an error; it is a special value chosen to mean 'not found'.

The best case is the least work among all valid inputs of the same size; the worst case is the most work. For an average case, we must specify how likely each input is. If each of five distinct elements is the target with probability 1/5, the average is (1+2+3+4+5)/5=3 inspections. Different target probabilities change this average.

Why does binary search need sorted data?

Search for 21 in [3,6,9,12,15,18,21,24]. The middle value 12 is less than 21. Every value to the left of 12 is also less than 21. We can safely discard those four elements. This conclusion would not be valid in an unsorted array. Binary search shrinks the candidate region at each inspection.

low and high (or l,r) mark the left and right index of the candidate region. mid is the middle index. The average of 0 and 7 is 3.5; choose integer index 3. Since 12 is too small, the new left index is 4 and 12 is not inspected again. Even the last remaining candidate must be inspected. That is why 1024=2¹⁰ elements may require 11, not 10, middle-element inspections in the worst case.

Best, average and worst: same size, different data

Consider [8, 3, 12, 5, 9]. A linear search for 8 needs one element inspection, for 12 needs three, for 9 needs five, and for 20 also needs five. All inputs have n=5, but the target changes the work.

Linear search

Algorithm (Python)

def linear(a, x):
    n = len(a)
    for i in range(n):
        if a[i] == x:
            return i
    return -1

Sorting is not required. The first element takes one comparison if it is the target. The last element or an unsuccessful search takes n comparisons. For a successful search with equally likely target positions, the expected count is (n+1)/2.

Binary search

Algorithm (Python)

def binary(a, x):
    l, r = 0, len(a) - 1
    while l <= r:
        m = l + (r - l) // 2
        if a[m] == x:
            return m
        if a[m] < x:
            l = m + 1
        else:
            r = m - 1
    return -1

The array must be sorted. Each step eliminates approximately half of the candidate range. For n ≥ 1, at most ⌊log₂ n⌋+1 middle-element inspections are needed.

10 / SPACE COMPLEXITY

How much extra memory is needed?

Bits, bytes and memory space

Memory is the space where a running program stores information. A bit holds 0 or 1. A byte contains 8 bits. For example, a 32-bit integer uses 4 bytes. This illustrates a packed 32-bit value; real Python int objects have different sizes and can grow with the integer value.

Input space is the data given to the algorithm. Auxiliary space is the extra memory needed to process it. Output space is the memory needed to store the result.

nArray of n four-byte integersTwo extra integers
1040 bytes8 bytes
100400 bytes8 bytes
10004000 bytes8 bytes

Space complexity measures the maximum amount of memory needed at one time. If a loop reuses the same variable at each iteration, the previous value is overwritten; n iterations do not create n variables. A program doing n² operations can therefore use Θ(1) extra space.

Memory in bytes versus growth

In a simplified model, if each value occupied a four-byte cell, n values would take 4n bytes and two values eight bytes. This is not the actual size of a Python list. Lists store references (links) to element objects; each int object has its own overhead. Under a fixed-size value assumption, n references require Θ(n) space and a fixed number of references require Θ(1) space. Use import sys followed by sys.getsizeof(a) to inspect the shallow size of the list, not the total size of objects it references.

11 / RECURSION

Recurrence relations

Function calls, base cases and the call stack

A function call asks another piece of code to do a job. If a function calls itself on a smaller problem, this is recursion. A base case is the smallest problem that can be answered directly without another call. Without a base case, the calls may never stop.

A function waiting for another function's result retains its execution state. This information is kept on the call stack. A stack works like a pile of plates: the last call placed on it finishes first. For sum_to(3), four calls with inputs 3,2,1,0 can be active at once.

sum_to(3)sum_to(2)=33+3=6

Before the recurrence: what does recursion mean?

Algorithm (Python)

def sum_to(n):
    if n == 0:
        return 0
    return n + sum_to(n - 1)

Assume n≥0 and small enough not to exceed Python's recursion limit. Our complexity model assumes constant-cost arithmetic. To compute sum_to(3), the function waits for sum_to(2), which waits for sum_to(1), which waits for sum_to(0). The base case stops the calls. The answers return in reverse order.

Expanding a recurrence

If a call costs one unit plus a smaller call, we can model it as T(0)=1 and T(n)=T(n−1)+1. Substitute the formula repeatedly until the base case appears.

T(n)=T(n−1)+1=T(n−2)+2=···=T(0)+n=n+1

T(8)=1+T(4)=2+T(2)=3+T(1)=4. In general T(n)=1+log₂ n.

When an algorithm calls itself on smaller inputs, we can express its cost with a recurrence relation. Assume that the base case has Θ(1) cost.

Decrease by one

T(n)=T(n−1)+Θ(1)

One constant amount of work per level, for Θ(n) levels: Θ(n) time. Stack depth Θ(n).

Divide by two

T(n)=T(⌊n/2⌋)+Θ(1)

A constant amount of work per level, for Θ(log n) levels: Θ(log n) time. Recursive binary search is an example.

Two subproblems, linear merging

T(n)=2T(n/2)+Θ(n)

Θ(n) total work per level, with Θ(log n) levels: Θ(n log n). This is the merge sort recurrence.

Master theorem — basic form

T(n)=aT(n/b)+Θ(nd)

a≥1, b>1 and d≥0 are constants; p=logba.

d<pΘ(np)
d=pΘ(np log n)
d>pΘ(nd)

This simplified form applies to polynomial nonrecursive work. It does not apply to every recurrence (for example, T(n−1)).

How to read a cost recurrence

Translate T(n)=2T(n/2)+n into words: a problem of n elements is split into two subproblems of n/2 elements. Each subproblem costs T(n/2). The current call does n more units of work. This rule relates costs at different input sizes. With T(1)=1, calculate n=8.

LevelNumber of subproblemsSize of eachTotal work

T(8)=2T(4)+8=2(2T(2)+4)+8=4T(2)+16=8T(1)+24=32

The first three levels do eight units each; the final level has eight base calls. For n=2ᵏ, there are k=log₂n splits and k+1 levels. This example totals n(log₂n+1), which is Θ(n log n) for large n.

The letters of the Master theorem and three examples

a is the number of subproblems produced by each call; b is the factor by which the problem size is divided; d is the exponent of non-recursive work, such as splitting or merging. For n¹, d=1; for n², d=2; for constant work n⁰=1, d=0. p=log_b a describes the exponent of the number of leaves.

T(n)=2T(n/2)+n²a=2, b=2, d=2, p=1Θ(n²): top-level work dominates

12 / APPLICATION

Common sorting algorithms

Sorting, comparisons and swaps

Sorting puts an array in a chosen order. We want to turn [3,1,2] into [1,2,3] in ascending order. A comparison determines which of two values is smaller. A swap exchanges two elements' positions. A method can perform many comparisons but few swaps; these are different operation types.

How does sorting actually work?

Sorting arranges data according to a chosen order. We use [5, 2, 4, 1] and ascending order. Selection sort finds the minimum of the unsorted portion and moves it to the front.

PassArray after passComparisons
Start[5, 2, 4, 1]–
1[1, 2, 4, 5]3
2[1, 2, 4, 5]2
3[1, 2, 4, 5]1

Algorithm (Python)

def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if a[j] < a[m]:
                m = j
        if m != i:
            temp = a[i]
            a[i] = a[m]
            a[m] = temp

The comparisons are (n−1)+(n−2)+…+1=n(n−1)/2. Even if the array is already sorted, the standard algorithm still scans the remaining portion. It has Θ(n²) time in all cases, with Θ(1) auxiliary space.

Insertion sort and merge sort: two other ideas

Insertion sort works like arranging cards in your hand. Take the next item and move it left until it fits into the sorted portion: [5] → [2,5] → [2,4,5] → [1,2,4,5]. An already sorted array requires only one key comparison per insertion, while reverse order requires quadratic work.

Merge sort splits the list into halves until each contains one item, then merges sorted pieces: [5,2,4,1] → [5,2] and [4,1] → [5],[2],[4],[1] → [2,5] and [1,4] → [1,2,4,5]. Each level merges a total of n elements; there are about log₂ n levels.

The worst-case lower bound for comparison sorting is Ω(n log n). Non-comparison methods such as counting sort and radix sort use different assumptions.

Bubble sort and quicksort

Bubble sort: compare two neighbouring elements and swap them if they are out of order. [3,1,2] → [1,3,2] → [1,2,3]. The largest element moves to the end on the first pass. A version that stops early when no swaps occur finishes a sorted input in one pass; a reverse-sorted input needs roughly n² comparisons.

Quick sort: choose a pivot (a separating value), place smaller elements on one side and larger elements on the other, then sort both parts. With [5,2,4,1] and pivot 4, the smaller values are [2,1] and the larger values are [5]. Sorting the parts gives [1,2,4,5]. Balanced partitions lead to about log₂n levels with n work per level; if each partition leaves one side empty and the other with n−1 elements, the work becomes n+(n−1)+…+1.

Why is n log n a lower bound for comparison sorting?

There are n! possible orders of n distinct elements. If we use only comparisons with two possible answers, such as 'is a smaller than b?', k comparisons distinguish at most 2ᵏ possible outcome paths. Distinguishing every possible order requires 2ᵏ≥n!, so k≥log₂(n!). Three elements have six orders; two comparisons distinguish at most four possibilities, so at least three are needed in the worst case.

For large n, log₂(n!)=Θ(n log n): the upper bound follows because every one of the n logarithms is at most log₂n; the lower bound follows because the last roughly n/2 terms are at least log₂(n/2). Counting sort uses a limited integer value range; radix sort processes digits. These methods rely on assumptions other than the pure two-value comparison model.

Five steps for analysing code

Worked exam example

Algorithm (Python)

for i in range(n):
    j = 1
    while j < n:
        work()
        j *= 2

1. Input size is n. Assume work() has constant cost. 2. The critical operation is a work() call. 3. For n=8, the outer loop runs eight times and the inner loop runs three times, with j=1,2,4. 4. The work is equal on every outer iteration, so there are 8×3=24 calls. In general the inner loop runs ⌈log₂n⌉ times. 5. The body count is T(n)=n⌈log₂n⌉, with tight growth Θ(n log n). There are only a fixed number of counters, so auxiliary space is Θ(1) if work() also uses constant extra space.

The harmonic sum in the formula summary is H(n)=1+1/2+1/3+…+1/n. For example H(4)=1+0.5+0.333…+0.25≈2.083. The value grows logarithmically. Why? Group terms by powers of two; each complete group adds roughly a constant amount, and there are logarithmically many groups. However, actually adding all n terms one by one takes n operations. The size of a mathematical result is not the same as the cost of computing it.

14 / ACTIVE LEARNING

Test yourself — explained answers

Each option includes its explanation.

1. What is the tight bound for T(n)=7n²+20n+9?

  1. A) Θ(n)✗ Incorrect option

    The linear term 20n is present, but 7n² eventually dominates it. Linear growth is too small to be a tight bound.

  2. B) Θ(n²)✓ Correct answer

    Divide by n²: T(n)/n² = 7 + 20/n + 9/n² → 7. The ratio approaches a positive constant, so the tight bound is Θ(n²).

  3. C) Θ(n³)✗ Incorrect option

    A cubic function grows faster than T(n). O(n³) is a valid upper bound, but Θ(n³) is not a tight bound.

2. A loop starts at i=1 and doubles i while i<n. What is its time complexity? (Constant work per iteration.)

  1. A) Θ(log n)✓ Correct answer

    The values are 1, 2, 4, 8, … . After k iterations, i=2ᵏ; the loop stops when 2ᵏ≥n. For n=16 it runs four times. Thus k=⌈log₂ n⌉.

  2. B) Θ(n)✗ Incorrect option

    Linear growth would result from a fixed increment such as i += 1, not from doubling.

  3. C) Θ(n²)✗ Incorrect option

    Quadratic growth would require work proportional to n². This loop performs only logarithmically many constant-cost iterations.

3. What is the tight worst-case bound for linear search?

  1. A) Ω(1) is the only possible notation✗ Incorrect option

    Ω(1) is a valid but weak lower bound. It is not the only possible notation; Θ can also describe worst-case cost.

  2. B) Θ(n)✓ Correct answer

    If the target is absent or first appears at the last position, the algorithm inspects all n elements. Hence the worst case is Θ(n).

  3. C) Θ(log n)✗ Incorrect option

    Linear search does not discard half the remaining array at each step. It may inspect every element, unlike binary search.

4. What is the solution of T(n)=2T(n/2)+Θ(n), with constant base-case cost?

  1. A) Θ(n)✗ Incorrect option

    Θ(n) accounts for one level only. There are logarithmically many levels of linear work.

  2. B) Θ(n²)✗ Incorrect option

    The number of subproblems doubles per level, but their sizes halve. Total work per level is Θ(n), not Θ(n²).

  3. C) Θ(n log n)✓ Correct answer

    At level 0 the work is Θ(n); at level 1 it is 2·Θ(n/2)=Θ(n). The same holds until the constant-size base cases. There are Θ(log n) internal levels, giving Θ(n log n).

5. Inner loop j=0…i; outer loop i=0…n−1. How many body executions?

  1. A) n²✗ Incorrect option

    n² would count n inner iterations on every outer iteration. Here the inner count starts at 1 and increases.

  2. B) n(n+1)/2✓ Correct answer

    For i=0 the body runs once; for i=1 twice; for i=n−1 it runs n times. Adding 1+2+…+n gives n(n+1)/2. For n=4: 1+2+3+4=10.

  3. C) n log₂ n✗ Incorrect option

    There is no logarithmic loop here. The inner counts grow arithmetically, not by repeated doubling or halving.

6. How much auxiliary space does iterative linear search require, excluding the input array?

  1. A) Θ(1)✓ Correct answer

    Only a fixed number of variables, such as the current index and target, are needed regardless of the array length.

  2. B) Θ(n)✗ Incorrect option

    Θ(n) would be needed if an additional array proportional to n were allocated. The input array is excluded here.

  3. C) Θ(log n)✗ Incorrect option

    A logarithmic call stack can arise in some recursive algorithms. This iterative search creates no such stack.

7. Which input size describes an array of 20 sensor readings?

  1. A) The largest reading✗ Incorrect option

    The largest value is a property of the data, not the number of entries in the array.

  2. B) 20✓ Correct answer

    When analyzing an array scan under the usual fixed-size element model, n is the number of elements. Here n=20.

  3. C) The sum of the readings✗ Incorrect option

    The sum is a computed value and can change even if the array length stays 20.

8. How many condition tests occur in a while loop starting at i = 0, with condition i < 5 and update i += 1?

  1. A) 4✗ Incorrect option

    Four tests omit some successful checks and the final failed check.

  2. B) 5✗ Incorrect option

    Five is the number of successful checks and body executions, not the total number of checks.

  3. C) 6✓ Correct answer

    The condition is tested at i=0,1,2,3,4 (true) and i=5 (false). Five true checks plus one false check make six.

9. Two consecutive loops each run n times, with constant work per iteration. What is the tight bound?

  1. A) Θ(n²)✗ Incorrect option

    Multiplication n×n applies to two fully nested n-iteration loops, not consecutive ones.

  2. B) Θ(n)✓ Correct answer

    The first loop runs n times and the second runs n times: n+n=2n. Ignoring the constant factor gives Θ(n).

  3. C) Θ(1)✗ Incorrect option

    The number of operations grows as n increases, so the cost is not constant.

10. A nested loop has n outer iterations and 5 inner iterations per outer iteration. How many inner body executions?

  1. A) 5n✓ Correct answer

    For each of n outer iterations, the inner body runs five times. For n=3 this is 5+5+5=15. In general the count is 5n, hence Θ(n).

  2. B) n²✗ Incorrect option

    n² assumes n inner iterations per outer iteration. Here there are always five.

  3. C) n+5✗ Incorrect option

    Adding n+5 would not count the five inner executions repeated on every outer iteration.

11. What is the tight bound for T(n)=100n+5?

  1. A) Θ(1)✗ Incorrect option

    The 5 is constant, but the term 100n grows with n. The whole function is not constant.

  2. B) Θ(n)✓ Correct answer

    Divide by n: T(n)/n=100+5/n → 100. A coefficient of 100 may affect actual running time, but not its linear order of growth.

  3. C) Θ(n²)✗ Incorrect option

    There is no quadratic term. O(n²) is a valid but loose upper bound; Θ(n²) is not tight.

12. What must be true before standard binary search on an array?

  1. A) The array must be sorted✓ Correct answer

    For ascending order, if the middle value is smaller than the target, all entries to its left are also smaller. This lets us discard that half safely. Descending order works with reversed comparisons.

  2. B) All values must be positive✗ Incorrect option

    Negative numbers can be searched too. For example, [−8, −3, 0, 4] is sorted and suitable for binary search.

  3. C) The length must be even✗ Incorrect option

    Odd lengths work as well: a sorted array [2, 5, 9] has a middle element and can be searched.
