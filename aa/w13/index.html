Week 13 / 14 · Grid dynamic programming and the Bellman idea

How can I reuse work across routes?

10 min · Engineering question

The robot inspects a fixture row by row. It may move only right or down. The task is to minimize the cost of entering cells. A partial route can be reused by many candidate routes.

25 min

Trace it on paper

Use the 3 × 3 cost grid [0,4,1] / [1,8,1] / [1,1,1]. Start at the top left with cost zero. Fill each cell from the cheaper reachable predecessor above or to the left, plus its entry cost. Write a parent and reconstruct the goal route.

Write your trace first. Compare your steps, then explain why the method works in three sentences.

Check your trace

The best-cost rows are [0,4,5], [1,9,6], [2,3,4]. Down, down, right, right costs 4. Each cell is computed once. This is the Bellman idea in this setting: the best cost to a state comes from a best predecessor cost plus a move. Related state and cost ideas also appear in optimal control.

20 min

Measure it

Compare repeated recursive calls with table filling on 5 × 5 and 9 × 9 grids. Record the call count and filled-cell count as different units. Compare timings. Discuss when a single row of storage would be enough.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

def recursive_cost(grid):
    calls = 0

    def cost(r, c):
        nonlocal calls
        calls += 1
        if r == c == 0:
            return 0
        above = cost(r - 1, c) if r else float("inf")
        left = cost(r, c - 1) if c else float("inf")
        return grid[r][c] + min(above, left)

    total = cost(len(grid) - 1, len(grid[0]) - 1)
    return total, calls


def table_cost(grid):
    width = len(grid[0])
    best = [[0] * width for _ in grid]
    for r, row in enumerate(grid):
        for c, entry in enumerate(row):
            if r == c == 0:
                continue
            above = best[r - 1][c] if r else float("inf")
            left = best[r][c - 1] if c else float("inf")
            best[r][c] = entry + min(above, left)
    return best[-1][-1], len(grid) * width


for n in (5, 9):
    grid = [[1 + (3 * r + 2 * c) % 9 for c in range(n)] for r in range(n)]
    slow, fast = recursive_cost(grid), table_cost(grid)
    assert slow[0] == fast[0]
    print(n, "-> (cost, recursive calls), (cost, table cells):", slow, fast)
    measure(f"{n}: recursion", lambda: recursive_cost(grid), repeats=3)
    measure(f"{n}: table", lambda: table_cost(grid))

Exam-style questions

  1. What is the best cost to the center?

    Show answer

    9, from the left.

  2. If only cost is needed, how can storage shrink?

    Show answer

    Keep one row and update it from left to right, reading the old entry above and the new entry on the left.

  3. Can this one-pass fill handle moving up and left too?

    Show answer

    No. Those moves can create cycles. For a nonnegative grid with such moves, use a path search such as Dijkstra.

More practice

  1. What is the base cost at the start?

    Show answer

    0.

  2. How do you fill a cell in the top row beyond the start?

    Show answer

    Use the predecessor on the left.

  3. What is the best cost to the goal?

    Show answer

    4.

  4. How many cells does a 10 × 20 table store?

    Show answer

    200.

  5. What else do you need for straightforward route reconstruction?

    Show answer

    A table of predecessor choices.
