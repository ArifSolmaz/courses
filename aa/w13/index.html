Week 13 / 14 · Grid dynamic programming and the Bellman idea

How can I reuse work across routes?

15 min · Engineering question

The robot inspects a fixture row by row. It may move only right or down. The task is to minimize the cost of entering cells. A partial route can be reused by many candidate routes.

Build the best route from saved partial results

You will be able to

  • Identify the state and base case.
  • Compute a cell from reachable predecessors.
  • Store a parent for route recovery.
  • Compare full-table and one-row memory.

Before you start

In a right-and-down grid, every legal predecessor is either immediately above or to the left.

Dynamic programming stores the answer to each smaller problem. Here a state is a cell, and its saved value is the cheapest cost of reaching it. Start with cost zero at S. For every other cell, choose the cheaper reachable predecessor and add the cell’s entry cost.

Rows left to right and top to bottom place both predecessors before the current cell. With a full table, one parent per cell gives a route. If only the final cost is needed, a one-row array can reuse each slot after its above value has been read.

The parent chain gives down then right. In one-row storage, start the second row with [0, 4]. Updating the left entry gives 2. The next entry compares the new left 2 with the old above 4.

What exactly are we minimizing?

Imagine a probe inspecting a fixture. Moving into a cell consumes the number of energy units written in that cell. The probe starts at (0,0), ends at the bottom right, and may move only right or down. Starting is free: the entry value at (0,0) is ignored. A blocked cell cannot be entered, including a blocked start or goal.

We need one legal route with the smallest sum of entered-cell costs. Coordinates are zero-based (row, column). The grid is fixed during one calculation. Future options depend only on the current cell; there is no battery constraint, turn penalty or changing terrain in this model.

Remember: Week 8 · Fewest moves does not mean cheapest

On an open 3 × 3 right/down grid, every start-to-goal route has four moves. In the paper grid, down–down–right–right costs 4, while right–right–down–down costs 7. BFS minimizes moves and does not distinguish these terrain costs.

Remember: Week 12 · A route and a wiring network have different goals

Kruskal selected AB=1, BC=2 and CD=4 for total cable cost 7, connecting all four stations. Here a route visits only the cells it needs, and pays their entry costs. A spanning tree or DSU does not solve this route recurrence.

Give every cell one precise question

D[r,c] means “the minimum cost of a legal route from the start to (r,c).” It is a total from the start, not the cell’s own entry cost and not a remaining-distance estimate. Let w[r,c] be the entry cost. Let ∞ mean unreachable.

D[0,0] = 0 if the start is open.
D[r,c] = ∞ for blocked cells.
Otherwise D[r,c] = w[r,c] + min(D[r−1,c], D[r,c−1]).

For a missing predecessor outside the grid, use ∞. Apply the start rule before the general rule. If both predecessors are unreachable, ∞ plus the entry cost stays ∞. The top row can only come from the left; the left column can only come from above.

Why is keeping only the best prefix safe?

Every route into (r,c) must finish with a move from above or from the left. Suppose an optimal route uses a more expensive prefix to its predecessor. Replacing that prefix with a cheaper one preserves all future options and reduces the total, contradicting optimality. Therefore comparing the two best predecessor costs is sufficient. This is the Bellman principle of optimality for this model.

If arriving facing north and arriving facing east have different future turn costs, they are different states. A suitable state could be (r,c,direction); merging them into one cell value can lose the best solution.

Remember: Week 9 · The same relaxation, a simpler schedule

Dijkstra tests a candidate such as 2+1=3 against a saved cost 5 and improves it to 3. Here the goal compares 6+1=7 from above with 3+1=4 from the left. Both predecessors are already final, so one calculation is enough.

Remember: Week 11 · The grid is a directed acyclic graph

For boot→scan→map, a valid order computes boot before scan before map. Grid moves similarly point right or down. Each move increases r+c by 1, so returning to an earlier cell is impossible. Row-by-row order is one valid topological order.

Three ways to evaluate the same recurrence

A recursive solution asks for the goal, then asks for its two predecessors, and continues backward. The problem is repeated work: cost(2,2) requests cost(1,2) and cost(2,1); both request cost(1,1). A plain function recomputes that shared subproblem.

Memoization: ask recursively, remember the answer

Use a cache keyed by (r,c). The first request for (1,1) computes 9; later requests return 9 immediately. With a fresh cache for each fixed grid, there are at most RC different states. A cached function must not silently reuse old answers after the grid changes.

Tabulation: calculate in a known order

Fill row 0, then row 1, then row 2, from left to right. At (1,1), above=4 and left=1 have already been computed. The answer is 8+min(4,1)=9. There is no recursion stack and no need to discover the dependency order at runtime.

Plain recursion, memoization and tabulation implement the same mathematical recurrence. Recursion alone is not dynamic programming: it must avoid solving the same state repeatedly. The lab deliberately keeps plain recursion so you can measure the repeated work.

Remember: Week 6 · Reuse an established result

Merging sorted [1,4] and [2,3] produces [1,2,3,4] by using the already-sorted halves. Dynamic programming also builds on solved smaller problems, but overlapping states matter: cost(1,1) is requested through both cost(1,2) and cost(2,1).

Remember: Week 5 · Cache by the complete state

An exact lookup for key 8 must distinguish it from key 9. Memoization uses (r,c) as the key: a second request for (1,1) returns the saved 9 in the paper grid. If remaining battery changes legal futures, (r,c) alone is no longer a sufficient key.

Remember: Week 3 · Order must match the operation

Binary search can halve a sorted list: for [2, 5, 8, 11], comparing 8 with key 5 discards the right part. Here the useful order is dependency order, not numeric order. Sorting the costs [4, 1, 8] would destroy their locations.

One row of storage: old above, new left

For the paper grid, the finished first row is [0,4,5]. While processing row 1, best[c] still holds the value from above until it is overwritten. best[c−1] already holds the value from the current row.

Row 2 then changes [1,9,6] → [2,9,6] → [2,3,6] → [2,3,4]. The final slot contains the answer 4. A blocked cell must reset its slot to ∞; leaving its old value would permit a route through a wall.

A tiny counterexample to right-to-left updates

Use [0,4] / [2,1]. Before row 1, storage is [0,4]. If you update the right slot first, it reads old-left=0 and old-above=4 and writes 1. That incorrectly pretends the start is directly left of the goal. Left-to-right updates give [2,4] then [2,3], the correct answer 3.

One-row storage returns a cost, not the full parent chain. If a full cost table is retained, a route can be recovered by checking which predecessor satisfies the recurrence; a parent table makes recovery direct. With only one row, older rows are gone, so recovering a route needs additional storage or recomputation.

Remember: Week 4 · A physical slot can change meaning

In a capacity-4 ring buffer, advancing head from 3 wraps to 0. Storage is reused while logical order is preserved. Here best[c] changes from “previous row, column c” to “current row, column c”; read the old value before overwriting it.

A small complete program: cost, route and obstacles

This independent example uses integers for costs and None for walls. It validates a nonempty rectangular grid, prefers the upper predecessor on equal costs, and returns (None, []) if no route exists. route_plan stores costs and parents; row_cost keeps only one cost row. Neither changes the input.

The code permits negative integer costs: right/down moves form an acyclic graph, so the recurrence still works. The energy examples use nonnegative costs. Do not transfer this allowance to ordinary Dijkstra on a graph with negative edges.

def validate(grid):
    if not grid or not grid[0]:
        raise ValueError("Use a nonempty rectangular grid")
    width = len(grid[0])
    if any(len(row) != width for row in grid):
        raise ValueError("Rows must have equal length")
    if any(value is not None and type(value) is not int
           for row in grid for value in row):
        raise ValueError("Use integer costs or None for blocked cells")


def route_plan(grid):
    validate(grid)
    rows, cols = len(grid), len(grid[0])
    inf = float("inf")
    best = [[inf] * cols for _ in grid]
    parent = [[None] * cols for _ in grid]
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] is None:
                continue
            if r == c == 0:
                best[r][c] = 0  # Starting is free.
                continue
            above = best[r - 1][c] if r else inf
            left = best[r][c - 1] if c else inf
            if min(above, left) == inf:
                continue
            # On a tie, choose above.
            parent[r][c] = (r - 1, c) if above <= left else (r, c - 1)
            best[r][c] = min(above, left) + grid[r][c]
    if best[-1][-1] == inf:
        return None, []
    path = []
    cell = (rows - 1, cols - 1)
    while cell is not None:
        path.append(cell)
        r, c = cell
        cell = parent[r][c]
    return best[-1][-1], path[::-1]


def row_cost(grid):
    validate(grid)
    inf = float("inf")
    best = [inf] * len(grid[0])
    for r, row in enumerate(grid):
        for c, entry in enumerate(row):
            if entry is None:
                best[c] = inf  # Erase the old value from above.
            elif r == c == 0:
                best[c] = 0
            else:
                above = best[c]
                left = best[c - 1] if c else inf
                best[c] = min(above, left) + entry
    return None if best[-1] == inf else best[-1]


grid = [[0, 4, 1], [1, 8, 1], [1, 1, 1]]
total, path = route_plan(grid)
print("Cost:", total)
print("Path:", path)
print("One row:", row_cost(grid))
assert total == row_cost(grid) == 4

blocked = [[0, 2, 3], [1, None, 1], [4, 1, 1]]
print("Obstacle:", route_plan(blocked)[0])
assert route_plan(blocked)[0] == row_cost(blocked) == 7
sealed = [[0, None], [None, 1]]
print("No route:", route_plan(sealed))
assert route_plan(sealed) == (None, [])
assert row_cost(sealed) is None
assert route_plan([[9]]) == (0, [(0, 0)])

Predict, run, explain

  1. Change the center 8 to 0 in the first grid. The optimum becomes 3. Update the expected assertion from 4 to 3 before running.
  2. Run route_plan([[9]]). It returns (0, [(0,0)]): an open start that is already the goal needs no move and has zero cost.
  3. Run route_plan([[None]]). It returns (None, []): a blocked start is not a zero-cost route.
  4. In the obstacle grid, both alternatives cost 7. The upper-predecessor tie rule selects the route along the top and right borders. A different tie rule can return a different equally good route.

Check a returned route independently: it must start at (0,0), end at the goal, avoid None, use only steps (0,+1) or (+1,0), and have an entered-cell sum equal to the reported cost. These checks establish feasibility and the stated cost; proving minimality still needs the recurrence argument or an independent search on small cases.

When this method applies—and when the state must change

Cheapest next step can be a trap

Consider [0,1,50] / [2,9,1] / [2,2,1]. Choosing the cheaper immediate neighbor leads right (1), down (9), right (1), down (1): total 12, using right to break the tie after 9. The route down, down, right, right costs 2+2+2+1=7. Dynamic programming compares complete prefix costs; it does not commit to the cheapest next cell.

Why one pass stops working with backward moves

If up and left are allowed, a cell may depend on a value that appears later in the scan. The graph can have cycles, so this row order no longer finalizes every predecessor. For arbitrary nonnegative movement costs, use a suitable shortest-path algorithm such as Dijkstra. With equal costs, BFS suffices. Negative edges require further analysis; a reachable negative cycle on a route to the goal can make a finite minimum impossible.

Two useful transfers

Layered production: a part advances through stages; keep the cheapest cost of reaching each station, using the best previous-stage station plus its transition cost. Route counting: on the same right/down grid, replace min-plus by addition: ways[r,c]=ways[r−1,c]+ways[r,c−1], with start=1 and walls=0. An open 2 × 2 grid has two routes; an open 3 × 3 grid has six. The dependency order stays the same while the meaning of the stored answer changes.

Remember: Week 7 · Do we need a priority queue?

A min-heap with priorities 5 and 2 removes 2 first. Dijkstra needs that selection rule. In this grid, (1,1) can be finalized after (0,1) and (1,0), even if another cell has a smaller cost. A known dependency order removes the need for heap selection.

Remember: Week 10 · A heuristic is optional, not the recurrence

A* orders candidates by f=g+h; g=2 and h=3 give f=5. This lesson stores exact cost-to-reach values D, not estimates h. It fills the table in dependency order without a goal-directed priority.

Work, memory and what the timer includes

For an R × C grid, tabulation takes Θ(RC) time and Θ(RC) auxiliary space. A parent table also takes Θ(RC), and recovering one right/down path takes O(R+C) time and output space. One-row cost calculation takes Θ(RC) time and Θ(C) auxiliary space. These bounds assume unit-cost integer arithmetic; very large integers can make arithmetic more expensive.

Memoization uses O(RC) cached answers and O(R+C) recursion-stack depth. Plain recursion also has O(R+C) maximum stack depth but repeats subproblems. On an open n × n grid, the number of monotone routes is binomial(2n−2,n−1), which grows exponentially with n. Do not describe recursion’s time as quadratic just because there are n² distinct cells.

The starter lab accepts a nonempty rectangular numeric grid without obstacles. Use the small complete program for None walls and route recovery. The starter counts the free start as a table cell, even though its update is skipped. The recursive counter counts every invocation, including repeated states and base cases.

For n=5, both methods return cost 31: 251 recursive calls versus 25 table cells. For n=9, cost is 64: 48,619 calls versus 81 cells. Those operation counts explain growth, but their ratio is not a predicted runtime ratio because a call and a cell update have different overheads.

The timer includes each function’s allocation, computation and counting. Grid creation, result printing and the outer correctness assertion are outside the timed call. The table and recursion use different repeat counts, but both times are normalized per call. A maximum of five batch averages is neither a worst-case runtime proof nor the slowest individual call.

Remember: Week 1 · Count work before timing

A scan of [2, 7, 9] for the first value ≥7 makes two checks and returns index 1. Here count recursive calls and table cells separately: 251 calls and 25 cells are different units of work.

Remember: Week 2 · Name both input dimensions

An n × n pair loop performs n² iterations. This grid has R rows and C columns, so filling it takes RC cell visits; doubling both dimensions gives four times as many cells.

Measure it

Compare repeated recursive calls with table filling on 5 × 5 and 9 × 9 grids. Record the call count and filled-cell count as different units. Compare timings. Discuss when a single row of storage would be enough.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

def recursive_cost(grid):
    calls = 0

    def cost(r, c):
        nonlocal calls
        calls += 1
        if r == c == 0:
            return 0
        above = cost(r - 1, c) if r else float("inf")
        left = cost(r, c - 1) if c else float("inf")
        return grid[r][c] + min(above, left)

    total = cost(len(grid) - 1, len(grid[0]) - 1)
    return total, calls


def table_cost(grid):
    width = len(grid[0])
    best = [[0] * width for _ in grid]
    for r, row in enumerate(grid):
        for c, entry in enumerate(row):
            if r == c == 0:
                continue
            above = best[r - 1][c] if r else float("inf")
            left = best[r][c - 1] if c else float("inf")
            best[r][c] = entry + min(above, left)
    return best[-1][-1], len(grid) * width


for n in (5, 9):
    grid = [[1 + (3 * r + 2 * c) % 9 for c in range(n)] for r in range(n)]
    slow, fast = recursive_cost(grid), table_cost(grid)
    assert slow[0] == fast[0]
    print(n, "-> (cost, recursive calls), (cost, table cells):", slow, fast)
    measure(f"{n}: recursion", lambda: recursive_cost(grid), repeats=3)
    measure(f"{n}: table", lambda: table_cost(grid))

Plan with a reduced memory budget

A right-and-down inspection grid has 50 rows and 80 columns. Each stored cost needs four bytes and each stored parent direction one byte. The planning scratch budget is 1 KiB.

Start individually for 10 minutes. Work with a partner for 20. Spend the last 15 comparing with another pair and revising your recommendation.

  1. Estimate cost-table and parent-table bytes. Decide whether a one-row cost update fits.
  2. Explain which result is available from one row and what would have to be added or recomputed to recover a route.
  3. Describe how an unreachable destination should be represented. Check a first-row obstacle with a paper example.
Compare a model answer

The full cost and parent arrays need 16,000 and 4,000 bytes respectively before overhead. One cost row needs 320 bytes. It gives the final cost but does not retain all parents. Route recovery needs more storage, recomputation or a different reconstruction strategy. Use a separate unreachable value, and never turn an unreachable predecessor into a finite cost.

Interpret the memory budget correctly

Here 1 KiB=1024 bytes, and the arithmetic describes packed fixed-width values, not the actual memory of Python lists and int objects. There are 50×80=4000 cells: costs use 4000×4=16,000 bytes and directions use 4000×1=4,000 bytes, totaling 20,000. One row uses 80×4=320 bytes, leaving 704 bytes in the budget. This budget assumes the input grid is stored elsewhere and output-route storage is considered separately. With fixed-width numbers, also design for overflow and the unreachable sentinel.

Why does updating a one-row table from right to left give the wrong predecessor for this recurrence?

Compare a sample exit answer
