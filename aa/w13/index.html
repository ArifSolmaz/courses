Dynamic programming: edit distance, partition, TSP

Build and interpret a small edit-distance table. Extend the state–transition–order method to linear partition, and see where the principle of optimality holds but the table is too big.

Exam scope: Final (emphasis)Cumulative review

By the end of this week you can…

  • Define the edit-distance state D(i,j), write its recurrence and fill a small table.
  • Reconstruct the edit sequence from a filled table.
  • Formulate linear partition as a DP: state, recurrence, fill order, cost O(kn²).

What information must a state retain for the remaining decision?

Find the edit distance from cat to cut, with insertion, deletion and substitution cost 1.

Step 1

Let D(i,j) be the distance between the first i source and first j target characters.

Step 2

Set D(i,0)=i and D(0,j)=j.

Step 3

Use the minimum of deletion D(i−1,j)+1, insertion D(i,j−1)+1 and diagonal D(i−1,j−1)+[characters differ].

Step 4

Rows including the empty prefix are [0,1,2,3], [1,0,1,2], [2,1,1,2], [3,2,2,1]. The answer is 1: substitute a→u.

Change the case. The final value is a cost, not the edit sequence. Retain or reconstruct predecessor choices to explain the edits. This table has O(mn) states.

Where an engineer meets this

A wrist accelerometer records a gesture as a series of samples. The same gesture done slowly and quickly gives series of different lengths with shifted peaks, so comparing sample i with sample i fails. Dynamic time warping (DTW) lets one sample match several.

DTW is edit distance for numbers: D[i,j] = |aᵢ − bⱼ| + min(D[i−1,j], D[i,j−1], D[i−1,j−1]). The three predecessors play the roles of deletion, insertion and match. Filling the table costs O(nm); two series of 100 samples need 10 000 cells, fine on a microcontroller. A band near the diagonal cuts time and memory when speeds differ by a bounded factor.

Mini-problem. a = [1, 3, 3, 1], b = [1, 3, 1]. Fill the DTW table and give the distance. What does sample-by-sample comparison of the first three samples give?

Check your answer

Rows for a, columns for b: [0, 2, 2], [2, 0, 2], [4, 0, 2], [4, 2, 0]. DTW distance 0: both 3s of a match the single 3 of b. Sample-by-sample: |1−1| + |3−3| + |3−1| = 2.

Question 1 · easy

With insertion, deletion and substitution each costing 1, what is the Levenshtein edit distance between “flaw” and “lawn”?

  1. 1
  2. 2
  3. 3
  4. 4

Answer: option B. Delete the f, insert the n.

Question 2 · easy

The length of the longest common subsequence of ABC and BCA is:

  1. 1
  2. 2
  3. 3
  4. 0

Answer: option B. BC appears in order in both; no three letters do.

Question 3 · easy

Why do many dynamic programs on two strings use only polynomially many states?

  1. the characters can be freely rearranged
  2. a state can use two prefix lengths, giving (m + 1)(n + 1) pairs
  3. randomness removes all repeated work
  4. a hash table makes every state unnecessary

Answer: option B. There are only (m + 1)(n + 1) pairs of prefix lengths. This is a useful property of these string problems, not a claim that dynamic programming works only on strings or always has polynomially many states.

Question 4 · easy

Dynamic programming solves TSP in O(n² 2ⁿ) because its state records:

  1. a prefix of the cities in a fixed order
  2. the set of cities visited so far and the current city
  3. only the current city
  4. a complete permutation of the cities

In simpler words: Count the information a TSP subproblem must remember.

Starting hint: Current city alone cannot tell which cities remain.

Answer: option B. There are 2ⁿ subsets times n current cities, each state costing O(n) to fill.

Step by step
  1. There are at most 2ⁿ visited sets and n current cities.
  2. Trying at most n transitions per state gives O(n²2ⁿ). Memoisation avoids repeats but cannot remove the exponential number of sets.

Question 5 · easy · course question

A gesture template has 100 samples and a live recording has 120. Filling the full dynamic-time-warping table costs about:

  1. 220 cell updates.
  2. 12 000 cell updates.
  3. 100 × lg 120 cell updates.
  4. 2¹⁰⁰ cell updates.

Answer: option B. DTW fills an n × m table with constant work per cell: 100 × 120 = 12 000. It is the same table shape as edit distance.

Question 7 · medium

Question 9 · medium

What is the length of a strictly increasing subsequence of maximum length in 3, 1, 4, 1, 5, 9, 2, 6?

  1. 3
  2. 4
  3. 5
  4. 6

Answer: option B. For example 3, 4, 5, 6 or 1, 4, 5, 9; no five elements increase.

Question 10 · medium

What is the maximum sum of a nonempty contiguous stretch of [2, −5, 3, 4, −1, 2]?

  1. 7
  2. 8
  3. 9
  4. 10

Answer: option B. 3 + 4 − 1 + 2 = 8, found by best[i] = max(a[i], best[i − 1] + a[i]).

Question 11 · medium

With only 1 egg and an 8-floor building, the number of drops needed in the worst case to find the critical floor is:

  1. 3
  2. 4
  3. 8
  4. 1

Answer: option C. You cannot risk breaking the only egg, so you must test floors 1, 2, 3, … in order.

Question 12 · medium

Which running time is pseudo-polynomial because it depends on a binary-encoded target value T rather than its bit length?

Answer & reasoning

Question 15 · easy

What is the length of the longest increasing subsequence of 5, 1, 6, 2, 7? Give an example.

Answer & reasoning

Question 16 · easy

Split {1, 2, 3, 4, 5}, in this order, into 2 contiguous ranges so that the larger range sum is as small as possible. What is that sum?

Answer & reasoning

The four nonempty cuts after positions 1, 2, 3 and 4 give maximum sums 14, 12, 9 and 10. The minimum is 9, achieved by {1, 2, 3} | {4, 5}. A cut before the first element would create an empty range and is not included.

Question 17 · easy

State the principle of optimality in one sentence and give one algorithm from the notes that relies on it.

Answer & reasoning

Once the state contains all information that can affect future choices, an optimal solution can use optimal subproblem solutions. In edit distance the state is a pair of prefix lengths; for shortest paths, a shortest route has shortest subroutes. This principle alone does not justify Dijkstra’s settled-once order, which also needs nonnegative edges.

Question 18 · medium

With coins of value 1, 3 and 4, make change for 6 using the fewest coins. Compare the greedy rule (always take the largest coin that fits) with dynamic programming.

Answer & reasoning

greedy takes 4, then 1, then 1: three coins. DP with best[a] = 1 + min(best[a − 1], best[a − 3], best[a − 4]) gives best[6] = 2 (3 + 3). Greedy fails; the DP considers every last coin.

Question 19 · medium

Fill in the edit-distance table for turning “sun” into “snow”, and read off the distance and an edit sequence.

Answer & reasoning

rows for the prefixes of “sun” against columns for the prefixes of “snow”: row 0: 0 1 2 3 4; row s: 1 0 1 2 3; row u: 2 1 1 2 3; row n: 3 2 1 2 3. Distance 3: keep s, substitute u → n, substitute n → o, insert w.

Question 20 · medium

Find the longest common subsequence of AGGTAB and GXTXAYB.

Answer & reasoning

GTAB, of length 4. (The table’s bottom-right entry is 4; tracing back the matches gives G, T, A, B.)

Question 21 · medium

Items have (weight, value) (1, 1), (3, 4), (4, 5), (5, 7) and the knapsack holds weight 7. Each item may be taken at most once. What is the best total value, and what DP recurrence solves it?

Answer & reasoning

9, taking the items of weight 3 and 4. Let V[i, w] be the best value using the first i items within weight w: V[i, w] = max(V[i − 1, w], V[i − 1, w − wᵢ] + vᵢ) when wᵢ ≤ w, else V[i − 1, w]; the table has (n + 1)(W + 1) cells.

Question 22 · medium

You leave mile 0 with a full tank; the car goes 60 miles on a tank. Stations are at miles 40, 70, 120 and 150, and the destination is at mile 190. What is the minimum number of fill-ups, and where?

Answer & reasoning

4, at 40, 70, 120 and 150. From 0 the only reachable station is 40; from 40, only 70 (120 is 80 miles away); from 70, only 120; from 120, only 150; from 150 the destination is 40 miles away. The recurrence G[i] = 1 + min over reachable j of G[j] gives the same count; here the “drive as far as you can” greedy also works because fill-ups are all equal in cost.

Question 23 · medium

A 10-character string must be broken after positions 2 and 5; breaking a string of length L costs L. What is the cheapest order and its cost?

Answer & reasoning

break at 5 first (cost 10), leaving a piece of length 5 that is then broken at 2 (cost 5): total 15. Breaking at 2 first costs 10 + 8 = 18. The DP C[i, j] = (j − i) + min over breaks k of C[i, k] + C[k, j] computes 15.

Question 24 · medium

Find the maximum sum of a contiguous stretch of the array [−2, 1, −3, 4, −1, 2, 1, −5, 4] using a one-pass DP.

Answer & reasoning

let best[i] be the best sum of a stretch ending at position i: best[i] = max(a[i], best[i − 1] + a[i]). The values are −2, 1, −2, 4, 3, 5, 6, 1, 5, and the answer is the maximum, 6, from the stretch 4, −1, 2, 1.

Question 25 · medium

Find the length of the longest palindromic subsequence of “character”, and say how to compute it with a tool from the notes.

Answer & reasoning

The length is 5; “carac” is a palindromic subsequence of “character”. An LCS computation against the reverse gives the correct optimal length, but an arbitrary reconstructed LCS need not itself be a palindrome. To recover a palindrome reliably, use interval DP: L[i,j] = 2 + L[i+1,j−1] when the endpoint characters match, otherwise max(L[i+1,j], L[i,j−1]); base cases are 0 for an empty interval and 1 for a single character.

Question 26 · medium

Why is filling the edit-distance table row by row, left to right, a valid evaluation order? Name one other valid order.

Answer & reasoning

cell (i, j) needs (i − 1, j − 1), (i, j − 1) and (i − 1, j), all of which lie in an earlier row or earlier in the same row. Column by column, top to bottom, works for the same reason; so does going along anti-diagonals.

Question 27 · medium

The travelling salesman problem satisfies the principle of optimality, yet dynamic programming does not make it polynomial. Explain exactly where the exponential comes from.

In simpler words: Count the states rather than assuming DP means polynomial.

Starting hint: Remember both the current city and the set already visited.

Answer & reasoning
Step by step
  1. A set of n cities has 2ⁿ subsets. The current city adds at most n possibilities.
  2. Each state considers at most n previous cities or next transitions, depending on the formulation.
  3. Multiplying gives O(n²2ⁿ). Reusing states beats enumerating n! tours, but there are still exponentially many states.

the state must record which cities have already been visited, because the best way to finish depends on it; that state is an arbitrary subset of the n cities, and there are 2ⁿ subsets. With n choices of current city the table has n · 2ⁿ entries, each costing O(n): O(n² 2ⁿ), much better than n! but still exponential. In string problems the corresponding state is a prefix, and there are only n of those.

Question 28 · medium

Greedy set cover repeatedly picks the subset covering the most still-uncovered elements. Give an instance where it does not find the smallest cover.

In simpler words: Make the largest first set leave two awkward uncovered elements.

Starting hint: Give those two elements different remaining sets.

Answer & reasoning
Step by step
  1. S₁ covers four elements, so greedy takes it first.
  2. Element 5 then requires S₂, and element 6 requires S₃: three sets total.
  3. But S₂∪S₃ already equals the whole universe. Two sets suffice, while no single listed set covers it.

U = {1, 2, 3, 4, 5, 6}, S₁ = {1, 2, 3, 4}, S₂ = {1, 2, 5}, S₃ = {3, 4, 6}. Greedy picks S₁ (4 new elements), then needs both S₂ and S₃ for 5 and 6: three sets. But S₂ and S₃ alone cover everything: two sets.

Question 29 · medium

Gesture template a = [1, 3, 3, 1] and recording b = [1, 3, 1]. Fill the dynamic-time-warping table D[i,j] = |aᵢ − bⱼ| + min(D[i−1,j], D[i,j−1], D[i−1,j−1]) with D[1,1] = |a₁ − b₁| and edges taken as ∞, give the DTW distance and the matching (warping path), and compare with sample-by-sample comparison of the first three samples.

Answer & reasoning

Local costs |aᵢ − bⱼ|, rows a = 1, 3, 3, 1 and columns b = 1, 3, 1: row 1 [0, 2, 0], row 2 [2, 0, 2], row 3 [2, 0, 2], row 4 [0, 2, 0]. Fill: D[1,1] = 0; D[1,2] = 2 + 0 = 2; D[1,3] = 0 + 2 = 2. D[2,1] = 2 + 0 = 2; D[2,2] = 0 + min(2, 2, 0) = 0; D[2,3] = 2 + min(2, 0, 2) = 2. D[3,1] = 2 + 2 = 4; D[3,2] = 0 + min(0, 4, 2) = 0; D[3,3] = 2 + min(2, 0, 0) = 2. D[4,1] = 0 + 4 = 4; D[4,2] = 2 + min(0, 4, 4) = 2; D[4,3] = 0 + min(2, 2, 0) = 0. DTW distance D[4,3] = 0. Path: (1,1), (2,2), (3,2), (4,3): both 3s of a match the single 3 of b, so the slower gesture is stretched onto the faster one at zero cost. Sample-by-sample on the first three samples: |1 − 1| + |3 − 3| + |3 − 1| = 2, and the fourth sample of a has no partner at all. The table has 4 × 3 = 12 cells: O(nm), the same shape as edit distance, with the three predecessors playing the roles of deletion, insertion and match.

Question 30 · hard

Give a DP for the longest path from s in a DAG, then explain why the same idea fails on a graph with cycles.

In simpler words: Change DAG shortest-path minimisation into maximisation.

Starting hint: Use minus infinity for an unreachable vertex so it cannot win a maximum.

Answer & reasoning
Step by step
  1. Set long[s]=0, all other values to −∞, and process topological order.
  2. For each reachable u, update long[v]=max(long[v],long[u]+w(u,v)).
  3. With cycles, a simple path must remember used vertices to avoid repetition. A state containing only the current vertex loses that information.

Initialise long[s] = 0 and every other value to −∞. In topological order, for every edge u→v from a reachable u, update long[v] = max(long[v], long[u] + w(u,v)). This takes O(n + m). In a cyclic graph, the longest simple path depends on which vertices have already been used, so the vertex alone is not a sufficient state. The longest-simple-path decision problem is NP-complete; the optimisation problem is NP-hard.

Question 31 · hard

Extend edit distance so that swapping two adjacent characters (“teh” → “the”) costs 1 instead of 2. Give the extra case in the recurrence.

In simpler words: Add a local case for swapping the last two characters.

Starting hint: Only use the new case when those characters match in reverse order.

Answer & reasoning
Step by step
  1. Suppose s ends in …ab and t ends in …ba at the prefixes being compared.
  2. Besides insertion, deletion and substitution, allow the cost for the prefixes two characters shorter, plus 1.
  3. This restricted recurrence gives optimal string alignment distance. It does not allow every combination of overlapping edits that unrestricted Damerau–Levenshtein permits.

For i,j ≥ 2, if s[i] = t[j−1] and s[i−1] = t[j], also consider D[i−2,j−2] + 1. Keep the usual insertion, deletion and substitution cases. This computes the restricted optimal-string-alignment distance, where a substring is not edited repeatedly. Fully unrestricted Damerau–Levenshtein distance requires more state; the extra local case alone does not compute it.

Question 32 · hard

Partition the sequence 3, 1, 4, 1, 5, 9, 2, 6 into 3 contiguous ranges minimising the largest range sum. Give the optimum and prove no better value exists.

In simpler words: Find a good split, then prove every smaller cap fails.

Starting hint: Test the cap 13 by packing each positive range as far right as possible.

Answer & reasoning
Step by step
  1. A cap of 14 works: [3,1,4,1] | [5,9] | [2,6], with sums 9,14,8.
  2. With cap 13, maximal packing gives [3,1,4,1] | [5] | [9,2] | [6]: four ranges.
  3. For positive entries, ending any earlier range sooner cannot improve how far the same number of ranges reaches. So three ranges cannot fit under 13, proving optimum 14.

The optimum is 14: 3,1,4,1 | 5,9 | 2,6 has sums 9,14,8. To rule out 13, greedily pack each range as far as possible under that cap: [3,1,4,1], [5], [9,2], [6]. Four ranges are needed. For positive entries, cutting an earlier range sooner cannot let any later range end farther right than this maximal packing, so three ranges cannot achieve cap 13. Hence 14 is optimal.

Question 33 · hard

You have 2 eggs and a 10-floor building. What is the minimum number of drops that always finds the critical floor, and what is the strategy?

In simpler words: Balance the number of remaining tests after an egg breaks.

Starting hint: With one egg left, you must test upwards one floor at a time.

Answer & reasoning
Step by step
  1. Try floors 4,7,9,10 while the first egg survives: the jumps are 4,3,2,1.
  2. If it breaks, search the skipped floors with the remaining egg. The worst branch still totals only four drops.
  3. With three drops, two eggs cover at most 3+2+1=6 floors. Four is therefore both sufficient and necessary for ten floors.

4. Drop from floor 4: if it breaks, test 1, 2, 3 one at a time with the last egg (up to 3 more drops). If not, drop from 7: if it breaks, test 5, 6; if not, drop from 9: if it breaks, test 8; if not, drop from 10. Each branch uses at most 4 drops. Three cannot suffice: with 3 drops and 2 eggs the most floors you can settle is 3 + 2 + 1 = 6. The recurrence E(k, n) = 1 + min over x of max(E(k − 1, x − 1), E(k, n − x)) gives E(2, 10) = 4.

Question 34 · hard

Solve the weighted movie-star problem from Week 1, Question 19 (each job has a fee, maximise the total fee) with dynamic programming, and give its running time.

Each fixed-time job has a fee; choose nonoverlapping jobs to maximise total fee, rather than the number of jobs. Define compatibility consistently; adjacent jobs may share a boundary if their intervals are half-open.

In simpler words: For each job, compare taking it with skipping it.

Starting hint: Sort by finish time, then find the last compatible earlier job.

Answer & reasoning
Step by step
  1. Let p(i) be the last earlier job ending no later than job i starts; use half-open intervals.
  2. Skipping earns OPT(i−1). Taking earns feeᵢ+OPT(p(i)), because only that compatible prefix remains available.
  3. Set OPT(0)=0 and keep the larger amount. Sorting and binary-searching all predecessors cost O(n log n); filling the table costs O(n).

Sort jobs by finish time and let p(i) be the last earlier job compatible with job i, found by binary search. For half-open intervals, compatibility means finish ≤ start. Set OPT(0) = 0 and OPT(i) = max(OPT(i−1), feeᵢ + OPT(p(i))). The first branch skips the job; the second includes it and the best compatible prefix. Sorting and predecessor searches take O(n log n); the DP itself takes O(n).

Question 35 · hard

Give a DP that decides whether a set of n positive integers has a subset summing to exactly T, state its running time, and explain why this does not contradict the hardness of subset sum (Lecture 21).

In simpler words: Track which target sums can be reached using a prefix of the items.

Starting hint: For an item s, a sum t either skips s or comes from t−s.

Answer & reasoning
Step by step
  1. Initially only sum 0 is reachable with no items.
  2. Use can[i,t]=can[i−1,t] OR can[i−1,t−sᵢ], with the second branch allowed only if t≥sᵢ.
  3. There are (n+1)(T+1) cells. A target such as T=2ᵇ has only b+1 binary digits but needs roughly 2ᵇ columns. That is why O(nT) is pseudo-polynomial.

Let can[i,t] mean that a subset of the first i positive numbers sums to t. Set can[0,0] true and can[0,t] false for t > 0. Use can[i,t] = can[i−1,t] or (t ≥ sᵢ and can[i−1,t−sᵢ]). The table takes O(nT) time. This is polynomial in the numeric value T, not in its bit length log₂ T; binary-encoded inputs can make T exponentially large. This is pseudo-polynomial time.

Two nested loops fill rows and columns after their dependencies. Draw the table before translating it into Python.

a, b = "cat", "cut"
d = [[0]*4 for _ in range(4)]
for i in range(4): d[i][0] = i
for j in range(4): d[0][j] = j
for i in range(1, 4):
    for j in range(1, 4):
        d[i][j] = min(d[i-1][j]+1, d[i][j-1]+1,

Lecture 17 · Warm-up: is Z a shuffle of X and Y?

Hazırlık: Z, X ile Y’nin sıralarını koruyan bir iç içe geçirmesi mi?

Z (length n + m) is a shuffle of X (length n) and Y (length m) if Z can be formed by interleaving X and Y while keeping each string’s own left-to-right order. So “cchocohilaptes” is a shuffle of “chocolate” and “chips” (pull out c-h-o-c-o-l-a-t-e in order and c-h-i-p-s remains, in order), while “chocochilatspe” is not (the leftover letters do not spell “chips” in order).

Z (uzunluğu n + m), X’in (uzunluğu n) ve Y’nin (uzunluğu m) karakterleri, her dizenin kendi soldan sağa sırası korunarak iç içe geçirilip oluşturulabiliyorsa, X ile Y’nin sıra koruyan iç içe geçirmesidir (shuffle). Dolayısıyla “cchocohilaptes”, “chocolate” ile “chips”in böyle bir iç içe geçirmesidir (c-h-o-c-o-l-a-t-e harflerini sırayla çıkarın; geriye yine sıralı c-h-i-p-s kalır). “chocochilatspe” ise değildir (kalan harfler sırayla “chips” oluşturmaz).

The DP: let S[i, j] be true if the first i + j characters of Z are a shuffle of the first i of X and the first j of Y. Then S[0, 0] = true, and S[i, j] is true if either (X[i] = Z[i + j] and S[i − 1, j]) or (Y[j] = Z[i + j] and S[i, j − 1]). Fill the (n + 1) × (m + 1) boolean table row by row and read S[n, m]: O(nm).

DP: Z’nin ilk i + j karakteri, X’in ilk i ve Y’nin ilk j karakterinin sıra koruyan iç içe geçirmesiyse S[i, j] doğru olsun. O hâlde S[0, 0] = true olur. S[i, j], (X[i] = Z[i + j] ve S[i − 1, j]) veya (Y[j] = Z[i + j] ve S[i, j − 1]) koşullarından biri sağlanıyorsa doğrudur. (n + 1) × (m + 1) Boole tablosunu satır satır doldurun ve S[n, m] değerini okuyun: O(nm).

Lecture 17 · The gas station problem

Benzin istasyonu problemi

Driving from New York to Florida past gas stations g₁, …, gₙ at mile markers m₁ < … < mₙ, with a car whose full tank goes R miles, what is the fewest fill-ups needed?

Dolu depoyla R mil gidebilen bir otomobille, m₁ < … < mₙ mil işaretlerindeki g₁, …, gₙ benzin istasyonlarını geçerek New York’tan Florida’ya gidiyorsunuz. Gereken en az yakıt ikmali sayısı nedir?

Let G[i] be the minimum number of fill-ups needed to reach station gᵢ. If we know the best cost of reaching every earlier station within range, then

G[i] =  minj<i, mi−mj<R ( G[j] + 1 ),    G[1] = 0

G[i], gᵢ istasyonuna ulaşmak için gereken minimum yakıt ikmali sayısı olsun. Menzil içindeki önceki her istasyona ulaşmanın en iyi maliyetini biliyorsak:

That gives an O(n²) algorithm. Observations: this is also just BFS on an unweighted directed graph (an edge from each station to every station within range), and indeed many dynamic programs are shortest-path problems on the right DAG in disguise. The formulation extends with extra state to richer questions:

Bu, O(n²) bir algoritma verir. Gözlemler: Bu aynı zamanda ağırlıksız yönlü bir çizgede BFS’dir (her istasyondan menzilindeki her istasyona bir kenar). Gerçekten de birçok dinamik program, uygun DAG üzerindeki en kısa yol probleminin farklı bir görünümüdür. Ek durum bilgisiyle formülasyon daha kapsamlı sorulara genişletilebilir:

Minimum average price. If station s charges p(s) per gallon, let G[i, k] = the minimum total per-gallon price to reach gᵢ in exactly k stops, with G[i, k] = min over reachable j of G[j, k − 1] + p(j); then choose the k minimising G[n, k]/k. (This does not yet capture buying more gas where it is cheaper.)

Minimum ortalama fiyat. s istasyonu galon başına p(s) ücret alıyorsa, G[i, k] = gᵢ’ye tam k duruşta ulaşmanın minimum toplam galon başına fiyatı olsun. G[i, k], erişilebilir j’ler üzerinden G[j, k − 1] + p(j) değerlerinin minimumudur. Sonra G[n, k]/k’yi en aza indiren k’yi seçin. (Bu, ucuz yerde daha fazla yakıt satın almayı henüz modellemez.)

Cheapest filling schedule. If gas is bought in whole gallons, let G[i, k] = the minimum cost to arrive at gᵢ with k gallons left. It is the cheaper of “arrive from some earlier j with c gallons and buy nothing” and “arrive at i with c < k gallons and buy k − c at price p(i)”. The extra dimension (fuel in the tank) is the state the simpler version lacked.

En ucuz yakıt ikmal planı. Yakıt tam galonlar hâlinde satın alınıyorsa, G[i, k] = gᵢ’ye depoda k galonla ulaşmanın minimum maliyeti olsun. Bu değer, “önceki bir j’den c galonla gelip hiçbir şey satın almamak” ile “i’ye c < k galonla gelip p(i) fiyatından k − c galon satın almak” seçeneklerinin ucuz olanıdır. Ek boyut (depodaki yakıt), basit sürümde eksik olan durum bilgisidir.

Lecture 17 · Warm-up 2: cheapest order of string breaks

Hazırlık 2: Dizeyi en ucuz sırayla bölme

A language breaks a string into two pieces by copying, so breaking a string of length n costs n. To break a 20-character string after positions 3, 8 and 10, left-to-right costs 20 + 17 + 12 = 49 while right-to-left costs 20 + 10 + 8 = 38: the order matters. Let C[i, j] be the cheapest way to make all required breaks strictly inside the segment from break-position i to break-position j (treating the two string ends as positions 0 and n). Then C[i, j] = (j − i) + min over required positions k between i and j of C[i, k] + C[k, j], with C[i, j] = 0 when no break lies between. O(b³) for b breaks, O(n³) at worst.

Bir programlama dili, dizeyi kopyalayarak iki parçaya ayırır; dolayısıyla n uzunluklu bir dizeyi bölmenin maliyeti n’dir. 20 karakterli bir dizeyi 3, 8 ve 10 konumlarından sonra bölmek, soldan sağa 20 + 17 + 12 = 49, sağdan sola ise 20 + 10 + 8 = 38 maliyetlidir: sıra önemlidir. C[i, j], i bölme konumundan j bölme konumuna kadar olan parçanın kesin olarak içinde kalan bütün gerekli bölmeleri yapmanın en ucuz maliyeti olsun (dizenin iki ucunu 0 ve n konumları kabul edin). O zaman C[i, j] = (j − i) + i ile j arasındaki gerekli k konumları üzerinden C[i, k] + C[k, j] değerlerinin minimumudur. Arada bölme yoksa C[i, j] = 0’dır. b bölme için O(b³), en kötü durumda O(n³).

Lecture 17 · Edit distance: the problem

Düzenleme uzaklığı: Problem

Misspellings make approximate string matching essential, and for that we need a distance between strings: the minimum cost of the changes needed to convert one into the other. Three natural single-character changes:

Yazım hataları yaklaşık dize eşleştirmeyi gerekli kılar. Bunun için dizeler arasında bir uzaklığa ihtiyaç duyarız: birini diğerine çevirmek için gereken değişikliklerin minimum maliyeti. Üç doğal tek karakterlik değişiklik vardır:

Substitution: change one character (“shot” → “spot”).

Değiştirme: Bir karakteri değiştir (“shot” → “spot”).

Insertion: add one character (“ago” → “agog”).

Ekleme: Bir karakter ekle (“ago” → “agog”).

Deletion: remove one character (“hour” → “our”).

Silme: Bir karakteri kaldır (“hour” → “our”).

Each costs 1; a character that already matches costs 0.

Her biri 1 maliyetlidir; zaten eşleşen bir karakterin maliyeti 0’dır.

Lecture 17 · The recurrence

Yineleme bağıntısı

Look at the last characters of the two strings. In an optimal edit sequence, the last character of S is either matched or substituted against the last character of T, or it is deleted, or a character is inserted into S to match T’s last character. If we knew the cost of editing the three resulting pairs of shorter strings, we could pick the best option. Recursion supplies those costs.

İki dizenin son karakterlerine bakın. Optimal bir düzenleme dizisinde S’nin son karakteri ya T’nin son karakteriyle eşleşir veya ona dönüştürülür, ya silinir ya da T’nin son karakterini eşleştirmek için S’ye bir karakter eklenir. Ortaya çıkan üç daha kısa dize çiftini düzenlemenin maliyetini bilseydik en iyi seçeneği seçebilirdik. Özyineleme bu maliyetleri sağlar.

Let D[i, j] be the minimum cost of converting the first i characters of S into the first j characters of T. Then D[i, j] is the minimum of:

D[i, j], S’nin ilk i karakterini T’nin ilk j karakterine dönüştürmenin minimum maliyeti olsun. O zaman D[i, j] aşağıdakilerin minimumudur:

D[i − 1, j − 1], if S[i] = T[j] (a free match);

S[i] = T[j] ise D[i − 1, j − 1] (maliyetsiz eşleşme);

D[i − 1, j − 1] + 1, if S[i] ≠ T[j] (a substitution);

S[i] ≠ T[j] ise D[i − 1, j − 1] + 1 (değiştirme);

D[i, j − 1] + 1 (insert T[j] into S);

D[i, j − 1] + 1 (S’ye T[j] ekle);

D[i − 1, j] + 1 (delete S[i]).

D[i − 1, j] + 1 (S[i]’yi sil).

Base cases: D[0, j] = j (insert all j characters) and D[i, 0] = i (delete all i characters).

Başlangıç durumları: D[0, j] = j (j karakterin tamamını ekle) ve D[i, 0] = i (i karakterin tamamını sil).

The direct recursive program is correct and exponentially slow, because it recomputes the same (i, j) pairs endlessly. But there are only |s| · |t| distinct pairs, so a table of that size caches everything: O(|s| · |t|) time.

Doğrudan özyinelemeli program doğrudur ve üstel ölçüde yavaştır; çünkü aynı (i, j) çiftlerini durmadan yeniden hesaplar. Ancak yalnızca |s| · |t| farklı çift vardır; dolayısıyla bu boyuttaki bir tablo her şeyi önbellekler: O(|s| · |t|) zaman.

Lecture 17 · The DP table

DP tablosu

Each cell m[i][j] stores two things: the cost of the best solution for that subproblem, and a parent pointer recording which of the three options (MATCH, INSERT, DELETE) achieved it, so that the edit sequence can be reconstructed later. The strings are padded with a blank in position 0 so that real characters start at index 1.

Her m[i][j] hücresi iki şey tutar: ilgili alt problemin en iyi çözümünün maliyeti ve bunu üç seçenekten (MATCH, INSERT, DELETE) hangisinin sağladığını kaydeden bir ebeveyn işaretçisi. Böylece düzenleme dizisi daha sonra yeniden oluşturulabilir. Gerçek karakterlerin 1 indisinden başlaması için dizelerin 0 konumuna bir boşluk eklenir.

string_compare(s, t):
    initialise row 0 and column 0 (row_init, column_init)
    for i from 1 to |s|:
        for j from 1 to |t|:
            opt[MATCH]  = m[i−1][j−1].cost + match(s[i], t[j])
            opt[INSERT] = m[i][j−1].cost + indel(t[j])
            opt[DELETE] = m[i−1][j].cost + indel(s[i])
            m[i][j].cost, m[i][j].parent = the smallest option and its name
    (i, j) = goal_cell(s, t)
    return m[i][j].cost

    0. satır ve 0. sütunu başlat (row_init, column_init)

Evaluation order. Cell (i, j) needs (i − 1, j − 1), (i, j − 1) and (i − 1, j) already computed. Filling row by row, left to right, guarantees that. In general, think of cells as vertices with an edge from each cell to the cells that need it; any topological sort (Lecture 12) of that DAG is a valid evaluation order.

Hesaplama sırası. (i, j) hücresi, (i − 1, j − 1), (i, j − 1) ve (i − 1, j) hücrelerinin önceden hesaplanmış olmasını gerektirir. Satır satır, soldan sağa doldurmak bunu garanti eder. Genel olarak hücreleri tepe, her hücreden ona ihtiyaç duyan hücrelere giden bağlantıları kenar olarak düşünün; bu DAG’nin herhangi bir topolojik sıralaması (Ders 12) geçerli bir hesaplama sırasıdır.

The slides’ example turns “thou shalt” into “you should” at cost 5, with the edit trace DSMMMMMISMS (D = delete, S = substitute, M = match, I = insert).

Slaytlardaki örnek, “thou shalt” ifadesini 5 maliyetle “you should” ifadesine dönüştürür; düzenleme izi DSMMMMMISMS biçimindedir (D = silme, S = değiştirme, M = eşleşme, I = ekleme).

Lecture 17 · Reconstructing the edits

Düzenlemeleri yeniden oluşturma

A DP solution is a path through the table from (0, 0) to the goal cell. Follow the parent pointers backwards from the goal; each pointer says which operation happened at that cell. Walking backwards produces the edits in reverse, but recursion reverses them for free: recurse first, print afterwards.

DP çözümü, tabloda (0, 0)’dan hedef hücreye giden bir yoldur. Hedeften geriye doğru ebeveyn işaretçilerini izleyin; her işaretçi o hücrede hangi işlemin gerçekleştiğini söyler. Geriye yürümek düzenlemeleri ters sırada üretir; fakat özyineleme bunları ek bir çaba gerektirmeden tersine çevirir: önce özyinelemeli çağrı yapın, sonra yazdırın.

reconstruct_path(s, t, i, j):
    if m[i][j].parent == −1: return
    if parent == MATCH:  reconstruct_path(s, t, i−1, j−1); print match/substitute at (i, j)
    if parent == INSERT: reconstruct_path(s, t, i, j−1);   print insert t[j]
    if parent == DELETE: reconstruct_path(s, t, i−1, j);   print delete s[i]
reconstruct_path(s, t, i, j):
    if m[i][j].parent == −1: return
    if parent == MATCH:
        reconstruct_path(s, t, i−1, j−1)
        (i, j)’deki eşleşme/değiştirme işlemini yazdır
    if parent == INSERT:
        reconstruct_path(s, t, i, j−1)
        t[j] ekleme işlemini yazdır
    if parent == DELETE:
        reconstruct_path(s, t, i−1, j)

Changing these pieces solves new problems with the same table:

Bu parçaları değiştirmek, aynı tabloyla yeni problemleri çözer:

Approximate substring matching. Find where a short pattern s best occurs inside a long text t, say “Skiena” among misspellings like Skienna, Skena, Skina. Plain edit distance is useless here: almost all the cost would be deleting the rest of the text. Two changes fix it. Make row_init set m[0][j].cost = 0 for every j, so starting the match anywhere in the text is free. Make goal_cell return the cheapest cell in the last row, so the match may end anywhere. Now the answer is the cheapest place to fit the whole pattern somewhere in the text.

Yaklaşık alt dize eşleştirme. Kısa bir s örüntüsünün uzun t metni içinde en iyi nerede yer aldığını bulun; örneğin Skienna, Skena, Skina gibi yanlış yazımlar arasında “Skiena”. Yalın düzenleme uzaklığı burada işe yaramaz; maliyetin neredeyse tamamı metnin kalanını silmekten gelir. İki değişiklik bunu düzeltir. row_init, her j için m[0][j].cost = 0 atasın; böylece metnin herhangi bir yerinde eşleşmeye başlamak ücretsiz olur. goal_cell, son satırdaki en ucuz hücreyi döndürsün; böylece eşleşme herhangi bir yerde bitebilir. Artık yanıt, örüntünün tamamını metnin bir yerine yerleştirmenin en ucuz konumudur.

Longest common subsequence (LCS). A subsequence keeps characters in order but need not be contiguous; the LCS of “democrat” and “republican” is “eca”. A common subsequence is exactly the set of identical-character matches in an edit trace, so to maximise matches we must forbid substitutions: make match(c, d) return 0 if c = d and a huge cost (MAXLEN) otherwise. Then the cheapest trace uses only matches, insertions and deletions, and the matches it contains form the LCS.

En uzun ortak alt dizi (LCS). Alt dizi, karakterlerin sırasını korur; fakat bitişik olmak zorunda değildir. “democrat” ile “republican” dizelerinin LCS’si “eca”dır. Ortak alt dizi, düzenleme izindeki özdeş karakter eşleşmelerinin tam kümesidir. Bu nedenle eşleşmeleri en çoğa çıkarmak için değiştirmeleri yasaklamalıyız: match(c, d), c = d ise 0, değilse çok büyük bir maliyet (MAXLEN) döndürsün. Böylece en ucuz iz yalnızca eşleşme, ekleme ve silme kullanır; içerdiği eşleşmeler LCS’yi oluşturur.

Longest increasing subsequence. Delete the fewest numbers from a sequence to leave a non-decreasing one; from 243517698 the answer is 23568. This is LCS in disguise: compute the LCS of the sequence with a sorted copy of itself. Any common subsequence appears in the original order (from the first string) and in increasing order (from the sorted one), so the longest common subsequence is the longest increasing one.

En uzun artan alt dizi. Bir diziden en az sayıda sayı silerek azalmayan bir dizi bırakın; 243517698 için yanıt 23568’dir. Bu, farklı bir görünüm altında LCS’dir: dizinin kendisiyle sıralanmış kopyasının LCS’sini hesaplayın. Her ortak alt dizi hem özgün sırada (ilk diziden) hem de artan sırada (sıralanmış olandan) görünür; dolayısıyla en uzun ortak alt dizi, en uzun artan alt dizidir.

Lecture 18 · Warm-up 1: dropping eggs

Hazırlık 1: Yumurta düşürme

In an n-storey building there is a critical floor f: an egg dropped from floor f breaks, from floor f − 1 it survives. You have k eggs, broken eggs are lost, and you want to find f with as few drops as possible in the worst case. Let E(k, n) be that minimum.

n katlı bir binada kritik bir f katı vardır: f katından bırakılan yumurta kırılır, f − 1 katından bırakılan sağlam kalır. k yumurtanız var, kırılanlar kaybediliyor ve en kötü durumda mümkün olduğunca az sayıda bırakmayla f’yi bulmak istiyorsunuz. E(k, n) bu minimum olsun.

E(1, n) = n. With one egg you cannot risk a break before you know the answer, so you must try floors 1, 2, 3, … in order; in the worst case that is n drops.

E(1, n) = n. Tek yumurtayla, yanıtı bilmeden kırılma riskini alamazsınız; bu yüzden 1, 2, 3, … katlarını sırayla denemelisiniz. En kötü durumda n bırakma gerekir.

E(k, n) = Θ(n^(1/k)). With two eggs, drop the first from floors √n, 2√n, 3√n, …; when it breaks, use the second egg to scan the √n floors below one at a time. About 2√n drops. With k eggs the same idea nests k times, giving about k · n^(1/k).

E(k, n) = Θ(n^(1/k)). İki yumurtayla ilkini √n, 2√n, 3√n, … katlarından bırakın. Kırıldığında, altındaki √n katı ikinci yumurtayla birer birer tarayın. Yaklaşık 2√n bırakma. k yumurtayla aynı fikir k kez iç içe uygulanır ve yaklaşık k · n^(1/k) verir.

Recurrence. Drop an egg from floor x. If it breaks, the answer is below x and you have k − 1 eggs and x − 1 floors: E(k − 1, x − 1). If not, you have k eggs and n − x floors above: E(k, n − x). You must plan for the worse outcome, and you choose x to make that as small as possible:

E(k, n) = 1 +  min1≤x≤n max( E(k−1, x−1),  E(k, n−x) )

Yineleme bağıntısı. Bir yumurtayı x katından bırakın. Kırılırsa yanıt x’in altındadır; k − 1 yumurta ve x − 1 kat kalır: E(k − 1, x − 1). Kırılmazsa k yumurta ve yukarıda n − x kat vardır: E(k, n − x). Daha kötü sonuca göre plan yapmalı, x’i bu sonucu mümkün olduğunca küçük kılacak biçimde seçmelisiniz:

with E(k, 0) = 0 and E(1, n) = n. The table has k · n cells and each takes O(n) to fill: O(kn²).

Burada E(k, 0) = 0 ve E(1, n) = n’dir. Tablo k · n hücre içerir ve her hücre O(n) sürede doldurulur: O(kn²).

Lecture 18 · Warm-up 2: lazy two-finger dialling

Hazırlık 2: İki parmakla en az hareket ederek numara çevirme

Dial an n-digit number on a keypad of k keys using two fingers that start on * and #, moving them the smallest total distance. The state after dialling the first i digits is where the two fingers are: one is on the ith digit’s key, the other is on some key. Let C[i, j] be the minimum distance to have dialled the first i digits with the idle finger on key j. Digit i + 1 is pressed either by the finger already on digit i’s key or by the idle finger, giving a transition to each new state in O(1); there are n · k states and O(k) ways to enter each, well within the O(nk³) asked for.

k tuşlu bir tuş takımında, başlangıçta * ve # üzerinde bulunan iki parmağı toplam en küçük uzaklıkta hareket ettirerek n basamaklı bir numarayı tuşlayın. İlk i basamak tuşlandıktan sonraki durum, iki parmağın bulunduğu konumlardır: biri i. basamağın tuşunda, diğeri bir başka tuştadır. C[i, j], boşta kalan parmak j tuşundayken ilk i basamağı tuşlamanın minimum hareket uzaklığı olsun. i + 1 basamağına ya zaten i. basamağın tuşundaki parmak ya da boşta kalan parmak basar; böylece her yeni duruma geçiş O(1) sürer. n · k durum ve her birine girmenin O(k) yolu vardır; bu, istenen O(nk³) sınırının rahatça içindedir.

Lecture 18 · A real win: high-density bar codes

Gerçek bir başarı: Yüksek yoğunluklu barkodlar

Symbol Technology designed the PDF-417 bar code, which stores several hundred bytes, and asked how best to encode text into it. The code has several modes (upper case, lower case, mixed digits and symbols, punctuation) with latch commands that switch mode permanently and shift commands that switch for one character. Symbol’s own encoder was greedy, deciding each character locally.

Symbol Technology, birkaç yüz bayt saklayan PDF-417 barkodunu tasarladı ve metnin içine en iyi nasıl kodlanacağını sordu. Kodun çeşitli kipleri vardır (büyük harf, küçük harf, karışık rakamlar ve simgeler, noktalama). Latch komutları kipi kalıcı olarak, shift komutları ise tek karakter için değiştirir. Symbol’ün kendi kodlayıcısı açgözlüydü; her karakter için yerel karar veriyordu.

The insight: for any prefix of the text you want the optimal encoding ending in each possible mode, since a cheaper prefix in the wrong mode may cost more later. With M[i, j] = the cheapest encoding of the first i characters that ends in mode j,

M[i, j] =  mink ( M[i−1, k] + cost of encoding character i from mode k ending in mode j )

M[i, j] =  mink ( M[i−1, k] + i karakterini k kipinden başlayıp j kipinde sonlanacak biçimde kodlamanın maliyeti )

Temel kavrayış: Metnin herhangi bir ön eki için, mümkün olan her kipte sonlanan optimal kodlamayı bilmek istersiniz; çünkü yanlış kipteki daha ucuz bir ön ek sonradan daha pahalıya mal olabilir. M[i, j], ilk i karakterin j kipinde sonlanan en ucuz kodlaması olmak üzere:

This simple dynamic program improved the capacity of PDF-417 by an average of 8%.

Bu basit dinamik program, PDF-417’nin kapasitesini ortalama %8 artırdı.

Lecture 18 · The linear partition problem

Doğrusal bölme problemi

A shelf of books is to be scanned by k workers, and to avoid rearranging books each worker gets one contiguous stretch of the shelf. What is the fairest split? If all books are equal, cut into equal counts:

Bir raf dolusu kitap k çalışan tarafından taranacak. Kitapları yeniden düzenlememek için her çalışana rafta bitişik bir bölüm veriliyor. En adil bölüşüm nedir? Bütün kitaplar eşitse eşit sayıda kitaba bölün:

100 100 100 | 100 100 100 | 100 100 100
100 100 100 | 100 100 100 | 100 100 100

But if the books grow along the shelf, equal counts are unfair (the third worker gets 2,400 pages against the first worker’s 600):

Fakat rafta ilerledikçe kitaplar büyüyorsa eşit sayıda kitap vermek adil değildir (üçüncü çalışan 2,400 sayfa alırken birinci 600 alır):

100 200 300 | 400 500 600 | 700 800 900
100 200 300 | 400 500 600 | 700 800 900

The fairest possible split balances the largest load:

Mümkün olan en adil bölüşüm, en büyük yükü dengeler:

100 200 300 400 500 | 600 700 | 800 900
100 200 300 400 500 | 600 700 | 800 900

The problem. Input: an arrangement S of non-negative numbers s₁, …, sₙ and an integer k. Output: partition S into k contiguous ranges so that the maximum range sum is as small as possible. No single fixed pattern works for all inputs of a given (n, k), and greedily filling each part up to the average (total ÷ k) from the left does not give the optimum either.

Problem. Girdi: negatif olmayan s₁, …, sₙ sayılarından oluşan bir S sıralı düzeni ve bir k tam sayısı. Çıktı: S’yi, en büyük aralık toplamı mümkün olduğunca küçük olacak şekilde k bitişik aralığa bölmek. Belirli bir (n, k) için bütün girdilerde çalışan tek bir sabit düzen yoktur. Her parçayı soldan başlayarak ortalamaya (toplam ÷ k) kadar açgözlü biçimde doldurmak da optimumu vermez.

Recursive idea. The kth range begins right after the (k − 1)st divider. That divider sits between elements i and i + 1 for some i. The cost of placing it there is the larger of two quantities: the sum of the last range, s_{i+1} + … + sₙ, and the best possible largest range among the first i elements split into k − 1 ranges. That second quantity is a smaller instance of the same problem.

Özyinelemeli fikir. k. aralık, (k − 1). ayırıcıdan hemen sonra başlar. Bu ayırıcı, bir i için i ve i + 1 elemanları arasındadır. Onu buraya koymanın maliyeti iki niceliğin büyüğüdür: son aralığın s_{i+1} + … + sₙ toplamı ve ilk i elemanın k − 1 aralığa bölünmesiyle elde edilebilecek en iyi en-büyük-aralık değeri. İkinci nicelik, aynı problemin daha küçük bir örneğidir.

Recurrence. Let M[n, k] be the minimum possible cost (largest range sum) of partitioning s₁, …, sₙ into k ranges:

M[n, k] =  min1≤i≤n max( M[i, k−1],  n∑j=i+1 sj )

Yineleme bağıntısı. M[n, k], s₁, …, sₙ dizisini k aralığa bölmenin mümkün olan minimum maliyeti (en büyük aralık toplamı) olsun:

with base cases M[1, k] = s₁ for every k (one element, however many ranges) and M[n, 1] = s₁ + … + sₙ (one range takes everything).

Başlangıç durumları her k için M[1, k] = s₁ (kaç aralık olursa olsun tek eleman) ve M[n, 1] = s₁ + … + sₙ’dir (tek aralık her şeyi alır).

Running time. The number of cells times the work per cell: k · n cells, each looking at up to n possible divider positions, so O(kn²). (Precomputing prefix sums makes each range sum O(1); without them it would be O(kn³).) Storing which i achieved each minimum lets the actual partition be reconstructed, as with edit distance.

Çalışma süresi. Hücre sayısı × hücre başına iş: k · n hücre vardır; her biri en fazla n ayırıcı konumuna bakar, dolayısıyla O(kn²). (Ön ek toplamlarını önceden hesaplamak her aralık toplamını O(1) yapar; bunlar olmadan O(kn³) olurdu.) Her minimumu hangi i’nin sağladığını saklamak, düzenleme uzaklığında olduğu gibi gerçek bölmenin yeniden oluşturulmasını sağlar.

Lecture 18 · When can you use dynamic programming?

Dinamik programlamayı ne zaman kullanabilirsiniz?

DP computes recurrences efficiently by storing partial results, so it is only efficient when there are few partial results to store:

DP, kısmi sonuçları saklayarak yineleme bağıntılarını verimli hesaplar; dolayısıyla yalnızca saklanacak az sayıda kısmi sonuç varsa verimlidir:

There are n! permutations of n items and 2ⁿ subsets, so we cannot hope to store a best solution for every sub-permutation or every subset polynomially.

n elemanın n! permütasyonu ve 2ⁿ alt kümesi vardır; dolayısıyla her alt permütasyon veya her alt küme için en iyi çözümü polinom boyutta saklamayı bekleyemeyiz.

But there are only n(n − 1)/2 contiguous substrings of a string, so string problems are fine.

Ancak bir dizenin yalnızca n(n − 1)/2 bitişik alt dizesi vardır; bu yüzden dize problemleri uygundur.

There are only n subtrees of a rooted tree (cut the edge to each node), so optimisation on rooted trees is fine.

Köklü bir ağacın yalnızca n alt ağacı vardır (her düğüme giden kenarı kesin); bu yüzden köklü ağaçlarda optimizasyon uygundur.

DP works best on objects that are linearly ordered and cannot be rearranged: characters in a string, matrices in a chain, points around a polygon, the left-to-right leaves of a search tree. Whenever your objects are ordered left to right, you should smell dynamic programming.

DP, doğrusal olarak sıralanmış ve yeniden düzenlenemeyen nesnelerde en iyi çalışır: bir dizedeki karakterler, bir zincirdeki matrisler, çokgen çevresindeki noktalar, arama ağacının soldan sağa yaprakları. Nesneleriniz soldan sağa sıralandığında dinamik programlama olasılığını düşünmelisiniz.

Lecture 18 · The principle of optimality

Optimallik ilkesi

DP also requires the principle of optimality: whatever the current state, the remaining decisions must be optimal with respect to that state alone, not with respect to how the state was reached.

DP ayrıca optimallik ilkesini gerektirir: mevcut durum ne olursa olsun, kalan kararlar o duruma nasıl ulaşıldığına göre değil, yalnızca o duruma göre optimal olmalıdır.

Dijkstra’s algorithm works because we only care about the length of the shortest path to x, not the route taken.

Dijkstra algoritması çalışır; çünkü x’e en kısa yolun yalnızca uzunluğuyla ilgileniriz, izlenen rotayla değil.

Edit distance works because we only care about the cheapest way to edit two prefixes, not the sequence of edits so far.

Düzenleme uzaklığı çalışır; çünkü yalnızca iki ön eki düzenlemenin en ucuz yoluyla ilgileniriz, şimdiye kadarki düzenleme dizisiyle değil.

It would fail if, say, a deletion cost more when other deletions were nearby: then the best continuation would depend on history, and the table entry would no longer summarise everything that matters.

Örneğin yakınında başka silmeler varken bir silmenin maliyeti artsaydı yöntem başarısız olurdu: en iyi devam yolu geçmişe bağlı hâle gelir ve tablo hücresi artık önemli bütün bilgileri özetlemezdi.

Lecture 18 · When the principle holds but the table is too big: TSP

İlke geçerli ama tablo çok büyükse: TSP

The travelling salesman problem (Lecture 1) obeys the principle of optimality, yet DP does not rescue it. Let T(i; j₁, …, jₖ) be the cost of the best path from city 1 to city i that passes through each of the cities j₁, …, jₖ exactly once. Then

T(i; j1, …, jk) =  min1≤m≤k ( C[i, jm] + T(jm; j1, …, jk without jm) )

T(i; j1, …, jk) =  min1≤m≤k ( C[i, jm] + T(jm; j1, …, jk, jm hariç) )

Gezgin satıcı problemi (Ders 1) optimallik ilkesine uyar, ancak DP onu kurtarmaz. T(i; j₁, …, jₖ), j₁, …, jₖ şehirlerinin her birinden tam bir kez geçen, 1 şehrinden i şehrine en iyi yolun maliyeti olsun. O zaman:

with T(i, j) = C(i, j) + C(j, 1) as the base. The trouble is that the state includes an arbitrary subset of cities, not a contiguous interval, so there are exponentially many states. The result is O(n² 2ⁿ) time, which is far better than the n! of brute force (for n = 20: about 4 × 10⁸ versus 2.4 × 10¹⁸) but still exponential.

Başlangıç durumu T(i, j) = C(i, j) + C(j, 1)’dir. Sorun, durumun bitişik bir aralık yerine şehirlerin keyfî bir alt kümesini içermesidir; bu nedenle üstel sayıda durum vardır. Sonuç O(n² 2ⁿ) zamandır. Bu, kaba kuvvetin n! maliyetinden çok daha iyidir (n = 20 için yaklaşık 4 × 10⁸’e karşı 2.4 × 10¹⁸), fakat hâlâ üsteldir.
