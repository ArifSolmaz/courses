0.1 Hafta 12: Fibonacci’de üç yol

Tekrar · Hafta 12 — Fibonacci F(0)=0, F(1)=1, F(n)=F(n−1)+F(n−2). Üç yol: (1) yalın özyineleme (tanımı koda dökmek): aynı değerleri defalarca hesaplar, çağrı sayısı tam olarak 2F(n+1)−1 = Θ(φⁿ), φ = (1+√5)/2 ≈ 1,618 (kabaca “1,6ⁿ gibi”), üstel. (2) bellekleme (memoization): özyinelemeyi koru, her sonucu bir tabloya yaz, önce tabloya bak: her değer bir kez hesaplanır, Θ(n). (3) tablo doldurma (DP, bottom-up): özyinelemeyi at, f[2], f[3], … diye döngüyle doldur: Θ(n). Ders: bellek alanı verip zaman kazandık. “Önce doğru özyinelemeli algoritmayı bul, sonra sonuç tablosuyla hızlandır.”
n = 6’da kırmızı düğümleri sayın: F(4) iki kez, F(3) üç kez, F(2) beş kez hesaplanır (Hafta 12’deki cümle). n = 30’da yalın yöntem 2,7 milyon çağrı yapar, oysa yalnızca 31 farklı değer vardır.
def fib_r(n):                      # yalın: Θ(φⁿ), φ ≈ 1,618
    return n if n < 2 else fib_r(n-1) + fib_r(n-2)

def fib_c(n, f={0: 0, 1: 1}):      # bellekleme: Θ(n)
    if n not in f: f[n] = fib_c(n-1) + fib_c(n-2)
    return f[n]

def fib_dp(n):                     # tablo: Θ(n)
    f = [0, 1] + [0] * (n - 1)
    for i in range(2, n + 1): f[i] = f[i-1] + f[i-2]
    return f[n]

0.2 Hafta 12: iki boyutlu tablo ve geri izleme

Tekrar · Hafta 12 — binom katsayısı, backtracking Pascal üçgeni: C(n,k) = C(n−1,k−1) + C(n−1,k), taban C(n,0)=C(k,k)=1. Neden doğru? n. eleman ya seçilmiş alt kümededir (kalan n−1’den k−1 seç) ya değildir (kalan n−1’den k seç). Sabit genişlikli tamsayılarda faktöriyel formülü çok hızlı taşabilir. Tablo yöntemi faktöriyel bölmelerini gerektirmez; ancak binom katsayılarının kendileri yine çok büyüyebileceği için kullanılan sayı türü önemlidir. Tablonun hücre sayısı ≈ n·k ve hücre başı iş sabit.
Geri izleme (backtracking) “hepsini dene”dir (üstel olabilir) ve budama (pruning) ile kesilir: kısmi çözüm zaten geçersizse alt ağacın tamamı atlanır. DP, tanımlanan alt problemleri sistematik biçimde çözüp sonuçları yeniden kullanır. Açgözlü bir yöntemin ise yalnızca sezgisel olarak makul görünmesi yeterli değildir: doğruluk/optimallik garantisi için ayrıca ispat gerekir (Hafta 1). İspatın henüz verilmemiş olması yöntemin mutlaka yanlış olduğu anlamına gelmez.

0.3 Hafta 11: en kısa yollar da bir DP’dir

Tekrar · Hafta 11 — Dijkstra, Bellman–Ford, Floyd Dijkstra, en küçük tahmini uzaklıklı tepeyi “kesinleşmiş” sayar; bu yalnızca kenar ağırlıkları negatif değilse güvenlidir. Karşı örnek: A→B=2, A→C=5, C→B=−4: Dijkstra B’yi 2’de kesinleştirir ama gerçek uzaklık 5−4 = 1. Bellman–Ford negatif ağırlığa dayanır: n−1 turda her kenarı gevşetir. Floyd bütün çiftler için d[i][j] = min(d[i][j], d[i][k]+d[k][j]) güncellemesini k = 1…n için yapar: Θ(n³).
DP bağlantısı: Floyd’un durumu “yalnızca ilk k tepeyi ara durak kullanarak i→j en kısa yol”dur; bir DAG’da en kısa yol ise topolojik sırayla doldurulan bir tablodur. Ortak ilke: en kısa yolun alt yolları da en kısadır.
Hafta 11’deki örnek: A→B=2, A→C=5, B→C=1. A’dan uzaklıklar 0, 2, 3 (C’ye B üzerinden 2+1=3 < 5). Floyd tablosunda k=2 (B ara durak) adımında d[A][C] 5’ten 3’e düşer.

0.4 Hafta 3’ten kalıcı araç: tablo maliyeti nasıl sayılır?

Tekrar · Hafta 3 — döngü sayma İç içe iki döngü for i in range(m): for j in range(n): → m·n iş (çarp). Arka arkaya iki döngü → topla. Bir DP tablosunu doldururken maliyet = hücre sayısı × hücre başına iş. Hücre başına iş sabitse Θ(m·n); her hücre bir döngüyle n’e kadar seçenek tarıyorsa bir döngü daha eklenir. Tabloyu doldurmak döngü değişmezi gibi düşünülebilir: “i. satıra geldiğimde 0…i−1 satırlar doğru ve eksiksiz”.

1.2 Üç adım (Lecture 17)

Kural 1 — DP’nin üç adımı 1. Cevabı bir yineleme bağıntısı (recurrence) ya da özyinelemeli algoritma olarak yaz.
2. Farklı alt problemlerin (farklı “örneklerin”) sayısının polinomla sınırlı olduğunu göster: tablo yeterince küçük.
3. Bir değeri hesaplarken bağlı olduğu değerler tabloda hazır olacak şekilde bir hesaplama sırası belirle.
Hepsinin altında bir kavram yatar: durum (state) = “kalan kararlar için bilmem gereken her şey”. Durum iki öneki gösteren iki sayıysa (i, j) tablo (m+1)(n+1) hücre olur.
Her satırı sesli okuyun: “Bu hücre … demek; … hücrelerinden hesaplanır; … ile başlar; … sırayla doldurulur; cevap … hücresinde.” Bu beş cümleyi söyleyebiliyorsanız DP’yi çözmüşsünüzdür. Yazılacak kod bundan sonra mekaniktir.

1.3 İlk gerçek DP: para üstü (coin change)

Sezgi. Kasada 1, 5 ve 6 liralık paralar var ve 10 lira para üstü vereceksiniz; en az kaç para kullanırsınız? Açgözlü: “hep en büyüğünü ver”: 6 + 1 + 1 + 1 + 1 = 5 para. Oysa 5 + 5 = 2 para. Açgözlü yanıldı, çünkü yerel seçim (6’yı almak) geleceği bozdu.

DP düşüncesi. Son verdiğim para hangisi olabilir? 1, 5 ya da 6. Hangisi olursa olsun, kalan tutarı en az parayla vermeliyim. Yani best[a] = 1 + min( best[a−c] ) (tüm c ≤ a için), best[0] = 0.

1.4 Yalın özyineleme → bellekleme → tablo

Para üstünü de, Fibonacci’yi de, düzenleme uzaklığını da önce özyineleme olarak yazabiliriz. Yalın özyineleme doğrudur ama aynı alt problemlere defalarca girer. Aşağıda çağrı sayıları gerçekten sayılıyor.

INF = float("inf")

def para_ustu_ozyineleme(coins, a):      # doğru ama üstel
    if a == 0: return 0
    return min((1 + para_ustu_ozyineleme(coins, a - c) for c in coins if c <= a),
               default=INF)             # ulaşılamıyorsa sonsuz

def para_ustu_memo(coins, a, memo=None):     # bellekleme
    if memo is None: memo = {0: 0}       # her üst düzey çağrıda yeni önbellek
    if a not in memo:
        memo[a] = min((1 + para_ustu_memo(coins, a - c, memo)   # önbellek özyinelemeye geçirilir
                       for c in coins if c <= a), default=INF)
    return memo[a]

def para_ustu_tablo(coins, A):           # tablo: Θ(A · |coins|)
    best = [0] + [float("inf")] * A
    for a in range(1, A + 1):
        for c in coins:
            if c <= a: best[a] = min(best[a], best[a - c] + 1)
    return best[A]

print(para_ustu_tablo([1, 3, 4], 6))     # 2
print(para_ustu_memo([1, 3, 4], 6))      # 2
print(para_ustu_memo([1, 5, 6], 6))      # 1 (önbellek paylaşılmaz)
Şimdilik atla Bellekleme ile tablo arasındaki fark yalnızca sıradır: bellekleme gereken alt problemleri “istendikçe” hesaplar (özyineleme yığını kullanır), tablo hepsini küçükten büyüğe hesaplar. Sınavda ikisi de kabul edilir; üçüncü adımı (sıra) açıkça yazmak tablo yönteminde zorunludur.

2.2 Alt problem ve yineleme

Alt problem: S’nin ilk i harfini T’nin ilk j harfine çevirmenin en ucuz yolu = D[i][j]. Neden önek? Çünkü son harfe bakıp “onunla ne oldu?” diye sorarız, geri kalanı daha kısa aynı problemdir.

Son harfe bakın. S’nin son harfi (S[i]) için üç ihtimal var: (a) T’nin son harfiyle eşleşir ya da ona dönüştürülür (kalan: D[i−1][j−1]); (b) silinir (kalan: D[i−1][j]); (c) T’nin son harfi S’ye eklenir (kalan: D[i][j−1]). Hangisi daha ucuzsa onu seçeriz.

Kural 2 — düzenleme uzaklığı yinelemesi D[i][j] = en küçüğü şunların: D[i−1][j−1] (S[i] = T[j] ise, bedava eşleşme) · D[i−1][j−1] + 1 (S[i] ≠ T[j] ise, değiştirme) · D[i][j−1] + 1 (ekle) · D[i−1][j] + 1 (sil).
Taban: D[0][j] = j (j harfin hepsini ekle), D[i][0] = i (i harfin hepsini sil).
Cevap: D[|S|][|T|] (sağ-alt hücre). Durum sayısı (|S|+1)(|T|+1), hücre başı sabit iş → O(|S|·|T|).

2.6 Çözümü geri okuma (traceback)

Sezgi. Tablo yalnızca maliyeti verir. “Hangi işlemleri yaptık?” sorusunun cevabı için her hücrede hangi seçeneğin kazandığını (ebeveyn işaretçisi: MATCH / INSERT / DELETE) saklarız ya da sonradan yeniden hesaplarız. Sağ-alt hücreden başlayıp işaretçileri takip ederek (0,0)’a gideriz; işlemler tersten çıkar. Özyineleme bunu bedavaya düzeltir: önce özyinelemeli çağrı, sonra yazdır.

def edit_distance(s, t):
    m, n = len(s), len(t)
    D = [[0] * (n + 1) for _ in range(m + 1)]
    P = [[""] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1): D[i][0], P[i][0] = i, "D"
    for j in range(1, n + 1): D[0][j], P[0][j] = j, "I"
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            opts = {"M": D[i-1][j-1] + (s[i-1] != t[j-1]),   # eşleş / değiştir
                    "D": D[i-1][j] + 1,                      # sil
                    "I": D[i][j-1] + 1}                      # ekle
            P[i][j] = min(opts, key=opts.get)
            D[i][j] = opts[P[i][j]]
    return D, P

def yol(P, s, t, i, j):                 # önce çağır, sonra yazdır
    if i == 0 and j == 0: return
    if P[i][j] == "M": yol(P, s, t, i-1, j-1); print("eşleş/değiştir", s[i-1], t[j-1])
    elif P[i][j] == "D": yol(P, s, t, i-1, j);   print("sil", s[i-1])
    else:                yol(P, s, t, i, j-1);   print("ekle", t[j-1])

D, P = edit_distance("sun", "snow"); print(D[3][4])   # 3

2.8 Özyineleme neden çok yavaş, tablo neden hızlı?

3.1 En uzun ortak alt dizi (LCS)

Sezgi. Alt dizi (subsequence) harfleri sırayla korur ama bitişik olmak zorunda değildir: “democrat”tan “eca” bir alt dizidir (e-c-a sırayla var). İki dizinin ortak alt dizilerinin en uzunu LCS’dir; “democrat” ve “republican” için eca (uzunluk 3). Kullanım: diff programları, DNA karşılaştırma.

Düzenleme uzaklığıyla bağ. Bir düzenleme izindeki özdeş harf eşleşmeleri tam olarak ortak alt dizidir. Eşleşmeleri çoğaltmak için değiştirmeyi yasaklarız (match(c,d) = çok büyük, c≠d ise): en ucuz iz yalnızca eşleşme, ekleme ve silme kullanır; eşleşmeler LCS’yi verir. Doğrudan yazarsak:

Kural 3 — LCS yinelemesi L[i][j] = L[i−1][j−1] + 1 (S[i] = T[j] ise) · aksi halde max( L[i−1][j], L[i][j−1] ). Taban: L[0][j] = L[i][0] = 0. Cevap L[|S|][|T|], süre O(|S|·|T|).
Bağ: yalnız ekle/sil ile düzenleme uzaklığı = |S| + |T| − 2·LCS. (democrat/republican: 8+10−2·3 = 12.)
Deneyin: “ABCD / ACBD” → LCS 3, örneğin ABD. “Yolu geri oku” özetindeki kontrol satırı, m+n−2·LCS değerini gösterir. Aynı tabloda “Düzenleme uzaklığı” izleyicisini “değiştirme maliyeti = 2” ile çalıştırırsanız aynı sayıyı (12) alırsınız.

3.2 En uzun artan alt dizi (LIS): LCS ile bir indirgeme

Sezgi. Bir diziden en az sayıda sayıyı silip kalanı artan yapmak istiyoruz: 2 4 3 5 1 7 6 9 8 → 2 3 5 6 8 (ya da 2 4 5 7 9), uzunluk 5. Hile: diziyi sıralı kopyasıyla karşılaştırın. Ortak alt dizi hem özgün sırayı hem artan sırayı izler, dolayısıyla artan alt dizidir; en uzunu da LIS’tir.

“Kesin artan” kutusu sıralı kopyadan tekrarları atar. 3 1 4 1 5 9 2 6 dizisinde uzunluk 4 (örneğin 3, 4, 5, 6). Sınavda 5 uzunluğunda artan alt dizi aramak boşunadır.

3.3 İç içe geçirme (shuffle) mı?

Soru. Z, X ile Y’nin harflerini her dizinin kendi sırasını bozmadan karıştırarak oluşturulabilir mi? “cchocohilaptes”, “chocolate” ile “chips”in iç içe geçirmesidir; “chocochilatspe” değildir (kalan harfler “chips” sırasını vermez). Durum: S[i][j] = “Z’nin ilk i+j harfi, X’in ilk i ve Y’nin ilk j harfinin iç içe geçirmesi mi?”. S[0][0] = ✓; S[i][j] doğrudur eğer (X[i] = Z[i+j] ve S[i−1][j]) veya (Y[j] = Z[i+j] ve S[i][j−1]). Boolean tablo (n+1)(m+1): O(nm).

3.4 Yaklaşık alt dize eşleştirme

Soru. Uzun bir metinde (yazım hatalarıyla dolu) kısa bir örüntü “Skiena”nın en iyi nerede geçtiğini bulun. Düz düzenleme uzaklığı işe yaramaz: maliyetin çoğu metnin kalanını silmekten gelir. İki değişiklik: (1) 0. satırı hep 0 yap: eşleşmeye metnin her yerinde bedavaya başlanır; (2) goal_cell = son satırdaki en küçük hücre: eşleşme her yerde bitebilir.

Kural 4 — motor ve parçalar Düzenleme uzaklığı: klasik. LCS: değiştirme yasak (ya da doğrudan yineleme). LIS: elemanlar birbirinden farklıysa LCS(dizi, sıralı dizi) dönüşümü kullanılabilir. Tekrarlı değerlerde “sıkı artan” ile “azalmayan” alt dizi ayrımını korumak için bu dönüşüm doğrudan kullanılmamalı; tekrarların nasıl ele alınacağı açıkça tanımlanmalıdır. Yaklaşık eşleştirme: row_init = 0, goal = son satırın minimumu. Hepsi iki öneke bağlı durum, O(mn) hücre.
Şimdilik atla — en uzun palindrom alt dizi “character” içinde en uzun palindrom alt dizi uzunluğu 5’tir (“carac”). Dizinin tersiyle LCS uzunluğu doğru verir; ama yeniden kurulan LCS’nin kendisi palindrom olmayabilir. Güvenli yol aralık DP’dir: L[i][j] = 2 + L[i+1][j−1] (uç harfler aynıysa), değilse max(L[i+1][j], L[i][j−1]); taban: boş aralık 0, tek harf 1. LCS aracında “character / tersi” hazır örneğini deneyin: uzunluk 5.

Aynı tarifi (durum, yineleme, taban, sıra, cevap) yedi yeni problemde uygulayacağız. Her birinde önce “son karar ne?” diye soruyoruz.

4.1 0/1 sırt çantası (knapsack)

Sezgi. Çantaya en fazla W kg sığıyor. Her eşyayı ya alırsınız ya almazsınız (0/1). Amaç toplam değeri en büyük yapmak. Açgözlü kurallar yanılır: “en değerli önce” kuralı (2,3), (3,4), (4,5) ve W=5’te (4,5)’i alır ve 5 değer bulur; oysa en iyisi 7’dir. “Değer/ağırlık oranı en yüksek önce” kuralı da (1,6), (2,10), (3,12) ve W=5’te 6+10 = 16 bulur, oysa 10+12 = 22 mümkündür. İzleyicide bu iki örneği ve kendi eşyalarınızı deneyin.

Son karar: i. eşyayı alıyor muyum? Durum: V[i][w] = ilk i eşya, w kapasite ile en iyi değer.

Kural 5 — 0/1 sırt çantası V[i][w] = max( V[i−1][w] (i’yi alma), V[i−1][w−wᵢ] + vᵢ (i’yi al; yalnızca wᵢ ≤ w ise) ). V[0][w] = 0. Cevap V[n][W]. Hücre sayısı (n+1)(W+1), hücre başı sabit iş: O(nW). Buradaki W kapasitenin sayısal değeridir; ağırlıklar ve W ikili kodlanıyorsa bu süre girdi bit uzunluğuna göre yalancı-polinomdur (pseudo-polynomial).

Çözümlü örnek (alıştırma sorusu): eşyalar (ağırlık, değer) = (2,3), (3,4), (4,5), W = 5. Satırlar (w = 0…5): eşya 0: 0 0 0 0 0 0; eşya 1: 0 0 3 3 3 3; eşya 2: 0 0 3 4 4 7; eşya 3: 0 0 3 4 5 7. En iyi değer 7: ağırlığı 2 ve 3 olan eşyalar (3+4), toplam ağırlık 5. (4,5) tek başına 5 değer verir ve 1 kg boşta kalır.

4.2 Alt küme toplamı ve yalancı-polinom zaman

Soru. Pozitif tam sayılardan oluşan bir kümenin bir alt kümesi tam olarak T eder mi? Durum: can[i][t] = ilk i sayıyla t yapılabilir mi? Yineleme: can[i][t] = can[i−1][t] veya (t ≥ sᵢ ve can[i−1][t−sᵢ]). Taban: can[0][0] = ✓. Tablo (n+1)(T+1): O(nT).

Neden çelişki değil? Alt küme toplamının karar sürümü NP-tamdır (Hafta 14), buna rağmen O(nT) bir DP var. Çünkü T bir sayıdır, T’nin bit uzunluğu log₂ T’dir; tablo T’nin değeri kadar sütun ister. T = 2ᵇ iken girdi b bit, tablo 2ᵇ sütun. Buna yalancı-polinom (pseudo-polynomial) zaman denir.

Karşılaştırma: düzenleme uzaklığı O(|S|·|T|), sütun sayısı dize uzunluğudur (girdinin kendisi), yani gerçekten polinomdur. LCS, Floyd O(n³) de öyle. Sırt çantası O(nW) ve alt küme toplamı O(nT) yalancı-polinomdur.

4.3 Ağırlıklı aralık planlama (Hafta 1’in problemi, ücretli)

Tekrar · Hafta 1 Film oyuncusu problemi: çakışmayan en çok sayıda rolü seç. “En erken biten” açgözlü kuralı sayı için optimaldir (değiş-tokuş argümanı). Şimdi her rolün bir ücreti var ve toplam ücreti en büyük yapmak istiyoruz. Aynı kural artık yanılır: Küme 1’de A [1,10) 10 TL, B [2,3) 3 TL, C [4,5) 4 TL; en erken biten B ve C’yi seçer (7 TL) ama A tek başına 10 TL.

DP. İşleri bitiş zamanına göre sıralayın. p(i) = i ile çakışmayan son önceki iş (yarı açık aralıklarda bitiş ≤ başlangıç). Son karar: i. işi alıyor muyum? Almazsam: OPT(i−1). Alırsam: ücretᵢ + OPT(p(i)) (çünkü i ile çakışan işler dışarıda kalır).

Kural 6 — ağırlıklı aralık planlama OPT(0) = 0; OPT(i) = max( OPT(i−1), ücretᵢ + OPT(p(i)) ). Sıralama + p(i)’ler için ikili arama: O(n log n); tablo: O(n). Cevap OPT(n).
Üç kuralın (en erken biten, en yüksek ücret, en yüksek ücret/süre) hangi kümede başarısız olduğuna bakın. DP her kümede doğru, çünkü her işte iki seçeneği de dener.

4.4 En büyük toplamlı ardışık bölüm (Kadane)

Soru. Dizinin ardışık bir bölümünün toplamını en büyük yap. Durum: best[i] = i’de biten bölümlerin en iyisi. Yineleme: best[i] = max( a[i], best[i−1] + a[i] ): ya yeni bölüm başlatırım ya öncekine eklerim. Cevap = tüm best[i]’lerin en büyüğü (bölüm sonu belli değil).

Çözümlü örnek: [−2, 1, −3, 4, −1, 2, 1, −5, 4] → best = −2, 1, −2, 4, 3, 5, 6, 1, 5; en büyüğü 6, bölüm 4, −1, 2, 1. Bir de [2, −5, 3, 4, −1, 2]: cevap 8 (3+4−1+2).

4.5 Yumurta düşürme

Soru. n katlı binada kritik bir kat f var: f’den atılan yumurta kırılır, f−1’den sağlam kalır. k yumurtanız var, kırılanlar gider. En kötü durumda en az kaç bırakmayla f bulunur? E(k,n) olsun. Taban: E(1,n) = n (tek yumurtayla risk alamazsınız, alttan sırayla), E(k,0) = 0. Yineleme: x. kattan bırakın; kırılırsa E(k−1, x−1), kırılmazsa E(k, n−x) kalır, kötüsünü alırsınız, x’i bu kötüyü küçültecek şekilde seçersiniz:

Kural 7 — yumurta E(k,n) = 1 + min over x (1…n) of max( E(k−1, x−1), E(k, n−x) ). Hücre sayısı k·n, hücre başı O(n) iş: O(kn²). İki yumurtada yaklaşık √(2n) bırakma gerekir; tam değer ⌈(√(8n+1)−1)/2⌉ (n = 100 için 14; çünkü b bırakma 1+2+…+b = b(b+1)/2 katı çözer).

Örnekler: E(1,8) = 8; E(2,10) = 4 (4, 7, 9, 10. katlar: aralıklar 4, 3, 2, 1). Üç bırakma 2 yumurtayla en çok 3+2+1 = 6 kat çözer, 10’a yetmez.

4.6 Dizeyi en ucuz sırayla kırma (aralık DP)

Soru. Bir dil, dizeyi kopyalayarak ikiye böler: n uzunluklu dizeyi kırmanın maliyeti n. 20 karakterlik dizeyi 3, 8 ve 10. konumlardan kırmak soldan sağa 20+17+12 = 49, sağdan sola 20+10+8 = 38: sıra önemlidir. Durum: C[i][j] = i. ve j. kırma konumları arasındaki parçanın içindeki tüm kırmaları yapmanın en ucuz yolu. Yineleme: C[i][j] = (j−i konum farkı) + min over k ( C[i][k] + C[k][j] ). Durum, iki kırma konumu (bir aralık); b kırma için O(b²) durum × O(b) = O(b³).

20: 3, 8, 10 için DP 37 bulur (önce 10’dan, sonra 3, sonra 8); alıştırma sorusu 10: 2, 5 için 15 (önce 5, sonra 2); önce 2 kırarsanız 10+8 = 18.

4.7 Benzin istasyonu (en az yakıt ikmali)

Soru. New York’tan Florida’ya giderken istasyonlar m₁ < … < mₙ mil işaretlerinde, dolu depoyla en çok R mil gidiliyor. En az kaç ikmal? Başlangıcı m₀=0, varışı da son nokta kabul edin. Durum: L[i] = i. noktaya ulaşmak için gereken en az yol ayağı sayısı; L[0]=0. Yineleme: L[i] = 1 + min L[j] (j < i ve mᵢ − mⱼ ≤ R). O(n²). Varışa kadar L[d] ayak varsa, başlangıçta depo dolu olduğundan ikmal sayısı L[d]−1’dir. Örnek: R = 60, istasyonlar 40, 70, 120, 150, varış 190: 5 yol ayağı ve 4 ikmal (40, 70, 120, 150). Burada “olabildiğince uzağa git” açgözlüsü de çalışır çünkü bütün ikmaller aynı maliyetli; fiyatlar farklıysa (örneğin durum i ve depodaki yakıt miktarını birlikte içermelidir) açgözlü bozulur.

5Doğrusal bölme (linear partition) 15 dk

5.1 Sezgi: raftaki kitapları taramak

Sezgi. Bir rafta sırayla dizili kitaplar k işçi tarafından taranacak. Kitapları yeniden dizmemek için her işçiye rafta bitişik bir bölüm veriliyor. En adil bölüşüm hangisi? Kitaplar eşitse eşit sayıda dağıtırsınız: 100 100 100 | 100 100 100 | 100 100 100. Ama kitaplar rafta büyüyorsa (100, 200, …, 900 sayfa) eşit sayıda kitap adil değildir: 100 200 300 | 400 500 600 | 700 800 900 bölüşümünde üçüncü işçi 2 400 sayfa alır, birinci 600. En adil bölüş en büyük yükü küçültür: 100 200 300 400 500 | 600 700 | 800 900 (yükler 1 500, 1 300, 1 700; en büyük 1 700).

Problem. Girdi: negatif olmayan s₁,…,sₙ ve tam sayı k. Çıktı: diziyi k bitişik aralığa böl; en büyük aralık toplamı en küçük olsun. “Ortalamaya (toplam÷k) kadar soldan doldur” da, eşit sayıda eleman da optimumu garanti etmez.

5.2 Alt problem ve yineleme

Son karar: son (k.) aralık nerede başlıyor? Son ayırıcı x. ve x+1. elemanlar arasındaysa, son aralığın toplamı sₓ₊₁+…+sₙ’dir; geri kalanı ilk x elemanın k−1 aralığa bölünmesi (aynı problemin küçüğü). Bu seçimin maliyeti ikisinin büyüğüdür.

Kural 8 — doğrusal bölme M[i][j] = ilk i sayıyı j boş olmayan aralığa bölmenin en küçük “en büyük toplam”ı (j > i ise bölme yoktur: M[i][j] = ∞).
M[i][j] = min over x (j−1 ≤ x < i) of max( M[x][j−1], sₓ₊₁ + … + sᵢ ).
Taban: M[i][1] = s₁+…+sᵢ (tek aralık her şeyi alır; M[1][1] = s₁); j > i için M[i][j] = ∞ (örneğin M[1][2] = ∞). Cevap M[n][k] (k ≤ n varsayılır).
Süre: k·n hücre × hücre başına n ayırıcı = O(kn²). Aralık toplamları önek toplamlarıyla O(1)’de bulunur; yoksa O(kn³) olurdu. Hangi x’in kazandığını saklarsak bölmeyi geri okuruz.

Çözümlü örnek (alıştırma sorusu): 1 2 3 4 5, k = 2. İlk sütun (tek aralık): M[i][1] = 1, 3, 6, 10, 15. Tek elemanı 2 boş olmayan aralığa bölemeyiz: M[1][2] = ∞. M[2][2] = max(M[1][1], 2) = 2. M[3][2] = min( max(1, 5), max(3, 3) ) = 3 (x=2). M[4][2] = min( max(1,9), max(3,7), max(6,4) ) = 6 (x=3). M[5][2] = min( max(1,14), max(3,12), max(6,9), max(10,5) ) = min(14, 12, 9, 10) = 9 (x=3). Bölme: {1,2,3} | {4,5}, toplamlar 6 ve 9. Aynı zamanda “ilk dört ayırıcı konumunun en büyük toplamları 14, 12, 9, 10” cümlesi (alıştırma sorusu 16) budur.

Deneyin: 100…900, k=3 → 1 700 (yukarıdaki adil bölüşüm). 3 1 4 1 5 9 2 6, k=3 → 14 (3 1 4 1 | 5 9 | 2 6: toplamlar 9, 14, 8). “Eşit sayıda eleman” ve “ortalamaya kadar doldur” satırlarında bu iki sezgiselin bazen daha kötü, bazen eşit sonuç verdiğini görün.
Şimdilik atla — 13’ün neden iyi olamadığının ispatı (zor) 3 1 4 1 5 9 2 6, k=3 için 14’ten iyisi yoktur. Kanıt: tavanı 13 alın ve her aralığı tavanı aşmadan olabildiğince sağa uzatın: [3 1 4 1], [5], [9 2], [6] → dört aralık gerekir. Pozitif elemanlarda bir aralığı daha erken bitirmek sonraki aralıkların daha sağa ulaşmasını sağlamaz; dolayısıyla üç aralık 13’ün altında yetmez.
Tekrar · Hafta 12 ve Blok 2 Bu tablonun bir iki parametreli durumu (i, j) var ve her hücre bir döngüyle (x = 1…i−1) hesaplanıyor: hücre başına O(n) iş. Düzenleme uzaklığında hücre başı iş sabitti (3 komşu). Maliyeti “hücre sayısı × hücre başı iş” ile bulmak, Hafta 3’teki iç içe döngü sayma kuralıdır.

6DP ne zaman işe yarar? 10 dk

6.1 İki koşul

Kural 9 — DP ne zaman kullanılır? (a) Az sayıda durum. DP, kısmi sonuçları saklayarak çalışır; saklanacak az şey varsa verimlidir. n elemanın n! permütasyonu ve 2ⁿ alt kümesi vardır: “her alt permütasyon/alt küme için en iyiyi sakla” ümitsizdir. Oysa n uzunluklu bir dizenin n(n+1)/2 tane boş olmayan bitişik alt dizesi, köklü bir ağaçta her düğüm için, o düğüm ve tüm torunlarından oluşan bir doğal köklü alt ağaç vardır; bu tür alt ağaçların sayısı n’dir: dizeler ve köklü ağaçlar uygundur. DP, özellikle soldan sağa sıralı veya doğal bir alt-problem sırası olan yapılarda sık görülür (dizideki harfler, zincirdeki matrisler, çokgen köşeleri); ancak DP bununla sınırlı değildir. “Soldan sağa sıralı bir şey görüyorsanız DP ihtimalini düşünün” iyi bir sezgidir, tanım değildir.
(b) Optimallik ilkesi (principle of optimality). Mevcut durum ne olursa olsun, kalan kararlar yalnızca o duruma göre optimal olmalı, o duruma nasıl gelindiğine göre değil.

6.2 Optimallik ilkesi: ne zaman geçerli, ne zaman bozulur?

Bozulma örneği: bir silme, yakında başka silmeler varsa daha pahalı olsaydı, en iyi devam geçmişe bağlı olurdu; tablo hücresi artık önemli her şeyi özetlemezdi. Bir başka klasik örnek: DAG’da en uzun yol DP ile kolaydır (topolojik sırada long[v] = max(long[v], long[u]+w), ulaşılmayanlar −∞, O(n+m)); ama çevrimli çizgede “en uzun basit yol” için hangi köşelerin kullanıldığını bilmek gerekir. Durum yalnızca “şu anki köşe” ise önemli bilgi kaybolur; problem NP-zordur (karar sürümü NP-tamdır).

6.3 İlke geçerli ama tablo çok büyük: TSP

Gezgin satıcı (TSP, Hafta 1) de optimallik ilkesine uyar, ama DP onu polinoma çevirmez. T(i; j₁,…,jₖ) = 1. şehirden i’ye, j₁,…,jₖ şehirlerinin her birinden tam bir kez geçen en kısa yol olsun. Yineleme: T(i; {j}) = min over m of ( C[i,jₘ] + T(jₘ; {j} \ jₘ) ). Sorun: durum keyfî bir şehir alt kümesini içeriyor (bitişik aralık değil). 2ⁿ alt küme × n “şu anki şehir” = n·2ⁿ durum, her biri O(n) iş: O(n²·2ⁿ). Kaba kuvvetin n!’sinden çok daha iyi (n=20: ≈ 4×10⁸ işleme karşı ≈ 2,4×10¹⁸), ama hâlâ üstel. Dizelerde karşılığı bir önek: yalnızca n tane.

Hesaplayıcıda polinom problemlerde “n’yi 2 katına çıkar” oranı sabit kalırken (×4, ×8, …) TSP DP’de oranın n ile birlikte büyüdüğüne dikkat edin: 2ⁿ’in doğası bu.
Sık yapılan hatalar (Blok 6)
  • “DP bir problemi hep polinoma çevirir”: hayır, durum sayısı polinom değilse çevirmez.
  • “Optimallik ilkesi = açgözlü”: hayır; açgözlü tek bir seçime bağlanır, DP tüm seçenekleri dener.
  • Durumdan bir bilgiyi çıkarmak: TSP’de “şu anki şehir” yetmez, ziyaret edilen küme de gerekir.

7Hareket tanıma: dinamik zaman bükme (DTW) 10 dk

Bir mühendis bununla nerede karşılaşır? Bileğe takılan bir ivmeölçer, bir hareketi (jest) bir örnek dizisi olarak kaydeder. Aynı hareket yavaş ve hızlı yapılınca farklı uzunlukta, tepe noktaları kaymış iki dizi çıkar; bu yüzden “i. örneği i. örnekle karşılaştır” yöntemi çöker. DTW, bir örneğin birden fazla örnekle eşleşmesine izin verir.

DTW, sayılar için düzenleme uzaklığıdır: D[i][j] = |aᵢ − bⱼ| + min( D[i−1][j], D[i][j−1], D[i−1][j−1] ). Üç öncül, silme, ekleme ve eşleşme rollerini oynar. Tabloyu doldurmak O(nm) sürer: 100 örnekli iki dizi için 10 000 hücre, bir mikrodenetleyici için rahat. Hız farkı sınırlıysa köşegen etrafında bir bant hem zamanı hem belleği kısar (aşağıda “bant” seçeneği).

Mini problem
a = [1, 3, 3, 1], b = [1, 3, 1]. DTW tablosunu doldurun, mesafeyi ve eşleşme yolunu bulun; ilk üç örneği tek tek karşılaştırmanın sonucuyla kıyaslayın.
CevapYerel maliyetler |aᵢ−bⱼ|: satır 1: 0 2 0; satır 2: 2 0 2; satır 3: 2 0 2; satır 4: 0 2 0. D (a satırları, b sütunları): [0, 2, 2], [2, 0, 2], [4, 0, 2], [4, 2, 0]. DTW = 0: a’nın iki 3’ü, b’nin tek 3’üyle eşleşir (yol: (1,1) → (2,2) → (3,2) → (4,3)). Örnek-örnek (ilk 3 örnek): |1−1|+|3−3|+|3−1| = 2, ve a’nın 4. örneğinin eşi yoktur. Tablo 4×3 = 12 hücre.
Bir de bilin: DP’nin gerçek bir zaferi (PDF-417 barkodu)
Symbol Technology, birkaç yüz bayt saklayan PDF-417 barkodunu tasarladı. Kodun birkaç kipi (büyük harf, küçük harf, karışık, noktalama) vardır; kip değiştirmek bazen kalıcı (latch), bazen tek karakterliktir (shift). Symbol’ün kodlayıcısı açgözlüydü: her karakter için yerel karar. Çözüm: M[i][j] = ilk i karakterin j kipinde biten en ucuz kodlaması; yanlış kipteki ucuz önek sonradan pahalıya patlayabilir. Bu basit DP, kapasiteyi ortalama %8 artırdı. Durum yine “önek + ek bilgi (kip)”tir.

Özet

9Tek sayfalık özet

Hafta 13’ün 8 kuralı
  1. DP tarifi: durum nedir → yineleme → taban → doldurma sırası → cevap hücresi. İş = hücre sayısı × hücre başı iş.
  2. Düzenleme uzaklığı: D[i][j] = min(D[i−1][j−1]+[≠], D[i−1][j]+1, D[i][j−1]+1); D[0][j]=j, D[i][0]=i; O(mn); geri okuma ebeveyn işaretçileriyle (özyineleme: önce çağır, sonra yazdır).
  3. LCS: eşitse çapraz+1, değilse max(üst, sol). Yalnız ekle/sil uzaklığı = m+n−2·LCS. Elemanlar birbirinden farklıysa LIS = LCS(dizi, sıralı kopya). Tekrarlı değerlerde sıkı artan ve azalmayan alt dizi ayrımı ayrıca ele alınmalıdır.
  4. Yaklaşık eşleştirme: 0. satır hep 0, cevap son satırın minimumu. Shuffle: boolean tablo.
  5. Sırt çantası: max(V[i−1][w], V[i−1][w−wᵢ]+vᵢ); O(nW) yalancı-polinom. Alt küme toplamı O(nT) yalancı-polinom.
  6. Ağırlıklı aralık: OPT(i) = max(OPT(i−1), ücretᵢ + OPT(p(i))); açgözlü “en erken biten” burada yanılır.
  7. Doğrusal bölme: M[i][j] = min over x max(M[x][j−1], aralık toplamı); O(kn²) (önek toplamıyla). Yumurta O(kn²). Aralık DP (dize kırma) O(b³).
  8. DP ne zaman? Az sayıda durum + optimallik ilkesi. Dizeler/köklü ağaçlar: polinom. TSP: n·2ⁿ durum, O(n²2ⁿ): n!’den iyi ama üstel. DTW: sayılar için düzenleme uzaklığı, O(nm).
