Our counting contract

One unit = one test of whether two values are equal. A “no” result still takes one check. None of these four checks returned “equal”, but that does not mean no work was done.

We do not include position increments, loop-condition checks or displaying the report in this counter. The number here is neither a time in seconds nor a count of every operation in the program.

= means “equals”; ≠ means “does not equal”. An equality check can return either yes or no; we count both.

The same list, another target

If the target were 7, how many checks would the first-match search make? Has the length of the list changed?

Compare my prediction

Two checks: 18 ≠ 7, then 7 = 7. The length is still four. For inputs of the same length, the target’s position can change the amount of work done.

02 · From a small count to a general expression

n describes the input.
C(n) counts the work.

n is the number of records. For [18, 7, 18, 24], n = 4. Two occurrences of 18 do not reduce n; they are two records at different positions. Nor does the largest ID, 24, make n equal to 24.

Now fix one condition: the target is absent from the list. A search for the first match checks every record in this case.

n = 00 checks
n = 11 check
n = 44 checks

Call the count under this condition C(n). C(4) = 4 means “four equality checks for four records”. The parentheses do not mean multiplication; they show which number of records we use for n.

C(n) = n for a search where the target is absent

The reason is not simply that our table contains 0, 1 and 4: each record is compared exactly once, and no early match stops the search. Each of the n records therefore adds one to the counter.

What if we leave out the condition?

“If there are four records, the search must make four checks.” Disprove this claim by choosing a target in the same list.

Compare my answer

Target 7: the search stops after two checks. Target 18: it stops after one. We derived C(n) = n for the case where the target is absent. We did not claim that the search does the same amount of work for every target.

The maintenance team’s request changes. It no longer wants the position of the first message. Instead, it needs a two-column report covering every record: “Is this record from device 7?” and “Is this record from device 24?”

C(n) = n + n = 2n

2n means “2 × n”. For four records, 4 + 4 = 8 checks. This report’s count does not depend on the record IDs: every record is compared with two separate targets.

Seeing two loops does not automatically mean n². Here, one loop does not run inside the other; we add two separate pieces of work.

04 · Start again on every turn

For each record,
check every record: n × n.

This time, the team needs a table comparing every record position with every record position. Each cell says whether the two IDs are equal. Rows and columns represent record positions, not device IDs.

The equal cells in a row show which positions contain messages from that device. This lets us see repeated messages from the same device. The required output here is the entire table; we count a method that fills it by making a separate comparison for every cell.

In this full table, (1,2) and (2,1) are separate cells. Comparisons of a record with itself, such as (1,1), are also required. We are not counting only unordered pairs of different records.

Pseudocode

for each record position i:
    for each record position j:
        does the ID at i equal the ID at j?  (one check)

i is the row position; j is the column position. For each new i, the inner loop starts j again at the first position. There are exactly n cells in every row and n rows in total.

C(n) = n × n = n² n² is n squared; it is not the same expression as 2n

For three records: 3 rows × 3 cells = 9 checks. For four records: 4 × 4 = 16. A “no” result still requires a check to fill that cell.

Reveal the checks one at a time

Every revealed cell is one equality check. = means equal; ≠ means different. Both kinds of revealed cell add one to the counter.

    Does nesting always mean more work?

    Compare the two full scans’ count, 2n, with the full table’s count, n², for n = 1 and n = 2.

    Check my comparison

    n = 1: 2n = 2, n² = 1. n = 2: both are 4. n = 0: both are 0. The claim “nested loops do more work for every n” is false. The two patterns also produce different reports; a smaller count does not automatically meet the other request.
