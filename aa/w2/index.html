Week 02 / 14 · Growth shapes, counts and timing

What happens when n grows 10×?

15 min · Engineering question

The robot gets a denser range scan. A single pass checks each point. A divide-and-merge pass does about n log₂ n work, while a comparison of every ordered pair does n². Which is likely to grow beyond the budget first?

Make an individual prediction, then compare with a partner. Write down the input, measurement unit or limit you would need to make the decision.

Show the worked steps
  1. Ordered pairs make a 4 × 4 table, so there are 16 comparisons. Diagonal matches compare a sample with itself.
  2. Unordered pairs compare positions (0,1), (0,2), (0,3), (1,2), (1,3) and (2,3). Only (0,2) matches. The count is 6, or n(n − 1)/2 in general.

45 min

Measure it

Predict the ratios before running. Compare scans, merge sort and pair loops at n = 100 and 1,000. Compare ratios within each method. Explain why Python timings need not match the operation-count ratios.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

def scan(values):
    for value in values:
        if value < 0:
            return True
    return False


def merge_sort(values):
    if len(values) < 2:
        return values
    mid = len(values) // 2
    left = merge_sort(values[:mid])
    right = merge_sort(values[mid:])
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    return merged + left[i:] + right[j:]


def compare_pairs(values):
    matches = 0
    for a in values:
        for b in values:
            matches += a == b
    return matches


for n in (100, 1000):
    values = list(range(n, 0, -1))
    measure(f"{n}: scan", lambda: scan(values))
    measure(f"{n}: merge", lambda: merge_sort(values), repeats=20)
    measure(f"{n}: pairs", lambda: compare_pairs(values), repeats=2)

def unordered_pairs(values):
    checks = matches = 0
    for i, left in enumerate(values):
        for j in range(i + 1, len(values)):
            matches += left == values[j]
            checks += 1
    return checks, matches

assert unordered_pairs([8, 3, 8, 5]) == (6, 1)
for n in (200, 400):

45 min

Choose a method for a denser scanner

A 100-point batch takes 0.02 ms to scan, 0.07 ms to sort, and 0.10 ms for pair processing. Estimate the same three at 1,000 points. Pair processing emits a one-byte entry per ordered pair. The allocation is 2 ms and 256 KiB.

Start individually for 10 minutes. Work with a partner for 20. Spend the last 15 comparing with another pair and revising your recommendation.

  1. Scale the scan by n, sorting by n log₂ n and pair work by n². State which model applies to each measured baseline.
  2. Compute the pair table’s size at both inputs and decide which constraints it fails at 1,000.
  3. Distinguish a request to find a duplicate from a request to emit every pair result. Recommend a method for each and state what you need to measure next.
Compare a model answer

The estimates are 0.20 ms, 1.05 ms and 10 ms. A dense table grows from 10,000 to 1,000,000 bytes, beyond 256 KiB. Sorting and scanning can answer the duplicate question if the estimated costs hold. If every pair is genuinely required, changing only the search algorithm does not remove the output cost. A tiled or streamed result changes storage and needs its own timing measurement.
