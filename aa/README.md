# AA Algorithm Analysis

The 14-week course follows the topic order of the supplied bilingual Skiena CSE 373 notes. Document lectures 1–22 are grouped into teaching weeks; the dashboard and every weekly page identify the corresponding lectures and reading sections.

No prior Python knowledge is assumed. The core route uses a specified problem, labelled figure, worked trace, correctness and cost reasoning, and an edge case. Short Python demonstrations are supporting material. Python help is embedded in each weekly Notes view; former library URLs redirect to the matching week.

## Animation workspace (26 September 2026)

Each week's demonstrations sit in one workspace generated by `tools/aligned/compact.py`: a toolbar
(previous/next, chooser, zoom with an "Auto fit" default, Expand), a stage, and a hint line.

`assets/compact.js` packs each widget on a wide stage (from 860 px). Every block the widget renders — title,
option rows, the code, its variables and output, the play bar, each visual, stats, message — becomes an item of
one CSS grid on the widget root; wrappers on the way to a code trace or play bar get `display: contents`, so a
wrapper the widget hides for its other mode hides its blocks too, and a tall plain container of stacked blocks
(a `.ct-extra` holding a grid, a table and a chart) is opened up the same way. The packer measures each block's
natural width once, then tries 1–4 columns in two variants (a block wider than a column spans as many columns
as it needs and the rest flow around it, or the zoom is capped so it fits one column), splits the remaining
blocks into columns of nearly equal height with the linear-partition DP (block order kept, columns already
holding a spanning block start lower), and scales the whole widget with CSS `zoom` (0.62–1.7) so the tallest
column just fills the stage. The variant with the largest zoom wins; leftover space under a column goes to a
scroll box in it, and a listing that cannot fit even at the smallest zoom scrolls. Text is one size everywhere
in the widget. While a run plays nothing moves: blocks keep their columns and rows, a block that grows gets
more rows, and the zoom only steps down if the stage would scroll; the end of the run (`aa:end` from the
Player), a click, a block appearing or vanishing, or a resize triggers a new packing.

Expand moves the toolbar and stage into a full-screen dialog whose toolbar hides itself after two seconds; the
mouse at the top edge, the small tab, PageUp/PageDown or Alt+arrows bring it back or switch demonstrations;
Escape returns. On phones the stage flows with the page in a single column. Widgets keep their own DOM, so
`anim-w*.js` and `anim-aa.js` need no changes. Layout rules are in `assets/course.css` under "animation
widgets on a wide stage". Checked with a headless sweep of all 93 demonstrations at start, middle and end
frames at 1366×768 and 2000×1014 (expanded), inline at 1366 px and at 390 px: no console errors, no scrolling
stage, no clipped code, no overlapping blocks. Week 3's evens grid now draws 100 numbers as a 10 × 10 square and
200 or 400 as plain coloured cells.

## Small-group pilot kit (October 2026)

`bridge/capstone/pilot/` supplies a student handout for a suggested 25-minute
session with 6–8 students, a four-dimension teacher assessment form, and an
eight-slot comparison template (P01–P08). The teacher applies the existing
0–2 reasoning criteria separately to the initial and transfer explanations,
with an evidence note for each assigned score. Missing work remains unscored;
an explicit zero is an observed rating and is never inferred from a blank.

separate. Dimension comparisons use matched pre/post pairs with their own
sample counts; total-score comparisons require all four dimensions in each
phase. Invalid records are shown and excluded from aggregates. These are
small-pilot descriptive results, not an estimate of a causal learning effect.

Records stay in the open tab only. Download the filled CSV before refreshing
or leaving; the blank CSV is a reusable comparison template. Student,
teacher-form and results print views are separate. Without JavaScript, the

available. The existing integrated activity is unchanged outside one marked
access panel; no weekly lesson is replaced.

`python3 aa/tools/verify_pilot.py` alongside the capstone and course checks.
