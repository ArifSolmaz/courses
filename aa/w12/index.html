Lecture notes: Connect every station at minimum cost

A factory needs communication cables between four stations. Not every station requires a direct cable to the controller: data may pass through intermediates. But every installed cable costs money. This week we design an entire physical network, not a single journey.

A minimum spanning tree (MST) is a connected, cycle-free subgraph spanning every vertex of a connected undirected weighted graph, with minimum total edge weight. Kruskal builds it by considering candidates from cheapest to most expensive. Recall earlier weeks, solve an example by hand, then use the interactive experiment and Python lab.

Separate the concepts

G=(V,E): V is the set of stations and E available cables. An edge {u,v} is bidirectional; w(u,v)=w(v,u) is its installation cost. If A–B–C exists, A and C are connected without a direct cable. A component is a group of mutually reachable stations. A tree is connected and acyclic; a forest is acyclic and may contain multiple components. A spanning tree includes every station; minimizing cost is an additional requirement.

For selected edges F, minimize Σ w(e), e∈F, subject to connecting every vertex. In the triangle AB=2, BC=2, AC=3, AB+BC costs 4 in total. The A-to-C route within that network costs 4, whereas direct AC costs 3; buying AB+AC would cost 5. Dijkstra and Kruskal answer different questions.

Buy a connected network, not one journey

A controller A and three stations B,C,D need cables. A cable may connect them indirectly: A need not have a direct cable to every sensor. We pay each installed cable’s cost once. The task is to select available undirected links so every station is connected and the total installation cost is minimum. This model uses nonnegative costs and does not yet require backup connections.

A spanning tree includes all vertices, is connected and contains no cycle. For n≥1 it has n−1 edges. With nonnegative installation costs, any connected design with cycles can lose cycle edges without increasing cost, so a minimum-cost connected design can be chosen as a tree. If the available graph is disconnected, no full spanning tree exists; Kruskal finds a minimum spanning forest within its components.

Before you start

A component is a set of stations already connected through accepted links. Initially each station is alone.

Kruskal examines links in increasing cost. Accept a link if it joins two different components, then merge those components. If the endpoints are already connected, adding the link would create a cycle. Track the accepted link costs, rather than the costs of all inspected links.

The cheapest way to connect components can be built by taking a least-cost link that joins two groups. A connected tree with n stations uses n − 1 links. If available links cannot connect all stations, the result is a spanning forest, one tree per component.

These three links connect all four stations. If CD is unavailable, D remains isolated and the forest’s total is only 5. That smaller number does not buy the required connectivity.

Why taking a cheapest connecting link is safe

Imagine a boundary separating one current component from the other stations. Any full spanning tree must cross that boundary. Kruskal’s next accepted edge e is a cheapest available edge crossing the chosen component boundary. Take an optimal tree compatible with the edges accepted so far. If it lacks e, adding e creates a cycle; that cycle contains another crossing edge x. Replace x with e. Since cost(e)≤cost(x), the total does not increase and connectivity is preserved. This exchange argument justifies the greedy choice; “cheap looks good” alone would not.

Ties do not break this argument. They may give different trees with the same optimum total. This proof concerns a spanning tree (or one tree per available component), not a shortest route or a redundant network.

Why does Kruskal work?

Initially there are V separate components and zero selected edges. Each edge joining distinct components reduces the component count by one without creating a cycle. After k acceptances there are V−k components. In a connected network, reaching one component gives k=V−1. For a forest with C components, k=V−C. This explains why four stations need three cables in a tree.

Greedy choice and the cut property

Blindly buying cheap cables is not correct. With AB:1, BC:2, AC:3, CD:4, the three cheapest exclude D. Kruskal skips AC because A and C are already connected.

Proof idea: Assume an optimal tree T contains all edges F selected so far. Kruskal's next accepted edge e joins two distinct components. If e is already in T, nothing changes. Otherwise adding e to T creates one cycle. That cycle contains another edge f leaving the F-component of one endpoint of e. This f cannot belong to F, whose edges stay within components. Because f also joins different current components, it cannot be cheaper than e: if cheaper, Kruskal would have considered and accepted it earlier. Replacing f with e in T produces a spanning tree without increasing cost. Therefore an optimal tree still exists containing F∪{e}. By induction every acceptance is safe.

A cut partitions the vertices into two sets; consider one F-component and all remaining vertices. A lightest edge crossing that cut is a safe choice. Equal weights may produce different optimal trees; a unique layout is not guaranteed.

How does the computer recognize a component?

A disjoint-set union structure (DSU, also called union–find) maintains groups. root(x) returns a representative of x’s group. Two stations are already connected exactly when their representatives are equal. To accept an edge, merge the two roots. The representative is an internal label, not a special physical hub.

Stepparent[A,B,C,D]Component interpretation
Initialize[A,B,C,D]Four separate roots
Accept AB[A,A,C,D]{A,B}, {C}, {D}
Accept BC; root(B)=A[A,A,A,D]{A,B,C}, {D}
Skip AC[A,A,A,D]Same root A
Accept CD[A,A,A,A]One component

DSU parents are not installed cables. After accepting BC, parent[C]=A even though the selected cable is BC, not AC. After CD, parent[D]=A even though AD is not even an available edge. Keep the chosen edge list separately; never draw the wiring from the parent array.

Union by size and path halving

When roots differ, attach the smaller group under the larger group’s root. Only a root’s size entry is authoritative; this keeps the parent trees shallow. In root, parent[node] = parent[parent[node]] makes a node point to its grandparent, shortening future walks. For a possible parent chain D→C→A, a call root(D) changes D’s parent to A and returns A. This changes the bookkeeping, not the selected network or its cost.

Remember: Week 5 · Lookups and group queries are different

A dictionary maps 'dock-C' to integer ID 2. Looking up that ID does not say whether C is connected to A. DSU answers the second question by comparing root(2) with root(0). We use array indices once IDs are known.

Remember: Week 4 · Storage rules serve different operations

A FIFO containing A,B returns A first; a ring buffer changes where entries are stored, not which stations are connected. DSU is not a queue. Its operations are find-a-group and merge-groups, so the data structure should match those operations.

Print the actual wiring, not just its cost

This standalone example returns (chosen links, total cost, component count). Stations use IDs A=0,B=1,C=2,D=3. Each tuple is (cost,a,b), representing one undirected candidate. For predictable alphabetical ties, enter endpoints in ascending ID order. The code sorts by cost, then a, then b.

def wiring_plan(n, links):
    if type(n) is not int or n < 0:
        raise ValueError("n must be a nonnegative integer")
    for cost, a, b in links:
        if type(cost) is not int or cost < 0:
            raise ValueError("Use nonnegative integer installation costs")
        if any(type(v) is not int or not 0 <= v < n for v in (a, b)):
            raise ValueError("Endpoints must be integer IDs from 0 to n-1")
    parent = list(range(n))
    size = [1] * n
    chosen = []
    total = 0
    components = n

    def root(node):
        while node != parent[node]:
            parent[node] = parent[parent[node]]
            node = parent[node]
        return node

    for cost, a, b in sorted(links):
        left, right = root(a), root(b)
        if left == right:
            continue
        if size[left] < size[right]:
            left, right = right, left
        parent[right] = left
        size[left] += size[right]
        chosen.append((cost, a, b))
        total += cost
        components -= 1
    return chosen, total, components

Check feasibility and optimality separately

Every returned edge must be an available candidate; sum its cost once. Independently traverse the chosen undirected links to check connectivity and absence of cycles. For a forest, accepted+components=n. These checks establish structure, not minimum cost: the triangle’s AB+AC tree is valid but costs 5 instead of the optimum 4. For a tiny graph, enumerate spanning trees to verify the optimum; for larger tests compare with an independent MST method.

Sorting and connectivity do different jobs

Remember: Week 6 · Sort first, then use the ordering

For median filtering, sorting [7,2,3,2,100] gives [2,2,3,7,100], and we read the middle value 3. Kruskal sorts complete edge records instead: (3,A,C),(1,A,B),(2,B,C) become AB:1,BC:2,AC:3. We then inspect the whole sequence as needed, rather than taking its middle.

Remember: Week 7 · A heap can provide cheapest-first access

A min-heap of priorities 4,1,3 returns 1 next. It could likewise supply edges in increasing cost. This lesson already has the complete edge list, so sorted(links) is simpler. Whether a heap or sorting supplies the next edge, the same-component rejection is still essential.

Remember: Week 3 · A cheap edge is not automatically acceptable

Binary search for 30 in sorted [10,20,30,40] locates a key. It cannot answer whether accepting AC closes the existing A–B–C path. Sorting determines which candidate to inspect next; DSU determines whether its endpoints are already connected.

Remember: Week 2 · Count stations and links separately

A scan of n records grows linearly; comparing every pair grows quadratically. Here V is stations and E is available links. Initializing DSU costs O(V), sorting costs O(E log E), and union–find with size balancing plus path halving has near-constant amortized operation cost, conventionally expressed using α(V), the inverse Ackermann function. A useful overall bound is O(V + E log E + E α(V)).

“Amortized” describes the average over a sequence of operations; it does not mean every root walk has exactly one step. Python’s sorted creates an edge-list copy, so auxiliary memory is O(V+E), including the returned chosen edges in the small example. A network with many stations but no links still requires O(V) setup; do not hide that term inside sorting.

Remember: Week 1 · Know when an early exit is justified

A scan seeking any reading above 8 can stop at the first match in [2,9,12]. Kruskal may stop after V−1 successful merges for V≥1, because one component remains. It cannot stop after merely inspecting V−1 links: rejected links do not merge components. The teaching code scans all edges to keep the loop simple.

Calculate complexity and growth

Initializing two arrays for V stations costs O(V). Validating E candidate cables costs O(E); sorting costs O(E log(E+1)). Each candidate needs two root calls and possibly a union. With union by size, whenever a vertex gets deeper, its component at least doubles, so even without compression depth is O(log(V+1)). Combined with path halving, amortized operation cost over a sequence is O(α(V)), the extremely slowly growing inverse Ackermann function. Do not assume that every individual call has exactly constant cost.

Total time is O(V+E log(E+1)+E α(V)), auxiliary space O(V+E): parent/size O(V), sorted copy O(E), selected tree at most V−1 edges. For ordinary connected graphs E≥V−1, commonly summarized by O(E log E); retain initialization O(V) for disconnected or edgeless inputs.

def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats

def kruskal(n, links):
    if type(n) is not int or n < 0:
        raise ValueError("n must be a nonnegative integer")
    for cost, a, b in links:
        if type(cost) is not int or cost < 0:
            raise ValueError("Use nonnegative integer installation costs")
        if any(type(v) is not int or not 0 <= v < n for v in (a, b)):
            raise ValueError("Endpoints must be integer IDs from 0 to n-1")
    parent = list(range(n))
    size = [1] * n

    def root(node):
        while node != parent[node]:
            parent[node] = parent[parent[node]]
            node = parent[node]
        return node

    total = accepted = 0
    for cost, a, b in sorted(links):
        left, right = root(a), root(b)
        if left == right:
            continue
        if size[left] < size[right]:
            left, right = right, left
        parent[right] = left
        size[left] += size[right]
        total += cost
        accepted += 1
    return accepted, total, n - accepted

Minimum cost, budget feasibility and reliability are different

Kruskal minimizes purchase/installation cost. Latency, cable capacity, electromagnetic interference, safety and survival of failures must be evaluated separately. Every tree edge is a bridge: losing it splits the network into two components. Adding one spare cable protects only the edges on the cycle it creates.

ScenarioCostComponentsDecision (budget 6)
All design cables41Feasible
CD unavailable71Over budget
CD and BD unavailable32Not fully connected

The original tree selects AB=1, CD=1, BC=2. Adding AC=3 protects the A–B–C cycle, but CD remains a bridge; total cost becomes 7. If single-failure resilience is required, an MST alone is insufficient. Evaluate budget, connectivity and redundancy as distinct constraints.

This design task uses a different cost set from the paper trace: CD costs 1 and BD costs 4. Keep the input written beside your calculation.

A tree has exactly one path between each pair of vertices. Every installed tree edge is therefore a bridge: losing it disconnects the network. Adding one spare link only protects the edges on the cycle that it creates, not automatically every station against every failure. For example, adding AC to the original AB,BC,CD tree protects the triangle ABC, but CD is still D’s only link.

If the requirement becomes “stay connected after any one cable failure,” plan a network with no bridges and verify each allowed single-edge removal. That is a different optimization problem; an MST alone cannot certify it. Also distinguish a cable route that is unavailable before construction from a failure after construction. Recompute with the current candidate set, then report both the feasibility and budget result.

Use the model in another setting

The same graph model can connect campus buildings with fiber or stations with maintenance access links. The weights must represent the actual objective: construction cost, cable length or another additive installation measure. If links are one-way, bandwidth-limited, or required to provide redundancy, write those constraints explicitly instead of assuming Kruskal solves them.
