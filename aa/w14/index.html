Computational limits and cumulative review

Distinguish finding from checking, explain reduction direction, and recognise what NP-completeness does and does not establish.

What can we conclude when no fast exact method is known?

You want to show a decision problem X is NP-complete, using a known NP-complete problem A.

Step 1

Show that proposed yes-certificates for X can be checked in polynomial time: X is in NP.

Step 2

Construct a polynomial-time transformation A→X preserving yes/no answers.

Step 3

A fast solver for X would then solve A quickly. This establishes NP-hardness of X.

Step 4

Combine membership and hardness. This does not prove that a polynomial-time algorithm is impossible: P versus NP remains unresolved.

Change the case. Reducing X to A proves that X is no harder than A; it does not establish that X is NP-hard. Detailed SAT gadget proofs are optional depth this week.

Question 1 · easy

A polynomial-time reduction from problem A to problem B shows that:

  1. A is easy
  2. B is at least as hard as A
  3. A is at least as hard as B
  4. A and B are both in P

Answer: option B. A fast algorithm for B would give one for A, so if A is hard, B is too.

Question 2 · easy

A decision problem is in NP when every yes-instance has:

  1. no polynomial-time solution
  2. a known polynomial-time solving algorithm
  3. a polynomial-size certificate verifiable in polynomial time
  4. no algorithm at all

Answer: option C. NP requires efficiently checkable certificates for yes-instances. It includes P; being in NP does not mean a problem is known to be hard.

Question 3 · easy

Which decision problem is known to be NP-complete?

  1. nonnegative-weight shortest path of cost at most K
  2. existence of an Eulerian circuit
  3. existence of a vertex cover of size at most k
  4. satisfiability of a 2-CNF formula

Answer: option C. The other three are in P.

Question 4 · easy

The smallest vertex cover of a triangle has size:

  1. 1
  2. 2
  3. 3
  4. 0

Answer: option B. One vertex misses the opposite edge; any two vertices touch all three edges.

Question 5 · easy

The largest independent set of a 4-cycle has size:

  1. 1
  2. 2
  3. 3
  4. 4

Answer: option B. Two opposite corners; any three corners include an adjacent pair.

Question 6 · easy

The clause set {x}, {¬x, y}, {¬y} is:

  1. satisfiable with x = true, y = true
  2. satisfiable with x = false
  3. not satisfiable
  4. satisfiable only with y = false

Answer: option C. The first clause forces x true, the second then forces y true, and the third forbids it.

Question 7 · easy

The P versus NP question asks whether:

  1. every problem whose answers can be checked quickly can also be solved quickly
  2. sorting can be done in linear time
  3. every graph is a tree
  4. SAT is in NP

Answer: option A. It is the gap between verifying and finding.

Question 8 · easy

Skiena’s preferred source problem for targets about ordering or routing is:

  1. 3-SAT
  2. integer partition
  3. vertex cover
  4. Hamiltonian path

Answer: option D. Vertex cover is for selection, integer partition for large numbers, 3-SAT for everything else.

Question 9 · easy

If a single NP-complete problem were solved in polynomial time, then:

  1. nothing would follow
  2. P = NP
  3. P ≠ NP
  4. NP would be empty

Answer: option B. Every problem in NP reduces to it.

Question 10 · easy

Which listed decision problem has a known polynomial-time algorithm?

  1. Hamiltonian-cycle existence
  2. simple-path existence with at least k edges
  3. Eulerian-circuit existence
  4. 3-colourability

Answer: option C. Using every edge once is easy; visiting every vertex once is hard.

Question 11 · medium

The chain construction turns the clause {a, b, c, d} into:

  1. {a, b, c} and {d}
  2. {a, b, v} and {¬v, c, d}
  3. {a, b, v} and {v, c, d}
  4. {a, v} and {¬v, b} and {c, d}

Answer: option B. The new variable v links the two halves and cannot satisfy both clauses by itself.

Question 12 · medium

A graph on n vertices with a vertex cover of size k has an independent set of size:

  1. k
  2. n − k
  3. n
  4. k²

Answer: option B. The vertices outside a cover are pairwise non-adjacent.

Question 13 · medium

A clique in G corresponds, in the complement graph of G, to:

  1. a clique
  2. a vertex cover
  3. an independent set
  4. a spanning tree

Answer: option C. All-edges-present becomes no-edges-present when edges are complemented.

Question 14 · medium

In the standard reduction from 3-SAT to vertex cover, each variable gets an edge and each 3-literal clause gets a triangle. For n variables and c clauses, how many vertices are created?

  1. n + c vertices
  2. 2n + 3c vertices
  3. 3n + 2c vertices
  4. nc vertices

Answer: option B. Two per variable gadget, three per clause triangle.

Question 15 · medium

In the same construction (one edge per variable and one triangle per clause), with n variables and c clauses, what vertex-cover size bound is used?

  1. n + 2c
  2. 2n + c
  3. n + c
  4. 3c

Answer: option A. One vertex per variable edge plus two per triangle.

Question 16 · medium

In the incidence-digit reduction from vertex cover to subset sum described in the notes, what base prevents carries from edge columns?

  1. 2
  2. 3
  3. 4
  4. 10

Answer: option C. Base 4. Each edge column can receive two endpoint contributions and one filler contribution, totalling at most 3. Thus no edge column carries. The notes use “integer partition” for this target-sum variant; equal-partition is treated separately in question 119.

Question 17 · medium

To recover sorted order from a convex-hull algorithm that returns vertices in boundary order, map each distinct real number x to which point?

  1. (x, 0)
  2. (x, x)
  3. (x, x²)
  4. (x², x)

Answer: option C. Points on a parabola are all on the hull, in x order.

Question 18 · medium

“Does G contain a simple path with at least k edges?” is shown NP-complete by:

  1. local replacement
  2. restriction: k = n − 1 is Hamiltonian path
  3. reducing it to SAT
  4. dynamic programming

Answer: option B. Set k = n − 1 to obtain Hamiltonian path, which proves NP-hardness. Also verify a proposed simple path in polynomial time to establish membership in NP. Both are needed for NP-completeness.

Question 19 · hard · optional challenge

For positive labelled subset-sum items of total W > 0 and target 0 ≤ t ≤ W, which two extra labelled items give the equal-partition reduction?

  1. t
  2. W − t
  3. 2W − t and W + t
  4. W

In simpler words: Force a target sum inside one equal half.

Starting hint: Find the new total before deciding where the large items can go.

Answer: option C. Add 2W − t and W + t. The new total is 4W, so each half must sum to 2W. The extra items sum to 3W and cannot share a half; the half containing 2W − t therefore needs original items totalling t.

Step by step
  1. Total W+(2W−t)+(W+t)=4W, so each half is 2W.
  2. The large items sum to 3W and must be separated. The half containing 2W−t needs precisely t from the original items.

Question 20 · hard · optional challenge

Which statement is an established algorithmic guarantee?

  1. every unsatisfiable formula is known to have a polynomial-size certificate verifiable in polynomial time
  2. both endpoints of a maximal matching form a vertex cover of size at most twice the optimum
  3. the doubled-MST shortcut tour can have three times the optimum length in a complete metric graph
  4. a polynomial-time algorithm is known for general 3-colourability

In simpler words: Use a matching as a lower bound on any vertex cover.

Starting hint: No one vertex can cover two disjoint matching edges.

Answer: option B. A matching uses disjoint edges, so every cover needs at least one endpoint per matched edge. Selecting both gives at most twice optimum; maximality ensures every edge is covered. The doubled-MST guarantee is at most 2, and no general polynomial algorithm for 3-colourability is known. General short certificates for unsatisfiability are also not known.

Step by step
  1. For r disjoint edges, every cover needs at least r vertices.
  2. Taking both endpoints uses 2r. Maximality ensures no uncovered edge remains, so this is a valid cover with the factor-2 guarantee.

Written questions

Read each question together with its explanation, trace or proof. Numbering continues from the test questions.

Question 21 · easy

What is a reduction, and in which direction does hardness travel along it?

Answer & reasoning

a translation of every instance of problem A into an instance of problem B that preserves the yes/no answer, computable in polynomial time. If A is hard, then B is at least as hard (a fast B would give a fast A). Fast algorithms travel the other way, from B to A.

Question 22 · easy

Define P, NP and NP-complete, one sentence each.

Answer & reasoning

P: problems solvable in polynomial time. NP: problems for which a proposed yes-answer can be checked in polynomial time. NP-complete: problems in NP to which every problem in NP reduces, so they are the hardest problems in NP.

Question 23 · easy

Why is satisfiability in NP?

Answer & reasoning

given a proposed truth assignment, you can check every clause in time linear in the size of the formula.

Question 24 · easy

Give a satisfying assignment for the clauses {x, y}, {¬x, y}, {¬y, z}.

Answer & reasoning

y = true and z = true satisfy all three clauses whatever x is.

Question 25 · easy

Is the clause set {x}, {¬x} satisfiable? What about the single clause {x, ¬x}?

Answer & reasoning

no: x would have to be both true and false. Yes: one literal of {x, ¬x} is always true.

Question 26 · easy

Write the decision version of the shortest-path problem.

Answer & reasoning

given a weighted graph, two vertices s and t, and a number k, is there a path from s to t of total weight at most k?

Question 27 · easy

What is the size of the smallest vertex cover of the path 1–2–3–4? Give one.

Answer & reasoning

2, for example {2, 3}: it touches the edges 1–2, 2–3 and 3–4. One vertex cannot touch all three edges.

Question 28 · easy

What is the size of the largest independent set of the same path?

Use the path graph with vertices 1, 2, 3, 4 and edges 1–2, 2–3, 3–4.

Answer & reasoning

2, for example {1, 3}, {1, 4} or {2, 4}. This is 4 − 2, the complement of a minimum vertex cover.

Question 29 · easy

What is the largest clique in a triangle? In the path 1–2–3–4?

Answer & reasoning

3 (the whole triangle); 2 (any single edge; no three vertices are mutually adjacent).

Question 30 · easy

In each pair, which problem is NP-complete: shortest path or longest simple path; Eulerian circuit or Hamiltonian circuit; edge cover or vertex cover?

Answer & reasoning

The decision versions of longest simple path, Hamiltonian circuit and vertex cover are NP-complete. Unweighted or nonnegative-weight shortest-path decision, Eulerian-circuit existence, and edge-cover decision have polynomial algorithms. Keep the input assumptions and decision/optimisation distinction explicit.

Question 31 · easy

Which of 2-SAT and 3-SAT has a fast algorithm, and why does the chain construction not settle the other?

Answer & reasoning

2-SAT is in P. The chain construction for proving hardness needs a spare slot in each clause to hold a linking variable, and clauses of size 2 have none, so it does not apply; 3-SAT is NP-complete.

Question 32 · easy

What does the question “P = NP?” ask, in plain words?

Answer & reasoning

whether every problem whose answers can be checked quickly can also be solved quickly. Nobody knows; it is the biggest open problem in computer science.

Question 33 · easy

Which four problems does Skiena use as sources for reductions, and what kind of target problem suits each?

Answer & reasoning

3-SAT (the general-purpose choice), integer partition (targets whose hardness involves large numbers), vertex cover (graph problems about selecting a subset), Hamiltonian path (graph problems about ordering or routing).

Question 34 · easy

If someone found a polynomial-time algorithm for vertex cover, what would follow?

Answer & reasoning

P = NP: every problem in NP reduces to vertex cover in polynomial time, so all of them, including SAT, TSP and the rest, would have polynomial algorithms.

Question 35 · medium

Convert the 4-literal clause {a, b, c, d} into clauses of exactly three literals using the chain construction, and check that the new clauses are satisfiable exactly when the old one is.

Answer & reasoning

Introduce v and use (a ∨ b ∨ v) ∧ (¬v ∨ c ∨ d). If a or b is true, choose v = false: the first clause is already satisfied and ¬v satisfies the second. Otherwise, if c or d is true, choose v = true: v satisfies the first and c or d satisfies the second. If all four original literals are false, the two clauses require v and ¬v simultaneously. Thus the new formula is satisfiable exactly when the original clause is.

Question 36 · medium

Convert the single-literal clause {a} into 3-literal clauses.

Answer & reasoning

with new variables v₁, v₂: {a, v₁, v₂}, {a, v₁, ¬v₂}, {a, ¬v₁, v₂}, {a, ¬v₁, ¬v₂}. Every combination of v₁, v₂ falsifies the other two literals of one clause, so only a = true satisfies all four.

Question 37 · medium

Prove that a graph on n vertices has a vertex cover of size k if and only if it has an independent set of size n − k.

Answer & reasoning

if S is a vertex cover, no edge has both endpoints outside S (such an edge would be uncovered), so V − S is independent. If I is independent, every edge has at most one endpoint in I, hence at least one in V − I, so V − I is a cover. The sizes are complementary.

Question 38 · medium

Describe the complement of the 4-cycle 1–2–3–4–1, and show how an independent set in the cycle becomes a clique in the complement.

Answer & reasoning

the complement has exactly the missing edges, 1–3 and 2–4. The independent set {1, 3} of the cycle is an edge, that is a clique of size 2, in the complement; likewise {2, 4}.

Question 39 · medium

Show that subset sum and the TSP decision problem are both in NP.

Answer & reasoning

subset sum: the certificate is the subset; add it up and compare with t, polynomial time. TSP: the certificate is the tour; check it visits every city once and add its edge weights, polynomial time.

Question 40 · medium

You want to prove that your problem X is NP-complete. Why is a reduction from X to SAT useless for that purpose, and what would it prove instead?

Answer & reasoning

A polynomial reduction X → SAT gives a method for solving X using a SAT solver; it establishes membership in NP for an ordinary polynomial many-one reduction to SAT, not NP-hardness of X. To prove X NP-hard, reduce a known NP-complete problem to X. To conclude NP-completeness, also establish that X is in NP. A SAT solver is not assumed to take exponential time on every input.

Question 41 · medium

Show that “does G contain a simple path with at least k edges?” is NP-complete, using restriction.

Answer & reasoning

the special case k = n − 1 asks whether G has a path through all n vertices, which is exactly the Hamiltonian path problem, known to be NP-complete. A problem with an NP-complete special case is NP-complete (membership in NP: the path is a checkable certificate).

Question 42 · medium

Write the integer-programming constraints that encode the clause (x ∨ ¬y ∨ z) in the reduction from SAT.

Answer & reasoning

Use integer variables X, X̄, Y, Ȳ, Z, Z̄ in {0,1}. Require X + X̄ = Y + Ȳ = Z + Z̄ = 1 and X + Ȳ + Z ≥ 1. The last inequality says at least one literal is true. Integrality is essential: allowing arbitrary fractions in [0,1] would not encode Boolean truth values.

Question 43 · medium

Someone hands you a graph and a colouring of its vertices with three colours. How quickly can you check whether it is a proper colouring, and what does that say about the 3-colouring problem?

Answer & reasoning

Check that every vertex is assigned one of the three allowed colours, then check each edge has differently coloured endpoints: O(n + m). This puts the decision problem in NP. Deciding whether such a colouring exists is NP-complete; finding a colouring is the associated search task.

Question 44 · medium

Explain why every problem in P is also in NP.

Answer & reasoning

if you can solve the problem in polynomial time, you can check any proposed answer in polynomial time simply by ignoring it, solving from scratch, and comparing.

Question 45 · medium

Give a polynomial reduction from “independent set of size ≥ k” to “clique of size ≥ k”.

Answer & reasoning

build the complement graph Ḡ (same vertices, an edge exactly where G has none), which takes O(n²), and ask for a clique of size k in Ḡ. A set is independent in G if and only if it is a clique in Ḡ.

Question 46 · medium

Show that set cover is NP-complete by a reduction from vertex cover.

Answer & reasoning

let the universe be the set of edges of G, and for each vertex v make the subset Sᵥ of edges touching v. A collection of k subsets covers all edges exactly when the corresponding k vertices form a vertex cover. Set cover is in NP (a proposed collection is easy to check), so it is NP-complete.

Question 47 · medium

Using the travelling salesman problem, explain the difference between verifying a solution and finding one.

Answer & reasoning

A proposed tour is checked by verifying the visits and adding its edge weights, then comparing with the bound; this takes polynomial time in the encoded input. Finding a qualifying tour requires an algorithm to select one. Exhaustive enumeration is one method, but is not known to be necessary. No polynomial-time exact algorithm for general TSP is known; that is not a proof that every method must enumerate all tours.

Question 48 · medium

Prove: if any single NP-complete problem is in P, then P = NP.

Answer & reasoning

let X be NP-complete and in P. Every problem Y in NP reduces to X in polynomial time. To solve Y: translate the instance to X (polynomial), solve X (polynomial), return the answer. Two polynomials compose to a polynomial, so Y is in P. Hence NP ⊆ P, and with P ⊆ NP always, P = NP. Equally, proving that one NP-complete problem needs exponential time would prove P ≠ NP.

Question 49 · hard · optional challenge

The partition problem asks whether a set of integers can be split into two halves with equal sums. Prove it is NP-complete by reducing subset sum to it.

In simpler words: Turn a target-sum question into an equal-halves question.

Starting hint: Create two large items that must go into different halves.

Answer & reasoning
Step by step
  1. Original total W plus new weights 2W−t and W+t gives total 4W; each half must weigh 2W.
  2. The two new weights together are 3W, so they cannot share a half.
  3. The half containing 2W−t needs exactly t from the original items. This proves both directions, and the numbers have polynomial bit length. Finally, checking a proposed partition is polynomial, giving NP membership.

Use positive-integer subset sum with total W > 0 and 0 ≤ t ≤ W; targets outside the range can be handled directly. Add two labelled items of weights 2W − t and W + t. The total is 4W, so equal halves each weigh 2W. The new items cannot share a half because together they weigh 3W > 2W. The half containing 2W − t needs original items totalling exactly t. Conversely such a subset determines a partition. Labels preserve distinct items even when weights coincide. The transformation has polynomial bit length; a proposed partition is easy to verify.

Question 50 · hard · optional challenge

Prove that Hamiltonian cycle is NP-complete by reducing Hamiltonian path to it.

In simpler words: Close any all-vertex path by adding one universal vertex.

Starting hint: A universal vertex is adjacent to every original vertex.

Answer & reasoning
Step by step
  1. For an undirected graph with at least two vertices, add z and edges from z to all original vertices.
  2. An original Hamiltonian path u→…→v becomes the cycle z→u→…→v→z.
  3. Conversely, delete z from any Hamiltonian cycle of the new graph to get a path through every old vertex. Tiny inputs can be handled separately; a cycle certificate is polynomial to check.

given G, add a new vertex z joined to every vertex of G, giving G′. If G has a Hamiltonian path from u to v, then z–u–…–v–z is a Hamiltonian cycle of G′. Conversely a Hamiltonian cycle of G′ passes through z once; deleting z leaves a path through every vertex of G. Membership in NP is clear (the cycle is the certificate).

Question 51 · hard · optional challenge

Two-colouring is easy (BFS, Lecture 11) but three-colouring is NP-complete. Explain why the BFS approach breaks down for three colours.

In simpler words: See why two colours force choices but three colours do not.

Starting hint: After colouring one vertex, count its neighbour’s available colours.

Answer & reasoning
Step by step
  1. With two colours, each neighbour has just one allowed colour.
  2. With three, each neighbour may have two allowed colours, and choices can interact across distant edges.
  3. Thus the forced BFS procedure no longer solves every case. This explains why that argument fails, not why every possible algorithm must be exponential.

With two colours, choosing a component’s first colour forces every neighbour to use the other colour; BFS can detect a conflict. With three colours, a neighbour can have two choices, and those choices affect later edges. The simple forced-colouring argument therefore fails. Backtracking may explore exponentially many choices, but that is not a proof that every possible algorithm must take exponential time.

Question 52 · hard · optional challenge

Give a simple algorithm that always finds a vertex cover at most twice the size of the smallest one, and prove the factor of 2.

In simpler words: Cover both ends of disjoint edges and compare with any optimum.

Starting hint: Each chosen edge forces every cover to include at least one endpoint.

Answer & reasoning
Step by step
  1. Pick an uncovered edge, add both endpoints, and discard every edge now covered. Continue until none remain.
  2. Chosen edges have no shared endpoints, so they form a matching of size r. Every cover needs at least r vertices.
  3. Your cover uses exactly 2r vertices, hence at most twice optimum. “Maximal” means no more disjoint edges can be added; it need not be the largest matching.

while some edge is uncovered, pick one and put both its endpoints into the cover. The chosen edges share no endpoints (each new edge was uncovered by all earlier endpoints), so they form a matching M. Any vertex cover, including the optimal one, must contain at least one endpoint of every edge of M, so OPT ≥ |M|. Our cover has exactly 2|M| vertices, hence at most 2 × OPT.

Question 53 · hard · optional challenge

For points in the plane (where the triangle inequality holds), prove that walking around the minimum spanning tree gives a travelling-salesman tour at most twice the optimal length.

In simpler words: Compare an MST walk with the unknown best tour.

Starting hint: An optimal tour with one edge removed is a spanning tree.

Answer & reasoning
Step by step
  1. Therefore the MST weight is at most the optimal tour length.
  2. Traverse each tree edge in both directions: a closed walk of length 2·MST visits every vertex.
  3. Skip repeated vertices. Triangle inequality ensures a direct shortcut is no longer than the replaced detour. The resulting tour costs at most 2·OPT.

remove one edge from the optimal tour: what remains is a spanning tree, so MST ≤ OPT. Doubling every MST edge gives a closed walk that visits all vertices with length 2 × MST ≤ 2 × OPT. Walk it, skipping vertices already visited; by the triangle inequality each shortcut is no longer than the detour it replaces, so the resulting tour is at most 2 × MST ≤ 2 × OPT.

Question 54 · hard · optional challenge

SAT is in NP because a satisfying assignment is a short certificate. Is “this formula is unsatisfiable” obviously in NP? Explain.

In simpler words: Distinguish showing that one assignment works from showing none work.

Starting hint: A failed candidate does not rule out the other candidates.

Answer & reasoning
Step by step
  1. A satisfying assignment is a short witness: check every clause.
  2. For unsatisfiability, no universal polynomial-size certificate with a polynomial-time checker is known; restricted cases may still have easy proofs.
  3. UNSAT belongs to co-NP. Whether it also belongs to NP is unresolved and equivalent to NP=co-NP. Do not turn “unknown” into “impossible.”

No general polynomial-size, polynomially checkable certificate for unsatisfiability is known. Such certificates do exist for some restricted formulas. UNSAT is in co-NP because its no-instances have satisfying assignments as certificates. Whether UNSAT is also in NP is equivalent to NP = co-NP and remains open; exhaustive enumeration is one method, not a proven necessity.

Question 55 · hard · optional challenge

Apply the 3-SAT to vertex cover reduction to the formula with clauses {x, y, ¬z} and {¬x, y, z}. How many vertices does the graph have, what cover size is asked for, and which vertices form a cover for the assignment x = y = z = true?

In simpler words: Count the small building blocks, then cover their edges.

Starting hint: Use one vertex from each variable pair and two from each clause triangle.

Answer & reasoning
Step by step
  1. There are 3 variable edges: 6 vertices. Two clause triangles add 6 more, giving 12; the target is 3+2·2=7.
  2. Select variable vertices x,y,z. In triangle (x,y,¬z), leave x out and select y,¬z. In triangle (¬x,y,z), leave y out and select ¬x,z.
  3. Each variable edge is covered; two vertices cover every triangle edge. A skipped clause vertex has its same-literal variable endpoint selected, so its cross edge is covered too.

n = 3 variables and c = 2 clauses give 2·3 + 3·2 = 12 vertices and a target cover size of n + 2c = 7. Variable gadgets: take the true literals x, y, z (3 vertices). Clause triangle {x, y, ¬z}: its x-vertex’s cross edge is already covered from the variable side (x is true), so take the other two, the y-vertex and the ¬z-vertex. Triangle {¬x, y, z}: y is true, so take the ¬x-vertex and the z-vertex. Total 3 + 2 + 2 = 7 vertices, covering every variable edge, every triangle edge and every cross edge.

Stephen Cook ve Richard Karp’ın 1970’lerin başında geliştirdiği NP-tamlık kuramı, bunların aslında aynı problemin farklı görünümleri olduğunu gösterir: herhangi biri için hızlı algoritma, hepsi için hızlı algoritma verir.

Skiena’s summary, which he calls his most profound tweet: “An NP-completeness proof ensures that a dumb algorithm that is slow isn’t a slow algorithm that is dumb.”

Skiena’nın “en derin tweet’im” dediği özeti: “Bir NP-tamlık kanıtı, yavaş çalışan basit bir algoritmanın, yalnızca aptalca tasarlandığı için yavaş olmadığını güvenceye alır.”

Lecture 19 · The main idea: reductions

Temel fikir: İndirgemeler

Suppose I hand you this algorithm for a problem called Bandersnatch:

Size Bandersnatch adlı bir problem için şu algoritmayı verdiğimi varsayın:

Bandersnatch(G):
    convert G into an instance Y of the Bo-billy problem
    call the Bo-billy subroutine on Y
    return Bo-billy's answer as the answer for G
Bandersnatch(G):
    G’yi Bo-billy probleminin bir Y örneğine dönüştür
    Y üzerinde Bo-billy alt yordamını çağır
    Bo-billy’nin yanıtını G’nin yanıtı olarak döndür

A translation of instances of one problem into instances of another that preserves the answers is called a reduction. Say the translation from G to Y takes O(P(n)) time. Two consequences:

Bir problemin örneklerini başka bir problemin örneklerine yanıtları koruyarak dönüştürmeye indirgeme denir. G’den Y’ye dönüşüm O(P(n)) zaman alsın. İki sonuç:

Upper bound flows forward. If Bo-billy can be solved in O(P′(n)), then Bandersnatch can be solved in O(P(n) + P′(n′)): translate, then solve. (n′ is the size of the translated instance.)

Üst sınır ileriye aktarılır. Bo-billy O(P′(n)) sürede çözülebiliyorsa Bandersnatch O(P(n) + P′(n′)) sürede çözülebilir: dönüştür, sonra çöz. (n′, dönüştürülmüş örneğin boyutudur.)

Hardness flows backward. If Bandersnatch is known to require Ω(P′(n)) time, then Bo-billy must require Ω(P′(n) − P(n′)); otherwise translating and solving Bo-billy would beat Bandersnatch’s lower bound.

Zorluk geriye aktarılır. Bandersnatch’in Ω(P′(n)) zaman gerektirdiği biliniyorsa Bo-billy, Ω(P′(n) − P(n′)) zaman gerektirmelidir. Aksi hâlde dönüştürüp Bo-billy’yi çözmek, Bandersnatch’in alt sınırını aşardı.

The second consequence is the whole trick for proving problems hard: if a known-hard problem reduces to your problem, your problem is at least as hard. Fast algorithms transfer from the target of the reduction to its source; hardness transfers from the source to the target.

İkinci sonuç, problemlerin zor olduğunu kanıtlama tekniğinin özüdür: zor olduğu bilinen bir problem sizin probleminize indirgeniyorsa, probleminiz en az onun kadar zordur. Hızlı algoritmalar indirgeme hedefinden kaynağına, zorluk ise kaynaktan hedefe aktarılır.

Reductions are not new in this course. Lecture 7 showed that element uniqueness, finding the mode, closest pair and others reduce to sorting: solve sorting and you have solved them all. (Skiena’s joke: an engineer and a computer scientist each want tea. The engineer fills the kettle and boils it. The computer scientist, finding the kettle already full, empties it, thereby reducing the situation to a previously solved problem.)

İndirgemeler bu derste yeni değildir. Ders 7, eleman benzersizliği, mod bulma, en yakın çift ve başka problemlerin sıralamaya indirgendiğini gösterdi: sıralamayı çözerseniz hepsini çözmüş olursunuz. (Skiena’nın şakası: Bir mühendis ve bir bilgisayar bilimci çay ister. Mühendis çaydanlığı doldurup kaynatır. Bilgisayar bilimci çaydanlığı dolu bulunca boşaltır; böylece durumu daha önce çözülmüş bir probleme indirger.)

Lecture 19 · Problems, instances and decision problems

Problemler, problem örnekleri ve karar problemleri

A problem is a general question with parameters for the input and conditions on what counts as a satisfactory answer. The travelling salesman problem: given a weighted graph G, which tour v₁, v₂, …, vₙ minimises d[v₁, v₂] + d[v₂, v₃] + … + d[vₙ, v₁]?

Problem, girdi parametreleri ve kabul edilebilir yanıtın koşulları olan genel bir sorudur. Gezgin satıcı problemi: ağırlıklı G çizgesi verildiğinde hangi v₁, v₂, …, vₙ turu, d[v₁, v₂] + d[v₂, v₃] + … + d[vₙ, v₁] toplamını en aza indirir?

An instance is the problem with its input filled in. A TSP instance is a specific set of distances, such as d[1, 2] = 10, d[1, 3] = 5, d[1, 4] = 9, d[2, 3] = 6, d[2, 4] = 9, d[3, 4] = 3, for which the best tour is 1, 2, 3, 4 with cost 27.

Problem örneği, girdisi belirlenmiş problemdir. Bir TSP örneği, d[1, 2] = 10, d[1, 3] = 5, d[1, 4] = 9, d[2, 3] = 6, d[2, 4] = 9, d[3, 4] = 3 gibi belirli bir uzaklıklar kümesidir. Bunun için en iyi tur, 27 maliyetli 1, 2, 3, 4 turudur.

A decision problem is one whose answer is yes or no. Most optimisation problems have a decision version that captures the essential difficulty. For TSP: given a weighted graph G and an integer k, is there a tour of cost at most k? If you could answer that quickly, binary search on k would find the optimal cost quickly too, so nothing important is lost by restricting attention to yes/no questions. From here on, the theory deals only with decision problems, because it makes reductions much cleaner: a reduction must map yes-instances to yes-instances and no-instances to no-instances.

Karar problemi, yanıtı evet veya hayır olan problemdir. Çoğu optimizasyon probleminin temel zorluğunu yakalayan bir karar sürümü vardır. TSP için: ağırlıklı G çizgesi ve k tam sayısı verildiğinde, maliyeti en fazla k olan bir tur var mı? Bunu hızlı yanıtlayabilseydiniz k üzerinde ikili arama optimal maliyeti de hızla bulurdu; dolayısıyla yalnızca evet/hayır sorularına odaklanmak önemli bir şey kaybettirmez. Bundan sonra kuram yalnızca karar problemleriyle ilgilenir; çünkü indirgemeler böyle çok daha temizdir: indirgeme, evet örneklerini evet örneklerine, hayır örneklerini hayır örneklerine eşlemelidir.

Lecture 20 · Warm-up: from a yes/no oracle to an actual tour

Hazırlık: Evet/hayır kâhininden gerçek bir tura

Suppose a subroutine answers the TSP decision question (“is there a tour of cost ≤ k?”) in linear time. To find the actual tour with polynomially many calls: first binary-search on k to find the optimal cost k*. Then, for each edge in turn, raise its weight to something huge and ask whether a tour of cost k* still exists. If yes, the edge is not needed; leave it expensive. If no, the edge is essential; restore it. After all m edges, the edges left at their original weights form the optimal tour. About log(max cost) + m calls in total.

Bir alt yordamın TSP karar sorusunu (“maliyeti ≤ k olan bir tur var mı?”) doğrusal sürede yanıtladığını varsayın. Gerçek turu polinom sayıda çağrıyla bulmak için önce k üzerinde ikili arama yapıp optimal k* maliyetini bulun. Ardından her kenarı sırayla ele alın, ağırlığını çok büyük bir değere yükseltin ve maliyeti k* olan bir turun hâlâ var olup olmadığını sorun. Evetse kenar gerekli değildir; pahalı bırakın. Hayırsa kenar zorunludur; eski ağırlığını geri yükleyin. m kenarın tamamı ele alındıktan sonra özgün ağırlıklarında kalan kenarlar optimal turu oluşturur. Toplamda yaklaşık log(maksimum maliyet) + m çağrı.

Lecture 20 · Satisfiability

Sağlanabilirlik

Instance: a set V of boolean variables and a set C of clauses over V. A literal is a variable or its negation (v or v̄); a clause is a set of literals, satisfied when at least one of them is true.

Problem örneği: Boole değişkenlerinden oluşan V kümesi ve V üzerinde tanımlanan yan tümcelerden oluşan C kümesi. Literal, bir değişken veya onun değillemesidir (v veya v̄). Yan tümce, en az biri doğru olduğunda sağlanan bir literaller kümesidir.

Question: is there a truth assignment (true/false for each variable) that satisfies every clause?

Soru: Her yan tümceyi sağlayan bir doğruluk ataması (her değişken için doğru/yanlış) var mı?

Example 1: V = {v₁, v₂}, C = {{v₁, v̄₂}, {v̄₁, v₂}}. Setting v₁ = v₂ = true satisfies both clauses: satisfiable.

Örnek 1: V = {v₁, v₂}, C = {{v₁, v̄₂}, {v̄₁, v₂}}. v₁ = v₂ = true ataması iki yan tümceyi de sağlar: sağlanabilir.

Example 2: V = {v₁, v₂}, C = {{v₁, v₂}, {v₁, v̄₂}, {v̄₁}}. The third clause forces v₁ false; then the second clause forces v₂ false; but then the first clause is false. Not satisfiable, however hard you try (Skiena: you can get no satisfaction).

Örnek 2: V = {v₁, v₂}, C = {{v₁, v₂}, {v₁, v̄₂}, {v̄₁}}. Üçüncü yan tümce v₁’i yanlış olmaya zorlar; ardından ikincisi v₂’yi yanlış olmaya zorlar; fakat bu kez ilk yan tümce yanlıştır. Ne kadar uğraşırsanız uğraşın sağlanamaz (Skiena’nın kelime oyunuyla: “tatmin elde edemezsiniz”).

SAT is known, or at least universally assumed, to be hard. Every top algorithms expert has tried and failed to find a fast general algorithm, and many strange, impossible-to-believe consequences would follow if one existed. Cook’s theorem (1971) proved that every problem in NP reduces to SAT, which makes SAT the anchor of the whole theory.

SAT’ın zor olduğu bilinir ya da en azından yaygın biçimde böyle varsayılır. Üst düzey algoritma uzmanlarının hepsi hızlı bir genel algoritma bulmayı denemiş ve başaramamıştır; böyle bir algoritma var olsaydı çok sayıda tuhaf, inanılması güç sonuç doğardı. Cook teoremi (1971), NP’deki her problemin SAT’a indirgendiğini kanıtladı; bu, SAT’ı bütün kuramın dayanağı yapar.

Lecture 20 · 3-SAT

3-SAT

Instance: a collection of clauses each containing exactly three literals.

Problem örneği: Her biri tam üç literal içeren yan tümceler topluluğu.

Question: is there a satisfying assignment?

Soru: Sağlayan bir atama var mı?

This is a more restricted problem than SAT. Restricting a problem can only make it easier, so “3-SAT is NP-complete” is a stronger statement than “SAT is NP-complete”, and it needs its own proof. Perhaps long clauses are what makes SAT hard? After all, 1-SAT (every clause is a single literal) is trivial: just set each literal true and check for contradictions.

Bu, SAT’tan daha kısıtlı bir problemdir. Bir problemi kısıtlamak onu ancak kolaylaştırabilir; bu yüzden “3-SAT NP-tamdır” ifadesi, “SAT NP-tamdır” ifadesinden daha güçlüdür ve kendi kanıtını gerektirir. Belki SAT’ı zorlaştıran uzun yan tümcelerdir? Sonuçta 1-SAT (her yan tümce tek literaldir) basittir: her literali doğru yapın ve çelişki olup olmadığını denetleyin.

Reduction from SAT to 3-SAT. Transform each clause independently according to its length k:

SAT’tan 3-SAT’a indirgeme. Her yan tümceyi k uzunluğuna göre bağımsız olarak dönüştürün:

k = 1, clause {z₁}: create two new variables v₁, v₂ and four clauses {v₁, v₂, z₁}, {v₁, v̄₂, z₁}, {v̄₁, v₂, z₁}, {v̄₁, v̄₂, z₁}. Every combination of v₁, v₂ appears, so the only way to satisfy all four is z₁ = true, exactly the effect of the original clause.

k = 1, {z₁} yan tümcesi: İki yeni v₁, v₂ değişkeni ve dört yan tümce oluşturun: {v₁, v₂, z₁}, {v₁, v̄₂, z₁}, {v̄₁, v₂, z₁}, {v̄₁, v̄₂, z₁}. v₁, v₂’nin her birleşimi bulunur; dolayısıyla dördünü birden sağlamanın tek yolu z₁ = true’dur. Bu, özgün yan tümcenin etkisinin aynısıdır.

k = 2, clause {z₁, z₂}: one new variable v₁ and two clauses {v₁, z₁, z₂}, {v̄₁, z₁, z₂}. Again, only z₁ or z₂ being true satisfies both.

k = 2, {z₁, z₂} yan tümcesi: Bir yeni v₁ değişkeni ve iki yan tümce: {v₁, z₁, z₂}, {v̄₁, z₁, z₂}. Yine yalnızca z₁ veya z₂’nin doğru olması ikisini de sağlar.

k = 3: copy the clause unchanged.

k = 3: Yan tümceyi değiştirmeden kopyalayın.

k > 3, clause {z₁, …, zₖ}: create k − 3 new variables and a chain of k − 2 clauses: {z₁, z₂, v₁}, {v̄₁, z₃, v₂}, {v̄₂, z₄, v₃}, …, {v̄ₖ₋₃, zₖ₋₁, zₖ}.

k > 3, {z₁, …, zₖ} yan tümcesi: k − 3 yeni değişken ve k − 2 yan tümcelik bir zincir oluşturun: {z₁, z₂, v₁}, {v̄₁, z₃, v₂}, {v̄₂, z₄, v₃}, …, {v̄ₖ₋₃, zₖ₋₁, zₖ}.

Why the chain works. If none of the original literals is true, each clause must be satisfied by its new variable, and the pattern forces v₁ true, then v₂ true (because v̄₁ is false), and so on down the chain, until the last clause has nothing left to make it true: unsatisfiable, as it should be. If any original literal is true, the clause containing it is satisfied, and the k − 3 free variables can be set to satisfy the clauses before it (true) and after it (false). So any SAT solution extends to a 3-SAT solution and any 3-SAT solution restricts to a SAT solution. The two instances are equivalent, and the construction is polynomial.

Zincir neden çalışır? Özgün literallerin hiçbiri doğru değilse her yan tümce yeni değişkeniyle sağlanmalıdır. Düzen, önce v₁’i, sonra (v̄₁ yanlış olduğu için) v₂’yi doğru olmaya zorlar ve zincir boyunca sürer; sonunda son yan tümceyi doğru yapacak hiçbir şey kalmaz: olması gerektiği gibi sağlanamaz. Özgün literallerden biri doğruysa onu içeren yan tümce sağlanır; k − 3 serbest değişken, öncesindeki yan tümceleri (doğru), sonrasındakileri (yanlış) sağlayacak biçimde atanabilir. Dolayısıyla her SAT çözümü bir 3-SAT çözümüne genişler ve her 3-SAT çözümü bir SAT çözümüne kısıtlanır. İki örnek eşdeğerdir ve yapım polinom zamanlıdır.

The same trick proves 4-SAT, 5-SAT and so on NP-complete. It breaks for 2-SAT: with only two slots per clause there is no room to chain anything, and indeed 2-SAT has a fast algorithm.

Aynı teknik 4-SAT, 5-SAT vb. problemlerin NP-tamlığını kanıtlar. 2-SAT’ta işlemez: her yan tümcede yalnızca iki yer olduğundan zincir kuracak alan kalmaz. Nitekim 2-SAT’ın hızlı algoritması vardır.

Lecture 20 · The direction of a reduction

İndirgeme yönü

3-SAT instances are smaller and more regular than general SAT instances, which makes 3-SAT the convenient starting point for further reductions: SAT ∝ 3-SAT ∝ X.

3-SAT örnekleri genel SAT örneklerinden daha küçük ve düzenlidir; bu nedenle 3-SAT, sonraki indirgemeler için uygun başlangıç noktasıdır: SAT ∝ 3-SAT ∝ X.

A perpetual point of confusion: to prove problem X hard, you must transform every instance of a known NP-complete problem into an instance of X. Doing it the other way round (X into SAT) proves nothing; it just gives a slow way to solve X by calling an exponential subroutine.

Sürekli karıştırılan nokta: X probleminin zor olduğunu kanıtlamak için, bilinen bir NP-tam problemin her örneğini X’in bir örneğine dönüştürmelisiniz. Tersini yapmak (X’i SAT’a dönüştürmek) hiçbir şey kanıtlamaz; yalnızca üstel bir alt yordam çağırarak X’i çözmenin yavaş bir yolunu verir.

Lecture 20 · Vertex cover

Tepe örtüsü

Instance: a graph G = (V, E) and an integer k ≤ |V|.

Problem örneği: G = (V, E) çizgesi ve k ≤ |V| tam sayısı.

Question: is there a set of at most k vertices such that every edge has at least one endpoint in the set?

Soru: Her kenarın en az bir ucunu içeren, en fazla k tepeli bir küme var mı?

Finding some vertex cover is trivial (take all the vertices); the difficulty is finding a small one. In the slides’ example four of eight vertices suffice.

Herhangi bir tepe örtüsü bulmak basittir (bütün tepeleri alın); zorluk küçük bir örtü bulmaktadır. Slaytlardaki örnekte sekiz tepenin dördü yeterlidir.

Reduction from 3-SAT to vertex cover. From a 3-SAT instance with n variables and c clauses, build a graph with 2n + 3c vertices:

3-SAT’tan tepe örtüsüne indirgeme. n değişkenli ve c yan tümceli bir 3-SAT örneğinden 2n + 3c tepeli bir çizge kurun:

Variable gadgets. For each variable vᵢ create two vertices, labelled vᵢ and v̄ᵢ, joined by an edge. Any cover must take at least one endpoint of each of these n edges: at least n vertices, one per variable.

Değişken düzenekleri. Her vᵢ değişkeni için vᵢ ve v̄ᵢ etiketli, aralarında bir kenar bulunan iki tepe oluşturun. Her örtü, bu n kenarın her birinin en az bir ucunu almak zorundadır: her değişken için bir tane, toplam en az n tepe.

Clause gadgets. For each clause create three vertices, one per literal, joined in a triangle. Covering a triangle’s three edges needs at least two of its vertices: at least 2c vertices in total.

Yan tümce düzenekleri. Her yan tümce için, literal başına bir tane olmak üzere, üçgen biçiminde bağlanmış üç tepe oluşturun. Üçgenin üç kenarını örtmek, en az iki tepesini gerektirir: toplam en az 2c tepe.

Cross edges. Connect each literal-vertex in a triangle to the variable-gadget vertex carrying the same literal.

Çapraz kenarlar. Üçgendeki her literal tepesini, aynı literali taşıyan değişken düzeneği tepesine bağlayın.

Claim: G has a vertex cover of size n + 2c if and only if the formula is satisfiable. Any cover needs at least n + 2c vertices, so the question is whether that minimum is achievable.

İddia: G’nin n + 2c boyutlu tepe örtüsü vardır ancak ve ancak formül sağlanabilirse. Her örtü en az n + 2c tepe gerektirir; dolayısıyla soru, bu minimuma ulaşılıp ulaşılamayacağıdır.

Satisfying assignment ⇒ cover. Put the n variable-gadget vertices corresponding to the true literals in the cover; that covers all variable edges. For each clause, at least one of its three literals is true, so at least one of its three cross edges is already covered from the variable side; put the other two triangle vertices in the cover, which covers the triangle’s edges and the remaining two cross edges. Total n + 2c.

Sağlayan atama ⇒ örtü. Doğru literallere karşılık gelen n değişken düzeneği tepesini örtüye alın; böylece bütün değişken kenarları örtülür. Her yan tümcede üç literalden en az biri doğrudur; dolayısıyla üç çapraz kenardan en az biri zaten değişken tarafından örtülmüştür. Diğer iki üçgen tepesini örtüye alın; böylece üçgenin kenarları ve kalan iki çapraz kenar örtülür. Toplam n + 2c.

Cover of size n + 2c ⇒ satisfying assignment. Such a cover must use exactly one vertex per variable gadget and exactly two per triangle. Read the truth assignment off the variable gadgets (a variable is true if its vᵢ vertex is in the cover). In each triangle one vertex is not in the cover, so its cross edge must be covered from the variable side, meaning that literal is true: every clause is satisfied.

n + 2c boyutlu örtü ⇒ sağlayan atama. Böyle bir örtü, her değişken düzeneğinden tam bir tepe ve her üçgenden tam iki tepe kullanmalıdır. Doğruluk atamasını değişken düzeneklerinden okuyun (vᵢ tepesi örtüdeyse değişken doğrudur). Her üçgende bir tepe örtünün dışındadır; bu yüzden onun çapraz kenarı değişken tarafından örtülmelidir. Bu da ilgili literal doğru demektir: her yan tümce sağlanır.

The slides run the construction on an example with v₁ = v₂ = true and v₃ = v₄ = false. Reductions can be clever and intricate; choosing the right starting problem (here 3-SAT, whose clauses map neatly onto triangles) makes them far easier to find.

Slaytlarda yapım, v₁ = v₂ = true ve v₃ = v₄ = false olan bir örneğe uygulanır. İndirgemeler zekice ve karmaşık olabilir; doğru başlangıç problemini seçmek (burada, yan tümceleri üçgenlere düzgünce eşlenen 3-SAT) onları bulmayı çok kolaylaştırır.

Lecture 20 · Independent set

Bağımsız küme

Instance: a graph G and an integer j.

Problem örneği: G çizgesi ve j tam sayısı.

Question: is there a set of j vertices with no edge between any two of them?

Soru: Hiçbir ikisi arasında kenar olmayan j tepeli bir küme var mı?

The movie star scheduling problem of Lecture 1 was a special case (jobs are vertices, overlapping jobs are joined; a schedule is an independent set), which happened to be easy because of the special structure of intervals.

Ders 1’deki film yıldızının çizelgeleme problemi özel bir durumdu (işler tepe, örtüşen işler kenarla bağlıdır; bir çizelge bağımsız kümedir). Aralıkların özel yapısı nedeniyle bu durum kolaydı.

To prove a graph problem hard it is natural to start from a graph problem, and vertex cover is the one we have. The connection is immediate: if S is a vertex cover, then V − S is an independent set, because any edge between two vertices outside S would be an edge with no endpoint in S. The smallest vertex cover gives the largest independent set and vice versa. So independent set is NP-complete: G has a vertex cover of size k exactly when it has an independent set of size |V| − k.

Bir çizge probleminin zor olduğunu kanıtlamak için çizge probleminden başlamak doğaldır; elimizdeki problem tepe örtüsüdür. Bağlantı doğrudandır: S bir tepe örtüsüyse V − S bağımsız kümedir; çünkü S dışındaki iki tepe arasında bulunacak herhangi bir kenarın S içinde hiçbir ucu olmazdı. En küçük tepe örtüsü en büyük bağımsız kümeyi verir; tersi de geçerlidir. Dolayısıyla bağımsız küme NP-tamdır: G’nin k boyutlu tepe örtüsü olması, tam olarak |V| − k boyutlu bağımsız kümesi olmasıyla eşdeğerdir.

Lecture 20 · Clique

Klik

Instance: a graph G and an integer j.

Problem örneği: G çizgesi ve j tam sayısı.

Question: is there a set of j vertices with an edge between every pair?

Soru: Her çifti arasında kenar bulunan j tepeli bir küme var mı?

A clique is the opposite of an independent set: all edges present rather than none. Take the complement graph Ḡ, which has an edge exactly where G does not. An independent set in G is a clique in Ḡ, and a clique in G is an independent set in Ḡ. Hence the punch line: if S is a vertex cover of G, then V − S is a clique in Ḡ; if C is a clique of G, then V − C is a vertex cover of Ḡ. Finding the largest clique is NP-complete.

Klik, bağımsız kümenin tersidir: hiç kenar olmaması yerine bütün kenarlar vardır. G’de kenar bulunmayan yerlerde tam olarak kenar içeren tümleyen çizge Ḡ’yi alın. G’deki bağımsız küme, Ḡ’de kliktir; G’deki klik, Ḡ’de bağımsız kümedir. Dolayısıyla sonuç: S, G’nin tepe örtüsüyse V − S, Ḡ’de kliktir; C, G’de klikse V − C, Ḡ’nin tepe örtüsüdür. En büyük kliğin bulunması NP-tamdır.

Lecture 21 · Warm-up: dense subgraph

Hazırlık: Yoğun alt çizge

Show that dense subgraph is NP-complete: given a graph G and integers k and y, does G have a subgraph on exactly k vertices with at least y edges? Reduce from clique (Lecture 20): a clique on k vertices is exactly a subgraph with k vertices and k(k − 1)/2 edges, so ask for y = k(k − 1)/2. A yes to the dense-subgraph question is then a yes to the clique question, and vice versa.

Yoğun alt çizgenin NP-tam olduğunu gösterin: G çizgesi ile k ve y tam sayıları verildiğinde, G’nin tam k tepeli ve en az y kenarlı bir alt çizgesi var mı? Klikten indirgeyin (Ders 20): k tepeli bir klik, tam olarak k tepeli ve k(k − 1)/2 kenarlı alt çizgedir; dolayısıyla y = k(k − 1)/2 isteyin. Yoğun alt çizge sorusunun evet yanıtı böylece klik sorusunun evet yanıtıdır; tersi de geçerlidir.

Skiena’s addendum to his tweet: “Just because you use backtracking doesn’t mean your problem has no fast algorithm.” Failing to find an algorithm is not a proof; a reduction is.

Skiena’nın tweet’ine eki: “Geri izleme kullanmanız, probleminizin hızlı algoritması olmadığı anlamına gelmez.” Algoritma bulamamak kanıt değildir; indirgeme kanıttır.

Lecture 21 · Integer partition (subset sum)

Tam sayı bölüşümü (alt küme toplamı)

Instance: a set S of integers and a target integer t.

Problem örneği: Tam sayılardan oluşan S kümesi ve hedef t tam sayısı.

Question: is there a subset of S whose elements add up to exactly t?

Soru: S’nin, elemanları toplamı tam t olan bir alt kümesi var mı?

Example: S = {1, 4, 16, 64, 256, 1040, 1041, 1093, 1284, 1344} and t = 3754 has the answer 1 + 16 + 64 + 256 + 1040 + 1093 + 1284. This is the knapsack puzzle of Lecture 2, and it is the first number problem in the hardness chain.

Örnek: S = {1, 4, 16, 64, 256, 1040, 1041, 1093, 1284, 1344} ve t = 3754 için yanıt 1 + 16 + 64 + 256 + 1040 + 1093 + 1284’tür. Bu, Ders 2’deki sırt çantası bulmacası ve zorluk zincirindeki ilk sayısal problemdir.

Reduction from vertex cover. Represent the graph G by its incidence matrix: one row per vertex, one column per edge, with a 1 where the vertex is an endpoint of the edge. Every column has exactly two 1s (an edge has two endpoints); a row has as many 1s as the vertex’s degree. From this matrix, build n + m numbers written in base 4:

Tepe örtüsünden indirgeme. G çizgesini geliş matrisiyle gösterin: her tepe için bir satır, her kenar için bir sütun; tepe kenarın ucuysa hücrede 1 bulunur. Her sütunda tam iki tane 1 vardır (kenarın iki ucu bulunur); bir satırda tepenin derecesi kadar 1 vardır. Bu matristen 4 tabanında yazılmış n + m sayı oluşturun:

A vertex number xᵢ for each vertex: read row i of the matrix as base-4 digits, and add a high-order digit 1 at position |E|. So a row 10100 becomes 4⁵ + (4⁴ + 4²) in the example.

Her tepe için bir xᵢ tepe sayısı: Matrisin i. satırını 4 tabanındaki basamaklar olarak okuyun ve |E| konumuna yüksek basamak değeri 1 ekleyin. Örnekte 10100 satırı böylece 4⁵ + (4⁴ + 4²) olur.

An edge number yⱼ = 4ʲ for each edge j: a single 1 in column j.

Her j kenarı için bir yⱼ = 4ʲ kenar sayısı: j sütununda tek bir 1.

The target t = k × 4^|E| + Σⱼ 2 × 4ʲ: the high-order digit is k and every edge digit is 2. In the example, t = 222222 in base 4 = 2730.

Hedef t = k × 4^|E| + Σⱼ 2 × 4ʲ: Yüksek basamak k’dir ve her kenar basamağı 2’dir. Örnekte t = 4 tabanında 222222 = 2730.

Why base 4? Each column contains at most three 1s across all the numbers (two vertex numbers plus the edge number), so adding any subset of the numbers never produces a carry from one digit to the next. Digits stay independent, and each digit can be reasoned about separately.

Neden 4 tabanı? Bütün sayılar birlikte düşünüldüğünde her sütunda en fazla üç tane 1 bulunur (iki tepe sayısı ve kenar sayısı). Bu nedenle sayıların herhangi bir alt kümesini toplamak, bir basamaktan diğerine asla elde üretmez. Basamaklar bağımsız kalır ve her biri ayrı ayrı incelenebilir.

Vertex cover ⇒ subset sum. Take the k vertex numbers of a cover; the high-order digit sums to k. Every edge is incident to one or two cover vertices, so its digit sums to 1 or 2; where it is 1, add the edge number yⱼ to make it 2. The total is exactly t.

Tepe örtüsü ⇒ alt küme toplamı. Bir örtünün k tepe sayısını alın; yüksek basamağın toplamı k olur. Her kenar bir veya iki örtü tepesine bağlıdır; bu yüzden ilgili basamak toplamı 1 veya 2’dir. 1 olduğunda yⱼ kenar sayısını ekleyerek 2 yapın. Toplam tam t olur.

Subset sum ⇒ vertex cover. The high-order digit of t is k and there are no carries, so any solution uses exactly k vertex numbers. Every edge digit must reach 2, and the edge number alone supplies only 1, so at least one chosen vertex number has a 1 in every edge column: those k vertices cover every edge.

Alt küme toplamı ⇒ tepe örtüsü. t’nin yüksek basamağı k’dir ve elde yoktur; dolayısıyla her çözüm tam k tepe sayısı kullanır. Her kenar basamağı 2’ye ulaşmalıdır; kenar sayısı tek başına yalnızca 1 sağladığı için seçilen tepe sayılarından en az biri her kenar sütununda 1 içermelidir: bu k tepe bütün kenarları örter.

Skiena: “Neat, sweet, and NP-complete!” The reduction also shows that the hardness of subset sum comes from big numbers: the values are exponential in the number of edges. With small numbers, subset sum has a fast DP (a table indexed by target value).

Skiena: “Düzenli, güzel ve NP-tam!” İndirgeme ayrıca alt küme toplamının zorluğunun büyük sayılardan geldiğini gösterir: değerler, kenar sayısına göre üsteldir. Küçük sayılarla alt küme toplamının hızlı DP çözümü vardır (hedef değerle indislenen bir tablo).

Lecture 21 · Integer programming

Tam sayılı programlama

Instance: a set of integer variables, a set of linear inequalities over them, a function f to maximise, and a bound B.

Problem örneği: Tam sayı değişkenleri kümesi, bu değişkenler üzerinde doğrusal eşitsizlikler kümesi, en büyüklenmek istenen f fonksiyonu ve B sınırı.

Question: is there an integer assignment satisfying every inequality with f ≥ B?

Soru: Bütün eşitsizlikleri sağlayan ve f ≥ B yapan bir tam sayı ataması var mı?

Example: v₁ ≥ 1, v₂ ≥ 0, v₁ + v₂ ≤ 3, f = 2v₂, B = 3. Then v₁ = 1, v₂ = 2 gives f = 4 ≥ 3: yes. With B = 5 the answer is no, since f can be at most 2 × 2 = 4 under the constraints.

Örnek: v₁ ≥ 1, v₂ ≥ 0, v₁ + v₂ ≤ 3, f = 2v₂, B = 3. v₁ = 1, v₂ = 2 ataması f = 4 ≥ 3 verir: evet. B = 5 için yanıt hayırdır; çünkü kısıtlar altında f en fazla 2 × 2 = 4 olabilir.

Reduction from SAT. For each boolean variable vᵢ make two integer variables, Vᵢ and V̄ᵢ, and add constraints:

SAT’tan indirgeme. Her vᵢ Boole değişkeni için Vᵢ ve V̄ᵢ adlı iki tam sayı değişkeni oluşturun ve şu kısıtları ekleyin:

0 ≤ Vᵢ ≤ 1 and 0 ≤ V̄ᵢ ≤ 1, so each behaves like a true/false value;

0 ≤ Vᵢ ≤ 1 ve 0 ≤ V̄ᵢ ≤ 1; böylece her biri doğru/yanlış değeri gibi davranır;

Vᵢ + V̄ᵢ = 1 (written as 1 ≤ Vᵢ + V̄ᵢ ≤ 1), so exactly one of a variable and its negation is “true”;

Vᵢ + V̄ᵢ = 1 (1 ≤ Vᵢ + V̄ᵢ ≤ 1 biçiminde yazılır); böylece değişkenle değillemesinden tam biri “doğrudur”;

for each clause, say {v₁, v̄₂, v̄₃}, the constraint V₁ + V̄₂ + V̄₃ ≥ 1, so at least one literal in the clause is true.

Her yan tümce için, örneğin {v₁, v̄₂, v̄₃}, V₁ + V̄₂ + V̄₃ ≥ 1 kısıtı; böylece yan tümcenin en az bir literali doğrudur.

The objective is irrelevant: f = V₁ and B = 0. Any SAT solution gives an IP solution (true literals become 1s, and each clause sum is ≥ 1), and any IP solution gives a SAT solution (every variable is 0 or 1, a variable and its complement are never both 1, and every clause has a true literal). Polynomial time, and a clean example of a reduction that preserves the structure of the problem rather than solving it.

Amaç fonksiyonu önemsizdir: f = V₁ ve B = 0. Her SAT çözümü bir IP çözümü verir (doğru literaller 1 olur ve her yan tümcenin toplamı ≥ 1’dir); her IP çözümü de SAT çözümü verir (her değişken 0 veya 1’dir, değişkenle tümleyeni aynı anda 1 olamaz ve her yan tümcede doğru bir literal vardır). Polinom zamanlıdır; problemi çözmek yerine yapısını koruyan indirgemeye temiz bir örnektir.

Two things to notice. The IP instances produced are a tiny, special subset of all IP instances, yet since some of them are hard, IP in general must be hard. And the reduction pinpoints why IP is hard: not big coefficients or big variable ranges, since restricting every variable to 0 or 1 is already enough.

İki noktaya dikkat edin. Üretilen IP örnekleri bütün IP örneklerinin küçücük, özel bir alt kümesidir; yine de bazıları zor olduğu için IP genel olarak zor olmalıdır. Ayrıca indirgeme, IP’nin neden zor olduğunu belirler: büyük katsayılar veya geniş değişken aralıkları nedeniyle değil; çünkü her değişkeni 0 veya 1’le sınırlamak zaten yeterlidir.

Lecture 21 · The reduction idea in reverse: convex hull needs Ω(n log n)

İndirgeme fikrini ters yönde kullanma: Dışbükey zarf Ω(n log n) gerektirir

Reductions also transfer lower bounds we already know. Lecture 9 proved that sorting needs Ω(n log n) comparisons. Now consider the convex hull problem (Lecture 7): the smallest convex polygon containing a set of points.

İndirgemeler, zaten bildiğimiz alt sınırları da aktarır. Ders 9, sıralamanın Ω(n log n) karşılaştırma gerektirdiğini kanıtladı. Şimdi dışbükey zarf problemini (Ders 7) düşünün: verilen noktalar kümesini içeren en küçük dışbükey çokgen.

Sorting reduces to convex hull. Map each number x to the point (x, x²) on the parabola y = x². The parabola is convex, so every point lies on the hull, and neighbouring hull points have neighbouring x-values. So:

Sıralama, dışbükey zarfa indirgenir. Her x sayısını y = x² parabolü üzerindeki (x, x²) noktasına eşleyin. Parabol dışbükey olduğundan her nokta zarf üzerindedir; komşu zarf noktalarının x değerleri de sıralı düzende komşudur. Dolayısıyla:

Sort(S):
    for each number x in S, create the point (x, x²)
    call convex_hull on those points
    starting from the leftmost hull point, read the points off left to right
Sort(S):
    S’deki her x sayısı için (x, x²) noktasını oluştur
    bu noktalar üzerinde convex_hull yordamını çağır
    zarfın en sol noktasından başlayarak noktaları soldan sağa oku

The translation takes O(n). If the convex hull could be found faster than n log n, this would sort faster than Ω(n log n), contradicting the sorting lower bound. Therefore convex hull also requires Ω(n log n). (And conversely, any O(n log n) convex hull algorithm is a roundabout but correct O(n log n) sorting algorithm.) This is the same two-way logic as in Lecture 19: fast algorithms flow from the target back to the source, lower bounds flow from the source to the target.

Dönüşüm O(n) sürer. Dışbükey zarf n log n’den daha hızlı bulunabilseydi bu yöntem, Ω(n log n)’den daha hızlı sıralama yapar ve sıralamanın alt sınırıyla çelişirdi. Dolayısıyla dışbükey zarf da Ω(n log n) gerektirir. (Tersine, herhangi bir O(n log n) dışbükey zarf algoritması, dolambaçlı ama doğru bir O(n log n) sıralama algoritmasıdır.) Bu, Ders 19’daki aynı iki yönlü mantıktır: hızlı algoritmalar hedeften kaynağa, alt sınırlar kaynaktan hedefe aktarılır.

Lecture 22 · Warm-up: hitting set

Hazırlık: Kesişen küme (hitting set)

Show that hitting set is NP-complete: given a collection C of subsets of a set S and an integer k, is there a subset S′ of S with at most k elements that intersects (“hits”) every subset in C? Reduce from vertex cover: let S be the vertices and let C contain, for each edge, the two-element set of its endpoints. A set of k vertices hits every edge-pair exactly when it is a vertex cover of size k. (This is the technique called restriction below: vertex cover is just hitting set with all subsets of size 2.)

Kesişen küme probleminin NP-tam olduğunu gösterin: S kümesinin alt kümelerinden oluşan C topluluğu ve k tam sayısı verildiğinde, S’nin en fazla k elemanlı ve C’deki her alt kümeyle kesişen (“isabet eden”) bir S′ alt kümesi var mı? Tepe örtüsünden indirgeyin: S tepeler olsun; C ise her kenar için uçlarından oluşan iki elemanlı kümeyi içersin. k tepeli bir küme, ancak ve ancak k boyutlu bir tepe örtüsüyse her kenar çiftiyle kesişir. (Bu, aşağıda kısıtlama olarak adlandırılan tekniktir: tepe örtüsü, bütün alt kümeleri 2 elemanlı olan kesişen küme problemidir.)

Lecture 22 · Two general techniques

İki genel teknik

Restriction. Show that a special case of your problem is already NP-complete. “Is there a simple path of length k?” contains Hamiltonian path (k = n − 1) as a special case, so it is hard. Hitting set contains vertex cover.

Kısıtlama. Probleminizin bir özel durumunun zaten NP-tam olduğunu gösterin. “Uzunluğu k olan basit bir yol var mı?” sorusu, özel durum olarak Hamilton yolunu (k = n − 1) içerir; dolayısıyla zordur. Kesişen küme, tepe örtüsünü içerir.

Local replacement. Change the structure piece by piece with small gadgets. SAT ∝ 3-SAT was local replacement, one clause at a time. Another example: to show graph isomorphism is no easier on bipartite graphs, replace every edge by a path of length two through a new vertex; the result is bipartite and isomorphism is preserved.

Yerel değiştirme. Yapıyı küçük düzeneklerle parça parça değiştirin. SAT ∝ 3-SAT, her seferinde bir yan tümceyi dönüştüren yerel değiştirmeydi. Başka örnek: çizge izomorfizminin iki parçalı çizgelerde daha kolay olmadığını göstermek için her kenarı, yeni bir tepeden geçen iki uzunluklu bir yolla değiştirin. Sonuç iki parçalıdır ve izomorfizm korunur.

Lecture 22 · The art of proving hardness

Zorluğu kanıtlama sanatı

Skiena’s advice, from long practice. The dirty secret of NP-completeness proofs is that they are usually easier to recreate than to read, just as old code is easier to rewrite than to understand. Once you have the hang of it, it is surprisingly straightforward and even pleasurable.

Skiena’nın uzun uygulama deneyiminden gelen önerileri: NP-tamlık kanıtlarının pek söylenmeyen sırrı, genellikle onları yeniden kurmanın okumaktan daha kolay olmasıdır; eski kodu yeniden yazmanın anlamaktan kolay olması gibi. Mantığını kavradığınızda şaşırtıcı derecede anlaşılır, hatta keyifli hâle gelir.

Make your source problem as simple (restricted) as possible. Never start from full TSP. Better: TSP with the triangle inequality. Better still: Hamiltonian cycle (all weights 1 or ∞). Better again: Hamiltonian path. Best: Hamiltonian path on directed planar graphs with every vertex of degree 3. All are equally hard, and the more restricted the source, the less your reduction has to handle.

Kaynak probleminizi mümkün olduğunca basit (kısıtlı) yapın. Genel TSP’den asla başlamayın. Daha iyisi: üçgen eşitsizliğini sağlayan TSP. Daha da iyisi: Hamilton döngüsü (bütün ağırlıklar 1 veya ∞). Bir adım daha iyisi: Hamilton yolu. En iyisi: her tepenin derecesi 3 olan yönlü düzlemsel çizgelerde Hamilton yolu. Hepsi aynı derecede zordur; kaynak ne kadar kısıtlıysa indirgeme o kadar az durumla uğraşır.

Make your target problem as hard as possible. Do not be afraid to add extra constraints, weights or freedoms to your target, at least temporarily; a more general target is easier to reduce to.

Hedef probleminizi mümkün olduğunca zor yapın. En azından geçici olarak hedefe ek kısıtlar, ağırlıklar veya serbestlikler eklemekten çekinmeyin; daha genel bir hedefe indirgeme yapmak daha kolaydır.

Pick the right source for the right reason. Skiena uses only four sources, so that he knows them intimately:

Doğru kaynağı doğru nedenle seçin. Skiena, çok iyi tanımak için yalnızca dört kaynak problem kullanır:

SourceUse it when the hardness is about…
KaynakZorluk şu konudaysa kullanın…
3-SATAnything, when none of the others fits: the old reliable
3-SATDiğerleri uymadığında her şey: eski ve güvenilir seçenek
Integer partitionLarge numbers; the one choice for numerical problems
Tam sayı bölüşümüBüyük sayılar; sayısal problemler için temel seçenek
Vertex coverSelecting a subset of vertices or edges (chromatic number, clique, independent set)
Tepe örtüsüTepe veya kenar alt kümesi seçme (kromatik sayı, klik, bağımsız küme)

Amplify the penalties for undesired choices. You are translating one problem into another while keeping them as alike as possible. Be bold: “if you pick this, you are forced to pick up this huge set that dooms you.” The sharper the consequences of deviating, the easier the if-and-only-if proof.

İstenmeyen seçimlerin cezalarını büyütün. Bir problemi diğerine çevirirken onları mümkün olduğunca benzer tutuyorsunuz. Cesur olun: “Bunu seçerseniz sizi başarısızlığa götüren şu dev kümeyi de seçmek zorunda kalırsınız.” Sapmanın sonuçları ne kadar keskinse, ancak ve ancak kanıtı o kadar kolaydır.

Think strategically, then build gadgets to enforce tactics. The questions to ask: how do I force that A or B is chosen but not both? How do I force A before B? How do I clean up the things I did not select? Each answer is a gadget (the variable edge and clause triangle of Lecture 20 are gadgets).

Stratejik düşünün, sonra taktikleri zorunlu kılan düzenekleri kurun. Sorularınız: A veya B’nin seçilmesini, fakat ikisinin birden seçilmemesini nasıl zorlarım? A’yı B’den önceye nasıl zorlarım? Seçmediğim nesneleri nasıl ele alırım? Her yanıt bir düzenektir (Ders 20’deki değişken kenarı ve yan tümce üçgeni birer düzenektir).

Alternate between seeking an algorithm and seeking a reduction. Sometimes the reason you cannot prove hardness is that the problem is easy. Switching sides for a while keeps you honest.

Algoritma aramakla indirgeme aramak arasında gidip gelin. Bazen zorluğu kanıtlayamamanızın nedeni problemin kolay olmasıdır. Bir süre karşı taraftan bakmak sizi dürüst tutar.

In class Skiena then takes a live challenge: a volunteer picks one of the 400-plus problems from the appendix of Garey and Johnson’s Computers and Intractability, and he builds the reduction on the spot. That book’s list is the first place to look whenever you suspect your problem is NP-complete.

Skiena derste ardından canlı bir meydan okumayı kabul eder: bir gönüllü, Garey ve Johnson’ın Computers and Intractability kitabının ekindeki 400’ü aşkın problemden birini seçer ve Skiena indirgemeyi o anda kurar. Probleminizin NP-tam olduğundan kuşkulandığınızda ilk bakacağınız yer, bu kitaptaki listedir.

Lecture 22 · P versus NP

P ve NP

Now the definitions the whole theory rests on, stated informally (the precise versions need Turing machines and formal languages):

Şimdi bütün kuramın dayandığı tanımları biçimsel olmayan şekilde verelim (kesin sürümler Turing makineleri ve biçimsel diller gerektirir):

A problem is in P if it can be solved in time polynomial in the size of the input.

Bir problem, girdi boyutunda polinom olan sürede çözülebiliyorsa P sınıfındadır.

A problem is in NP if a proposed answer can be checked in polynomial time.

Önerilen bir yanıt polinom zamanda denetlenebiliyorsa problem NP sınıfındadır.

Satisfiability is in NP: guess a true/false assignment and check every clause in polynomial time. The real issue is the gap between finding a solution and verifying one. Every problem in P is in NP (if you can find the answer you can certainly check it), but nobody knows whether NP contains anything P does not.

Sağlanabilirlik NP’dedir: bir doğru/yanlış ataması tahmin edin ve her yan tümceyi polinom zamanda denetleyin. Asıl mesele, çözümü bulmakla doğrulamak arasındaki farktır. P’deki her problem NP’dedir (yanıtı bulabiliyorsanız elbette denetleyebilirsiniz); ancak NP’nin P’de olmayan bir şey içerip içermediğini kimse bilmez.

Examples:

Örnekler:

In P: is there a path from s to t in G of length less than k? (BFS or Dijkstra finds it.)

NP’de (olduğu bilinen) değil: Uzunluğu k’den küçük kaç TSP turu vardır? Üstel sayıda olabilir; dolayısıyla önerilen bir yanıt bile hepsini listeleyerek denetlenemez.

An NP-complete problem is one in NP to which every problem in NP reduces. Cook showed SAT is NP-complete; every reduction in Lectures 20 and 21 extends the family. So if any NP-complete problem is in P, then P = NP and all of them are easy; if any one is provably not in P, then P ≠ NP and none of them are. Skiena’s caution: do not let the formalities distract you; the important idea is reductions as a way of proving hardness.

NP-tam problem, NP’de olan ve NP’deki her problemin kendisine indirgendiği problemdir. Cook, SAT’ın NP-tam olduğunu gösterdi; Ders 20 ve 21’deki her indirgeme bu aileyi genişletir. Dolayısıyla herhangi bir NP-tam problem P’deyse P = NP’dir ve hepsi kolaydır. Herhangi birinin P’de olmadığı kanıtlanırsa P ≠ NP’dir ve hiçbiri P’de değildir. Skiena’nın uyarısı: biçimsel ayrıntıların dikkatinizi dağıtmasına izin vermeyin; önemli fikir, zorluğu kanıtlamanın yolu olarak indirgemelerdir.

Lecture 22 · Is P = NP?

First, the five words

All of Big-O is about one question: as the input gets bigger, how fast does the work grow? Not the exact number of steps — just the growth. Here are the five symbols in plain words. Whenever you see one, read the plain words instead.

SymbolSay it asEveryday meaning
OBig Ohgrows no faster than — a ceiling
ΩBig Omegagrows no slower than — a floor
ΘBig Thetagrows at the same rate (a ceiling and a floor at the same height)
olittle ohstrictly slower (below, and never catches up)
ωlittle omegastrictly faster (above, and pulls away)

Two handy facts that come up again and again:

  • Θ = O and Ω together. If something is both a ceiling and a floor, it pins the rate exactly.
  • Big-O ignores constant factors and smaller pieces. 5n, n, and 1000n all count as the same: linear. And in n² + n, the little + n does not matter — only the biggest piece, n², counts.

The growth ladder (your everyday tool)

Almost every problem in this chapter is solved by this one picture. It lists common functions from slowest-growing to fastest-growing. The symbol ≪ means “grows slower than”.

1  ≪  log n  ≪  √n  ≪  n  ≪  n log n  ≪  n²  ≪  n³  ≪  2ⁿ  ≪  3ⁿ  ≪  n!

The recipe for almost every true/false or relationship question: replace each side by where it sits on the ladder, then compare. If the left side is lower on the ladder, it is O of the right. If higher, it is Ω. If they land on the same rung, it is Θ.

A few ladder facts worth memorising, because they settle most questions instantly:

  • Any power of n (even tiny √n) beats any logarithm.
  • Any exponential (like 2ⁿ) beats any polynomial (like n³ or n¹⁰⁰).
  • n! beats every fixed-base exponential.
  • Bases matter for exponentials: 2ⁿ ≪ 3ⁿ. But adding a constant to n does not matter: 2ⁿ⁺¹ = 2·2ⁿ is the same rate as 2ⁿ.

Problem 2-43 interview

In plain words Numbers arrive one at a time, like cars passing a window. You want to keep a fair random handful of k of them, giving every number the same chance of being kept — and you only get one look at each, and you do not even know how many will pass in the end.

This is called reservoir sampling. Start with the easiest version, keeping just k = 1.

The rule: when the i-th number arrives (counting 1, 2, 3, …), keep it with probability 1/i; otherwise stick with the one you already hold. So you always keep the 1st. You swap to the 2nd with chance 1/2. You swap to the 3rd with chance 1/3. And so on.

Why is that fair? The very last number, number n, is kept with chance 1/n straight away — good. An earlier number j was kept when it arrived (chance 1/j) and then had to survive every later number choosing not to replace it. Those survival chances multiply out to j/n. Put together, everyone ends up with the same 1/n. Fair.

For a handful of k: keep the first k as your starting "reservoir". When the i-th number arrives (with i bigger than k), keep it with chance k/i; if you keep it, randomly throw out one of the k you were holding to make room. The same argument gives every number the final chance k/n.

import random

def reservoir(stream, k):
    keep = []
    for i, item in enumerate(stream):   # i counts from 0; n never needed
        if i < k:
            keep.append(item)           # fill the reservoir first
        else:
            j = random.randint(0, i)    # keep with probability k/(i+1)
            if j < k:
                keep[j] = item
                # evict a random held item and insert the new one
    return keep

It reads the stream once, stores only k items, and never needs to know the total ahead of time — perfect for a stream too big to hold or of unknown length.

Answer Reservoir sampling: hold the first k items; for each later item i, keep it with probability k/i and evict a random current member. One pass, stores only k, and n need not be known in advance.

Why it matters It is the standard way to sample fairly from a stream you cannot store or measure — a real interview favourite.

Problem 2-44 interview

In plain words You have 1000 items spread over 1000 computers (nodes), and each node holds 3 items. Nodes sometimes die. How should you place things so you lose as little as possible, and roughly how much do you expect to lose if 3 random nodes fail at once?

The core idea is simple: keep three copies of every item, on three distinct nodes, and never let two items live on the exact same trio of nodes. An easy way: put item i on nodes i, i+1 and i+2 (wrapping around at the end). Now every item has three homes, every node still holds three items, and each item's trio of homes is different.

An item is only lost if all three of its nodes die. If 3 random nodes fail, one item is lost only if those 3 dead nodes are exactly its 3 homes. The chance of that for one item is 1 divided by the number of ways to pick 3 nodes out of 1000 — a huge number, about 166 million. So one item's chance of loss is tiny. Add it up over all 1000 items:

E[items lost] = 1000 / C(1000, 3) ≈ 6.02 × 10⁻⁶

Read that carefully: it is not "6 lost per million items". It means the expected number of items lost per 3-node failure is about 6 × 10⁻⁶ — equivalently, only about a 6-in-a-million chance that a given random 3-node failure destroys even one item. Almost always you lose nothing.

Answer Keep three copies of each item on three distinct nodes, with no two items sharing the same trio. The expected number of items lost when 3 random nodes fail is 1000 / C(1000, 3) ≈ 6.02 × 10⁻⁶ — i.e. about a 6-in-a-million chance that one item is lost, essentially zero.

Why it matters It shows how a little replication plus spreading copies out makes data survive hardware failures almost for free.

Problem 2-45 interview

In plain words To find the smallest value in an array A[0..n] (that is n+1 numbers), start with tmp = A[0], then scan A[1], A[2], …, A[n] and set tmp = A[i] whenever A[i] is smaller. On a random ordering, how many times, on average, does that assignment tmp = A[i] actually run?

Careful about what is counted. Setting up tmp = A[0] at the start is the initial value, not one of the assignments we are counting. We only count the assignments made during the scan, at positions i = 1 .. n.

When does position i assign? Only when A[i] is smaller than everything seen before it — i.e. when A[i] is the smallest among the first i+1 numbers A[0..i]. In a random order, each of those i+1 numbers is equally likely to be the smallest, so the chance is 1/(i+1).

Add the chances over the scanned positions i = 1 .. n:

expected assignments = ∑i=1n 1/(i+1) = 1/2 + 1/3 + … + 1/(n+1) = Hn+1 − 1

Here Hm = 1 + 1/2 + … + 1/m is the harmonic number, and Hn+1 − 1 is just it with the first term (the 1) removed. It grows about like ln n — painfully slowly:

array size (n+1 elements)expected assignments = Hn+1 − 1
n = 10about 2.02
n = 100about 4.19
n = 1 000about 6.49
n = 1 000 000about 13.4

(A quick simulation over many random shuffles agrees: about 2.0 for n = 10 and about 3.5 for n = 50.) If your array is defined as exactly n elements instead, the same argument gives Hn − 1.

Answer The assignment fires at position i with probability 1/(i+1), so the expected number is Hn+1 − 1 = 1/2 + 1/3 + … + 1/(n+1) ≈ ln n — that is O(log n). (It is not the full Hn: the initial tmp = A[0] is not a counted assignment.)

Why it matters A tiny index shift changes the exact answer — and it is a lovely case of very slow, logarithmic growth hiding inside a plain loop.

Problem 2-46 puzzle

In plain words A 100-floor building. Dropped from some floor and above, a marble breaks; below it, the marble is fine. You want the lowest breaking floor. How few drops do you need (a) with lots of marbles, and (b) with only two?

(a) Lots of marbles → binary search. A broken marble costs you nothing, so you can gamble on the middle floor every time. Drop from 50. If it breaks, the answer is below 50; if not, above. Each drop halves the range, so you need ⌈lg 100⌉ = 7 drops — the same halving trick as binary search.

(b) Only two marbles → you cannot halve. If your first marble breaks at floor 50, you only have one marble left, and you dare not gamble with it — you must walk up one floor at a time from the last safe floor. So a big first jump risks up to 49 more drops. The fix: make the first marble take shrinking steps, so that whichever gap it breaks in, the walk-up with the second marble is short.

Drop the first marble at floors 14, 27, 39, 50, 60, 69, 77, 84, 90, 95, 99, 100 — gaps of 14, then 13, then 12, shrinking by one each time.

Why start at 14? If the first marble breaks on drop number d, you have already spent d drops and the gap left to walk is 14 − d floors — always about 14 total. You want the first step k big enough that k + (k−1) + … + 1 = k(k+1)/2 covers all 100 floors. The smallest k that works is 14, because 14 × 15 / 2 = 105 ≥ 100, while 13 × 14 / 2 = 91 falls short.

Answer 7 drops with plenty of marbles (binary search); about 14 drops in the worst case with only two, using shrinking gaps. Two marbles cost you the logarithm — you go from lg n up to roughly √n.

Why it matters It shows how few resources (only 2 marbles) forces a slower strategy than clean halving.

Problem 2-47 puzzle

In plain words Ten bags of coins. Nine bags have real 10-gram coins; one bag has fake 9-gram coins. Your scale shows exact grams. Find the fake bag with just one weighing.

The trick is to make each bag leave a different, recognisable fingerprint on one pile. Number the bags 1 to 10. Take 1 coin from bag 1, 2 coins from bag 2, 3 from bag 3, …, 10 from bag 10 — that is 55 coins in all.

If every coin were real, the pile would weigh 55 × 10 = 550 grams. Each fake coin is 1 gram light, and bag k put in exactly k coins. So if bag k is the fake one, the pile reads 550 − k grams. The number of grams missing is the guilty bag's number.

weights = [10] * 10       # ten bags, all 10-gram coins to start
weights[6] = 9            # bag number 7 secretly holds 9-gram coins

# take (i+1) coins from bag i and weigh them all together
total = sum((i + 1) * weights[i] for i in range(10))
print(550 - total)        # 7  -> the light bag is number 7

Weigh 5 grams missing? Bag 5. Weigh 7 missing? Bag 7. One weighing tells you everything.

Answer Take k coins from bag k, weigh all 55 together, and read off 550 − (scale reading). That difference is the light bag's number. One weighing, no searching.

Why it matters A neat counting trick: you can pack ten possible answers into a single number.

Problem 2-48 puzzle

In plain words Eight balls look identical, but one is slightly heavier. Using a balance scale only twice, find the heavy one.

A balance scale gives three possible answers each time: left heavier, right heavier, or level. So two weighings can tell apart up to 3 × 3 = 9 things, and 9 ≥ 8. That count tells you it must be possible. Here is how. Split the 8 balls into groups of 3, 3 and 2.

  1. Weighing 1: put the two groups of 3 on the pans.
    • If they balance, the heavy ball is one of the 2 set aside. Weigh those two against each other — the heavier pan shows it. Done in two.
    • If one side is heavier, the heavy ball is among those 3.
  2. Weighing 2 (heavy ball is in a group of 3): take that group and weigh 1 ball against another 1. If one is heavier, that is it; if they balance, it is the third ball you left off.

Answer Split the balls 3 / 3 / 2 and you always finish in two weighings. It works because each weighing has 3 outcomes, so two weighings carry 3² = 9 results — more than the 8 balls to tell apart.

Why it matters It shows how counting outcomes ahead of time tells you a puzzle is solvable before you find the exact moves.

Problem 2-49 interview

In plain words n companies keep merging, two at a time, until only one is left. How many merges does that take, and how many different orders can the merges happen in?

The easy half first: each merge turns two companies into one, so it shrinks the count by exactly one. Going from n down to 1 always takes n − 1 merges, whatever the order.

The harder half is: how many different orders can the merges play out in? Do the small cases by hand:

number of merge orders = n! · (n−1)! / 2n−1

Problem 2-50 interview

In plain words A Ramanujan number is one that can be written as the sum of two cubes in two different ways: a³ + b³ = c³ + d³. Find all of them with a, b, c, d below n — faster than trying every four numbers.

The lazy way is four nested loops over a, b, c, d — that is O(n⁴), hopeless. The trick is the same "remember what you have seen" idea from the fast anagram and two-sum solutions: build every two-cube sum once and look for collisions.

Go over every pair (a, b) with a ≤ b < n (about n²/2 of them), compute a³ + b³, and drop it into a dictionary whose key is that sum. Any key that ends up with two or more different pairs is a Ramanujan number.

def ramanujan(n):
    seen = {}                     # sum -> list of (a, b) pairs
    for a in range(1, n):
        for b in range(a, n):     # a <= b avoids counting a pair twice
            seen.setdefault(a**3 + b**3, []).append((a, b))
    return {s: p for s, p in seen.items() if len(p) >= 2}

print(sorted(ramanujan(20)))
[(1729, [(1, 12), (9, 10)])]

The smallest is the famous 1729 = 1³ + 12³ = 9³ + 10³ — the "taxicab number" from the Hardy–Ramanujan story. Building the dictionary is one pass over the ≈ n²/2 pairs, each insert O(1) on average, so the whole thing is O(n²) time and O(n²) space.

Answer Store every a³ + b³ (for a ≤ b < n) in a dictionary keyed by the sum; the keys hit two or more times are the Ramanujan numbers. Time O(n²), far better than brute-force O(n⁴). The smallest is 1729.

Why it matters "Compute a value once and hash it, then look for repeats" turns an O(n⁴) search into O(n²) — the same move behind the fast anagram and two-sum solutions.

Problems 2-51 & 2-52 puzzle

In plain words Pirates split treasure by rank. The top pirate proposes a split; everyone (including him) votes; if at least half agree it passes, otherwise he is thrown overboard and the next pirate proposes. Pirates are perfectly logical and care most about staying alive, then about money. With $300 and 6 pirates, who gets what (2-51)? And what if there is only one indivisible dollar (2-52)?

The trick for every puzzle like this is to reason backwards from the smallest case, because when a pirate votes he compares "what I get now" against "what I would get if this proposer is thrown overboard". Call the pirates P1 (most junior) up to P6 (most senior); the senior proposes first. "At least half" means a tie is enough to pass.

Part 2-51, splitting $300. Build it up one pirate at a time:

pirates leftvotes neededproposer keepswho gets $1 (to buy the vote)
2 (P2, P1)1$300nobody — P2's own vote is half of 2
32$299P1 (who would get $0 if it fell to 2 pirates)
42$299P2 (who gets $0 in the 3-pirate outcome)
53$298P3 and P1 (the two who get $0 with 4 pirates)
63$298P4 and P2 (the two who get $0 with 5 pirates)

Each proposer only bribes the cheapest pirates — the ones who would get nothing in the next round — and only just enough of them to reach half the votes. So with 6 pirates, the senior P6 needs 3 votes (his own plus two), and he gets them by handing $1 each to P4 and P2, keeping $298.

Part 2-52, a single indivisible dollar. Now the proposer has almost nothing to bribe with, so survival votes do the work. Reason down the chain: with 5 pirates the proposer P5 would need 3 votes but can only bribe one pirate with the single dollar — so a 5-pirate proposal fails and P5 would be thrown overboard. That fact is the key: P5 is desperate to never reach a 5-pirate game.

So when 6 pirates face the single dollar, the senior P6 needs 3 votes and gets them like this: his own vote; P5's vote for free (because if P6 goes overboard the game drops to 5 pirates where P5 dies, so P5 backs almost anything that keeps P6 afloat); and one more vote bought by giving the single dollar to one pirate who would otherwise get nothing (P4, P3, or P1). That is three votes — it passes.

One honest caveat (the assumption behind 2-51 and 2-52). Skiena specifies survival first and money second, but does not say how a pirate votes when both outcomes give him exactly the same survival and money. The solutions here use the standard convention that an indifferent pirate votes against the current proposal — equivalently, a non-proposer backs a proposal only if it makes him strictly better off in survival or money. Under this convention the backward-induction outcomes below follow (note the $300 case relies on it too: a pirate who would get $0 next round is actually paid $1, rather than assumed to vote yes for the same $0). A different tie-breaking rule can change the result.

Answer (2-51) The top pirate keeps $298 and gives $1 each to P4 and P2, passing 3-to-3; P5, P3, P1 get nothing. (2-52) The top pirate survives and no one need die: he gives the one dollar to a single pirate whose vote he needs, and relies on P5's free vote (P5 votes yes just to avoid dying next round).

Why it matters It shows the power of working backwards from the simplest case — the same habit behind many algorithms.

Programming Challenges practice

In plain words Three short online-judge (UVA) problems that go with this chapter. Each needs one clever observation, not heavy machinery. Here is a plain approach for each.

Primary Arithmetic — count the carries when you add two numbers. Add them the grade-school way, digit by digit from the right, keeping a running carry. Every column where the two digits plus the incoming carry reach 10 makes a carry into the next column. Count those events. It is O(number of digits) — really just "do primary-school addition and watch the carries", then report none, one, or the count.

A Multiplication Game — two players start from a product of 1 and take turns multiplying it by any number from 2 to 9; the first to reach or pass n wins, and Stan goes first. Solve it by reasoning backwards. With best play the winner depends only on which "band" n falls in, and the band edges are 9, 18, 162, 324, 2916, … — the gaps alternate ×2 then ×9 (not "powers of nine"): Stan wins for n in 2–9, the second player for 10–18, Stan for 19–162, the second player for 163–324, Stan for 325–2916, and so on. A clean way to decide: repeatedly replace n by ceil(n / 18) until n ≤ 18; then Stan (first) wins exactly when the leftover n ≤ 9. No search needed — a handful of divisions.

Light, More Light — lamps 1..N start off; person i flips every lamp whose number is a multiple of i, so lamp k is flipped once for each of its divisors. A lamp ends on only if it was flipped an odd number of times, i.e. if k has an odd number of divisors. Divisors normally come in pairs (d and k/d), except when k is a perfect square (the square root pairs with itself). So the only lamps left on are the perfect squares. The whole problem becomes: is k a perfect square? Check with an integer square root, O(1) per query.

Answer Primary Arithmetic: count carries during digit-by-digit addition. A Multiplication Game: the winner is decided by which band n falls in, where the band edges 9, 18, 162, 324, 2916… grow by alternating ×2 and ×9 (decide by dividing n by 18 repeatedly, then testing n ≤ 9). Light, More Light: the lamps left on are exactly the perfect squares.

Why it matters Each shows that the right observation turns a scary-looking problem into a few lines of code.
