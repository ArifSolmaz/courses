Week 07 / 14 · Priority queues and timer heaps

Which timer comes next?

15 min · Engineering question

A robot reads sensors, updates its position and sends telemetry at different times. How can it keep track of these times and quickly select the next one? We will build the answer from structures you already know.

Start with the scheduling problem, compare familiar methods, then follow the heap examples. The worked reminders let you connect each new idea to Weeks 1–6.

1. Start with a problem

A robot creates three timer records in this order. The current time is 4 ms. Which task has become ready?

Three timer records
Insertion orderTaskRelease time
1Send telemetry9 ms
2Read a sensor4 ms
3Write a log entry7 ms

A release time is the earliest time a task becomes ready to start. The answer is the sensor-reading task: its release time is 4 ms. Telemetry entered first, but its time arrives later.

Remember Week 4 · FIFO follows arrival order

Add A, B and C to a FIFO queue: they leave A → B → C. Now give them release times A: 9 ms, B: 4 ms and C: 7 ms. Time order becomes B → C → A. The first task added is not necessarily the first whose time arrives.

A priority queue selects the highest-priority entry. Here, earlier release time means higher priority. This selects the next timer; it does not describe a task’s safety importance.

2. Can we solve it with a list?

Option A: Keep an unsorted list

Store [9, 4, 7]. Start with 9 as the smallest value seen. Compare 4 with 9 and update the minimum to 4. Compare 7 with 4 and keep 4. Only then do we know the answer.

Remember Week 1 · First match versus minimum

In [33, 20, 17, 12], the first reading below 20 was 17. We stopped after checking three readings, even though 12 was smaller. Finding a minimum is different: after seeing 4 in [9, 4, 7], we must still inspect 7 because an unchecked entry could be smaller. A general minimum scan inspects all n entries.

Option B: Keep a sorted list

In [4, 7, 9], the earliest time is easy to read. New timer records must still be inserted at the correct position.

Remember Week 3 · Finding a position does not create a slot

Binary search finds that 25 belongs at index 2 in [10, 20, 30, 45]. To obtain [10, 20, 25, 30, 45], we must still move 30 and 45 right. Finding the position takes O(log n); shifting entries can take O(n).

We repeatedly add a timer, inspect the earliest one, remove it and add its next release. We do not need every entry to remain fully sorted. A min-heap supports these operations with a weaker ordering rule.

3–6. Understand the heap, then trace its operations

A binary min-heap has two properties: the tree is filled level by level, left to right; every parent is less than or equal to its children. The array [4, 9, 7, 12, 15, 10] can be read as this tree:

Check: 4 ≤ 9 and 4 ≤ 7; 9 ≤ 12 and 9 ≤ 15; 7 ≤ 10. Starting at the root, values cannot decrease as we move downward. Therefore no descendant is smaller than the root: the minimum is at index 0. Siblings need not be sorted.

Remember Week 6 · Full sorting and the median

We sorted [6, 30, 5, 7, 8] into [5, 6, 7, 8, 30] and selected the middle value 7. Heap order is weaker: [4, 9, 7] is valid, but its middle entry 9 is not its median 7. A heap gives the minimum, not every entry’s sorted position.

Is heap[1] always second-smallest?

No. In [4, 9, 7], heap[1] is 9 but the second-smallest value is 7.

4. Read the index relationships

For index i: left child = 2i + 1; right child = 2i + 2; parent = (i − 1) // 2 when i > 0. The symbol // means integer division. A child exists only if its index is less than the array length.

Remember Week 4 · Storage and logical order

A ring buffer could contain [D, B, C] physically while its FIFO order was B, C, D because the head pointed to B. In a heap, array positions also have a special meaning: their indices define parents and children. The tree is another view of the same array.

5. Insert: append, then sift up

Insert 3 into [4, 9, 7]. Appending preserves the tree shape. At index 3, the parent is (3 − 1) // 2 = 1, holding 9. Since 3 < 9, swap them. Now compare 3 with its new parent 4 and swap again.

[4, 9, 7]
[4, 9, 7, 3]
[4, 3, 7, 9]
[3, 4, 7, 9]

Only the new entry’s upward path can need repair. Stop at the root or when the parent is no larger. Try inserting 8 instead: [4, 9, 7, 8] → [4, 8, 7, 9]. Stop because 4 ≤ 8.

6. Remove: replace the root, then sift down

Remove 3 from [3, 4, 7, 9]. Move the last entry 9 to the root to preserve the shape: [9, 4, 7]. Compare the children and swap with the smaller one, 4: [4, 9, 7]. Now 9 is a leaf, so stop.

Why not swap with 7? That would produce [7, 4, 9], where the root is still larger than child 4. If there is only a left child, compare with it; with no children, stop.

7. How much work does a heap do?

Remember Week 2 · Compare growth

A full scan makes 8 visits at n = 8 and 16 visits at n = 16: doubling the input doubles the visits. A complete binary tree has height 3 edges at n = 8 and 4 edges at n = 16. A sift follows one path rather than scanning every entry.

Size and height
nFull-scan visitsMaximum path length (edges)
883
16164
1281287
1024102410

For a nonempty heap, height is floor(log₂ n). Repairing one path takes O(log n) work. This does not mean one comparison per level: sift-down may compare both children first.

Operation costs
StructureAddRead minimumRemove minimum
Unsorted dynamic arrayO(1) amortizedO(n)O(n)
Sorted array, minimum at endO(n)O(1)O(1)
Binary min-heapO(log n)*O(1)O(log n)

In an unsorted array, scan for the minimum, then fill its gap with the last entry. In the sorted-array row, the minimum is kept at the end so removing it needs no shifts. *Heap insertion has O(log n) ordering work; dynamic-array growth may occasionally cost O(n), accounted for amortized across insertions.

A better growth rate does not guarantee a faster result for every small input. Measure your actual workload.

8. Paper practice

Start with heap [4, 9, 7]. Insert release time 3, then remove the minimum. Use zero-based child indices 2i + 1 and 2i + 2. Break equal release times by insertion order.

Write your trace first. Compare your steps, then explain why the method works in three sentences.

Check your trace

Append 3 and swap upward past 9 and 4 to get [3, 4, 7, 9]. Remove 3, move 9 to the root and swap down with 4 to get [4, 9, 7]. Peeking reads one entry. An insertion or removal moves along at most one tree path, so work grows roughly with log₂ n.

Compare a three-sentence explanation

The root is the minimum because each parent is no larger than its children. Insertion only needs to move the new entry up its parent path. After removing the root, move the last entry there and swap it down with the smaller child until the heap rule holds.

Trace timer priorities and ties

A min-heap has root (3, A), with children (7, B) and (5, C). Insert (3, D), then remove the next two timers. Equal release times are ordered by sequence A, B, C, D.

Show the worked steps
  1. Append D under B. D moves past B because deadline 3 comes first, then stops below A because A wins the tie.
  2. Remove A and move the last element B to the root. Compare D and C. Swap B with D, leaving D first.
  3. Remove D next. Move C to the root. B comes later, so the earliest remaining release is C at time 5.

Additional practice: insert, remove and diagnose

Start with [5, 8, 6, 12, 10]. Insert 3, then remove the minimum. Record the array, compared indices, each swap and the stopping reason.

Show answer

Insertion: [5, 8, 6, 12, 10, 3] → [5, 8, 3, 12, 10, 6] → [3, 8, 5, 12, 10, 6]. Removal: [6, 8, 5, 12, 10] → [5, 8, 6, 12, 10].

Is [4, 9, 7, 12, 6] a min-heap? Name the exact broken relationship.

Show answer

No. Parent 9 at index 1 is larger than child 6 at index 4. Checking only the root is not enough.

Python heap operations
OperationMeaning
heappush(heap, item)Add and restore heap order.
heappop(heap)Remove and return the minimum.
heap[0]Read the minimum without removing it.
heapify(items)Build a heap in place in O(n); it does not fully sort.

Check for an empty heap before reading, popping or replacing. Store a timer as (release_time, insertion_sequence, task_name). Python compares release times first, then sequence numbers.

(6, 2, "I")
(6, 3, "M")

I comes first because the times tie and 2 < 3. Use a fresh sequence number for every insertion. This gives deterministic ties and prevents comparison from reaching task objects that may not support ordering. The sequence is not a deadline, period or safety priority.

11. A complete example with two robot tasks

Teaching example: two tasks
TaskMeaningPeriodFirst release
MMotor update2 ms2 ms
IIMU reading3 ms3 ms

These periods are chosen for teaching. Each task first becomes ready at the end of its own period.

Remember Week 5 · Retrieve information by a key

A fault dictionary such as {"E01": "Stop the motor", "E02": "Check the sensor"} retrieves a response by its exact code. Here, period = {"M": 2, "I": 3} answers “What is M’s period?” with 2. The heap answers “Which timer comes next?” We use both structures together.

from heapq import heappush, heappop
from itertools import count

period = {"M": 2, "I": 3}
sequence = count()
heap = []

for task in ("M", "I"):
    heappush(heap, (period[task], next(sequence), task))

for now in range(1, 8):
    while heap and heap[0][0] <= now:
        release, _, task = heappop(heap)
        print(f"{now} ms: {task}")
        next_release = release + period[task]
        heappush(heap, (next_release, next(sequence), task))

Expected output

2 ms: M
3 ms: I
4 ms: M
6 ms: I
6 ms: M

Printing represents handling a release. This simulation does not model task execution durations or operating-system scheduling.

Follow the events

Read the code one decision at a time

  • I comes first at 6 ms because its record was inserted at 3 ms; M’s was inserted at 4 ms.
  • heap[0] is the earliest tuple; the second [0] reads its release time.
  • <= now includes records due exactly now and overdue records.
  • while checks again because several records may be due. With if, only I is handled at 6 ms and M waits until 7 ms.
  • If the earliest time is in the future, none of the pending records is due. If the heap is empty, the condition avoids reading index 0.

12. Keep the original periodic schedule

A task planned for 10 ms is handled at 11 ms. Its period is 10 ms. Compare:

Scheduling after a delay
CalculationNext releaseEffect
release + period20 msPreserves the original schedule
now + period21 msShifts the schedule

We use release + period. If the system is far behind, that new release may still be in the past. Choose an explicit policy: catch up by handling missed releases, skip to a future release, or coalesce missed releases into one useful update. For telemetry, sending the latest state may be more useful than repeating old transmissions.

At 2 ms, I and M are both due. I comes first because it was inserted earlier. At 10 ms, the same rule gives O, I, M. T stays in the heap throughout the trace because its first release is at 50 ms.

Schedule the next time with release + period. For example, O runs at 10 ms and is pushed back for 20 ms. If its 10 ms release were handled at 11 ms, adding the period to 10 would still keep the original schedule. A real controller needs a policy for missed releases, such as catching up, skipping or coalescing them.

At 10 ms, O comes first because its record was inserted at initialization. The I and M records for 10 ms were inserted later. This is a timer tie-break rule, not a CPU-priority decision.

Check the predictions

Equal periods: M then I at shared times, given the initial insertion order. Using if: I at 6 ms and M’s overdue record at 7 ms. Empty initialization: no output; the condition prevents an invalid read.

Each operation replaces the earliest record with a later one, so queue size stays constant. The second field is a fixed identifier here; release times remain distinct, so this benchmark does not test tie-breaking. Initial construction is outside the measurement.

Select Run or copy into Python 3. The two values are the median and largest of five batch averages, in milliseconds per operation. They include the timed loop and function-call overhead.

from heapq import heapify, heapreplace
from statistics import median
from timeit import default_timer

def list_step(queue, n):
    index = min(range(len(queue)), key=queue.__getitem__)
    old = queue[index]
    release, identifier = old
    queue[index] = (release + n, identifier)
    return old

def heap_step(queue, n):
    release, identifier = queue[0]
    return heapreplace(queue, (release + n, identifier))

def check_correctness(n):
    plain = [(i, i) for i in range(n)]
    heap = plain.copy()
    heapify(heap)
    for _ in range(3 * n):
        assert list_step(plain, n) == heap_step(heap, n)
    assert sorted(plain) == sorted(heap)

def measure(step, n, operations=2000):
    samples = []
    for _ in range(5):
        queue = [(i, i) for i in range(n)]
        if step is heap_step:
            heapify(queue)
        start = default_timer()
        for _ in range(operations):
            step(queue, n)
        elapsed = default_timer() - start
        samples.append(elapsed * 1000 / operations)
    return median(samples), max(samples)

for n in (8, 32, 128, 512):
    check_correctness(n)
    for label, step in (("list", list_step), ("heap", heap_step)):
        typical, largest = measure(step, n)
        print(f"{n}: {label:4}  {typical:.6f} ms  {largest:.6f} ms")

15. What if the cycle budget is too small?

At time 20 ms, the queue contains releases 18, 19, 20 and 24. Each processed record costs exactly 0.07 ms, including all work charged to this budget. The cycle has 0.15 ms available. These are one-time events: processing does not insert replacements.

Remember Week 1 · Share the cycle budget

In a 1 ms cycle, other work used 0.7 ms, leaving 1.00 − 0.70 = 0.30 ms for searching. Timer handling must share the available time in the same way.

  1. Work alone for 10 minutes: mark due and overdue records, then calculate how many fit.
  2. Work with a partner for 20 minutes: choose what happens to the due record that does not fit. Distinguish release time from completion deadline.
  3. Use the last 15 minutes to compare solutions and write acceptance tests for empty, future-only and equal-time queues.
Compare a model answer

18, 19 and 20 are due; 18 and 19 are overdue. Two operations cost 2 × 0.07 = 0.14 ms; three cost 0.21 ms. Process 18 and 19. Records 20 and 24 remain. Only 0.01 ms is left, too little for another operation. Deferring 20 may be acceptable or may require a fault response; the release time alone does not specify its completion deadline.

Acceptance tests
CaseExpected result
Empty queueProcess nothing.
Root at 24 ms, now = 20 msNo record is due.
Three equal-time records, budget for twoUse sequence order; leave the third queued.
Due record; only 0.01 ms remainsLeave it queued.

Release time is the earliest permitted start; a deadline is the latest required completion. In real measurements, justify costs and allow for variation. A heap reduces selection overhead; it does not create more execution time.

16. Common mistakes and glossary

  • Treating the heap as sorted. [4, 9, 7] is a valid min-heap. The ordering rule applies between a parent and its children.
  • Reading heap[1] as the second smallest. Here that gives 9, while the second smallest is 7.
  • Peeking or popping when empty. Check if heap: first.
  • Confusing due and overdue. At tick 20, a release at 20 is due. A release at 19 that still waits is overdue.
  • Forgetting the tie-breaker. Use a fresh sequence number so the comparison never reaches the task object.
  • Swapping with any child. During sift-down, choose the smaller child.
  • Changing a queued priority directly. This can break heap order.
  • Confusing release and deadline. Readiness is not required completion.
  • Reading averages as guarantees. Batch averages do not bound individual durations.

What real systems use

FreeRTOS keeps delayed tasks in a linked list ordered by wake time. Linux high-resolution timers use a balanced red-black tree for time ordering. For a small queue, a simple structure can be fast enough. Compare the lab timings with the queue sizes your controller actually sees. FreeRTOS source · Linux hrtimers documentation

17. Exam-style questions

  1. For [2, 6, 4, 9, 8, 7], give the minimum, children of index 1, and parent of index 5.

    Show answer

    Minimum 2. Children: indices 3 and 4, values 9 and 8. Parent: index 2, value 4.

    Show answer

  3. Remove the minimum from [2, 6, 4, 9, 8, 7].

    Show answer

More practice

  1. Binary search finds an insertion point in O(log n). Why can sorted-array insertion still take O(n)?

    Show answer

    Entries may need to shift to make space.

  2. Which leaves first: (10, 12, "M") or (10, 8, "I")?

    Show answer

    I: release times tie and 8 < 12.

  3. An operation costs 0.03 ms and 0.02 ms remains. Does it fit?

    Show answer

    No. Choosing correctly does not make the operation fit.

  4. Choose structures for first-arriving sample, exact fault-code response, earliest timer and a small-window median.

    Show answer

    FIFO; dictionary or other exact lookup; min-priority queue; for the Week 6 method, a sorted copy and its middle value.

  5. If the heap is empty, or its root is later than now, what should happen?

    Show answer

    Process nothing. Do not pop an empty heap or a future release.
