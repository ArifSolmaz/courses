Week 07 / 14 · Priority queues and timer heaps

Which task runs next?

15 min · Engineering question

The robot scheduler stores future release times for diagnostics and telemetry. A min-heap helps it find the next timer to release. Once a timer is due, the scheduler still needs a policy for running the released tasks.

Read the heap rule, the cost comparison and the insert and remove examples before tracing on paper.

Before you start

Recall the sorted array from Week 6. Inserting into the middle meant shifting neighboring values. This week we still use an array, with a weaker ordering rule.

  • A heap is stored in an array. The tree is a way to see the index relationships.
  • In a min-heap every parent is less than or equal to its children.
  • At index i, the children are 2i + 1 and 2i + 2. For a non-root index i, the parent is (i − 1) // 2.

A priority queue returns the item with highest priority first. Here that means the earliest release time. Fill the tree from top to bottom and left to right at each level. The parent rule holds along every path from the root, so the root is at most every entry. Siblings can appear in either order.

Assume the sorted list keeps the earliest item at its right end, so popping it takes one step. In an unsorted list, once a scan finds the minimum index, you can fill the gap with the last item. Appending usually takes one step, with occasional resizing.

Each tree level holds about twice as many entries as the one above it. At 1,000 timers a heap update can travel about 10 levels, while a full scan checks 1,000 entries. A swap and a comparison are different operations. Sifting down can also require comparing both children before choosing one. Use the lab to see what that means for time.

The same steps in the tree and array

Sift up. Put the new item at the end. Compare it with its parent. Swap if it is smaller. Stop at the root or when the parent is smaller or equal.

Sift down. Remove the root. Move the last item to the root. If it is larger than its smaller child, swap them. Stop at a leaf or when neither child is smaller.

The small number in each array cell is the index. The large number is the value. Highlights show the entries compared or moved in that frame.

Python heapq cheat sheet

heapq manages an ordinary list as a min-heap. Use its operations to preserve the parent rule.

Python heap operations
OperationBehavior
heappush(heap, item)Insert an item and restore heap order.
heappop(heap)Remove and return the minimum. Raises IndexError on an empty heap.
heapreplace(heap, item)Return the old minimum and insert the replacement. The heap must be nonempty.
heapify(items)Rearrange an existing list into a heap in place.
heap[0]Peek at the minimum without removing it. Check that the heap is nonempty first.

Store (release, seq, task). Python compares the release time first and the sequence number next. Give every insertion a unique seq so equal release times come out in insertion order. Without it, equal release times can make Python compare task objects. Objects that have no ordering raise TypeError.

For example, (2, 1, imu) comes before (2, 4, motor). This sequence number breaks ties only. It does not set task priority or a completion deadline.

At 2 ms, I and M are both due. I comes first because it was inserted earlier. At 10 ms, the same rule gives O, I, M. T stays in the heap throughout the trace because its first release is at 50 ms.

Schedule the next time with release + period. For example, O runs at 10 ms and is pushed back for 20 ms. If its 10 ms release were handled at 11 ms, adding the period to 10 would still keep the original schedule. A real controller needs a policy for missed releases, such as catching up, skipping or coalescing them.

35 min

Trace it on paper

Start with heap [4, 9, 7]. Insert release time 3, then remove the minimum. Use zero-based child indices 2i + 1 and 2i + 2. Break equal release times by insertion order.

Write your trace first. Compare your steps, then explain why the method works in three sentences.

Check your trace

Append 3 and swap upward past 9 and 4 to get [3, 4, 7, 9]. Remove 3, move 9 to the root and swap down with 4 to get [4, 9, 7]. Peeking reads one entry. An insertion or removal moves along at most one tree path, so work grows roughly with log₂ n.

Compare a three-sentence explanation

The root is the minimum because each parent is no larger than its children. Insertion only needs to move the new entry up its parent path. After removing the root, move the last entry there and swap it down with the smaller child until the heap rule holds.

Trace timer priorities and ties

A min-heap has root (3, A), with children (7, B) and (5, C). Insert (3, D), then remove the next two timers. Equal release times are ordered by sequence A, B, C, D.

Show the worked steps
  1. Append D under B. D moves past B because deadline 3 comes first, then stops below A because A wins the tie.
  2. Remove A and move the last element B to the root. Compare D and C. Swap B with D, leaving D first.
  3. Remove D next. Move C to the root. B comes later, so the earliest remaining release is C at time 5.

Compare the two traces. Record one boundary case and a clue that would expose a wrong result. Then take a 10-minute break.

Common mistakes

  • Treating the heap as sorted. [4, 9, 7] is a valid min-heap. The ordering rule applies between a parent and its children.
  • Reading heap[1] as the second smallest. Here that gives 9, while the second smallest is 7.
  • Peeking or popping when empty. Check if heap: first.
  • Confusing due and overdue. At tick 20, a release at 20 is due. A release at 19 that still waits is overdue.
  • Forgetting the tie-breaker. Use a fresh sequence number so the comparison never reaches the task object.

What real systems use

FreeRTOS keeps delayed tasks in a linked list ordered by wake time. Linux high-resolution timers use a balanced red-black tree for time ordering. For a small queue, a simple structure can be fast enough. Compare the lab timings with the queue sizes your controller actually sees. FreeRTOS source · Linux hrtimers documentation

45 min

Measure it

Predict how selecting and replacing one timer scales in an unsorted list and a heap. Time one replacement per call at two queue sizes. Keep initial heap construction outside the timing.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

from heapq import heapify, heapreplace


def list_job(timers):
    index = min(range(len(timers)), key=timers.__getitem__)
    release, sequence = timers[index]
    timers[index] = release + len(timers), sequence


def heap_job(timers):
    release, sequence = timers[0]
    heapreplace(timers, (release + len(timers), sequence))


for n in (32, 512):
    timers = [(i, i) for i in range(n)]
    heap = timers.copy()
    heapify(heap)
    measure(f"{n}: list", lambda: list_job(timers))
    measure(f"{n}: heap", lambda: heap_job(heap))
    assert min(timers) == heap[0]

45 min

Schedule timers with a per-cycle budget

At tick 20, the queue contains release times 18, 19, 20 and 24. Each dispatch costs 0.07 ms including queue work. The robot can spend at most 0.15 ms on dispatch in this cycle.

Start individually for 10 minutes. Work with a partner for 20. Spend the last 15 comparing with another pair and revising your recommendation.

  1. Trace which timers are due, which run this cycle, and what remains. State how the oldest due timer is selected.
  2. Choose what to do with the due timer that does not fit. Distinguish its release time from the cost of running its handler.
  3. Write an acceptance test for several equal release times and another for a queue whose earliest release is in the future.
Compare a model answer

Three timers are due. Two dispatches fit at 0.14 ms, so run releases 18 and 19 first. Release 20 is due now and stays pending. It becomes overdue at tick 21 if it still waits. Release 24 is pending and will be due later. One policy records lateness at the next tick, unless the task’s completion deadline requires a fault response.

Exam-style questions

  1. Which child should replace a larger root during a sift-down?

    Show answer

  2. Two timers have the same release time. How can the order be deterministic?

    Show answer

More practice

  1. What is the next release time in [4, 9, 7]?

    Show answer

    4.

  2. What parent index belongs to child index 5?

    Show answer

    Index 2.

  3. Is the whole array [4, 9, 7] sorted?

    Show answer

    No. Each parent is at most its children.

  4. What should the scheduler do if its heap is empty?

    Show answer

    Report no pending timer and avoid popping.

  5. What does a heap tell you when the earliest timer is later than now?

    Show answer

    No pending timer is due yet.
