Mergesort and quicksort

Split problems into smaller parts and trace how the results combine. Compare balanced splitting with bad pivots.

Where does n log n come from?

Merge the sorted runs [1,4,7] and [2,3,8].

Step 1

Compare the front values: choose 1, then 2, then 3.

Step 2

Compare 4 with 8: choose 4. Compare 7 with 8: choose 7.

Step 3

The first run is empty; append 8 without another key comparison. Five comparisons merge six items.

Step 4

Mergesort handles n items per level across about log₂n levels: Θ(n log n).

Change the case. Quicksort can split into sizes 0 and n−1 repeatedly, giving Θ(n²). Random pivots give an expected O(n log n) bound, not a worst-case guarantee.

Test questions

Choose one option. Cost questions state their model and whether the bound is tight, expected or worst-case. Here lg means log₂, and heap positions start at 1.

Question 1 · easy

Two nested loops each run n times around a constant-time body. Which is the tightest listed upper bound as n grows?

  1. O(n)
  2. O(n log n)
  3. O(n²)
  4. O(2ⁿ)

Answer: option C. Nested loops multiply.

Question 2 · easy

Ignoring rounding and constant factors, which recurrence models mergesort, with T(1) constant?

  1. T(n) = T(n/2) + 1
  2. T(n) = 2T(n/2) + n
  3. T(n) = T(n − 1) + n
  4. T(n) = 2T(n − 1) + 1

Answer: option B. Two halves plus a linear merge; (a) is binary search and (c) is selection sort.

Question 3 · easy

For n distinct keys and standard two-way last-element-pivot quicksort, which input order guarantees Θ(n²) work?

  1. every randomly shuffled input
  2. already sorted input
  3. every input with distinct keys
  4. only arrays of fixed small size

Answer: option B. Every pivot is then an extreme element and one side of the partition is empty.

Question 4 · easy

Which listed sorting method naturally supports an external-memory implementation using sequential runs and merges?

  1. quicksort
  2. heapsort
  3. mergesort
  4. insertion sort

Answer: option C. It streams data sequentially, which suits disks.

Question 5 · medium

The best-case running time of insertion sort is:

  1. Θ(n)
  2. Θ(n log n)
  3. Θ(n²)
  4. Θ(1)

Answer: option A. On already sorted input, each outer iteration performs a constant amount of work and no shifting. There are n − 1 such iterations, giving Θ(n). The inner condition is still checked.

Question 6 · medium

Apply Lomuto partition to [4, 9, 1, 7, 3]: scan left to right, move keys strictly below the last pivot 3 into the next low slot, then swap the pivot into that slot. What is the result?

  1. [1, 3, 4, 7, 9]
  2. [1, 3, 9, 4, 7]
  3. [3, 1, 4, 7, 9]
  4. [1, 9, 4, 7, 3]

Answer: option A. Only 1 is smaller than the pivot; it is swapped to the front, then the pivot is swapped into position 1, giving [1, 3, 4, 7, 9].

Question 7 · medium

In the worst case over two nonempty sorted lists with 10 items in total, how many key comparisons does the standard merge need?

  1. 5
  2. 9
  3. 10
  4. 45

Answer: option B. n − 1: the last element is copied without a comparison.

Question 8 · medium

For n distinct keys and uniformly random pivots, the leading term of quicksort’s expected comparison count is:

  1. n²/2
  2. 1.39 n lg n
  3. n
  4. 2ⁿ

Answer: option B. The exact expectation is 2(n + 1)Hₙ − 4n. Its leading term is 2n ln n = (2 ln 2)n lg n ≈ 1.386n lg n; lower-order terms are omitted.

Question 9 · medium

The median-of-three pivot rule takes:

  1. the mean of three values
  2. the median of the first, middle and last elements
  3. a random element
  4. the last element

Answer: option B. The median is an actual element and is not dragged around by one extreme value.

Question 10 · hard · optional challenge

For n distinct keys and the standard implementations, which statement is FALSE?

  1. array heapsort can sort in place
  2. mergesort has Θ(n log n) worst-case time
  3. comparison sorting needs Ω(n log n) comparisons on average over uniformly random permutations
  4. random-pivot, two-way quicksort has Θ(n log n) worst-case time

In simpler words: Distinguish expected cost from worst-case cost.

Starting hint: Random choices can be unlucky even when their average is good.

Answer: option D. Random pivots give expected Θ(n log n) work on every fixed distinct-key input. Some pivot sequences still cause Θ(n²) work. Expected performance is not a worst-case guarantee.

Step by step
  1. Balanced pivot splits give about log n levels, with linear work per level.
  2. An unlucky sequence of extreme pivots leaves n−1,n−2,… items. Summing those costs gives Θ(n²), so (d) is false.

Written questions

Read each question together with its explanation, trace or proof. Numbering continues from the test questions.

Question 11 · easy

Write the recurrence for mergesort’s running time and its solution.

Answer & reasoning

T(n) = 2T(n/2) + Θ(n), so T(n) = Θ(n log n): linear merging on each of lg n levels.

Question 12 · easy

Merge [1, 4, 9] and [2, 3, 10]. Give the output and count the comparisons.

Answer & reasoning

1, 2, 3, 4, 9, 10. Comparisons: 1 vs 2, 4 vs 2, 4 vs 3, 4 vs 10, 9 vs 10; five comparisons, then 10 is copied with none. That is n − 1 = 5 for n = 6.

Question 13 · easy

What input makes quicksort with the last element as pivot take Θ(n²)?

Answer & reasoning

an already sorted (or reverse sorted) array: every pivot is the largest or smallest element, so one side of every partition is empty.

Question 14 · easy

Which O(n log n) sort is preferred when the data does not fit in memory, and why?

Answer & reasoning

mergesort, because it reads and writes data in long sequential streams, which is what disks do well, instead of jumping around.

Question 15 · medium

Partition the array [8, 3, 6, 1, 9, 2, 5] around the pivot 5 (the last element) using the partition routine from Lecture 8. Show the array after each swap and the pivot’s final index.

Use zero-based Lomuto partitioning: scan all items before the last pivot, swapping each item strictly less than the pivot into the next low slot, then swap the pivot into that slot.

Answer & reasoning

firsthigh starts at index 0. 8 stays. 3 < 5: swap with index 0 → [3, 8, 6, 1, 9, 2, 5], firsthigh 1. 6 stays. 1 < 5: swap with index 1 → [3, 1, 6, 8, 9, 2, 5], firsthigh 2. 9 stays. 2 < 5: swap with index 2 → [3, 1, 2, 8, 9, 6, 5], firsthigh 3. Finally swap the pivot into index 3 → [3, 1, 2, 5, 9, 6, 8]. Everything left of 5 is smaller and everything right is larger.

Question 16 · medium

Why is the guarantee of randomised quicksort stronger than the statement “quicksort runs in Θ(n log n) on random inputs”?

Answer & reasoning

For distinct keys, random pivots give expected Θ(n log n) work for every fixed input, with expectation over the algorithm’s random choices. This does not require the input itself to be random. The worst case remains Θ(n²). With many duplicates, a two-way partition can still be quadratic even with random pivots; use a three-way partition and analyse that implementation separately.

Question 17 · medium

When choosing a pivot as the “median of three” (first, middle, last), why take the median rather than the mean of the three values?

Answer & reasoning

the median is one of the actual elements, so it can be swapped into place and it splits the values around it. The mean may not be an element at all, and one extreme value drags it far from the middle of the data.

Question 18 · medium

Prove that merging two sorted lists with n elements in total needs at most n − 1 comparisons.

Answer & reasoning

every comparison moves exactly one element to the output. Once one list is empty, the rest of the other is copied without comparisons, so at least the last element costs nothing; therefore at most n − 1 comparisons occur.

Question 19 · medium

Two sets of sizes m and n, with 2 ≤ m ≤ n, are supplied as unsorted arrays. Give a comparison-based method and an expected-time hashing method to test disjointness.

Answer & reasoning

Sort the smaller set in O(m log m), then binary-search each of the n larger-set items in it in O(n log m), for O((m + n) log m) total. Alternatively hash the smaller set and scan the larger in O(m + n) expected time under suitable hashing assumptions. Empty sets are immediately disjoint; for m = 1 a linear scan suffices.

Question 20 · medium

Why might quicksort run faster than heapsort on a particular machine even though both have n log n behaviour in the relevant case?

Answer & reasoning

Big-O hides constants and memory-access effects. Quicksort often has good locality and a simple inner loop, while heap operations jump between array positions. The actual comparison depends on input, implementation and hardware; measure it. Randomised quicksort is expected Θ(n log n) under the appropriate distinct-key or duplicate-handling assumptions and can have a quadratic worst case; heapsort has an O(n log n) worst-case guarantee.

Question 21 · hard · optional challenge

Let H(n) = 1 + 1/2 + 1/3 + … + 1/n (the harmonic number from the quicksort analysis). Show without calculus that H(n) = Θ(log n).

In simpler words: Estimate 1 + 1/2 + … + 1/n without adding each term.

Starting hint: Group denominators between consecutive powers of two.

Answer & reasoning
Step by step
  1. For n = 8, use blocks 1; 1/2; 1/3+1/4; 1/5+…+1/8.
  2. A block ending at 2ᵏ has 2^(k−1) terms, each between 1/2ᵏ and 1/2^(k−1). Its sum lies between 1/2 and 1.
  3. There are about log₂ n such blocks. Constant work per block gives matching upper and lower bounds proportional to log n. A final incomplete block does not change that growth.

group the terms into blocks: (1), (1/2), (1/3 + 1/4), (1/5 + … + 1/8), …, the k-th block holding the 2ᵏ⁻¹ terms from 1/(2ᵏ⁻¹ + 1) to 1/2ᵏ. Each block’s terms are each at most 1/2ᵏ⁻¹ and at least 1/2ᵏ, so each block sums to at most 1 and at least 1/2. There are about lg n blocks, so H(n) is between roughly (lg n)/2 and lg n + 1: Θ(log n).

Question 22 · hard · optional challenge

Run quicksort with the partition routine of Lecture 8 on an array where all n keys are equal. What happens, and how would you fix it?

Use the two-way partition described in source exercise 77: only values strictly less than the last-element pivot enter the low partition.

In simpler words: Trace what happens when the partition never finds a smaller key.

Starting hint: With all keys equal, every strict “less than pivot” test fails.

Answer & reasoning
Step by step
  1. The pivot moves to one end and the remaining subproblem has n−1 keys.
  2. Work is proportional to n+(n−1)+…+1, so it is quadratic.
  3. Three-way partition collects equal keys into a middle block. No recursion is needed on that block; all-equal data is handled in one linear scan.

no element is strictly less than the pivot, so every element stays on the “high” side; each partition removes only the pivot and the recursion depth becomes n, giving Θ(n²). Fix: a three-way partition into “less than”, “equal to” and “greater than” the pivot, and recurse only on the outer two parts; the all-equal case then finishes in O(n).

Lecture 8 · Warm-up: are two sets disjoint?

Hazırlık: İki küme ayrık mı?

Given two sets of sizes m and n, do they share any element? Three approaches:

Boyutları m ve n olan iki küme veriliyor. Ortak bir elemanları var mı? Üç yaklaşım:

Sort both, then walk through them together like a merge: O(n log n + m log m).

İkisini de sırala, ardından birleştirme işlemindeki gibi birlikte ilerle: O(n log n + m log m).

Sort only the smaller set (say m ≤ n), then binary-search each of the n items of the larger set in it: O(m log m + n log m). When m is much smaller than n this is better, because only the small set pays the sorting cost.

Yalnızca küçük kümeyi sırala (m ≤ n olsun), ardından büyük kümenin n elemanının her birini küçük kümede ikili aramayla ara: O(m log m + n log m). m, n’den çok küçük olduğunda bu daha iyidir; çünkü sıralama maliyetini yalnızca küçük küme öder.

Put one set in a hash table and look up each item of the other: O(n + m) expected.

Bir kümeyi karma tablosuna yerleştir ve diğerinin her elemanını burada ara: beklenen O(n + m).

The lesson is to notice which set is small and make the expensive work depend on it.

Buradan çıkarılacak ders, hangi kümenin küçük olduğunu fark etmek ve pahalı işlemi onun boyutuna bağlı hâle getirmektir.

Lecture 8 · Mergesort

Birleştirmeli sıralama (mergesort)

Recursive algorithms reduce a big problem to smaller copies of itself. Mergesort sorts a list by splitting it into two halves, sorting each half recursively (a list of one item is already sorted), and then merging the two sorted halves into one sorted list:

Özyinelemeli algoritmalar büyük bir problemi kendisinin daha küçük örneklerine indirger. Birleştirmeli sıralama, listeyi iki yarıya ayırır, her yarıyı özyinelemeli olarak sıralar (tek elemanlı liste zaten sıralıdır) ve ardından sıralı iki yarıyı tek bir sıralı listede birleştirir:

mergesort(s, low, high):
    if low < high:
        middle = (low + high) / 2
        mergesort(s, low, middle)
        mergesort(s, middle + 1, high)
        merge(s, low, middle, high)
mergesort(s, low, high):
    if low < high:
        middle = (low + high) / 2
        mergesort(s, low, middle)
        mergesort(s, middle + 1, high)
        merge(s, low, middle, high)

Merging two sorted lists. The smallest item overall must be the first item of one list or the other. Compare the two heads, take the smaller, and repeat until both lists are empty. With A = {5, 7, 12, 19} and B = {4, 6, 13, 15} the merged output is 4, 5, 6, 7, 12, 13, 15, 19; each output item cost one comparison, so merging n items takes at most n − 1 comparisons, O(n). The implementation keeps the two halves in two queues and repeatedly dequeues the smaller head into the array.

İki sıralı listeyi birleştirme. Tüm elemanların en küçüğü, listelerden birinin ilk elemanı olmak zorundadır. İki baş elemanı karşılaştır, küçüğünü al ve her iki liste de boşalana kadar tekrarla. A = {5, 7, 12, 19} ve B = {4, 6, 13, 15} için birleştirilmiş çıktı 4, 5, 6, 7, 12, 13, 15, 19 olur. Her çıktı elemanı bir karşılaştırmaya mal olduğundan n elemanın birleştirilmesi en fazla n − 1 karşılaştırma, yani O(n) gerektirir. Gerçeklemede iki yarı iki kuyrukta tutulur ve her seferinde küçük baş eleman kuyruktan çıkarılarak diziye yazılır.

Analysis. Picture the recursion as a tree: the full list at the top, two halves below it, four quarters below that, down to single items. At every level the merges together touch every item once, so each level costs O(n). Halving until size 1 takes lg n levels. Total: O(n log n), and this is the worst case, because mergesort’s work does not depend on the input order.

Analiz. Özyinelemeyi bir ağaç olarak düşünün: tepede tam liste, altında iki yarı, onların altında dört çeyrek ve en altta tek elemanlar. Her düzeydeki birleştirmeler, birlikte tüm elemanlara birer kez dokunur; dolayısıyla her düzey O(n) maliyetlidir. Boyut 1’e ulaşana kadar ikiye bölmek lg n düzey gerektirir. Toplam O(n log n)’dir ve bu en kötü durumdur; çünkü birleştirmeli sıralamanın yaptığı iş, girdinin sırasına bağlı değildir.

Lecture 8 · Divide and conquer, and its recurrence

Böl ve yönet ve yineleme bağıntısı

Divide and conquer means: split the problem into two smaller subproblems, solve each recursively, then meld the partial answers. Mergesort, binary search, the fast Fourier transform and Strassen’s matrix multiplication all work this way. The method wins when melding is cheaper than solving the two halves. For mergesort the running time obeys the recurrence

T(n) = 2 T(n/2) + Θ(n)  ⟹  T(n) = Θ(n log n)

Böl ve yönet şu anlama gelir: problemi daha küçük iki alt probleme böl, her birini özyinelemeli olarak çöz ve kısmi yanıtları birleştir. Birleştirmeli sıralama, ikili arama, hızlı Fourier dönüşümü ve Strassen’in matris çarpımı bu şekilde çalışır. Birleştirme, iki yarıyı çözmekten daha ucuz olduğunda yöntem avantaj sağlar. Birleştirmeli sıralamanın çalışma süresi şu yineleme bağıntısına uyar:

Read it as: “the time for n items is twice the time for n/2 items, plus linear time to merge”. Every level of the recursion tree costs n and there are log n levels.

Şöyle okuyun: “n eleman için gereken süre, n/2 eleman için gereken sürenin iki katı ile birleştirme için gereken doğrusal sürenin toplamıdır.” Özyineleme ağacının her düzeyi n maliyetlidir ve log n düzey vardır.

External sorting. Which O(n log n) algorithm you use barely matters until the data no longer fits in memory. Then mergesort wins, because it reads and writes data in long sequential streams, which is what disks are good at, rather than jumping around.

Dış sıralama. Veri belleğe sığmamaya başlayana kadar hangi O(n log n) algoritmasını kullandığınız pek fark etmez. Bundan sonra birleştirmeli sıralama üstün gelir; çünkü veriye rastgele sıçramak yerine, disklerin iyi yaptığı biçimde uzun ve ardışık akışlar hâlinde okuma ve yazma yapar.

Lecture 8 · Quicksort

Hızlı sıralama (quicksort)

In practice the fastest in-memory sort is quicksort, whose main idea is partitioning. Pick one element, the pivot. Rearrange the array so that everything smaller than the pivot is to its left and everything larger is to its right. Example, pivot 10:

Uygulamada bellek içi sıralamanın en hızlısı, temel fikri bölümleme olan hızlı sıralamadır. Pivot adı verilen bir eleman seçin. Diziyi, pivottan küçük her şey onun solunda, büyük her şey sağında olacak biçimde yeniden düzenleyin. Pivotun 10 olduğu örnek:

before:  17 12  6 19 23  8  5 10
after:    6  8  5 10 23 19 12 17
önce:  17 12  6 19 23  8  5 10
sonra:  6  8  5 10 23 19 12 17

Two things are now true: the pivot sits in its final sorted position, and no element will ever need to cross from one side of the pivot to the other. So the left part and the right part can be sorted independently, recursively:

Artık iki şey doğrudur: pivot, sıralanmış dizideki son konumundadır ve hiçbir elemanın pivotun bir tarafından diğer tarafına geçmesi gerekmeyecektir. Dolayısıyla sol ve sağ parçalar birbirinden bağımsız olarak, özyinelemeli biçimde sıralanabilir:

quicksort(s, l, h):
    if h − l > 0:
        p = partition(s, l, h)
        quicksort(s, l, p − 1)
        quicksort(s, p + 1, h)
quicksort(s, l, h):
    if h − l > 0:
        p = partition(s, l, h)
        quicksort(s, l, p − 1)
        quicksort(s, p + 1, h)

Partitioning in one pass. Choose the last element as the pivot. Keep a marker firsthigh at the start of the region of items known to be ≥ pivot. Scan left to right; whenever an item is smaller than the pivot, swap it to position firsthigh and advance the marker. At the end, swap the pivot into position firsthigh. The array is maintained in three zones (< pivot, ≥ pivot, unexplored), and the scan does at most n swaps: O(n).

Tek geçişte bölümleme. Son elemanı pivot seçin. ≥ pivot olduğu bilinen elemanlar bölgesinin başında firsthigh adlı bir işaret tutun. Soldan sağa tarayın; bir eleman pivottan küçük olduğunda onu firsthigh konumundaki elemanla değiştirin ve işareti ilerletin. Sonunda pivotu firsthigh konumuna taşıyın. Dizi üç bölge hâlinde tutulur (< pivot, ≥ pivot, henüz incelenmemiş) ve tarama en fazla n yer değiştirme yapar: O(n).

partition(s, l, h):
    p = h                     (pivot = last element)
    firsthigh = l
    for i from l to h − 1:
        if s[i] < s[p]:
            swap s[i] and s[firsthigh]
            firsthigh = firsthigh + 1
    swap s[p] and s[firsthigh]
    return firsthigh
partition(s, l, h):
    p = h                     (pivot = son eleman)
    firsthigh = l
    for i from l to h − 1:
        if s[i] < s[p]:
            s[i] ile s[firsthigh] yer değiştir
            firsthigh = firsthigh + 1
    s[p] ile s[firsthigh] yer değiştir
    return firsthigh
Lecture 8 · Best case, worst case

En iyi durum, en kötü durum

Because every element eventually becomes a pivot and lands in its correct spot, quicksort is correct. How fast is it?

Her eleman sonunda pivot olup doğru yerine yerleştiği için hızlı sıralama doğrudur. Peki ne kadar hızlıdır?

Best case: the pivot splits the array exactly in half every time. Then, as in mergesort, each level of the recursion tree does O(n) partitioning work and there are lg n levels: O(n log n).

En iyi durum: Pivot her seferinde diziyi tam ikiye böler. Birleştirmeli sıralamada olduğu gibi, özyineleme ağacının her düzeyinde O(n) bölümleme işi yapılır ve lg n düzey vardır: O(n log n).

Worst case: the pivot is always the smallest or largest element, so one side is empty and the other has n − 1 items. Now there are n − 1 levels instead of lg n, and the first n/2 of them each partition at least n/2 items: Θ(n²). With the last-element pivot rule, an already-sorted input is exactly this disaster.

En kötü durum: Pivot her zaman en küçük veya en büyük elemandır; bu nedenle bir taraf boş, diğeri n − 1 elemanlıdır. Artık lg n yerine n − 1 düzey vardır ve ilk n/2 düzeyin her biri en az n/2 elemanı bölümler: Θ(n²). Son elemanı pivot seçme kuralında, zaten sıralı bir girdi tam olarak bu felakete yol açar.

Skiena’s life advice from the analysis: if you break a job into pieces, make the pieces equal.

Skiena’nın bu analizden çıkardığı yaşam önerisi: Bir işi parçalara ayırıyorsanız parçaları eşit yapın.

Lecture 8 · The average case: why quicksort deserves its name

Ortalama durum: Hızlı sıralama neden adını hak eder?

Intuition. Suppose the pivot is chosen at random. Half the time it falls in the middle half of the sorted order (between positions n/4 and 3n/4). Such a “decent” pivot leaves a larger side of at most 3n/4 items. How many decent partitions shrink n down to 1? Solve (3/4)ˡ × n = 1, giving l = log₄/₃ n, which is less than 2 lg n. Since only half of random pivots are decent, we expect about twice that many levels, roughly 4 lg n. Each level costs O(n), so the average is O(n log n).

Sezgisel açıklama. Pivotun rastgele seçildiğini varsayın. Seçimlerin yarısında, sıralı düzenin ortadaki yarısına düşer (n/4 ile 3n/4 konumları arasına). Böyle “makul” bir pivot, büyük tarafta en fazla 3n/4 eleman bırakır. n’yi 1’e indirmek için kaç makul bölümleme gerekir? (3/4)ˡ × n = 1 denklemini çözün: l = log₄/₃ n elde edilir ve bu, 2 lg n’den küçüktür. Rastgele pivotların yalnızca yarısı makul olduğundan, bunun yaklaşık iki katı, kabaca 4 lg n düzey bekleriz. Her düzey O(n) maliyetlidir; dolayısıyla ortalama O(n log n)’dir.

Precise analysis. Let T(n) be the expected number of comparisons. Each of the n possible pivot positions p is equally likely, partitioning costs n − 1 comparisons, and then the two sides of sizes p − 1 and n − p are sorted:

T(n) = n∑p=1 1n ( T(p−1) + T(n−p) ) + n − 1

Kesin analiz. T(n), beklenen karşılaştırma sayısı olsun. Olası n pivot konumu p’nin her biri eşit olasılıklıdır. Bölümleme n − 1 karşılaştırma gerektirir; ardından boyutları p − 1 ve n − p olan iki taraf sıralanır:

The slides grind through the algebra: multiply by n, subtract the same equation written for n − 1, rearrange, and substitute aₙ = T(n)/(n + 1). What drops out is a sum of terms like 2/(i + 1), which is twice the harmonic number Hₙ = 1 + 1/2 + 1/3 + … + 1/n ≈ ln n. The result:

T(n) ≈ 2(n+1) ln n ≈ 1.38 n lg n

Slaytlarda cebirsel işlemler ayrıntılı olarak yapılır: n ile çarpılır, aynı denklemin n − 1 için yazılmış hâli çıkarılır, terimler düzenlenir ve aₙ = T(n)/(n + 1) dönüşümü uygulanır. Sonuçta 2/(i + 1) biçimindeki terimlerin toplamı ortaya çıkar; bu, Hₙ = 1 + 1/2 + 1/3 + … + 1/n ≈ ln n harmonik sayısının iki katıdır. Sonuç:

The two things worth understanding are where the recurrence comes from and how the logarithm appears out of the harmonic sum; the rest is messy algebra.

Anlaşılması gereken iki nokta, yineleme bağıntısının nereden geldiği ve harmonik toplamdan logaritmanın nasıl ortaya çıktığıdır; gerisi karmaşık cebirsel işlemlerdir.

Lecture 8 · Randomised quicksort

Rastgeleleştirilmiş hızlı sıralama

Imagine your sorting program will be run on data supplied by your worst enemy. Ordinary quicksort is fine on average but terrible on specific inputs, so the enemy simply hands you the worst-case input.

Sıralama programınızın en büyük düşmanınızın sağladığı veriler üzerinde çalışacağını düşünün. Olağan hızlı sıralama ortalamada iyidir, fakat belirli girdilerde çok kötüdür; dolayısıyla düşmanınız size doğrudan en kötü durum girdisini verir.

Now suppose you pick the pivot at random. The enemy can no longer construct a bad input, because whatever data they give, each pivot has the same chance of being decent. This changes the kind of promise we can make:

Şimdi pivotu rastgele seçtiğinizi varsayın. Düşman artık kötü bir girdi oluşturamaz; çünkü hangi veriyi verirse versin, her pivotun makul olma olasılığı aynıdır. Bu, verebileceğimiz garantinin türünü değiştirir:

Before: “If you give me random input, quicksort runs in expected Θ(n log n) time.”

Önce: “Bana rastgele girdi verirseniz hızlı sıralama beklenen Θ(n log n) sürede çalışır.”

After: “On any input, randomised quicksort runs in Θ(n log n) time with high probability.”

Sonra: “Herhangi bir girdide rastgeleleştirilmiş hızlı sıralama, yüksek olasılıkla Θ(n log n) sürede çalışır.”

The worst case still exists, but it no longer depends on the input; only on being astronomically unlucky with the random choices. Randomisation is a general tool for algorithms with a bad worst case but a good average case: shuffle the input (or the choices) so that the average case is what you get.

En kötü durum hâlâ vardır; ancak artık girdiye değil, yalnızca rastgele seçimlerde astronomik ölçüde talihsiz olmaya bağlıdır. Rastgeleleştirme, en kötü durumu kötü, ortalama durumu iyi algoritmalar için genel bir araçtır: girdiyi (veya seçimleri) karıştırın ki elde ettiğiniz davranış ortalama durum olsun.

Better pivot rules. Since sorted or nearly sorted input is common in practice, never use the first or last element blindly. Options: the middle element; a random element; or, best of all, the median of three (first, middle and last). Median rather than mean, because the median is guaranteed to be one of the actual elements and cannot be dragged around by one extreme value. With any of these rules the worst case is still O(n²); it is just much rarer.

Daha iyi pivot kuralları. Uygulamada sıralı veya sıralıya yakın girdiler yaygın olduğundan ilk ya da son elemanı körü körüne kullanmayın. Seçenekler: ortadaki eleman, rastgele bir eleman veya en iyisi üç elemanın medyanı (ilk, orta ve son). Ortalama yerine medyan kullanılır; çünkü medyanın gerçek elemanlardan biri olduğu garantidir ve tek bir uç değer onu sürükleyemez. Bu kuralların hepsinde en kötü durum yine O(n²)’dir; yalnızca çok daha seyrek görülür.

Lecture 8 · Is quicksort really faster than heapsort?

Hızlı sıralama gerçekten öbek sıralamasından daha mı hızlı?

Both are Θ(n log n), so on large inputs there is no contest against Θ(n²) sorts. Between the two, a well-written quicksort is typically 2 to 3 times faster than mergesort or heapsort, because the operations in its innermost loop are simpler. Since the difference is a constant factor, the quality of the implementation matters a great deal.

İkisi de Θ(n log n) olduğundan, büyük girdilerde Θ(n²) sıralamalarla aralarında bir yarış yoktur. Bu grupta, iyi yazılmış bir hızlı sıralama genellikle birleştirmeli veya öbek sıralamasından 2–3 kat hızlıdır; çünkü en iç döngüsündeki işlemler daha basittir. Fark sabit bir çarpan olduğundan, gerçeklemenin kalitesi çok önemlidir.
