Week 05 · Lectures 5, 6

Search trees and hashing

Use trees and hash tables to implement dictionaries. Relate tree height, collisions and load factor to the actual search cost.

Exam scope: Midterm and finalCumulative review

By the end of this week you can…

  • Trace search, insertion and the three deletion cases in a binary search tree.
  • Relate the height of a search tree to its worst-case search cost.
  • Trace hashing with chaining and with linear probing, including a lookup after deletion.
  • Compare expected and worst-case dictionary costs and state the assumptions behind each.

What assumptions make a lookup fast?

Insert 10,15,3,20 into five hash slots using h(k)=k mod 5 and linear probing.

Step 1

10 enters slot 0.

Step 2

15 also hashes to 0; slot 1 is the first free slot.

Step 3

3 enters slot 3.

Step 4

20 probes 0,1,2 and enters slot 2. A lookup must use the same probing rule.

Change the case. Deleting 10 by making slot 0 look never-used can break a later search for 20. Use a tombstone or a correct repair scheme. Expected constant lookup is conditional, not a worst-case guarantee.

Where an engineer meets this

A CAN node receives frames with 11-bit identifiers (0–2047) but handles perhaps twenty of them. A direct table of 2048 entries wastes RAM on an 8 KB device. A 32-slot hash table with h(id) = id mod 32 usually finds a key in one probe.

Collisions are the price. Identifiers are often spaced regularly (0x100, 0x120, 0x140 …), and a power-of-two modulus sends them all to one slot. The identifier set is fixed at design time, so test the table offline and pick a modulus, often a prime, that spreads the real keys.

Mini-problem. Insert 0x100 (256), 0x120 (288), 0x140 (320), 0x121 (289) into 32 slots with linear probing, h = id mod 32. Where does each land? How many probes to look up 0x121?

Check your answer

256, 288, 320 are all 0 mod 32: slots 0, 1, 2. 289 mod 32 = 1: probes 1, 2, takes 3. Lookup of 0x121: three probes. With mod 37 the keys land in 34, 29, 24, 30: no collision.

Test questions

Choose one option. Cost questions state their model and whether the bound is tight, expected or worst-case. Here lg means log₂, and heap positions start at 1.

Question 1 · easy

In a binary search tree the minimum key is found by:

  1. repeatedly going right
  2. repeatedly going left
  3. looking at the root
  4. a hash lookup

Answer: option B. Smaller keys always lie to the left.

Question 2 · easy

An in-order traversal of a BST prints the keys:

  1. level by level
  2. in the order they were inserted
  3. in sorted order
  4. in reverse sorted order

Answer: option C. Left subtree, node, right subtree.

Question 3 · easy

Insert distinct keys 1, 2, …, n into a plain, unbalanced BST, for n ≥ 3. Counting edges from root to deepest leaf, its height is:

  1. about log n
  2. n − 1
  3. 1
  4. about √n

Answer: option B. Each key becomes the right child of the previous one: a chain.

Question 4 · easy

With fixed-size keys, suitable uniform hashing and bounded load factor, what is the tightest listed expected search bound?

  1. O(1)
  2. O(log n)
  3. O(n)
  4. O(n log n)

Answer: option A. With those assumptions, the expected number of inspected entries stays bounded, so expected search cost is O(1). Bad collisions can still make the worst case linear.

Question 5 · easy

A table of size 5 uses linear probing with h(k) = k mod 5. Insert 10, 15, 3, 20 in that order. Key 20 ends up in slot:

  1. 0
  2. 1
  3. 2
  4. 4

In simpler words: Trace each insertion into the first available slot.

Starting hint: Start at k mod 5 and move right if occupied.

Answer: option C. 10 takes slot 0, 15 probes 0 then takes 1, 3 takes 3, and 20 probes 0, 1 and settles in 2.

Step by step
  1. 10 takes 0; 15 probes 0 and takes 1; 3 takes 3.
  2. 20 probes 0, then 1, then finds 2 empty. So the answer is slot 2.

Question 6 · medium

Using the successor-based deletion method, a BST node with two children is replaced by:

  1. its parent
  2. its left child
  3. its in-order successor (the minimum of its right subtree)
  4. the root

Answer: option C. The successor has at most one child, so it is easy to remove from its old place.

Question 7 · medium

The successor of a BST node that has a right child is:

  1. the minimum of its right subtree
  2. the maximum of its right subtree
  3. its parent
  4. the maximum of its left subtree

Answer: option A. The next larger key is the smallest key that is larger.

Question 8 · medium

With h(k) = k mod 8, the keys 8, 16, 24 and 32:

  1. spread evenly over the table
  2. all collide in slot 0
  3. produce exactly two collisions
  4. cannot be inserted

Answer: option B. All are multiples of 8; a table size that shares structure with the keys is a bad choice.

Question 9 · medium

Hash keys independently and uniformly into 365 slots. At about how many keys does the probability of at least one collision first exceed one half?

  1. 23 keys
  2. 183 keys
  3. 365 keys
  4. 730 keys

Answer: option A. The birthday paradox.

Question 10 · medium

Using fixed-word modular arithmetic and a precomputed outgoing-character multiplier, what is the tightest bound for updating a Rabin–Karp window hash by one character?

  1. O(m)
  2. O(1)
  3. O(log m)
  4. O(n)

Answer: option B. Subtract the outgoing contribution, multiply by the base and add the incoming character, all modulo a fixed-word modulus. This is constant work; confirming an actual match can still require comparing the window characters.

Question 11 · medium

Which structure gives the best guaranteed worst-case bound on all seven dictionary operations?

  1. a hash table
  2. an unsorted array
  3. a balanced binary search tree
  4. a sorted linked list

Answer: option C. A balanced BST supports each ordered-dictionary operation in O(log n) worst-case time. An ordinary hash table does not maintain key order, and its worst-case lookup can be linear.

Question 12 · medium

For distinct keys and ordinary implementations without extra cached minima, which statement is FALSE?

  1. a doubly linked list deletes a node you already hold in O(1)
  2. a sorted array finds a key’s predecessor in O(1) once the key is located
  3. a BST of height h answers a search in O(h)
  4. a hash table finds the minimum key in O(1) expected time

In simpler words: Separate location-based operations from ordered searches.

Starting hint: An ordinary hash table does not keep keys in numeric order.

Answer: option D. Hashing scatters keys, so finding the minimum means scanning the whole table.

Step by step
  1. A known linked-list node can be spliced out directly; a located sorted-array key has its predecessor next door; a BST search follows one height-h path.
  2. The hash table must examine stored keys to find the minimum unless it maintains extra information. That makes (d) false.

Question 13 · medium · course question

CAN identifiers 0x100, 0x120 and 0x140 are inserted in that order into a 32-slot table with h(id) = id mod 32 and linear probing. How many probes does a lookup of 0x140 take?

  1. 1
  2. 2
  3. 3
  4. 32

Answer: option C. 256, 288 and 320 are all 0 mod 32. 0x100 takes slot 0, 0x120 probes 0 and takes 1, 0x140 probes 0, 1 and takes 2. Looking it up repeats those three probes.

Written questions

Read each question together with its explanation, trace or proof. Numbering continues from the test questions.

Question 14 · easy

List the seven dictionary operations.

Answer & reasoning

search, insert, delete, minimum, maximum, predecessor, successor.

Question 15 · easy

In a sorted array, what do search and insert cost, and why is insert slow?

Answer & reasoning

search O(log n) by binary search; insert O(n), because after finding the right spot every later item must shift one place to make room.

Question 16 · easy

In a binary search tree, where is the largest key? The smallest?

Answer & reasoning

largest: start at the root and keep going right until you cannot. Smallest: keep going left.

Question 17 · easy

Insert 50, 30, 70, 20, 40, 60, 80 in that order into an empty BST. Describe the tree and give its height.

Answer & reasoning

50 is the root; 30 is its left child and 70 its right child; 20 and 40 hang under 30; 60 and 80 hang under 70. Three levels, height 2. It is perfectly balanced.

Question 18 · easy

What does an in-order traversal of the tree in Week 5, Question 17 print?

Week 5, Question 17 uses the BST obtained by inserting 50, 30, 70, 20, 40, 60, 80 in that order.

Answer & reasoning

20 30 40 50 60 70 80, the keys in sorted order.

Question 19 · easy

Insert 1, 2, 3, 4, 5 in that order into an empty BST. What is its height, and what does a search cost?

Answer & reasoning

each key goes to the right of the previous one, giving a chain of height 4; search costs O(n), no better than a linked list.

Question 20 · easy

What is a collision in a hash table, and what are the two standard ways to handle collisions?

Answer & reasoning

two different keys hashing to the same slot. Chaining (a linked list per slot) and open addressing (probe other slots by a fixed rule).

Question 21 · easy

Why is the worst-case cost of a hash-table search O(n)?

Answer & reasoning

an unlucky (or adversarial) set of keys can all hash to the same slot, so the search walks a list of all n keys.

Question 22 · medium

In a BST, node x has no right child. Where is its successor?

Answer & reasoning

walk up from x until you arrive at an ancestor from its left child; that ancestor is the successor (the next key in in-order). If you reach the root without ever coming up from a left child, x is the maximum.

Question 23 · medium

When deleting a BST node with two children, which node takes its place, and why is that node guaranteed to have at most one child?

Answer & reasoning

its successor, the minimum of the right subtree (the predecessor works symmetrically). Being a minimum, it cannot have a left child, so it has at most a right child and can be removed with the one-child case.

Question 24 · medium

How can you check in O(n) time whether a given binary tree with keys satisfies the BST property?

Answer & reasoning

For distinct keys and a strict BST ordering rule, traverse in order and check that successive keys are strictly increasing. Visit every node once: O(n) time. If duplicate keys are allowed, specify which subtree may contain them and enforce that policy with lower and upper bounds during traversal; a nondecreasing traversal alone cannot enforce a one-sided duplicate policy.

Question 25 · medium

Binary search on a sorted array costs O(log n). Why does the same idea not work on a sorted linked list?

Answer & reasoning

binary search needs to jump to the middle element in O(1); a linked list can only reach the middle by walking n/2 pointers, which already costs O(n).

Question 26 · medium

With h(k) = k mod 10 and keys 12, 22, 32, 42, what happens? What if the table size is 11 instead?

Answer & reasoning

Modulo 10 sends all four keys to slot 2. Modulo 11 sends 12, 22, 32, 42 to 1, 0, 10, 9. The changed modulus fixes this particular pattern; choosing a prime alone does not guarantee a good distribution for every key set. Expected constant-time lookup requires suitable hashing and controlled load.

Question 27 · medium

Keys are hashed at random into a table of 365 slots. Roughly how many keys can you insert before a collision becomes more likely than not?

Answer & reasoning

Assuming independent uniform slots, the no-collision probability is the product of (365−i)/365 for i = 0,…,n−1. At n = 23, collision probability is about 0.507; at n = 50 it is about 0.970. A collision is likely long before the table is full, so collision handling is essential.

Question 28 · medium

Explain in words why Rabin-Karp can move its window one character to the right in O(1) time.

Answer & reasoning

With a fixed-word modulus and a precomputed α^(m−1) modulo that modulus, remove the outgoing character contribution, multiply by α, then add the incoming character, all modulo the modulus. That uses constant word operations. Without bounded arithmetic or the precomputed power, this constant-time claim needs qualification; confirming a hash match still compares characters.

Question 29 · medium

Given n integers and a target T, decide whether some two of them add up to T. Give an O(n) expected-time method and an O(n log n) worst-case method.

Answer & reasoning

Expected linear method: scan once with an initially empty hash set. For each x, test whether T − x is already present before inserting x, so the same record is never used twice. This permits two distinct records with equal values. For an O(n log n) worst-case comparison method, sort and move pointers inward while their positions differ; advance the left pointer if the sum is too small and the right pointer if it is too large. Include sorting and any required copy in the costs.

Question 30 · medium

What is the height of a perfectly balanced BST holding 1,023 keys?

Answer & reasoning

9. A full tree of height h has 2ʰ⁺¹ − 1 nodes, and 2¹⁰ − 1 = 1,023, so there are 10 levels and 9 edges from root to leaf.

Question 31 · medium

Describe two ways to sort n numbers with a balanced BST, and their cost.

Answer & reasoning

Insert all records into a balanced BST in O(n log n), keeping a multiplicity count or list for duplicate keys. Then an in-order traversal outputs all n records in O(n). Alternatively, repeatedly find and delete a minimum, costing O(n log n) overall. A set-like tree that silently discards duplicates would not correctly sort the original sequence.

Question 32 · medium

A hash table of size 7 uses open addressing with linear probing and h(k) = k mod 7. Insert 7, 14, 21, 1 in that order and give each key’s slot. Then delete 14 by simply emptying its slot and search for 21. What goes wrong, and what is the fix?

In simpler words: Explain why a deleted hash slot must not look unused.

Starting hint: Searching stops at a never-used slot, but must continue past a deleted one.

Answer & reasoning
Step by step
  1. The four inserted keys occupy slots 0,1,2,3 respectively.
  2. If slot 1 becomes ordinary empty, searching for 21 stops there and misses slot 2.
  3. A tombstone means “used before, keep searching.” Insertion may reuse it, but must still check for an existing duplicate key if the interface is a set.

7 → slot 0; 14 hashes to 0, taken, so slot 1; 21 hashes to 0, then 1, taken, so slot 2; 1 hashes to 1, then 2, taken, so slot 3. After emptying slot 1, a search for 21 probes slot 0 (7, not it), then slot 1, finds it empty and stops: 21 is reported missing although it is in slot 2. Fix: mark deleted slots with a special “deleted” marker (a tombstone) that searches skip over but insertions may reuse.

Question 33 · medium

A CAN node handles identifiers 0x100, 0x120, 0x140 and 0x121. Insert them in that order into a table with linear probing using h(id) = id mod 32, then again using h(id) = id mod 37. Give each slot, the number of probes to look up 0x121 in each table, and explain why the second modulus can be chosen at design time.

Answer & reasoning

Decimal values: 0x100 = 256, 0x120 = 288, 0x140 = 320, 0x121 = 289. Mod 32: 256, 288 and 320 are multiples of 32, so all hash to 0; 289 hashes to 1. Insert: 256 → slot 0; 288 → probes 0, takes 1; 320 → probes 0, 1, takes 2; 289 → probes 1, 2, takes 3. Lookup of 0x121 probes 1, 2, 3: three probes. Mod 37: 256 = 6 × 37 + 34 → slot 34; 288 = 7 × 37 + 29 → slot 29; 320 = 8 × 37 + 24 → slot 24; 289 = 7 × 37 + 30 → slot 30. No collisions; every lookup is one probe. The identifier set of a bus is fixed when the system is designed, so the table can be built and tested offline and a modulus chosen that spreads exactly these keys; a prime modulus avoids the regular spacing of identifiers that a power of two maps onto one slot.

Question 34 · hard

Prove that an in-order traversal of any BST outputs its keys in sorted order.

In simpler words: Explain why left–root–right prints a search tree in order.

Starting hint: Assume each smaller subtree already prints correctly.

Answer & reasoning
Step by step
  1. For an empty tree, the output is empty and sorted.
  2. For distinct keys, every left-subtree key is below the root and every right-subtree key is above it.
  3. By induction, each subtree output is sorted. Joining sorted-left, root, sorted-right creates a sorted whole.

induction on the number of nodes. An empty tree prints nothing, which is sorted. For a tree with root r, by the induction hypothesis the left subtree prints its keys sorted and so does the right subtree. Every left key is < r < every right key by the BST property, so “left output, then r, then right output” is sorted.

Question 35 · hard

Design a set of distinct fixed-size keys supporting insert, delete and a uniformly random stored key in expected amortised O(1) time.

In simpler words: Support fast deletion without leaving holes in the array.

Starting hint: The array need not stay sorted: replace a removed item with the last one.

Answer & reasoning
Step by step
  1. Store [A,B,C] and a map A→0, B→1, C→2.
  2. Delete B by moving C into slot 1, changing C→1, and popping the old last slot. Remove B from the map.
  3. A uniform random index selects each stored key equally often. Hashing is expected constant time; resizing makes the array cost amortised, meaning averaged over a sequence of operations.

Use a dynamic array A and a hash map from each key to its array index. Insert a missing key by appending it and recording its index. To delete x at i, move the last key to i, update that key’s map entry, pop the last slot and remove x from the map. Choose a uniform random index for get-random; report empty if no key is stored. Hashing gives expected costs and array resizing gives amortised costs, assuming bounded load and constant-size records.

Question 36 · hard

Design a cache that holds at most k items and evicts the least recently used one, with get and put both in O(1).

In simpler words: Evict the item that has gone longest without a recent use.

Starting hint: Use a hash map to find an item and a linked list to record recency.

Answer & reasoning
Step by step
  1. The list front is most recent; the back is least recent. Map each key directly to its list node.
  2. For a successful get or an update, detach the node and move it to the front using its two links.
  3. For a new item at capacity, remove the back node and its map entry. Hash lookup is expected O(1); list changes are O(1). Define the k=0 case as storing nothing.

Use a doubly linked list ordered by recency and a hash map from keys to nodes. Get moves a found node to the front. Put inserts or updates at the front; if capacity is exceeded, unlink the tail and remove its map entry. Pointer changes are worst-case O(1); the combined operations are expected O(1) with suitable hashing, not a universal worst-case guarantee.

Question 37 · hard

Show that no comparison-based dictionary can support both insert and delete-minimum in o(log n) worst-case time each.

In simpler words: Use a hypothetical faster dictionary to build an impossibly fast sort.

Starting hint: Insert everything, then repeatedly remove the smallest.

Answer & reasoning
Step by step
  1. Little-o(log n) means a cost whose ratio to log n tends to zero, not just a small constant factor.
  2. If both operations had that worst-case cost, n insertions and n removals would use o(n log n) comparisons.
  3. The removals print sorted order. This contradicts the comparison-sorting lower bound, so the two assumed bounds cannot both hold.

Otherwise, insert n distinct keys and delete the minimum n times to sort them using o(n log n) comparisons in total. This contradicts the comparison-sorting lower bound. Thus both operations cannot simultaneously have o(log n) worst-case cost. The claim concerns this pair of operations, not every dictionary operation individually.

Lecture 5 · Binary trees and binary search trees

İkili ağaçlar ve ikili arama ağaçları

A binary tree is a rooted tree in which every node has at most two children, distinguished as the left child and the right child. A binary search tree (BST) is a binary tree with one extra rule, the search-tree property: for every node x, every key in x’s left subtree is smaller than x’s key, and every key in x’s right subtree is larger.

İkili ağaç, her düğümün sol çocuk ve sağ çocuk olarak ayrılan en fazla iki çocuğa sahip olduğu köklü bir ağaçtır. İkili arama ağacı (BST), ek bir kurala, arama ağacı özelliğine, sahip ikili ağaçtır: her x düğümü için x’in sol alt ağacındaki her anahtar x’in anahtarından küçük, sağ alt ağacındaki her anahtar ise büyüktür.

A node is stored as:

Bir düğüm şöyle saklanır:

node:
    item      (the key and data)
    left      (pointer to left child, or NULL)
    right     (pointer to right child, or NULL)
    parent    (pointer to parent; optional, since a stack of visited nodes can play the same role)
node:
    item      (anahtar ve veri)
    left      (sol çocuğa işaretçi veya NULL)
    right     (sağ çocuğa işaretçi veya NULL)
    parent    (ebeveyne işaretçi; isteğe bağlıdır, çünkü ziyaret edilen
               düğümlerden oluşan bir yığın aynı görevi üstlenebilir)

The search-tree property tells you where any key must be. Standing at a node, compare the key you want with the node’s key: smaller means go left, larger means go right, equal means found.

Arama ağacı özelliği, bir anahtarın nerede bulunması gerektiğini söyler. Bir düğümdeyken aradığınız anahtarı düğümün anahtarıyla karşılaştırın: küçükse sola gidin, büyükse sağa gidin, eşitse buldunuz.

Lecture 5 · Searching

Arama

search_tree(node, x):
    if node is NULL: return NULL          (not in the tree)
    if x == node.item: return node        (found)
    if x < node.item: return search_tree(node.left, x)
    else: return search_tree(node.right, x)
search_tree(node, x):
    if node is NULL: return NULL          (ağaçta yok)
    if x == node.item: return node        (bulundu)
    if x < node.item: return search_tree(node.left, x)
    else: return search_tree(node.right, x)

This works because the left and right subtrees of a BST are themselves BSTs: a recursive structure invites a recursive algorithm. Each step moves one level down, so the cost is proportional to the height h of the tree: O(h).

Bu yöntem çalışır; çünkü bir BST’nin sol ve sağ alt ağaçlarının kendileri de BST’dir: özyinelemeli bir yapı, özyinelemeli bir algoritmayı davet eder. Her adım bir düzey aşağı ilerler; dolayısıyla maliyet ağacın h yüksekliğiyle orantılıdır: O(h).

Lecture 5 · Minimum, maximum, predecessor, successor

Minimum, maksimum, öncül, ardıl

The smallest key is found by starting at the root and walking left until you cannot go left any more. The largest is found by walking right. Both cost O(h).

En küçük anahtar, kökten başlayıp daha fazla sola gidilemeyene kadar sola ilerleyerek bulunur. En büyük anahtar sağa ilerleyerek bulunur. İkisinin maliyeti de O(h)’dir.

The predecessor of a node x (the next smaller key) and the successor (the next larger key):

Bir x düğümünün öncülü (bir sonraki küçük anahtar) ve ardılı (bir sonraki büyük anahtar):

If x has a left child, its predecessor is the maximum of its left subtree. Symmetrically, if x has a right child, its successor is the minimum of its right subtree.

x’in sol çocuğu varsa öncülü, sol alt ağacının maksimumudur. Simetrik olarak, x’in sağ çocuğu varsa ardılı, sağ alt ağacının minimumudur.

If x has no left child, its predecessor is the nearest ancestor from which you last turned right on the way down to x (its “first left ancestor”). The successor of a node with no right child is found the mirror-image way.

x’in sol çocuğu yoksa öncülü, x’e doğru inerken son kez sağa döndüğünüz en yakın atasıdır (“ilk sol atası”). Sağ çocuğu olmayan bir düğümün ardılı, bunun ayna görüntüsü olan yöntemle bulunur.

Why these rules are right becomes obvious from the in-order traversal below.

Bu kuralların neden doğru olduğu, aşağıdaki kök-ortada dolaşımdan açıkça anlaşılır.

Lecture 5 · In-order traversal: visiting every key in sorted order

Kök-ortada dolaşım: bütün anahtarları sıralı olarak ziyaret etme

traverse(node):
    if node is not NULL:
        traverse(node.left)
        process(node.item)
        traverse(node.right)
traverse(node):
    if node is not NULL:
        traverse(node.left)
        process(node.item)
        traverse(node.right)

“Left subtree, then me, then right subtree” visits the keys in sorted order, because everything in the left subtree is smaller than the node and everything in the right subtree is larger. It spends O(1) at each of the n nodes, so it costs O(n). Predecessor and successor are simply the nodes visited immediately before and after x in this traversal.

“Sol alt ağaç, sonra ben, sonra sağ alt ağaç” düzeni, anahtarları sıralı olarak ziyaret eder; çünkü sol alt ağaçtaki her şey düğümden küçük, sağ alt ağaçtaki her şey büyüktür. n düğümün her birinde O(1) zaman harcar; toplam maliyet O(n)’dir. Öncül ve ardıl, bu dolaşımda x’ten hemen önce ve hemen sonra ziyaret edilen düğümlerdir.

Lecture 5 · Insertion

Ekleme

Do a search for the new key. The search ends at a NULL pointer, which is exactly where the key belongs. Replace that NULL with a new node. Cost O(h), like a search.

Yeni anahtarı arayın. Arama, anahtarın tam olarak ait olduğu yerdeki bir NULL işaretçisinde sona erer. Bu NULL’ı yeni bir düğümle değiştirin. Maliyet, aramada olduğu gibi O(h)’dir.

insert_tree(node_link, x, parent):
    if node_link is NULL:
        create a new node holding x, with no children, parent = parent
        make node_link point to it
        return
    if x < node.item: insert_tree(node.left, x, node)
    else: insert_tree(node.right, x, node)
insert_tree(node_link, x, parent):
    if node_link is NULL:
        x'i tutan, çocuksuz ve parent = parent olan yeni bir düğüm oluştur
        node_link işaretçisini bu düğüme yönlendir
        return
    if x < node.item: insert_tree(node.left, x, node)
    else: insert_tree(node.right, x, node)
Lecture 5 · Deletion: three cases

Silme: üç durum

Deletion is trickier than insertion because the doomed node may have children that must be kept:

Silme, eklemeden daha zordur; çünkü kaldırılacak düğümün korunması gereken çocukları olabilir:

The node is a leaf (no children). Just set its parent’s child pointer to NULL.

Düğüm yapraktır (çocuğu yoktur). Ebeveyninin ilgili çocuk işaretçisini NULL yapmanız yeterlidir.

The node has one child. Cut the node out by connecting its parent directly to its only child. The search-tree property survives.

Düğümün bir çocuğu vardır. Ebeveynini doğrudan tek çocuğuna bağlayarak düğümü aradan çıkarın. Arama ağacı özelliği korunur.

The node has two children. Find its successor, which is the minimum of its right subtree. That successor has at most one child (it cannot have a left child, or it would not be the minimum). Copy the successor’s key into the doomed node, then delete the successor using case 1 or 2.

Düğümün iki çocuğu vardır. Sağ alt ağacının minimumu olan ardılını bulun. Bu ardılın en fazla bir çocuğu vardır (sol çocuğu olamaz; olsaydı minimum olmazdı). Ardılın anahtarını silinecek düğüme kopyalayın, ardından 1. veya 2. durumu kullanarak ardılı silin.

The slides’ example tree (2 at the root, 1 on the left, 7 on the right, with 4 and 8 below 7 and 3, 6, 5 below 4) walks through all three: deleting the leaf 3, deleting 6 (one child, 5), and deleting 4 (two children: its successor 5 takes its place).

Slaytlardaki örnek ağaç (kökte 2, solda 1, sağda 7; 7’nin altında 4 ve 8, 4’ün altında 3, 6, 5), üçünü de adım adım gösterir: yaprak olan 3’ün silinmesi, 6’nın silinmesi (tek çocuğu 5) ve 4’ün silinmesi (iki çocuk: yerini ardılı 5 alır).

Every operation costs O(h). So the whole question of how good a BST is comes down to one thing: how tall is it?

Her işlem O(h) maliyetlidir. Dolayısıyla bir BST’nin ne kadar iyi olduğu tek bir soruya indirgenir: yüksekliği ne kadar?

Lecture 5 · Balance: the height decides everything

Denge: her şeyi yükseklik belirler

A perfectly balanced tree on n nodes has height about lg n, because each level can hold twice as many nodes as the one above (1 + 2 + 4 + … ≈ n). That would make every dictionary operation O(log n).

n düğümlü, kusursuz dengeli bir ağacın yüksekliği yaklaşık lg n’dir; çünkü her düzey bir üst düzeyin iki katı kadar düğüm tutabilir (1 + 2 + 4 + … ≈ n). Bu, her sözlük işlemini O(log n) yapardı.

But nothing forces a BST to be balanced. Insert the keys A, B, C, D in that order and each key goes to the right of the last: the “tree” is a chain of height n, and every operation degrades to O(n), no better than a linked list.

Fakat bir BST’yi dengeli olmaya zorlayan hiçbir şey yoktur. A, B, C, D anahtarlarını bu sırayla ekleyin; her anahtar bir öncekinin sağına gider. “Ağaç”, yüksekliği n olan bir zincirdir ve her işlemin maliyeti O(n)’ye kötüleşir; bağlı listeden daha iyi değildir.

Two pieces of good news:

İki iyi haber var:

If keys are inserted in random order, the expected height is Θ(log n). Half the time the new key lands nearer the middle of the range than the ends, which keeps things roughly even. The quicksort analysis in Lecture 8 makes this precise.

Anahtarlar rastgele sırayla eklenirse beklenen yükseklik Θ(log n) olur. Yeni anahtar, durumların yarısında aralığın uçlarından çok ortasına yakın düşer ve yapı kabaca dengeli kalır. Ders 8’deki hızlı sıralama analizi bunu kesinleştirir.

Keeping the tree perfectly balanced would be too expensive (inserting one key into the perfectly balanced example on the slide forces every node to move, Θ(n) work), but keeping it roughly balanced is cheap.

Ağacı kusursuz dengeli tutmak çok pahalı olurdu (slayttaki kusursuz dengeli örneğe tek anahtar eklemek her düğümün taşınmasını, yani Θ(n) iş yapılmasını gerektirir); ancak yaklaşık dengeli tutmak ucuzdur.

A balanced search tree means any tree whose height is guaranteed to stay O(log n). Insertion and deletion do a little rearranging whenever the tree gets lopsided. Red-black trees, AVL trees, 2-3 trees, splay trees and B-trees are the standard examples; the details differ, the guarantee is the same: all seven dictionary operations in O(log n) worst case. No comparison-based structure can beat Θ(log n) worst case on all of them.

Dengeli arama ağacı, yüksekliğinin O(log n) olarak kalması garanti edilen herhangi bir ağaç demektir. Ekleme ve silme, ağaç bir tarafa yığıldığında küçük düzenlemeler yapar. Kırmızı-siyah ağaçlar, AVL ağaçları, 2-3 ağaçları, splay ağaçları ve B-ağaçları standart örneklerdir. Ayrıntıları farklıdır, garantileri aynıdır: yedi sözlük işleminin tamamı en kötü durumda O(log n). Karşılaştırmaya dayalı hiçbir yapı, bütün işlemler için en kötü durumdaki Θ(log n) sınırından daha iyi olamaz.

Lecture 5 · Where the log comes from

Logaritma nereden gelir?

When an analysis produces an O(log n) term, it usually comes from one of two places: many operations on a balanced search tree used as a dictionary, or, more generally, from the idea of a balanced binary tree, splitting the items into smaller and smaller halves and doing a little work on each of log n levels. Binary search is the purest example, and it will reappear in mergesort (Lecture 8) and in many other places.

Bir analiz O(log n) terimi ürettiğinde, bu genellikle iki kaynaktan birinden gelir: sözlük olarak kullanılan dengeli bir arama ağacındaki çok sayıda işlemden veya daha genel olarak, elemanları giderek küçülen yarılara ayırıp log n düzeyin her birinde az miktarda iş yapan dengeli ikili ağaç fikrinden. İkili arama bunun en yalın örneğidir; birleştirmeli sıralamada (Ders 8) ve birçok başka yerde yeniden karşımıza çıkacaktır.

Lecture 6 · Warm-up: sorting with a dictionary

Hazırlık: sözlük kullanarak sıralama

Suppose you have a balanced dictionary where every operation costs O(log n). Three ways to sort n numbers in O(n log n), each using only a few of the operations:

Her işlemin O(log n) maliyetli olduğu dengeli bir sözlüğünüz olduğunu varsayalım. Yalnızca birkaç işlemi kullanarak n sayıyı O(n log n) sürede sıralamanın üç yolu:

Using minimum, successor, insert, search: insert all n numbers (n × O(log n)). Find the minimum, print it, then repeatedly print its successor until there is none. Each step costs O(log n), so the whole thing is O(n log n).

Minimum, ardıl, ekleme ve arama kullanarak: n sayının tamamını ekleyin (n × O(log n)). Minimumu bulun, yazdırın; ardından ardıl kalmayana kadar sürekli ardılı yazdırın. Her adım O(log n) tutar; dolayısıyla tüm işlem O(n log n)’dir.

Using minimum, insert, delete, search: insert everything, then repeatedly find the minimum, print it, and delete it. Again n rounds of O(log n).

Minimum, ekleme, silme ve arama kullanarak: her şeyi ekleyin; ardından minimumu bulup yazdırın ve silin; bunu tekrarlayın. Yine O(log n) maliyetli n tur.

Using insert and in-order traversal: insert everything, then do one in-order traversal (Lecture 5), which visits the keys in sorted order in O(n). Total O(n log n) for the insertions plus O(n) for the walk.

Ekleme ve kök-ortada dolaşım kullanarak: her şeyi ekleyin, sonra anahtarları O(n) sürede sıralı olarak ziyaret eden tek bir kök-ortada dolaşım (Ders 5) yapın. Toplam, eklemeler için O(n log n) ve dolaşım için O(n)’dir.

The point: a balanced dictionary is at least as powerful as a sorting algorithm. This will be echoed in Lecture 7, where sorting is treated as the fundamental tool.

Ana fikir: dengeli bir sözlük en az bir sıralama algoritması kadar güçlüdür. Sıralamanın temel araç olarak ele alındığı Ders 7’de bu fikir yeniden karşımıza çıkacaktır.

Lecture 6 · The idea of a hash table

Karma tablosu fikri

Looking up an array slot by its index costs Θ(1). If only every key were an index. A hash function h makes it so: it maps each key to an integer between 0 and m − 1, and the item is stored in slot h(key) of an array of size m (the table). To search for a key, compute h(key) and look in that slot.

Bir dizi gözüne indisiyle erişmek Θ(1) tutar. Keşke her anahtar bir indis olsaydı. h karma fonksiyonu bunu sağlar: her anahtarı 0 ile m − 1 arasında bir tam sayıya eşler ve eleman, m boyutlu dizinin (tablonun) h(key) gözünde saklanır. Bir anahtarı aramak için h(key)’i hesaplayın ve o göze bakın.

Lecture 6 · Collisions

Çakışmalar

Two different keys may hash to the same slot. This is a collision, and it is unavoidable: there are far more possible keys than slots. If the hash function spreads keys evenly, each slot receives only a few keys, and a few keys are easy to search through. Two standard ways to store the colliding keys:

İki farklı anahtar aynı göze karmalanabilir. Bu bir çakışmadır ve kaçınılmazdır: olası anahtar sayısı, göz sayısından çok daha fazladır. Karma fonksiyonu anahtarları dengeli dağıtırsa her göze yalnızca birkaç anahtar düşer; birkaç anahtar arasında arama kolaydır. Çakışan anahtarları saklamanın iki standart yolu vardır:

Chaining. Each slot holds a linked list of all keys hashed to it. Insert, delete and search reduce to the same operations on a short list. If n keys are spread evenly over m slots, each list has about n/m keys, so each operation costs O(n/m), which is O(1) when the table is about as big as the number of keys. The cost is memory: every item carries a pointer that could instead have been used to make the table bigger.

Zincirleme. Her göz, kendisine karmalanan bütün anahtarların bağlı listesini tutar. Ekleme, silme ve arama, kısa bir listedeki aynı işlemlere indirgenir. n anahtar m göze eşit dağılmışsa her listede yaklaşık n/m anahtar bulunur; dolayısıyla her işlem O(n/m) tutar. Tablo, anahtar sayısı kadar büyük olduğunda bu O(1)’dir. Bedeli bellektir: her eleman, yerine tabloyu büyütmek için kullanılabilecek bir işaretçi alanı taşır.

Open addressing. No pointers at all; everything lives in the array itself. If slot h(key) is taken, try another slot according to a fixed rule until a free one appears:

Açık adresleme. Hiç işaretçi yoktur; her şey dizinin kendisinde bulunur. h(key) gözü doluysa, boş bir göz bulana kadar sabit bir kurala göre başka gözleri deneyin:

Linear probing: try h, h+1, h+2, …

Doğrusal yoklama: h, h+1, h+2, … konumlarını deneyin.

Quadratic probing: try h, h+1², h+2², h+3², …

Karesel yoklama: h, h+1², h+2², h+3², … konumlarını deneyin.

Stride probing: try h, h+k, h+2k, h+3k, …

Sabit adımlı yoklama: h, h+k, h+2k, h+3k, … konumlarını deneyin.

Searching follows the same probe sequence until it finds the key or an empty slot. Deletion is ugly under open addressing: emptying a slot can break the chain of probes that leads to items inserted later, making them unreachable. (The usual fix is to mark the slot “deleted” rather than empty.)

Arama, anahtarı veya boş bir gözü bulana kadar aynı yoklama dizisini izler. Açık adreslemede silme sorunludur: bir gözü boşaltmak, sonradan eklenen elemanlara götüren yoklama zincirini koparıp bu elemanları erişilemez hâle getirebilir. (Yaygın çözüm, gözü boş bırakmak yerine “silindi” diye işaretlemektir.)

Lecture 6 · What makes a good hash function

İyi bir karma fonksiyonunun özellikleri

A good hash function is cheap to compute and uses every slot from 0 to m − 1 with about equal frequency. The usual recipe has two steps:

İyi bir karma fonksiyonunun hesaplanması ucuzdur ve 0’dan m − 1’e kadar her gözü yaklaşık eşit sıklıkla kullanır. Yaygın tarif iki adımdan oluşur:

Turn the key into a big integer. For a string, treat it as a number written in base 128 (or whatever the alphabet size is): h = Σ 128ⁱ × char(key[i]) over the characters.

Anahtarı büyük bir tam sayıya dönüştürün. Bir dizeyi 128 tabanında (veya alfabe boyutu neyse o tabanda) yazılmış sayı olarak ele alın: karakterler üzerinden h = Σ 128ⁱ × char(key[i]).

Squash that big integer into the table’s range with modular arithmetic: h(k) = k mod M, where M is the table size. M should be a large prime, and not one close to a power of two (like 2ⁱ − 1), because that would effectively ignore the high-order bits of the key.

Bu büyük tam sayıyı modüler aritmetik kullanarak tablonun aralığına sıkıştırın: h(k) = k mod M; burada M tablo boyutudur. M büyük bir asal olmalı; ikinin bir kuvvetine yakın bir asal (örneğin 2ⁱ − 1) olmamalıdır. Çünkü bu durum, anahtarın yüksek anlamlı bitlerini fiilen göz ardı eder.

The mod step works on the same principle as a roulette wheel: a large number “spins” around the wheel of M slots and lands somewhere that looks random.

mod adımı bir rulet çarkıyla aynı ilkeye dayanır: büyük bir sayı, M gözlü çarkın çevresinde “döner” ve rastgele görünen bir yere düşer.

A real example of good versus bad: hashing people by the first three digits of a US Social Security Number is bad, because those digits encode where the number was issued, so everyone from one state piles into the same slots. The last three digits are effectively random and spread evenly.

İyi ve kötü seçime gerçek bir örnek: insanları ABD Sosyal Güvenlik Numaralarının ilk üç basamağına göre karmalamak kötüdür; çünkü bu basamaklar numaranın nerede verildiğini kodlar ve aynı eyaletteki herkes aynı gözlere yığılır. Son üç basamak ise fiilen rastgeledir ve dengeli dağılır.

Lecture 6 · The birthday paradox: collisions are certain

Doğum günü paradoksu: çakışmalar kaçınılmazdır

However good the hash function, collisions come sooner than intuition expects. The probability of no collision after n insertions into a table with m slots is

n−1∏i=0 m − im = mm · m − 1m ⋯ m − n + 1m

Karma fonksiyonu ne kadar iyi olursa olsun, çakışmalar sezgimizin beklediğinden daha erken ortaya çıkar. m gözlü bir tabloya n eklemeden sonra hiç çakışma olmama olasılığı şöyledir:

With m = 366 (birthdays), this probability drops below 1/2 at n = 23 and is essentially 0 by n = 50. Put 23 people in a room and it is more likely than not that two share a birthday. So a hash table must always be prepared to handle collisions; the question is only how well.

m = 366 (doğum günleri) için bu olasılık n = 23’te 1/2’nin altına düşer; n = 50’de ise neredeyse 0’dır. Bir odaya 23 kişi koyduğunuzda, iki kişinin aynı doğum gününe sahip olması, olmamasından daha olasıdır. Dolayısıyla bir karma tablosu her zaman çakışmaları ele almaya hazır olmalıdır; soru yalnızca bunu ne kadar iyi yaptığıdır.

In practice a hash table is usually the best way to maintain a dictionary. Its weakness is the unpredictable worst case: an adversary who knows the hash function, or just bad luck, can force everything into one slot. When a guaranteed bound is required, balanced binary trees (Lecture 5) win. Skiena’s rule: use hashing for everything, except worst-case analysis.

Uygulamada sözlük tutmanın en iyi yolu genellikle karma tablosudur. Zayıf noktası, öngörülemez en kötü durumudur: karma fonksiyonunu bilen bir hasım veya yalnızca kötü şans, her şeyi tek göze yığabilir. Garanti edilmiş bir sınır gerektiğinde dengeli ikili ağaçlar (Ders 5) üstün gelir. Skiena’nın kuralı: en kötü durum analizi dışında her şey için karmalama kullanın.

Lecture 6 · Hashing beyond dictionaries

Sözlüklerin ötesinde karmalama

Udi Manber, then head of engineering at Google, said the three most important algorithms at Google are “hashing, hashing, and hashing”. A hash code is a short, distinctive fingerprint of a large object, which enables tricks like:

O dönemde Google’ın mühendislikten sorumlu yöneticisi olan Udi Manber, Google’daki en önemli üç algoritmanın “karmalama, karmalama ve karmalama” olduğunu söylemiştir. Karma kodu, büyük bir nesnenin kısa ve ayırt edici parmak izidir; şu tür yöntemleri mümkün kılar:

Is this document new? Hash it and compare against the hash codes of every document in the collection, instead of comparing full texts.

Bu belge yeni mi? Tam metinleri karşılaştırmak yerine belgenin karma kodunu hesaplayıp koleksiyondaki her belgenin karma koduyla karşılaştırın.

Is part of this document plagiarised? Hash every window of w consecutive words in both the document and the collection. Matching hash codes flag a possible copied passage.

Bu belgenin bir kısmında intihal var mı? Hem belgedeki hem koleksiyondaki ardışık w sözcüklük her pencerenin karma kodunu hesaplayın. Eşleşen karma kodları, kopyalanmış olabilecek bir bölümü işaretler.

Has this file been tampered with? Keep the cryptographic hash of the original; any change to the file changes the hash.

Bu dosya değiştirilmiş mi? Özgün dosyanın kriptografik özetini saklayın; dosyadaki herhangi bir değişiklik özeti değiştirir.

Bucketing by a canonical form. Hash each word by its sorted letters (skiena → aeikns): now anagrams like dog and god collide on purpose, and “which five letters make the most words?” becomes a question about the biggest bucket. Proximity-preserving hash functions extend the idea to put similar items in the same bucket.

Kanonik biçime göre kovalama. Her sözcüğü sıralanmış harflerine göre karmalayın (skiena → aeikns). Artık dog ve god gibi anagramlar kasıtlı olarak çakışır; “hangi beş harf en çok sözcüğü oluşturur?” sorusu, en büyük kovaya ilişkin bir soruya dönüşür. Yakınlığı koruyan karma fonksiyonları bu fikri genişleterek benzer elemanları aynı kovaya yerleştirir.

Lecture 6 · Rabin-Karp: string matching with hashing

Rabin–Karp: karmalama ile dize eşleştirme

The substring matching problem: given a text t of length n and a pattern p of length m, does p occur inside t, and where? (Skiena’s example: is “Skiena” in the Bible?)

Alt dize eşleştirme problemi: uzunluğu n olan t metni ve uzunluğu m olan p örüntüsü verildiğinde, p, t’nin içinde bulunur mu; bulunuyorsa nerede? (Skiena’nın örneği: Kutsal Kitap’ta “Skiena” geçiyor mu?)

Brute force slides the pattern along the text, one position at a time, and compares it character by character at each position: O(nm).

Kaba kuvvet, örüntüyü metin boyunca birer konum kaydırır ve her konumda karakter karakter karşılaştırır: O(nm).

The hashing idea. Compute the hash of p, and the hash of each m-character window of t. If two strings are identical their hashes are identical; if they differ, their hashes almost certainly differ. So only compare characters when the hashes agree, which should be rare (a false alarm costs O(m) to dismiss).

Karmalama fikri. p’nin ve t’nin m karakterlik her penceresinin karma değerini hesaplayın. İki dize özdeşse karma değerleri özdeştir; farklılarsa karma değerleri de neredeyse kesin olarak farklıdır. Bu nedenle yalnızca karma değerleri eşleştiğinde karakterleri karşılaştırın; bunun nadiren olması beklenir (yanlış alarmı elemek O(m) tutar).

The catch. There are n − m + 1 windows, and hashing an m-character window costs O(m). That is O(nm) again.

Pürüz. n − m + 1 pencere vardır ve m karakterlik bir pencereyi karmalamak O(m) tutar. Yine O(nm).

The trick: rolling hashes. Write the hash of the window starting at position j as

H(S, j) = m−1∑i=0 αm−(i+1) × char(si+j)

Püf noktası: kayan karma değerleri (rolling hashes). j konumunda başlayan pencerenin karma değerini şöyle yazın:

Sliding the window one step right drops the first character and appends a new one, and a little algebra shows

H(S, j+1) = (H(S, j) − αm−1 char(sj)) α + char(sj+m)

So from one window’s hash you get the next window’s hash with two multiplications, one subtraction and one addition: O(1). All n windows are hashed in O(n), and the whole search runs in expected O(n + m).

Böylece bir pencerenin karma değerinden sonrakini iki çarpma, bir çıkarma ve bir toplamayla elde edersiniz: O(1). n pencerenin tamamının karma değeri O(n) sürede hesaplanır ve bütün arama beklenen O(n + m) sürede çalışır.
