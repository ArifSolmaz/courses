Week 05 / 14 · Sorted tables and hash lookup

How do I look things up fast?

15 min · Engineering question

The robot gets a fault code and must retrieve its response. A static sorted table supports exact lookup and ordered queries. A hash table is convenient for exact keys when memory and lookup variation are acceptable.

Make an individual prediction, then compare with a partner. Write down the input, measurement unit or limit you would need to make the decision.

Trace it on paper

Insert codes 7, 12 and 17 into five empty slots using code mod 5 and linear probing. Then look up 17 and the absent code 22. Compare with binary search in the sorted table [7, 12, 17].

Write your trace first. Compare your steps, then explain why the method works in three sentences.

Check your trace

All three keys start at slot 2. They occupy slots 2, 3 and 4. A lookup for 17 probes three slots. A lookup for 22 continues to empty slot 0, after four probes. This example has no deletion. A hash table needs spare slots and collisions can increase work.

Trace a collision and an unsuccessful lookup

Put keys 2, 9 and 16 into a seven-slot table using key mod 7 and linear probing. Trace lookup of 16 and lookup of the missing key 23. No entries have been deleted.

Show the worked steps
  1. All three start at slot 2. Keys 2, 9 and 16 settle in slots 2, 3 and 4 respectively.
  2. Lookup of 16 inspects three slots. Lookup of 23 inspects those three and then the empty slot 5.
  3. If key 9 were erased by clearing slot 3, searching for 16 would stop early. A deletion-aware open-addressing table needs tombstones or a rule for reorganizing the cluster.

Compare the two traces. Record one boundary case and a clue that would expose a wrong result. Then take a 10-minute break.

45 min

Measure it

Predict which method will be quicker for repeated exact queries. Time a binary lookup and a Python dictionary lookup at both sizes. Prepare the structures before timing. Compare memory separately if choosing for a small controller.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

def lower_bound(values, key):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = (lo + hi) // 2
        if values[mid] < key:
            lo = mid + 1
        else:
            hi = mid
    return lo

def exact_lookup(values, key):
    index = lower_bound(values, key)
    if index < len(values) and values[index] == key:
        return values[index]
    return None


for n in (100, 1000):
    values = list(range(n))
    table = {value: value for value in values}
    keys = [n // 2, n]

    def binary_queries():
        return [exact_lookup(values, key) for key in keys]

    def hash_queries():
        return [table.get(key) for key in keys]

    assert binary_queries() == hash_queries()
    measure(f"{n}: binary pair", binary_queries)
    measure(f"{n}: hash pair", hash_queries)

45 min

Choose a fault table for deployment

The robot stores 120 fixed fault codes and updates the table only at boot. The team needs exact-code queries, a printable sorted list and an alarm when an unknown code arrives.

Start individually for 10 minutes. Work with a partner for 20. Spend the last 15 comparing with another pair and revising your recommendation.

  1. Design an interface with an explicit missing result and test a hit, an interior miss and a code above the maximum.
  2. Compare a sorted array of code–message pairs with a hash table. Explain setup cost, lookup behavior, space use and the work needed to print in order.
  3. Propose a benchmark for the target controller. Include a workload that could expose poor hashing and a way to estimate memory use.
Compare a model answer

A sorted array supports ordered output and bounded logarithmic search on static data. A hash table is convenient for exact queries but its overhead and collision handling depend on the implementation. Use a clear missing result, measure hit and miss workloads separately, and compare worst observed lookup costs and memory on the target.

More practice

  1. What is 17 mod 5?

    Show answer

    2.

  2. Why do 7 and 12 collide?

    Show answer

    Both produce starting slot 2.

  3. What key does exact lookup of 13 in [7, 12, 17] return?

    Show answer

    No match. Its insertion index alone is insufficient.

  4. What happens when many keys hash to the same slot?

    Show answer

    Probe sequences get longer.

  5. Does a single fast dictionary lookup guarantee a tight deadline?

    Show answer

    No. Consider collisions, possible resizing, and the target implementation.
