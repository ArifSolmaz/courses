Week 08 / 14 · Breadth-first search on an occupancy grid

What route uses the fewest moves?

15 min · Engineering question

A robot needs to reach a charging station without crossing obstacles. How can it find a route with the fewest moves, instead of guessing a direction and hoping it works? We will explore nearby cells first, using the FIFO queue you already know.

Read the concept and worked example first. Then make an individual prediction and compare it with a partner.

Start with a map, not with code

First use a free 2 × 2 grid. S is the start and G is the charging station. A dot is a free cell. The robot moves one cell up, right, down or left; diagonal movement is not allowed. Every legal move counts as one step.

Predict: How many moves are needed? Right then down takes two. Down then right also takes two. There can be more than one shortest route. One diagonal would be shorter, but it is not a legal move in this model.

Remember Week 4 · FIFO gives the oldest waiting entry first

After adding A, B and C, a FIFO removes A and leaves [B, C]. Add D and it becomes [B, C, D]. BFS uses this exact rule: process cells already waiting before cells just discovered. In Python, deque.append adds at the back and deque.popleft removes from the front without shifting the whole list.

The frontier is the queue of discovered cells waiting to be processed. A cell is discovered when we first record and enqueue it. It is expanded when we examine its neighbors. We test for the goal immediately after popping, so the goal is counted as popped but its neighbors are not expanded.

  1. Mark S and enqueue it. Its distance is 0 and its parent is None.
  2. Remove the oldest queued cell. If it is G, reconstruct the route and stop.
  3. Inspect neighbors in up, right, down, left order. Reject out-of-bounds, blocked and already discovered cells.
  4. For each new legal neighbor, record its parent, assign distance current distance + 1, then enqueue it.
  5. Continue until G is popped or the queue is empty.
Could we stop when G is first discovered?

Yes. Checking the goal at discovery is also correct for equal-cost BFS when implemented consistently, with a separate start-equals-goal check. We use pop-time stopping throughout this lesson so the traces and counts agree.

Why FIFO finds the fewest moves

S is at distance 0. Its neighbors enter at distance 1. When a distance-1 cell is processed, its new neighbors join the back at distance 2, behind the remaining distance-1 cells. This repeats at every layer. A longer route cannot reach a cell before all shorter-distance layers have been considered.

Remember Week 7 · Why not use last week’s heap?

A min-heap selected time 4 before times 7 and 9, regardless of insertion order. In equal-cost BFS, FIFO already keeps discovery distances in nondecreasing order: 0, then 1, then 2. A heap is unnecessary for this distance ordering. If entering one cell costs 9 and another costs 1, fewer moves may not mean lower total cost; that leads to Dijkstra in Week 9.

Why mark on enqueue?

In the 2 × 2 example, both (0,1) and (1,0) can reach G. The first records G before enqueueing it. When the other sees G, membership in parents says it is already discovered. Without that early mark, both can queue G before its first copy is popped.

Remember Week 5 · One dictionary, two useful jobs

A dictionary such as {"E02": "Check sensor"} maps an exact key to a response. BFS uses coordinates as keys: parents[(1,1)] = (0,1). This tells us who discovered (1,1). The check (1,1) in parents also tells us it has already been discovered. A separate visited set is not needed in this implementation.

A BFS parent is not a heap parent

In Week 7, a parent was defined by the heap’s array index. Here, a parent is the previous cell on the discovery route. We do not use (i − 1) // 2 to reconstruct a grid route.

Follow parents backward: G (1,1) → (0,1) → S (0,0). Reverse the sequence to get [(0,0), (0,1), (1,1)]. Three cells make two moves: moves = number of path cells − 1.

Remember Week 1 · Stop at the right condition

Searching [33, 20, 17, 12] for the first value below 20 stopped at 17. BFS also has a stopping condition, but FIFO’s layer order is what makes the first goal shortest in moves. If S = G, the route is [S] and has zero moves. If the queue empties without G, return no route, not zero moves.

Show the worked steps

Trace a detour visually

What if (2,1) becomes blocked?

Block (2,1). Only (0,0), (1,0) and (2,0) are reachable from S. After those three pops, the queue empties. Return no route. Do not return the partial explored corridor as a successful path.

Common mistakes

  • Marking visited only on pop and duplicating queue entries.
  • Counting cells on a path as moves.
  • Using BFS to minimize unequal terrain costs.
  • Treating a BFS parent like a heap index parent. It is the previous route cell.
  • Equating popped cells with route moves. BFS also explores branches not used in the final path.
  • Treating a blocked start as a zero-move route. Validate endpoints first.

First Python example: a two-move route

Before running the timing lab, run this small example. For this first version, assume a nonempty grid and valid, free start and goal coordinates. The laboratory version checks these inputs.

from collections import deque

def shortest_route(grid, start, goal):
    directions = [(-1, 0), (0, 1), (1, 0), (0, -1)]
    queue = deque([start])
    parents = {start: None}

    while queue:
        cell = queue.popleft()
        if cell == goal:
            path = []
            while cell is not None:
                path.append(cell)
                cell = parents[cell]
            path.reverse()
            return len(path) - 1, path

        row, col = cell
        for dr, dc in directions:
            neighbor = (row + dr, col + dc)
            r, c = neighbor
            if (0 <= r < len(grid)
                    and 0 <= c < len(grid[r])
                    and grid[r][c] != "#"
                    and neighbor not in parents):
                parents[neighbor] = cell
                queue.append(neighbor)

    return None, []

grid = ("S.", ".G")
moves, path = shortest_route(grid, (0, 0), (1, 1))
print("Moves:", moves)
print("Path:", path)
assert moves == 2
assert path == [(0, 0), (0, 1), (1, 1)]

A short route can require a large search

Remember Week 2 · Count what the algorithm actually visits

A single scan of 8 items makes 8 visits; 16 items make 16 visits. For BFS, count reachable vertices and their adjacency checks, not only path cells. Each discovered cell enters once and leaves at most once. A four-neighbor cell has at most four candidate directions.

With adjacency lists or generated neighbors, BFS takes O(V + E) time and O(V) auxiliary space in the worst case, assuming expected constant-time dictionary operations. V counts graph vertices and E edges. On a four-neighbor grid, E is O(V), so the search is linear in the number of cells it may visit.

Three different counts

On the 25 × 25 open map in the lab, the route has 6 moves but 73 cells are popped with our neighbor order and pop-time stopping rule. BFS also explores other directions in each layer. A narrow corridor can have fewer alternatives even when its final route is longer.

Make memory concrete

Suppose a compact implementation reserves one discovery byte and a four-byte parent index for each of 10,000 cells: 50,000 bytes. Reserving up to 10,000 four-byte queue entries adds 40,000 bytes: 90,000 bytes before the map and other overhead. These are explicit storage assumptions, not Python object sizes. Python tuples, dictionaries and deque entries need additional space.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call. The pop count includes the goal. BFS uses a FIFO queue; there are no heap entries here.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

from collections import deque

DIRECTIONS = [(-1, 0), (0, 1), (1, 0), (0, -1)]


def neighbors(grid, cell):
    row, col = cell
    for dr, dc in DIRECTIONS:
        r, c = row + dr, col + dc
        if 0 <= r < len(grid) and 0 <= c < len(grid[r]) and grid[r][c] != "#":
            yield r, c


def entry_cost(grid, cell):
    row, col = cell
    symbol = grid[row][col]
    return int(symbol) if symbol.isdigit() else 1


def result(grid, parents, goal, popped):
    path = [goal]
    while parents[path[-1]] is not None:
        path.append(parents[path[-1]])
    path.reverse()
    return len(path) - 1, sum(entry_cost(grid, cell) for cell in path[1:]), popped, path

def validate_endpoints(grid, start, goal):
    if not grid or not grid[0]:
        raise ValueError("Grid must be nonempty")
    width = len(grid[0])
    if any(len(row) != width for row in grid):
        raise ValueError("Grid must be rectangular")
    for row, col in (start, goal):
        if not (0 <= row < len(grid) and 0 <= col < width):
            raise ValueError("Endpoint outside grid")
        if grid[row][col] == "#":
            raise ValueError("Endpoint is blocked")

def bfs(grid, start, goal):
    validate_endpoints(grid, start, goal)
    queue = deque([start])
    parents = {start: None}
    popped = 0
    while queue:
        cell = queue.popleft()
        popped += 1
        if cell == goal:
            return result(grid, parents, goal, popped)
        for neighbor in neighbors(grid, cell):
            if neighbor not in parents:
                parents[neighbor] = cell
                queue.append(neighbor)
    return None, None, popped, []

def check_path(grid, start, goal, moves, cost, path):
    if moves is None:
        assert cost is None and path == []
        return
    assert path[0] == start and path[-1] == goal
    assert moves == len(path) - 1
    for row, col in path:
        assert 0 <= row < len(grid)
        assert 0 <= col < len(grid[row])
        assert grid[row][col] != "#"
    for (r1, c1), (r2, c2) in zip(path, path[1:]):
        assert abs(r1 - r2) + abs(c1 - c2) == 1
    assert cost == sum(entry_cost(grid, cell) for cell in path[1:])

maps = [
    (('S999G', '.###.', '.....'), (0, 0), (0, 4)),
    (["." * 25] * 25, (12, 12), (12, 18)),
]

planners = [("BFS", bfs)]

for grid, start, goal in maps:
    for name, planner in planners:
        def job():
            return planner(grid, start, goal)

        moves, cost, popped, path = job()
        check_path(grid, start, goal, moves, cost, path)
        print(name, "-> (moves, terrain cost, popped):", (moves, cost, popped))
        print("Path:", path)
        measure(name, job, repeats=30)

The measured call includes endpoint validation, the BFS search, route reconstruction and terrain-cost reporting. Grid construction stays outside the measurement. This is a measurement of the complete planner function, not only its queue operations.

Compare a model answer

The near exit is reached in two moves. With it blocked, the far exit is reached in five by following the top row to column 3 and moving down twice. Use membership in a goal set at the pop step. An empty goal set can immediately report no route. Check the path’s move count as well as its endpoints.

Adapt the stopping condition

Store valid free exits in a set. In the BFS loop, replace the single-goal equality check with membership. Reconstruct from the exit actually popped, not from a fixed goal variable. If the goal set is empty, return no route immediately.

if cell in goals:
    return result(grid, parents, cell, popped)

This is the replacement stopping fragment for the lab’s BFS, not a standalone program. When a pallet blocks (2,0), mark that map cell as # and remove it from the valid goal set.
