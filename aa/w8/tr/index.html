Bunu neden bilmeliyiz?Why should we know this?

Robotunuzun kontrol döngüsü saniyede 100 kez çalışıyorsa her turda 10 milisaniyeniz vardır. Rota hesabı bu süreye sığmazsa robot ya durur ya da eski bilgiyle hareket eder. Bir yöntemin bugün hızlı çalışması yetmez; sensör verisi ya da harita on kat büyüdüğünde ne olacağını önceden bilmeniz gerekir. Algoritma analizi bu tahmini yapmanın yoludur.

If your robot's control loop runs 100 times a second, you have 10 milliseconds per cycle. If route planning does not fit, the robot either stalls or moves on stale information. It is not enough that a method is fast today; you need to know in advance what happens when the sensor data or the map grows tenfold. Algorithm analysis is how you make that prediction.

Halka yöntemiThe ripple method

Suya taş atınca halkalar her yöne aynı hızla yayılır ve bir noktaya her zaman en kısa yoldan ulaşır. Aynısını haritada yapın.

Drop a stone in water and the ripple spreads at the same speed in every direction, reaching each point by the shortest way. Do the same on the map.

  1. R hücresine 0 yazın.
  2. 0'ın boş komşularına 1 yazın.
  3. 1'lerin henüz sayı yazılmamış boş komşularına 2 yazın.
  4. S hücresine sayı yazılana kadar böyle sürdürün.
  1. Write 0 in cell R.
  2. Write 1 in the empty neighbours of 0.
  3. Write 2 in the empty neighbours of the 1s that have no number yet.
  4. Keep going until cell S gets a number.

İki kural: sayı yazılmış bir hücreye bir daha yazılmaz, duvara yazılmaz.

Two rules: never write in a cell that already has a number, and never write in a wall.

Bilgisayar halkaları hangi sırayla yazar?In what order does a computer write the ripples?

Siz haritaya bakıp bütün 1'leri bir anda görürsünüz; bilgisayar her seferinde tek bir hücreye bakabilir. Bu yüzden sırası gelen hücreleri bir kuyrukta tutar. Kuyruk yemekhane sırası gibidir: yeni gelen sona eklenir, en önce gelen önce çıkar. Böylece 1'ler bitmeden 2'lere geçilmez.

You look at the map and see all the 1s at once; a computer can look at only one cell at a time. So it keeps the cells waiting their turn in a queue. A queue works like a cafeteria line: newcomers join the back, whoever came first leaves first. That way the 2s never start before the 1s are finished.

Hücreleri (satır, sütun) olarak yazıyoruz; sol üst köşe (0, 0). Komşulara hep aynı sırayla bakın: yukarı, sağ, aşağı, sol. İlk dört satır dolduruldu; sonraki dördünü siz doldurun.

Cells are written as (row, column); the top-left corner is (0, 0). Always check neighbours in the same order: up, right, down, left. The first four rows are filled in; do the next four yourself.

Bölüm 3: Kısa kodPart 3: Short code

Kod, kâğıtta çizdiğiniz halkaların aynısıdır. Kodu siz yazmayacaksınız; hazır alıp okuyacak, çıktısını tahmin edecek ve değiştireceksiniz.

The code is the same ripple you drew on paper. You will not write it; you will take it ready-made, read it, predict its output and change it.

from collections import deque

harita = [
    "R..#.",
    ".#.#.",
    ".#...",
    "..#.#",
    "#...S",
]

def en_kisa_hamle(harita, baslangic, hedef):
    kuyruk = deque([baslangic])        # sırası gelen hücreler
    uzaklik = {baslangic: 0}           # hücrelere yazdığımız sayılar
    while kuyruk:
        r, c = kuyruk.popleft()        # sıranın başındakini al
        if (r, c) == hedef:
            return uzaklik[(r, c)]
        for dr, dc in [(-1, 0), (0, 1), (1, 0), (0, -1)]:
            yr, yc = r + dr, c + dc
            if 0 <= yr < len(harita) and 0 <= yc < len(harita[0]):
                if harita[yr][yc] != "#" and (yr, yc) not in uzaklik:
                    uzaklik[(yr, yc)] = uzaklik[(r, c)] + 1
                    kuyruk.append((yr, yc))   # sıranın sonuna ekle
    return None                        # yol yok

print(en_kisa_hamle(harita, (0, 0), (4, 4)))
from collections import deque

grid = [
    "R..#.",
    ".#.#.",
    ".#...",
    "..#.#",
    "#...S",
]

def fewest_moves(grid, start, goal):
    queue = deque([start])             # cells waiting their turn
    dist = {start: 0}                  # the numbers we write in cells
    while queue:
        r, c = queue.popleft()         # take the one at the front
        if (r, c) == goal:
            return dist[(r, c)]
        for dr, dc in [(-1, 0), (0, 1), (1, 0), (0, -1)]:
            nr, nc = r + dr, c + dc
            if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
                if grid[nr][nc] != "#" and (nr, nc) not in dist:
                    dist[(nr, nc)] = dist[(r, c)] + 1
                    queue.append((nr, nc))    # join the back of the line
    return None                        # no route

print(fewest_moves(grid, (0, 0), (4, 4)))

Kâğıtta S'den geriye, her adımda bir küçük sayıya giderek yürümüştünüz. Kod da aynısını yapar. Önce halkaları bütün haritaya yayan, sonra geri yürüyen iki kısa fonksiyon:

On paper you walked back from S, moving to a number one smaller at each step. The code does the same. Two short functions: one spreads the ripple over the whole map, the other walks back.

YONLER = [(-1, 0), (0, 1), (1, 0), (0, -1)]

def halkalari_yay(harita, baslangic):
    kuyruk = deque([baslangic])
    uzaklik = {baslangic: 0}
    while kuyruk:
        r, c = kuyruk.popleft()
        for dr, dc in YONLER:
            yr, yc = r + dr, c + dc
            if 0 <= yr < len(harita) and 0 <= yc < len(harita[0]):
                if harita[yr][yc] != "#" and (yr, yc) not in uzaklik:
                    uzaklik[(yr, yc)] = uzaklik[(r, c)] + 1
                    kuyruk.append((yr, yc))
    return uzaklik

def rota_bul(uzaklik, hedef):
    rota = [hedef]
    r, c = hedef
    while uzaklik[(r, c)] > 0:
        for dr, dc in YONLER:
            komsu = (r + dr, c + dc)
            if uzaklik.get(komsu) == uzaklik[(r, c)] - 1:
                r, c = komsu
                rota.append(komsu)
                break
    return rota[::-1]              # ters çevir: baştan sona

uzaklik = halkalari_yay(harita, (0, 0))
print(rota_bul(uzaklik, (4, 4)))

def spread_ripple(grid, start):

            if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
                if grid[nr][nc] != "#" and (nr, nc) not in dist:
                    dist[(nr, nc)] = dist[(r, c)] + 1
                    queue.append((nr, nc))
    return dist

def find_route(dist, goal):
    route = [goal]
    r, c = goal
    while dist[(r, c)] > 0:
        for dr, dc in MOVES:
            nb = (r + dr, c + dc)
            if dist.get(nb) == dist[(r, c)] - 1:
                r, c = nb
                route.append(nb)
                break
    return route[::-1]             # reverse: start to goal

dist = spread_ripple(grid, (0, 0))
print(find_route(dist, (4, 4)))

The output is a list of 9 cells: 8 moves, 9 cells. If there is no route to the goal, find_route raises an error; check goal in dist first.

Bu yöntemin işi nasıl büyür?How does this method's work grow?

Her hücre kuyruğa en fazla bir kez girer ve çıkarıldığında 4 komşusuna bakılır. Demek ki iş, hücre sayısıyla orantılıdır: hücre sayısı iki katına çıkarsa iş de yaklaşık iki katına çıkar. Bu, kart aramayla aynı davranıştır. Dikkat edilecek nokta: haritanın kenarı iki katına çıkarsa hücre sayısı dört katına çıkar. Baştaki canlı haritada 5×5, 8×8, 12×12 ve 20×20 seçip "işlenen hücre" sayısını karşılaştırın.

Each cell enters the queue at most once, and when it is removed its 4 neighbours are checked. So the work is proportional to the number of cells: double the cells and the work roughly doubles. That is the card-search behaviour. One thing to watch: doubling the side of the map quadruples the number of cells. On the live map at the top, pick 5×5, 8×8, 12×12 and 20×20 and compare the "cells processed" count.
