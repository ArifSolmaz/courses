01 · From order to relationships

ID order
does not describe connections.

In Week 7 we sorted the directory by ID. The array [4, 7, 11, 18, 20, 24, 26, 31] does not tell us which devices can communicate directly. We will now provide the same devices’ direct connections separately.

What are we minimising in this task?

A line represents a connection that can be used in both directions. Each crossing is one step; there are no time or price weights. There are no lines from a device to itself or repeated edges. This is an undirected, simple, unweighted graph.

Output: for every device reachable from 18, the minimum number of edges and one example path. We are not calculating kilometres, latency or a cheapest weighted path. The starting device’s distance to itself is 0.

State the distinction first

Should device 7 always be selected before 24? Does being in the directory mean that a device is reachable through this network?

Compare my reasoning

A small ID is not a short network distance. We need the connections and the chosen source. Device 26 is in the directory but isolated in this first network; there is no path to it from 18. An ID absent from the graph is a different case: an invalid target.

03 · Use FIFO for a new purpose

Let the first discovered wait,
then process it when its turn comes.

In Week 4’s FIFO queue new records were added at the rear and the next record was taken from the front. Here, the queue will hold devices discovered but not yet finished with. Once a device is taken from the front, it is outside the queue while its neighbours are processed, in a separate “currently examining” area.

  1. Initially, all distances are unknown. For source 18, set d[18]=0, mark it as discovered and add it to the queue: [18].
  2. Take 18 from the front. Neighbours 7 and 24 are seen for the first time: give each distance 1 and parent 18, and add them at the rear. Queue [7, 24].
  3. Take 7. Give 4 and 11 distance 2 and parent 7. 18 has already been discovered. Queue [24, 4, 11].
  4. 24 is next; 4 does not move ahead just because it has not yet been taken out. FIFO completes the earlier layer first.

Will 11 be added twice?

The first neighbour of 24 is 11. 11 is waiting in the queue; its neighbours have not been processed yet. Should we add it again?

Compare my decision

No. We marked discovery when adding to the queue. 11 already has its distance and parent. Waiting for its turn to be processed does not mean being discovered again. Each vertex therefore enters the queue at most once.

04 · Discover layer by layer

BFS: discover a neighbour,
increase its distance by one.

BFS means breadth-first search. Take u from the front of the queue. For each neighbour v, only on its first discovery, set d[v]=d[u]+1 and parent[v]=u, then add v to the queue. Mark it at the same time. Continue until no work remains in either the queue or the vertex being examined.

for every vertex, distance = unknown
source distance = 0; add the source to the queue
while the queue is not empty:
    u = take from the front
    for each neighbour v of u:
        if v has not been discovered:
            d[v] = d[u] + 1
            parent[v] = u
            add v to the queue

In the display, the first step initialises V rows and the source. One “examine a neighbour” step scans one list entry; if it is new, the distance, parent and queue addition occur in that same step. The front of the queue is on the left.

Predict the next queue first

Each example resets the initial state. The search does not stop early at the target; it processes every vertex reachable from the source. Changing the path target does not reset the search.

All revealed steps

    Taking a vertex out can temporarily empty the queue; the search has not finished until its neighbours are finished too. “Not yet discovered” and “unreachable from this source” remain distinct until the search is complete.

    Compare the queue on paper

    Removal order [18, 7, 24, 4, 11, 20, 31]. Including the source, 7 additions and 7 removals. The largest queue holds 3 vertices. 26 was never discovered; once the search is complete we can say it is unreachable from 18.

    05 · From numbers to a path

    Distance counts edges.
    A parent gives one example path.

    FIFO processes vertices at distance k before those at k+1. When we first give a neighbour distance k+1, any shorter path would have discovered it from an earlier layer. Therefore, the distance at first discovery is the minimum edge count.

    d=0: 18.

    d=1: 7,24; their parent is 18.

    d=2: 4 and 11 have parent 7; 20 has parent 24.

    d=3: 31; its parent is 11.

    26: unreachable from this source. Its distance is not 0.

    Follow the parents backwards: 31 ← 11 ← 7 ← 18. Reverse it: 18 → 7 → 11 → 31. Four vertices, 3 edges; d[31]=3. The source has no parent; its path to itself is [18], length 0.

    Is there only one shortest path?

    18 → 24 → 20 → 31 also has three edges. If we reverse neighbour order, can the distance change, or the selected parent?

    Compare my answer

    Distances do not change in this network; the parent that first discovers a vertex and the removal order within a layer can change. With reversed neighbour order, 31 is discovered from 20; the example path is 18 → 24 → 20 → 31. BFS gives one shortest path; it does not claim that this path is unique.

    This meaning of distance relies on the contract that every connection is one step. If edges have different times, the fewest connections may not mean the shortest time. This lesson’s BFS rule does not guarantee a solution for that other goal.

    06 · State the unit of work

    There are 8 edges.
    Why were 16 entries scanned?

    Initially, we prepare the state of all V=8 vertices. From 18, 7 vertices are reachable; each enters and leaves the queue once. We scan each removed vertex’s adjacency list once. Since all 8 edges in this network belong to that component, 2E=16 adjacency entries are examined.

    If another disconnected component also had edges, this single-source search would not scan them. In general, the number of scanned entries is the sum of the degrees of the reached vertices; it need not always be 2E for the whole graph. With 26 as the source, there are 8 initial rows, 1 addition, 1 removal and 0 adjacency scans.

    Where does V+E come from?

    With the lists ready: V initial preparation; at most V queue additions and V removals; at most 2E adjacency entries. If initialisation, a queue operation and examining one list entry each take constant work, total work has an O(V+E) upper bound. We implement FIFO using front/rear pointers or a head index; we do not assume shifting the entire array on every removal.

    Extra space for the queue, distances and parents is on the scale of O(V); the adjacency representation is O(V+E). Building/sorting the ready-made lists and storing all snapshots for teaching are excluded from these BFS counters. The counters do not measure every physical memory write or seconds. After the search, reconstructing and writing a single path from its parents takes additional work proportional to that path’s vertex count; changing the path target does not increase the BFS counter.

    This lesson’s “scan” counter counts one adjacency entry; it does not count first-time edge discoveries or vertices. Looking from 24 at 11, already in the queue, is also a scan; it is not another addition.

    Now finish 24.

    After removing 24: [4, 11]. 11 and 18 are not added again; 20 is given d[20]=d[24]+1=2 and parent 24, then added at the rear. Final queue [4, 11, 20], length 3. All three entries were scanned; only 20 was newly discovered.
