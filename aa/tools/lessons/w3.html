01 · Scale up the count

The input doubles.
Does the work double too?

In Week 2, we found C(n) = 2n for two full scans and C(n) = n² for the full comparison table. Our counting unit was one equality check.

Work countn = 4n = 8Change
2n8 checks16 checks2 times as much
n²16 checks64 checks4 times as much

Replace n with 2n: 2 × (2n) = 4n, twice the original count. For the square, (2n) × (2n) = 4n², four times the original count. We compare these growth factors when n is positive.

Predict first, then change it

C(n) = 2n

Double n: twice the work.

C(n) = n²

Double n: four times the work.

Can these numbers choose a method for us?

“2n is smaller, so I will use two scans instead of the full comparison table.” Is the required output the same?

Compare my reasoning

Two scans produce two target columns; the n² method produces a table of every pair of positions. We can see how their workloads grow, but one report cannot replace the other. To choose a method, first define the same input and the same required output.

02 · Set up a fair comparison

This time, we search
a sorted device directory.

We are moving to a different input from the list of arriving messages: the maintenance team’s already prepared directory of device IDs, sorted from smallest to largest. IDs are distinct in this lesson. We can access any position directly.

47111824314256

A shared contract for both methods

Input
Distinct IDs in increasing order, and a target ID.
Output
The 1-based position in this given directory if the target is present; otherwise, “not found”.
Access
Given a position, we can read its value directly; we do not need to walk from the beginning.

For target 42, the output is 7. This is not the original arrival position from Week 1; it is a position in the given sorted directory. We do not sort the records during this search.

We will try two methods. Linear search starts on the left and moves on until it finds a match or reaches the end. Binary search uses the middle value to rule out the side that cannot contain the target.

One probe in this section = one abstract three-way comparison of a key with the target: less than, equal to or greater than. We count both methods using this same unit. It is not a count of separate == and < instructions in a programming language; we are also changing from Week 2’s equality-only counter.

03 · Check the middle, narrow the interval

Why can the discarded side
not contain the target?

The target is 42. Initially, the left position is 1 and the right position is 8. We choose the midpoint by rounding down the average of the two endpoint positions: (1 + 8) / 2 = 4.5 → position 4.

  1. Position 4, value 18. 18 < 42. Because the directory is sorted, every value at positions 1–4 is also less than 42. The new interval is 5–8.
  2. Position 6, value 31. 31 < 42. Discard positions 5–6. The new interval is 7–8.
  3. Position 7, value 42. A match: return position 7 and stop.

The same decision in pseudocode

← stores information under a name; ≤ means “less than or equal to”. When left passes right, no candidates remain.

left ← 1; right ← n
while left ≤ right:
    middle ← round (left + right) / 2 down
    compare the middle value with the target
    if equal: return the middle position and stop
    if less: left ← middle + 1
    if greater: right ← middle − 1
return “not found”

We do not leave the checked midpoint in the new interval. + 1 and − 1 prevent us from checking the same position repeatedly.

Trace the interval one step at a time

Crossed-out positions have been discarded; the outlined position was probed last. Answers stay hidden until you reveal their steps.

    0 probes
    Compare both traces for 42 on paper

    Binary: positions 4 → 6 → 7; three probes. Linear: positions 1 → 2 → 3 → 4 → 5 → 6 → 7; seven probes. Both return position 7 in the same given directory.

    We made three probes for this target; that does not mean every search among eight records finishes in three probes. For target 56, the positions are 4 → 6 → 7 → 8: four probes.

    Connect halving to growth

    After each unsuccessful midpoint check, at most half as many candidates remain. The longest path for eight candidates is 8 → 4 → 2 → 1; for sixteen, it is 16 → 8 → 4 → 2 → 1. How many checks are needed?

    Compare my count

    At most 4 probes for eight records, and at most 5 for sixteen. Doubling the input adds one probe to this worst-case bound. We cannot use the halving argument unless the method’s conditions hold. An empty directory takes zero probes.

    04 · Check the conditions

    Without order,
    we cannot justify discarding a side.

    Suppose the directory were given in this order: [4, 31, 7, 18, 24, 11, 42, 56]. Target 11 is present, at position 6. But if we split it as though it were sorted:

    1. At position 4, we use 18 > 11 to discard the right side. We wrongly discard the target too.
    2. At position 2, 31 > 11; then at position 1, 4 < 11.
    3. The interval becomes empty, and we wrongly return “not found”.

    Looking at the middle is not enough. Sorted order lets us infer something about an entire side from one comparison. Direct positional access also means that reaching the middle does not require a long walk of its own.

    Three questions before choosing a method

    1. What output do we need? A position in the given directory, or the first arrival position? Sorting changes the original positions; preserve that information separately if it is needed.
    2. Is the input ready? Is it sorted and accessible by index? If not, include the work of preparation and data updates.
    3. How many searches will there be? A single search and many searches share preparation work differently. Total work includes preparation and all the searches together.

    If a sorted directory already exists, binary search may be a good fit. For one search in unsorted data, a direct scan needs no preparation. For many searches, we can also consider the cost of sorting or building another search structure. One example’s probe count alone does not determine real running time or the entire workload.
