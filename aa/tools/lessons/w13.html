01 · Same question, different work

Many prefixes.
The same remaining work.

In Week 12, 24 → 11 → 24 and 24 → 18 → 24 were separate calls. Both reached device 24 after two edges; the possible continuations were the same. The network, k=4, traversal costs, and goal stay the same. We still want one minimum-cost walk; repeated devices and edges are allowed.

This time we will build a table forwards: store the minimum cost of reaching each device from the source using exactly r edges. We need not retain a more expensive prefix reaching the same cell; a cheaper prefix of the same length can replace it. Both allow the same continuations.

A different notation, the same problem

Last week, r in a call counted remaining edges. This week, the table column r counts used edges. For the prefix 24 → 20 → 31, last week we had 2 edges remaining; here we have used r=2. We check the exactly-k condition in the final column.

The source stays fixed at 24. We want D[31, 4]. D[31, 2]=6 answers the two-edge question; it cannot replace the four-edge answer.

03 · State what a cell means

D[device, edge count]
is more than a number.

State definition

D[v, r]: the minimum total traversal cost among walks starting at 24 and ending at v after exactly r edges. If no such walk exists, the value is ∞. A cost of ∞ is not 0.

P[v, r]: the device immediately before v in a walk achieving this cost. Store it when r>0 and D[v, r] is finite. A base or unreachable cell has no predecessor.

The table computes every target for the same source. If the source changes, rebuild the table. r is not the number of device positions: a four-edge walk contains five device positions; IDs may repeat.

Why can we forget a more expensive prefix?

Choose the cheaper of two prefixes reaching the same v and r. You can append any continuation of the more expensive prefix to the cheaper one: it starts at the same device with the same number of edges remaining, and costs add. The more expensive prefix therefore cannot give a better total.

This argument depends on allowing repetitions. If we added “visit each device at most once,” the devices already used would also matter; (v,r) alone would generally be insufficient.

04 · Place the empty walk

With zero edges,
I can only be at the source.

D[24, 0]=0. We have traversed no edges and paid nothing. For every other v, D[v, 0]=∞. This is more than “reachability is unknown”; those devices cannot be reached using zero edges.

Writing a base value of 0 in every row would allow us to start at every device for free. If a previous-column cell is ∞, that neighbor cannot produce a finite candidate. We will distinguish an uncomputed cell with ·; we have not yet decided its value.

What if k=0 and the target were 24?

Is the empty walk an answer? What changes when the target is 31?

Compare my base case

If source=target=24, [24] with cost 0 and 0 edges is valid. If the source is 24 and the target is 31, there is no answer. When k>0, we cannot copy the base cost for a return to the same target.

05 · Separate the last edge

Where did I enter v from?
How many edges came before it?

Every walk ending at v after exactly r edges traverses its last edge from some neighbor u. Before that edge, the source → u prefix uses exactly r−1 edges. Add the final edge cost w(u,v) to the best such prefix cost; take the minimum over all neighbors.

D[v, r] = min { D[u, r−1] + w(u, v) : u is a neighbor of v }

This recurrence applies for r≥1. Skip unreachable previous cells; if there is no finite candidate, the result is ∞. Record P[v, r]=u for a cheaper candidate; keep the earlier choice on a tie.

Compute one cell together

With column r=3 ready, consider the final neighbors for D[31, 4]:

  • From 11: D[11, 3]+5 = 7+5 = 12.
  • From 20: D[20, 3]+2 = 8+2 = 10.
  • From 26: D[26, 3]+4 = 10+4 = 14.

The minimum is 10; P[31, 4]=20. Do not confuse the last edge cost with the cost of the entire prefix: 2 pays only for the final traversal.

Correctness: each candidate adds one edge to a valid r−1 prefix, so it is a valid r-edge walk. Conversely, every r-edge walk has a final neighbor, and the corresponding choice in the minimum cannot use a more expensive prefix. If the base case and previous column are correct, the new column is also correct.

06 · Respect the dependency order

First, all of r−1.
Then, all of r.

Finish the base column. Then proceed through r=1,2,3,4 in order. The order of devices within a column does not affect correctness, provided every value read comes from the previous column. This display uses ID order.

Initialize all D[v, r] cells to ∞
D[24, 0] = 0
for r = 1, …, k:
  for each device v:
    for each neighbor u of v:
      if D[u, r−1] is finite:
        candidate = D[u, r−1] + w(u,v)
        if candidate < D[v, r]:
          D[v, r] = candidate
          P[v, r] = u

Even if the network has a cycle, the cell dependencies are acyclic: each dependency points one column back. Reading the same column can hide the use of multiple edges within one step. For example, reading D[20, 3]=8 and writing D[31, 3]=10 is wrong: that prefix already uses three edges; adding one edge makes four. The correct value is D[31, 3]=∞.

    07 · From cost to walk

    Follow the ID.
    Decrease the column by one, too.

    For finite D[31, 4], P[31, 4]=20. The next state going backwards is (20,3); not just “20.” P[20, 3]=31, P[31, 2]=20, and P[20, 1]=24. This reaches (24,0). Then reverse the IDs collected backwards.

    31 and 20 may appear again; we never return to the same (device,r) state, because r decreases at each step. Stopping the chain because “I have already seen this device” would truncate the four-edge answer. k predecessor steps give k+1 device positions. If the final cell is ∞, there is no predecessor chain; we do not invent a walk.

    Why is the final cost alone insufficient?

    Does knowing the number 10 tell us which edges to traverse? What would we have to do if we had not stored P?

    Compare my output

    10 is only the optimum cost. A walk also requires predecessors. Given the full D table, we could rescan the neighbors at each backward step to find one satisfying the equality; storing P makes that choice available during computation.

    08 · Number of states × transition work

    Store 40 cells.
    Scan 80 neighbor entries.

    V=8, E=10, k=4. Including the base, we initialize V(k+1)=40 D cells; 8 of these are base cells, and Vk=32 are computed by the recurrence. In each new column, every undirected edge contributes two adjacency entries: 2Ek=80 scans. Scans with an ∞ previous value still count; of the 80 scans, only 36 produce finite candidates. There are 22 strict improvements and 4 predecessor steps. Do not add the base cells again to the 40 initialized cells; those 8 base cells are already included.

    With adjacency lists ready, initializing and filling the entire table takes O((k+1)V+kE); for k≥1, this is O(k(V+E)). Saying only O(kE) omits work when k=0 or devices are isolated. The cost and predecessor tables use O((k+1)V) space; reconstructing and writing one walk requires O(k+1) additional work/output. Input space is O(V+E).

    In Week 12, the same k=4 required 96 calls without pruning. Here we have 40 state cells and 80 neighbor scans. A call and a scan are different counting units. The saving comes from solving a shared state once instead of separately expanding every possible walk prefix.

    Distinguish counters from the teaching display

    The model counts table cells, scans, finite candidates, strict improvements, and predecessor steps. These units exclude input validation/sorting, the full table copies stored in events, and rendering. This display stores the entire trace; its space use differs from that of the core DP table.

    Small transfer · text prefixes instead of devices

    We want to turn CAT into CUT; insertion, deletion, and substitution cost 1, while a match costs 0. The new state E[i, j] is the minimum number of operations needed to turn the i-letter prefix of the first text into the j-letter prefix of the second. Here i,j no longer count edges.

    Base cases: E[i, 0]=i (delete), E[0, j]=j (insert). The recurrence takes the minimum of deletion E[i−1, j]+1, insertion E[i, j−1]+1, and match/substitution E[i−1, j−1]+the character difference. The cells above, to the left, and diagonally above-left must be ready first. For C → C, E[1, 1]=0; for CA → CU, E[2, 2]=1; for CAT → CUT, E[3, 3]=1. One substitution is sufficient; zero operations cannot turn different texts into each other.

    Ask yourself: how does the “last operation” here use the same idea as the “last edge” in the device network? We did not copy the device and r; we redefined a sufficient state and its dependencies for a new problem.

    Where this leads

    Can every correct answer
    be found quickly?

    For this problem, the exact edge count, sufficient state, and column dependencies let us find the minimum-cost answer without expanding every walk. A new condition such as “never repeat a device” could increase the history we need to store. If an answer is easy to check, does that mean it is easy to find?
