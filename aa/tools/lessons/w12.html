Adding a constraint · Generating candidates

Reach the target.
Use exactly k edges.

Device 24 in the warehouse must send a message to 32. This time the protocol requires exactly four link traversals. A cheap two-edge answer is not enough. Generate possible continuations systematically, resume where you left off after each return, and explain which branch you can safely skip.

01 · First change the question

We had a cheapest answer.
Does it meet the new constraint?

In Week 11, the path 24 → 20 → 32 cost 4+2=6. This walk uses two edges. Now we need exactly four edges, rather than “at most four” or “at least four.” The same devices, existing links, and message traversal costs are retained.

The exactly-k-edge walk contract

Input: an undirected network with zero or positive weights; a source s, a target t, and a nonnegative integer k. Repeated devices and edges are allowed in a walk. Pay the edge cost again on every traversal.

Output: among walks that start at the source and finish at the target after exactly k edges, return one cheapest walk; if none exists, report “no solution for this k.” Listing all tied optima is outside this task.

What if you reach the target early?

At 24 → 20 → 32 you have reached the target, but must still use two more edges. Is it correct to stop here? Are you forbidden from leaving 32 and returning to 32?

Compare my constraint

You cannot stop; the edge count is too small. The walk 24 → 20 → 32 → 20 → 32 uses exactly four edges and costs 4+2+2+2=10. It is valid because repeated devices are allowed. Requiring a “simple path” would forbid repeats and change the problem.

03 · State and stopping

Where am I, how many edges remain,
and how much have I paid?

Each call carries (v, r, c): current device v, remaining edges r, and cost paid c. The initial state is (24,4,0). If edge v–u has weight w, the new call is (u, r−1, c+w). We also keep the walk prefix so that we can write the answer at the end.

  1. If r=0, stop: if v is the target, this is a valid candidate; otherwise, an invalid terminal. Check the target at exactly this point.
  2. If r>0, continue: make a choice for each neighbor of v. Reaching the target early is not a reason to stop.
  3. If there is no neighbor, return: you cannot complete the remaining edges.
  4. Every traversal decreases r by one. Even with zero-cost cycles and repeats, the depth is at most k; the search cannot continue forever.

k=0: if source and target are the same, the empty walk is valid and costs 0. Otherwise there is no solution. “No good candidate found yet” differs from having a candidate of cost 0.

Discard a device because it was visited?

Should you keep a device marked “visited” throughout the search after its first visit?

Compare my connection

No. The aim is to generate candidates with exactly k traversals, rather than visit each device once. For example, you would lose the optimum 24 → 20 → 32 → 20 → 32. From the DFS idea in Week 9, we use descent and return; we do not carry over the same problem contract.

      06 · Prove that skipping is safe

      To skip a branch,
      what must I know?

      Cost already paid is a lower bound

      We have paid c so far. If each remaining edge has zero or positive cost, every completion costs at least c. If we have a valid candidate costing B and c≥B, this branch cannot produce a cheaper result. Because we want one cheapest candidate, we can skip the branch.

      For example, with a best cost of 12, the prefix [24, 11, 32, 26] has c=3+5+4=12 and r=1. No continuation can cost less than 12: prune. Without a valid candidate found earlier, there is no finite B to compare against; do not prune by cost.

      Zero cost is allowed. Once B=0 is found, an internal branch with c=0 can also be pruned by the ≥ rule. This may skip other tied optima; the valid optimum already found is retained. If we wanted all tied winners, we would change the rule and the output contract.

      What if an edge were negative?

      With c=12 and B=10, a remaining edge of −4 could reduce the total to 8. Then c is no longer a safe lower bound on the completed total. Can we use the same rule unchanged?

      Compare my constraint

      No. Because exactly k is finite, enumerating walks with negative edges is still finite; however, this simple c≥B pruning is unsafe. This lesson’s model rejects every negative weight. With negative weights, a different lower bound needs a proof.

      Correctness has two parts: the unpruned search branches to every neighbor and covers all exactly-k-edge walks; pruning removes only internal branches proven unable to improve the current answer. We check r=0 first; the terminal counters describe the endpoints actually reached.

      07 · Separate candidate cost from search work

      The answer costs 10 units.
      How many calls found it?

      In the main unpruned example, the prefix counts by depth are 1, 3, 8, 23, 61. There are 96 calls in total; every non-root call arrived by one extension, giving 95 extensions. Of the 61 terminals, only 15 are at the target. Repeated entries to the same device are distinct prefixes; the call count is not V.

      In general, let Nᵢ be the number of prefixes with i edges: a total of N₀+N₁+…+Nₖ calls. If the maximum number of neighbors is Δ, then Nᵢ≤Δⁱ; a safe upper bound is O(1+Δ+…+Δᵏ). For Δ>1 this is O(Δᵏ); for Δ=1 it is O(k+1). In general, growth may be exponential as k increases. When Δ=0 there is only the root.

      Pruning sometimes reduces work; it does not generally turn this bound into a polynomial. The main network needs 96 rather than 88 calls without pruning; at k=3 no candidate is found, so cost pruning never applies and the 35 calls stay unchanged. Read the counter from the actual traversal; enabling pruning does not guarantee a speedup.

      Basic search and the teaching record

      With a ready adjacency list, depth-first search can use one mutable prefix and a call stack with O(k+1) extra space. Recording a good candidate also takes O(k+1) work to copy its k+1 device IDs; for I strict improvements, O(I(k+1)). Input space is O(V+E).

      This teaching model stores every call’s prefix, all events, and stack copies. Its displayed choice tree and history therefore use more than the basic DFS’s O(k) space. Counters measure calls/extensions/terminals/valid candidates/prunes/improvements/returns; they exclude drawing, input preparation, and record copies.

      08 · Reduce the support

      The best candidate costs 10.
      Should you open the branch at 26?

      Source 24, target 32, k=4. The prefix [24, 20, 32, 26] is open; its edge costs are 4,2,4. An earlier valid candidate with exactly four edges cost 10. All costs are nonnegative; we want just one optimum.

      Compare the solution after trying

      c=4+2+4=10, r=4−3=1; prune. We are not at the target with r=0. The remaining cost is at least 0, so every completion of this branch costs at least 10. We already have a valid 10; it cannot be cheaper. The ≥ rule is appropriate because we are not counting other tied optima. A negative cost could reduce the total; this lower bound would then be unusable.
