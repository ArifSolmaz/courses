01 · Examine the assumption

Count the work
of reaching the middle too.

In Week 3, binary search used a sorted directory with distinct IDs and direct access to its positions. Comparing a key with the target was one probe. We did not separately examine how we reached that position.

Now we will store the same record order in different ways: [4, 7, 11, 18, 24, 31]. The ID order stays the same; the way we reach the IDs changes. All positions in this lesson start at 1.

Predict first

You know the fourth record is 18. Do a starting address and a position let you access that record directly in every data layout?

Compare my prediction

They do for an array under the indexed-access assumption. For a singly linked list with only the head node’s address, we follow three next links to reach the fourth node. Knowing the target position is not the same as knowing that node’s address.

02 · Reach the same record in two ways

Does knowing a position
mean knowing an address?

Array

Cells are adjacent. The starting address and fixed cell size give us indexed access to position k.

1:4 · 2:7 · 3:11 · 4:18 · 5:24 · 6:31

k = 4 → one indexed read → 18.

Singly linked list

Each node holds a value and a reference to the next node. Only the head address is supplied.

head → N1 → N2 → N3 → N4 → N5 → N6 → end

Follow three links from N1 → read N4’s value → 18.

N1, N2… are fixed node names. Insertion can change a node’s position in the sequence, but not its name. “End” means there is no next node. Nodes do not need to be adjacent in memory.

The access contract

n
The number of existing records: 6 here.
k
The 1-based position to read: 1 ≤ k ≤ n.
Counted work
Indexed reads for the array; link follows and the final node-value read for the list, using separate counters.

For any valid k, the array takes 1 indexed read. From the head to position k, the list takes k − 1 link follows, then 1 node-value read. Obtaining the head address and the details of index arithmetic are not counted in this model. These units are not Week 3’s probes or seconds; we do not add them into one “speed score”.

Halving decisions can still make sense in a sorted linked list. But we must count the work of reaching the middle positions too; fewer comparisons do not automatically mean less total work. An empty directory has no valid k to read.

03 · Change the layout

Insert 15
at position 4.

The required result is [4, 7, 11, 15, 18, 24, 31]. The new position p = 4 is given. We are not searching for 15’s sorted position. For insertion, 1 ≤ p ≤ n + 1; p = n + 1 means append at the end.

Make room in the array

One spare cell is ready. Shift from right to left:

  1. 31 at position 6 → 7.
  2. 24 at position 5 → 6.
  3. 18 at position 4 → 5.
  4. Write 15 at position 4.

3 value shifts + 1 new-value write. A later write overwrites the source cell; temporary duplicates can appear while shifting.

Set two links in the list

The predecessor is at p − 1 = 3: follow two links from the head to N3. The new node is allocated and its value, 15, is ready.

  1. new.next ← N3.next (N4).
  2. N3.next ← new.

2 link follows + 2 pointer assignments. Existing node values do not move.

Why does the order of the steps matter?

Which old value would we overwrite if we shifted left to right in the array? If we linked N3 to the new node first, how would we preserve N4’s address?

Compare my reasoning

If we started with 4→5 and then did 5→6, we would copy the moved 18 instead of the old 24. In the list, changing N3.next first means we must save the old continuation address separately; immediately doing new.next ← N3.next would link the new node to itself. Our order first preserves the continuation address in the new node.

Say the next operation first

    Worked traces and boundary cases for paper

    Access k = 4: the array reads position 4. The list follows three links along N1→N2→N3→N4, then reads 18.

    Insert p = 4: the array shifts 6→7, 5→6, 4→5, then writes 15 at 4. The list follows N1→N2→N3, then sets new.next←N4 and N3.next←new.

    Insert at the head: the array shifts n values; the list follows 0 links and makes 2 pointer assignments, new.next←head and head←new. Append at the end: the array shifts 0 values; with only a head address, finding the old last node takes n − 1 link follows (n ≥ 1). Insertion into an empty list takes 0 link follows and still 2 pointer assignments.

    Keep the conditions beside the formula

    The array takes n − p + 1 value shifts and 1 new-value write. Capacity is at least n + 1; resizing or reallocating the whole array is outside this example.

    With only a head address, the list takes 0 link follows for p = 1; for p ≥ 2, it takes p − 2 link follows, followed by 2 pointer assignments. If the predecessor’s address is already known, we do not walk again to find it. Keeping a separate tail address would also change the work of reaching the end.

    Allocating the new node and writing its value are outside this count. The units cover different work; we do not infer a general comparison in seconds. If we must find position p by ID or search for the correct sorted position, count that work separately.

    04 · Choose the next job

    From storage layout
    to processing order.

    Here is a different need from the directory: maintenance messages arrive in order. The device IDs are 24, 4, 18. Process one message, then let 11 arrive, then process another message. Larger IDs do not mean higher priority; the arrival order is given.

    FIFO · Queue

    First in, first out. 24 leaves first. After 11 arrives, 4 leaves next. Waiting: 18, 11.

    LIFO · Stack

    Last in, first out. 18 leaves first. After 11 arrives, 11 leaves next. Waiting: 24, 4 (in arrival order).

    FIFO/LIFO is a selection rule; arrays and linked lists are storage layouts that can implement these rules. For example, an array queue with head and tail indices can avoid shifting every value on each removal. Here, we trace only the logical order; we do not measure an implementation’s time cost.

    Trace the same events with both rules
