01 · What are we looking for?

A device’s ID and a message’s position are different things.

A maintenance team stores messages from devices in the order they arrive. The numbers below are the IDs of the devices that sent the messages. A device can send more than one message, so a value may appear more than once.

position 118
position 27
position 318
position 424

The team asks: “At what position is device 24’s first message?” The answer is 4, because the value 24 is in the fourth record.

The task contract

Input
A finite list of message IDs and the ID we are looking for: the target.
Expected output
The position of the target’s first occurrence. If the target is absent, “not found”.
Position rule
Positions in this lesson start at 1. An empty list has no positions.

This contract defines what counts as a correct answer. If the target were 18, the answer would be 1: the third record is also 18, but we need the first message.

Pause and explain

“The target is 24; the result is 4.” What does each number tell us? If you sort the list, can you still use its positions to identify the original arrival order?

Think first, then compare

24 is the device’s ID; 4 is the message’s position in arrival order. Sorting moves the records. Our task is to find a position in the original arrival order, so we keep that order.

02 · Run a rule

Look at one record.
Decide. Move on if needed.

We do not need a programming language yet. An algorithm is a set of clear steps for completing a task. Here, we will look from left to right and stop at the first match.

  1. Start at the first position.
  2. If no position remains to be checked, return “not found” and stop.
  3. If the value at this position equals the target, return the position and stop.
  4. Otherwise, move to the next position and continue from step 2.

The repeated part is a loop: we apply the same rule at a new position. The state tells us where we are and what we know so far. For example, before reaching the second position, we have learned that the first record is not the target.

When we write comparisons, = means “equals” and ≠ means “does not equal”. For example, 18 ≠ 24: the two values differ.

See the same steps in pseudocode

This is not code in a particular programming language. ← means “store the information on the right under the name on the left”. The indented lines belong to the repeated part.

position ← 1
while position is a valid list position:
    value ← the record at this position
    if value equals target: return position and stop
    increase position by one
return “not found”

The information named position changes: 1, then 2, 3… if needed. When we find the target, “stop” prevents us from continuing to the “not found” result below.

03 · Give the numbers meaning

What questions do 4, 2 and 7 answer?

Now use the same list with target 7. We look at 18, then 7, and stop. The list still contains four records, but we made only two equality checks.

4

How many records are there?

The length of the list. We will call it n for short: here, n = 4.

2

At what position did we find it?

The result position. There are also 2 checks in this example, because we started on the left and skipped no records.

7

Which ID did we look for?

The target value. An ID of 7 does not mean there are seven records or that we made seven checks.

When reading a mathematical expression, first ask what the symbol represents. Here, n = 4 is shorthand for “the list contains four records”. We are not building a speed formula yet; first, we establish what the number means.

Make a prediction

Can we find a target in two checks when the list contains four records? Will every target in this list be found in two checks?

Compare my prediction

Yes: two checks are enough for 7. But 24 takes four checks. Changing the target can change the work done even when the list length stays the same.

How do we know we missed no earlier message?

At the start, we have checked no records. Whenever a record is not the target, we rule it out and move just one position forward. So, when we find a match, we know that all earlier records are not the target. If we reach the end without finding a match, we have ruled out every record.

This explanation connects why the rule works for every finite list to what each step does. A few correct examples alone do not cover all inputs. For example, the main example with target 24 disproves the rule “if the first record does not match, return not found”.

Model answer

  1. Position 1: 9 ≠ 14, move on. Position 2: 14 = 14, return 2 and stop. Two equality checks.
  2. n = 4 is the number of records. 2 is the position of the first match; 14 is the target device ID. They answer different questions.
  3. The team needs a record’s location to open it. It already knows the ID. If the target were 20, the result would be “not found” after checking all four records.
  4. The last match is at position 4. Stopping at position 2 prevents us from seeing the 14 at position 4. Even though only “first” has changed to “last”, we need to reconsider when to stop.

Assess your work
