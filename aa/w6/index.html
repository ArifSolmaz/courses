Before Activity 01 · Start from zero

First, understand the problem

We will learn one small idea at a time. No coding is needed.

Imagine three people are waiting

A arrives first. B arrives second. C arrives third. In a normal waiting line, A goes first, because A arrived first. This is called First In, First Out (FIFO).

Now imagine each person needs help, but one person needs help more urgently. We might help that person first, even if they arrived later. That is the basic idea of a priority queue.

Normal line: Who arrived first?
Priority line: Who needs to go first?

Important: In this lesson, a smaller number means a higher priority. For example, priority 1 goes before priority 5. This is our chosen rule, not a universal rule for all systems.

Read these four words before continuing

ItemA task or a number stored in our queue.
PriorityA number that helps us decide which item goes next.
MinimumThe smallest number. In our example, 2 is smaller than 5.
QueueA collection of items waiting for a turn.

Activity 01 · First, a problem

Who goes next?

Three maintenance requests arrive in order A, B, C. For this example, a smaller number means a more urgent request. Which job should be handled next?

Choose the scheduling rule

Think before clicking

Which information matters for your decision?

FIFO queue

The earliest arrival goes first. Its urgency does not change the order.

Priority queue

The job with the best priority goes first. Arrival order is not necessarily decisive.

A priority queue is an abstract data type: it describes what operations should do, not how the data must be stored.
Activity 02 · The interface

Three operations, one promise

We want a system that always gives us access to the smallest priority value.

INSERT

Add a job

insert(x) places a new element into the queue.

The item does not have to remain at the end of the internal structure.

PEEK

Look at the minimum

peekMin() returns the smallest element without removing it.

For a min-heap, this is the root.

EXTRACT

Remove the minimum

extractMin() removes and returns the smallest element.

The remaining elements must still satisfy the heap rules.

Key distinction: A priority queue is the behavior we want. A binary min-heap is one implementation. Other implementations are possible, with different time costs.

If the parent is 7 and one child is 3, is this a valid min-heap?

Show the explanation

No. For a min-heap, the parent must be no greater than each child. Here 7 is greater than 3. We must change their positions to repair the order.

Activity 03 · Two easy rules

What makes a binary min-heap?

A heap is not just “a sorted tree.” It has a structural rule and an ordering rule.

Rule A · Shape

The tree is complete: every level except possibly the last is full, and the last level is filled from left to right.

Rule B · Order

Every parent value is less than or equal to each of its children's values. Therefore the root is the minimum.

Not required: a whole heap does not have to be globally sorted. The two children may have any relative order.

Spot the valid heap

Does the array below satisfy the min-heap parent rule?

Why does an array represent a tree?

For a zero-based array, the children of node i have indices 2i + 1 and 2i + 2, if those indices exist. The parent of a non-root node is floor((i − 1) / 2). These formulas follow from the complete-tree shape.

Extra lesson · Before the animation

Two worked examples, very slowly

Read the steps below before you use the interactive heap.

Example A: Add the number 1

We begin with a valid heap containing 2, 5, 4. Our goal is to add 1 without breaking the heap rules.

  1. Start: We have [2, 5, 4].
  2. Add to the next free place: [2, 5, 4, 1]. This keeps the tree's shape correct.
  3. Look up: The parent of 1 is 5. Is 1 smaller than 5? Yes.
  4. Swap: Exchange 1 and 5. Now [2, 1, 4, 5].
  5. Look up again: The parent of 1 is 2. Is 1 smaller than 2? Yes.
  6. Swap again: Exchange 1 and 2. Now [1, 2, 4, 5]. Stop: 1 has reached the root.

Result:

1245

We moved the new number up. This process is called sift up. The word “sift” simply means moving an item until it reaches the correct place.

Example B: Remove the smallest number

Start with this valid heap: [1, 2, 4, 5]. We want to take out the smallest item.

  1. Find the minimum: The root is 1, so 1 must leave.
  2. Keep the tree's shape: Move the final number, 5, to the empty root. Now [5, 2, 4].
  3. Compare the children: They are 2 and 4. The smaller child is 2.
  4. Compare with the parent: 5 is greater than 2. That breaks the min-heap rule.
  5. Swap: Exchange 5 and 2. Now [2, 5, 4].
  6. Stop: The 5 has no children. The heap is valid again.

Result:

254

We moved the replacement number down. This process is called sift down.

Insert: why “sift up”?

The new item is placed in the next open position to preserve the shape rule. If it is smaller than its parent, swap upward. Stop when the parent rule is satisfied or when the item reaches the root.

new child < parent → swap

Remove: why “sift down”?

Remove the root, move the last item to the root, then compare it with its smaller child. If it is larger, swap downward. Stop when the parent rule is satisfied or there are no children.

parent > smaller child → swap
Activity 05 · Discover the mathematics

Why is it logarithmic?

To repair a heap, an item travels along one root-to-leaf path—not through every node. Watch how the height changes when we add more nodes. A tree with 32 nodes is only one level taller than a tree with 30 nodes.

Nodes15
Levels4
Tree height3

These examples are complete binary trees: we fill each level from left to right. Some examples also have a completely filled bottom level.

Observe, then generalize

With L fully occupied levels, there are 2L − 1 nodes. Tree height counts edges from root to deepest leaf, so h = L − 1.

h = ⌊log₂ n⌋

A perfect binary tree has every level completely filled (for example, 7 or 15 nodes). A complete binary tree fills its last level from left to right, but that level may be partly empty (for example, 30 or 32 nodes). For either kind of complete binary tree with n ≥ 1 nodes, the height is h = ⌊log₂ n⌋. The expression 2L − 1 applies only when all L levels are full.

Each sift-up step makes at most one key comparison. Each sift-down level uses at most two key comparisons (to choose the smaller child and compare with the parent). Both have O(log n) worst-case running time.

Transfer your understanding

A hospital manages 50,000 queued tasks. New tasks arrive frequently, and the most urgent task must be removed frequently. Would you choose a FIFO queue, an unsorted array, or a binary heap? Explain your decision in terms of correct behavior and operation cost.

See a model response after trying

If urgency determines which task goes next, FIFO does not meet the required behavior. An unsorted array can insert at the end in O(1) amortized time, but finding and removing the minimum requires O(n) scanning. A binary min-heap offers O(log n) worst-case insertion and extraction, with O(1) access to the minimum. Therefore a heap is a strong choice when both kinds of operations occur frequently. Real hospital triage also requires clinical rules and safety procedures that this simplified model does not represent.

Extra practice · Learn at your own pace

More easy questions and complete answers

Try each question first. Then open its answer to understand every step.

Part A — Understand priorities

Question 1. Three jobs have priority numbers 8, 3, and 5. Which goes first?

See the answer

Priority 3. In our lesson the smallest priority number goes first. We compare 8, 3, and 5 and choose the smallest: 3.

Question 2. Jobs arrive A, B, C. If we use FIFO, who goes first? What if C has the highest priority?

See the answer

FIFO always chooses A because A arrived first. In a priority queue, C may go first because priority—not arrival time—determines the next item.

Question 3. We have [2, 5, 4]. What does peekMin() return? Does it change the queue?

See the answer

It returns 2, the root. It does not remove 2, so the heap remains [2, 5, 4].

Part B — Read tiny heaps

Question 4. Is [2, 5, 4] a valid min-heap?

See the answer

Yes. The parent 2 is smaller than both children, 5 and 4. The values do not need to be fully sorted from left to right.

Question 5. Is [6, 2, 8] a valid min-heap?

See the answer

No. The root 6 is greater than its child 2. The parent must be smaller than or equal to both children.

Question 6. Is [2, 9, 4, 3] a valid min-heap?

See the answer

No. The number 9 is the parent of 3, but 9 is greater than 3. Checking only the root is not enough: we must check every parent-child relationship.

Part C — Move one number

Question 7. Start with [2, 5, 4]. Insert 3. What is the final heap?

See each step
  1. Add 3 at the end: [2, 5, 4, 3].
  2. Its parent is 5. Since 3 is smaller, swap: [2, 3, 4, 5].
  3. Its new parent is 2. Since 2 is smaller than 3, stop.

The answer is [2, 3, 4, 5].

Question 8. Start with [2, 5, 4]. Remove the minimum. What remains?

See each step
  1. Remove root 2.
  2. Move the final element 4 to the root: [4, 5].
  3. 4 is smaller than 5, so no swap is needed.

The answer is [4, 5].

Question 9. Insert 1 into [2, 5, 4]. How many swaps occur?

See each step

Add 1: [2, 5, 4, 1]. Swap 1 with 5, then swap 1 with 2. There are two swaps. The result is [1, 2, 4, 5].

Part D — Understand the idea of speed

Imagine going down a tree. You choose only one branch at each step. You do not visit every number.

Question 10. A full tree has 7 nodes. How many edges are there from its root to a bottom node?

See the answer

Two edges. The tree has three levels (top, middle, bottom), but only two moves from the top to the bottom. This difference between levels and edges is important.

Question 11. A full tree grows from 7 nodes to 15 nodes. Does its height double?

See the answer

No. Its height increases from 2 edges to 3 edges. Many new items fit into one additional level.

Question 12. Why do we say a binary heap is fast?

See the answer

When inserting or removing an item, we normally repair only one path in the tree. The path grows slowly as the heap gets larger. In the worst case, the number of levels we pass grows like log₂(n). This is why insertion and removal are O(log n).

Optional Python connection (read after the visual examples)

In Python, an array-like list can hold the values of a heap. Python also includes heapq, a library for min-heaps. You do not have to memorize this code today.

import heapq

jobs = []
heapq.heappush(jobs, 5)  # insert 5
heapq.heappush(jobs, 2)  # insert 2
heapq.heappush(jobs, 4)  # insert 4

print(jobs[0])          # peek: 2
print(heapq.heappop(jobs))  # remove: 2

Ask yourself: which operation changes the heap, and which operation only looks at the root?

One more gentle step · Check your thinking

Common mistakes and two more worked examples

These are normal beginner mistakes. Read each one, make a prediction, and open the explanation.

Three mistakes to watch for

Mistake 1: “Every number in a heap must be sorted.”

Not true. A min-heap only asks every parent to be no greater than its own children. For example, [2, 7, 4] is a valid min-heap even though 7 comes before 4 in the array.

Mistake 2: “We can place a new number anywhere.”

Not in a binary heap. First place it in the next empty position so the tree stays complete. Then move it up if needed.

Mistake 3: “The smallest number always stays in the same place.”

No. When we remove the minimum, another number moves to the root and may need to move down.

Worked example C — Insert a number that does not move

Start with [2, 5, 4]. Insert 8. Where does 8 go?

Open the slow explanation
  1. The next free position is at the end. The array becomes [2, 5, 4, 8].
  2. The parent of 8 is 5.
  3. Compare: 8 ≥ 5. The heap rule already holds.
  4. Stop. There are zero swaps.

Not every insertion needs a swap.

Worked example D — Remove a minimum from four numbers

Start with [1, 3, 4, 8]. What happens when we call extractMin()?

Open the slow explanation
  1. Remove and return 1.
  2. Move the last element, 8, to the root: [8, 3, 4].
  3. Compare the children 3 and 4. Choose the smaller child, 3.
  4. Since 8 > 3, swap them: [3, 8, 4].
  5. 8 has no children now. Stop.

The removed value is 1. The remaining heap is [3, 8, 4].

Two tiny review questions

Question 13. In [2, 7, 4], is 7 required to be smaller than 4?

Check your idea

No. The numbers 7 and 4 are siblings, not parent and child. The heap rule compares each parent with its own children.

Question 14. A heap has 30 elements. You insert one more item. Does the new item start at the root?

Check your idea

No. It starts at the next empty position (array index 30, because indexes start at 0). It may later move up through comparisons with its parents.
