Before the session

  1. Check the student language and a downloaded response file; prepare a paper fallback. Allocate anonymous codes to 6–8 learners.
  2. Keep the first attempt individual and save it before the guide. The guide is supported work. Keep transfer individual and save it before showing answers. Never overwrite an original attempt with the model explanation.
  3. Plan 5 minutes first response, 10 guided work (3+3+4), 7 transfer and 3 reflection/saving. Stop at 25 minutes; keep unfinished responses. Record actual phase times only if observed; navigation help, hints and seeing a solution are different observations.
  4. Assess the original explanations afterwards using the same four content rubrics. Support is recorded separately and does not automatically change a content score. “Unknown” means the support or language information was not recorded. Explicit “I do not know” can support 0; no response remains unscored.

Participant assessment

Score each written response separately from 0 to 2, and cite evidence for every selected score. Do not derive the score from a numeric answer, a choice, the learner’s self-rating or elapsed time. Missing response/evidence is blank, not 0. Explicit ‘I do not know’ is evidence for 0. Record independence, hint use or solution exposure separately; a content score does not by itself show independent performance. Do not overwrite the first attempt with corrections.

Teacher reference · model answers
Keep these explanations away from learners until both attempts are saved. These are assessment references, not automatic scoring rules.
First attempt
  1. Follow the search: 18 ≠ 7, 24 ≠ 7, then 7 = 7: return position 3 after 3 equality checks. Every earlier position was ruled out. The later 7 at position 5 does not change the first-match output.
  2. Name and count the unit: n = 6 records. A does 6 + 6 = 12 checks; B does 6 rows × 6 cells = 36 checks. Both count equality checks, including ‘no’. They produce different reports and cannot be substituted just because one count is smaller. Neither count measures seconds.
  3. Check the changed request: The last 7 is at position 5. ID 7 tells which device; position 5 tells which message to open. Stopping at position 3 misses position 5. Sorting changes arrival positions, so original positions must be retained separately if sorting is used.
  4. Test the reason for discarding: The target 7 is at position 6, inside the discarded side. Sorted order is what would justify concluding that every value to the right of 18 is larger than 7. The given order does not justify that inference. A left-to-right search reaches position 6 without discarding unchecked positions. Binary search needs sorted order for this inference and direct access for cheap midpoint access; preparation and the required output must also be accounted for.
Transfer attempt
  1. Follow the search: 24 ≠ 11, 7 ≠ 11, 18 ≠ 11, then 11 = 11: return position 4 after 4 equality checks. All earlier positions were ruled out. The later 11 at position 6 does not change the first-match result.
  2. Name and count the unit: n = 8 records. A does 8 + 8 = 16 checks; B does 8 rows × 8 cells = 64 checks. ‘No’ results count, and checks are not seconds. The formulas describe different required reports; a smaller count alone does not license substituting one report for the other.
  3. Check the changed request: The last 11 is at position 6. ID 11 identifies the device; position 6 locates the message. Stopping at position 4 misses the later message at 6. Sorting changes arrival positions; preserve those original positions separately when needed.
  4. Test the reason for discarding: Target 24 is at position 2, inside the discarded side. With no sorted-order guarantee, 18 < 24 at the middle says nothing about all values to its left. A left-to-right search finds 24 at position 2. Binary search needs sorted order for the discard argument and direct positional access for cheap midpoint access; preparation and output requirements still matter.
Guided work
  1. Week 1 · Trace and stop: Target 24: positions 1, 2, 3, 4 contain 18, 7, 18, 24; the decisions are no, no, no, yes. Return position 4 after 4 equality checks. For target 18, return position 1 after 1 check; another 18 at position 3 does not change the first result. ID, position and count answer different questions.
  2. Week 2 · Add or repeat: Two scans: 3 + 3 = 6 equality checks, so C(n) = 2 n. Full table: 3 rows × 3 cells = 9 checks, so C(n) = n². The first row is (1, 1), (1, 2), (1, 3); then comes (2, 1). n counts records, not distinct IDs; here two records have ID 18. When positive n doubles, 2 n doubles and n² quadruples. The two reports are different outputs, and check counts are not seconds.
  3. Week 3 · Check the conditions: For target 42, binary search checks position 4 (18), then 6 (31), then 7 (42): 3 probes, result position 7. A left-to-right search makes 7 probes in the same directory and returns 7. This is a given sorted-directory position, not the original arrival position. For target 56 the binary method takes 4 probes, so one example does not cover every target. Without sorted order, a single midpoint comparison cannot justify discarding all positions on one side. For one unsorted search, scanning needs no preparation; for many searches, include preparation and the required position information in the choice.
