Bunu neden bilmeliyiz?Why should we know this?

Gerçek bir robotta hamleler eşit değildir. Halıda tekerlek daha çok akım çeker, rampada motor zorlanır, dar koridorda robot yavaşlar. Navigasyon uygulamanız da en az sokaktan geçen yolu değil, en kısa sürede varan yolu arar. Bu haftanın yöntemi, "maliyet" dediğiniz şey ne olursa olsun (enerji, süre, risk) toplamı en küçük olan rotayı bulur.

On a real robot, moves are not equal. Wheels draw more current on carpet, the motor strains on a ramp, the robot slows down in a narrow corridor. Your navigation app, too, looks for the route that arrives soonest, not the one with the fewest streets. This week's method finds the route with the smallest total, whatever you choose to call "cost": energy, time or risk.

Bu fikrin adıNames for these ideas

Tabloyu doldurduktan sonra okuyun. Bir hamlenin maliyetine ağırlık denir. Ağırlıkların toplamı en küçük olan rotaya en kısa yol denir; "kısa" burada hamle sayısını değil toplam maliyeti anlatır. "En ucuz önce" kuralının adı Dijkstra algoritmasıdır. Bütün ağırlıklar 1 olduğunda Dijkstra, geçen haftanın halka yöntemiyle (BFS) aynı sonucu verir.

Read this after filling in the table. The cost of a move is called its weight. The route with the smallest total weight is called the shortest path; "short" here refers to total cost, not the number of moves. The cheapest-first rule is called Dijkstra's algorithm. When every weight is 1, Dijkstra gives the same result as last week's ripple method (BFS).

"En ucuz önce" yöntemiThe cheapest-first method

Dört istasyonda uyguladığınız kuralın aynısı. Kurşun kalemle yazılan sayı "şimdilik bulduğum en ucuz yol" demektir; daire içine alınan sayı kesindir.

This is the rule you used on the four stations. A number in pencil means "the cheapest way I have found so far"; a circled number is final.

  1. R hücresine 0 yazın.
  2. Daire içine alınmamış sayılar arasından en küçüğünü bulun ve daire içine alın. Eşitlik varsa önce üst satırdakini, aynı satırdaysa soldakini alın.
  3. O hücrenin dört komşusuna bakın (yukarı, sağ, aşağı, sol). Her komşu için: daire içindeki sayı + komşuya girmenin maliyeti. Komşu boşsa bu sayıyı yazın; komşuda daha büyük bir sayı varsa üzerini çizip yenisini yazın.
  4. S hücresi daire içine alınana kadar 2. ve 3. adımı tekrarlayın.
  1. Write 0 in cell R.
  2. Among the numbers not yet circled, find the smallest and circle it. On a tie take the one in the upper row; in the same row, the one further left.
  3. Look at that cell's four neighbours (up, right, down, left). For each one: the circled number + the cost of entering the neighbour. If the neighbour is empty, write this number; if it holds a larger number, cross it out and write the new one.
  4. Repeat steps 2 and 3 until cell S is circled.

İki kural: duvara yazılmaz; daire içine alınmış sayı bir daha değişmez. S'ye sayı yazılması yetmez, daire içine alınmasını bekleyin.

Two rules: never write in a wall, and a circled number never changes again. A number written at S is not enough; wait until S is circled.

Bölüm 3: Kısa kodPart 3: Short code

Kod, kâğıtta uyguladığınız kuralın aynısıdır. Geçen haftanın kodundan üç farkı var: kuyruk yerine öbek, "sayı yazılmış mı?" yerine "daha küçük mü?" sorusu ve her hamleye 1 yerine girilen hücrenin maliyetinin eklenmesi.

The code is the rule you applied on paper. It differs from last week's code in three ways: a heap in place of the queue, the question "is it smaller?" in place of "does it have a number?", and adding the cost of the cell entered in place of 1 for every move.

import heapq

harita = [
    "R.h..",
    "#.##.",
    "...#h",
    ".##..",
    "....S",
]
MALIYET = {".": 1, "h": 4, "R": 1, "S": 1}     # bir hücreye girmenin enerjisi

def en_ucuz_rota(harita, baslangic, hedef):
    en_ucuz = {baslangic: 0}               # hücrelere yazdığımız sayılar
    bekleyenler = [(0, baslangic)]         # (sayı, hücre) çiftleri
    while bekleyenler:
        sayi, (r, c) = heapq.heappop(bekleyenler)    # en küçük sayılıyı al
        if sayi > en_ucuz[(r, c)]:
            continue                       # üzeri çizilmiş eski bir sayı
        if (r, c) == hedef:
            return sayi                    # hedef daire içine alındı
        for dr, dc in [(-1, 0), (0, 1), (1, 0), (0, -1)]:
            yr, yc = r + dr, c + dc
            if not (0 <= yr < len(harita) and 0 <= yc < len(harita[0])):
                continue                   # harita dışı
            if harita[yr][yc] == "#":
                continue                   # duvar
            yeni = sayi + MALIYET[harita[yr][yc]]
            if yeni < en_ucuz.get((yr, yc), float("inf")):
                en_ucuz[(yr, yc)] = yeni
                heapq.heappush(bekleyenler, (yeni, (yr, yc)))
    return None                            # yol yok

print(en_ucuz_rota(harita, (0, 0), (4, 4)))
import heapq

grid = [
    "R.h..",
    "#.##.",
    "...#h",
    ".##..",
    "....S",
]
COST = {".": 1, "h": 4, "R": 1, "S": 1}        # energy needed to enter a cell

def cheapest_route(grid, start, goal):
    best = {start: 0}                      # the numbers we write in cells
    waiting = [(0, start)]                 # (number, cell) pairs
    while waiting:
        number, (r, c) = heapq.heappop(waiting)      # take the smallest number
        if number > best[(r, c)]:
            continue                       # an old, crossed-out number
        if (r, c) == goal:
            return number                  # the goal has been circled
        for dr, dc in [(-1, 0), (0, 1), (1, 0), (0, -1)]:
            nr, nc = r + dr, c + dc
            if not (0 <= nr < len(grid) and 0 <= nc < len(grid[0])):
                continue                   # off the map
            if grid[nr][nc] == "#":
                continue                   # wall
            new = number + COST[grid[nr][nc]]
            if new < best.get((nr, nc), float("inf")):
                best[(nr, nc)] = new
                heapq.heappush(waiting, (new, (nr, nc)))
    return None                            # no route

print(cheapest_route(grid, (0, 0), (4, 4)))

import heapq

corridors = {
    "R": {"A": 5, "B": 2},
    "A": {"R": 5, "B": 1, "S": 3},
    "B": {"R": 2, "A": 1, "S": 7},
    "S": {"A": 3, "B": 7},
}

best = {"R": 0}
came_from = {}
waiting = [(0, "R")]
while waiting:
    number, station = heapq.heappop(waiting)
    if number > best[station]:
        print("Skipped (crossed out):", station, number)
        continue
    print("Circled:", station, number)
    if station == "S":
        break
    for neighbour, cost in corridors[station].items():
        new = number + cost
        if new < best.get(neighbour, float("inf")):
            best[neighbour] = new
            came_from[neighbour] = station
            heapq.heappush(waiting, (new, neighbour))

route = ["S"]
while route[-1] != "R":
    route.append(came_from[route[-1]])
print("Cost:", best["S"])
print("Route:", " -> ".join(route[::-1]))

Bu yöntemin işi nasıl büyür?How does this method's work grow?

Her hücre, komşu sayısı kadar kez (en fazla 4) öbeğe eklenebilir ve öbeğe her ekleme ya da öbekten her alma, bekleyenlerin sayısının logaritması kadar iş ister. n hücreli bir haritada toplam iş n × log n ile orantılıdır: halka yönteminden biraz ağır, ama tokalaşma gibi kareyle büyüyen bir işten çok hafif. Baştaki canlı haritada 5×5, 8×8, 12×12 ve 20×20 seçip "işlenen hücre" sayısını karşılaştırın.

Each cell can be added to the heap as many times as it has neighbours (at most 4), and every heap insertion or removal takes work proportional to the logarithm of how many are waiting. On a map of n cells the total work is proportional to n × log n: a little heavier than the ripple method, far lighter than anything that grows with the square, like the handshakes. On the live map at the top, pick 5×5, 8×8, 12×12 and 20×20 and compare the "cells processed" count.
