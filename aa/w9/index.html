Start with a battery budget

A warehouse robot must reach its charging station. A short corridor has rough flooring; a longer corridor is smooth. If the battery has only 10 energy units left, which route can the robot actually complete? We assume the map and entry costs are known and remain fixed during this run.

RouteMovesEnergy calculationFits 10 units?
Across the top49 + 9 + 9 + 1 = 28No
Around the bottom81 + 1 + 1 + 1 + 1 + 1 + 1 + 1 = 8Yes; 2 units remain

We pay when entering the next cell. The starting cell is not charged initially, and entering G costs 1. Energy is an example of an additive cost: time or distance can also be used if their edge costs are known and nonnegative. This lesson does not yet model turn energy.

Remember: Week 8 · The question changes

BFS used a FIFO queue and selected the four-move top route on this very map. It was correct for fewest moves, even though that path costs 28. Dijkstra instead minimizes the sum of entry costs and returns the eight-move path costing 8.

Remember: Week 4 · Arrival order versus cost order

Enqueue A then B: FIFO returns A first. But if A costs 5 and B costs 2, Dijkstra must process B first. We replace the frontier’s queue rule; the robot still has the same legal moves.

Find the cheapest route when moves have different costs

Remember: Week 7 · Use the minimum, not the first arrival

With heap entries (5, A), (2, B), the next pop returns (2, B). If A improves to 3, push (3, A); the old (5, A) can remain until popped and skipped. Heap storage is not a fully sorted list.

Dijkstra keeps the cheapest known cost for each cell. To relax an edge, add the edge cost to the current cost and compare it with the saved cost at the neighbor. If the candidate is smaller, update the cost and parent and enqueue the improved entry.

The heap may still hold an older entry for that same cell. Skip it if its cost differs from the saved cost. With nonnegative edges, a current minimum pop settles that cell’s cost. Stop when the goal is popped with its current cost.

The fewer-move route S–A–G costs 8. The route through B uses three moves and costs 6. Comparing the final costs answers a different question from comparing step counts.

Read every update, including the stale pop

g(v) means the best cost found so far from S to v. Missing costs are treated as infinity, so the first finite route is an improvement. The frontier below is shown in extraction order for readability, not as the heap’s internal array.

The path is G ← A ← B ← S; reverse it to get S → B → A → G. Its cost is 2 + 1 + 3 = 6. There are five heap removals but only four current pops; the stale A entry contributes no expansion. G is counted as a current pop, but its neighbors are not scanned.

Remember: Week 5 · Store facts by vertex key

A dictionary lookup such as costs['A'] returns the saved value 3. parents['A'] = 'B' records which predecessor produced it. Unlike a simple visited set, these values may change after discovery: A was first 5 via S, then 3 via B.

Why the stopping rule is safe

When a current minimum-cost vertex is popped, every unfinished route must still pass through a frontier candidate whose cost is at least this minimum. Nonnegative extensions cannot make such a route cheaper. Therefore that popped cost is final. The goal’s first insertion is only a proposal: in our graph G first costs 10 and later costs 6.

Check staleness before checking the goal. Use strict improvement (<), not ≤: an equal-cost route needs no new entry. Zero-cost edges are allowed; negative edges are not. For a directed counterexample, S→G costs 2, S→A costs 3, A→G costs −4: stopping at G=2 misses the route costing −1.

Remember: Week 1 · Early exit needs a reason

A scan for any reading above a threshold can stop at its first match: [2, 9, 12] with threshold 8 returns 9. Cheapest-path search asks for the best match, so the first discovered goal is insufficient. We stop only when the goal’s current minimum cost is settled.

Show the worked steps

  2. Popping A at 3 improves G to 5. The older entry A at 4 stays in the heap but is stale.

Why use a separate graph for stale entries? In this grid, every incoming move to a cell has the same entry cost. With Dijkstra’s cost order, the first relaxation of that cell already comes from a cheapest reachable predecessor, so this particular model does not demonstrate repeated improvements. General edge-weighted graphs can have different incoming costs; the small graph above deliberately shows that case. Keeping the stale-entry check makes the implementation suitable for those extensions.

Run the small graph before the full laboratory

This standalone example prints each current pop and the stale entry. Vertices are strings, so Python can break equal-cost ties alphabetically. All vertices and nonnegative integer edge weights are checked before searching. A general application should also reject non-finite or nonnumeric weights.

from heapq import heappop, heappush

def cheapest_route(graph, start, goal):
    if start not in graph or goal not in graph:
        raise ValueError("Start and goal must be graph vertices")
    for edges in graph.values():
        for neighbor, weight in edges:
            if neighbor not in graph or not isinstance(weight, int) or weight < 0:
                raise ValueError("Use existing vertices and nonnegative weights")
    heap = [(0, start)]
    costs = {start: 0}
    parents = {start: None}
    while heap:
        cost, cell = heappop(heap)
        if cost != costs[cell]:
            print("Skip stale:", cell, cost)
            continue
        print("Settle:", cell, cost)
        if cell == goal:
            path = []
            while cell is not None:
                path.append(cell)
                cell = parents[cell]
            return cost, path[::-1]
        for neighbor, weight in graph[cell]:
            candidate = cost + weight
            if candidate < costs.get(neighbor, float("inf")):
                costs[neighbor] = candidate
                parents[neighbor] = cell
                heappush(heap, (candidate, neighbor))
    return None, []

graph = {
    "S": [("A", 5), ("B", 2)],
    "A": [("S", 5), ("B", 1), ("G", 3)],
    "B": [("S", 2), ("A", 1), ("G", 8)],
    "G": [("A", 3), ("B", 8)],
}
cost, path = cheapest_route(graph, "S", "G")
print("Cost:", cost)
print("Path:", " -> ".join(path))
assert (cost, path) == (6, ["S", "B", "A", "G"])

Common mistakes

  • Stopping when the goal is first inserted.
  • Expanding stale entries.
  • Using the same stopping rule with negative edges.

What does the algorithm cost?

Remember: Week 2 · Count operations as the map grows

A single scan over n cells performs n visits; comparing all pairs can require about n² comparisons. Dijkstra scans outgoing edges and performs heap operations. With lazy duplicate entries, a general bound is O((V+E) log(V+E)) time and O(V+E) auxiliary space. Here V counts free cells and E legal directed moves.

On a four-neighbor grid E≤4V, so the search bound becomes O(V log V) time and O(V) auxiliary space, assuming expected constant-time dictionary access. Validating a supplied rectangular map also scans all R×C cells. Memory includes costs, parents and heap entries, not just the returned route.

Remember: Week 3 · Two different reasons for a logarithm

Binary search in [10,20,30,40,50,60,70,80] discards half the sorted candidates at each comparison. A heap push or pop travels through a tree of logarithmic height. Dijkstra does not binary-search the map; the log factor comes from maintaining the priority queue.

Remember: Week 6 · Summarize measurements without hiding variation

Sort [7,2,3,2,100] to [2,2,3,7,100]: the median is 3. Our timing lab takes the median of five batch averages. It is a useful typical value, but it does not guarantee that every call meets a time limit. Filtering noisy sensor data and choosing a route are separate operations.

The lab now uses a direct dijkstra function: the heap stores (cost, cell), so equal costs are ordered by row then column. The input checker accepts a nonempty rectangular grid, valid free endpoints, and symbols . S G # or single digits 0–9. A digit 0 is allowed. A blocked endpoint is invalid input, not an unreachable free endpoint. The search assumes a fixed map.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

from collections import deque
from heapq import heappop, heappush

DIRECTIONS = [(-1, 0), (0, 1), (1, 0), (0, -1)]


def validate_grid(grid, start, goal):
    if not grid or not grid[0] or any(len(row) != len(grid[0]) for row in grid):
        raise ValueError("Use a nonempty rectangular grid")
    if any(symbol not in ".SG#0123456789" for row in grid for symbol in row):
        raise ValueError("Use only . S G # and single digits 0-9")
    for row, col in (start, goal):
        if not (0 <= row < len(grid) and 0 <= col < len(grid[0])):
            raise ValueError("Endpoint outside grid")
        if grid[row][col] == "#":
            raise ValueError("Endpoint is blocked")


def neighbors(grid, cell):
    row, col = cell
    for dr, dc in DIRECTIONS:
        r, c = row + dr, col + dc
        if 0 <= r < len(grid) and 0 <= c < len(grid[r]) and grid[r][c] != "#":
            yield r, c


def entry_cost(grid, cell):
    row, col = cell
    symbol = grid[row][col]
    return int(symbol) if symbol in "0123456789" else 1


def result(grid, parents, goal, popped):
    path = [goal]
    while parents[path[-1]] is not None:
        path.append(parents[path[-1]])
    path.reverse()
    return len(path) - 1, sum(entry_cost(grid, cell) for cell in path[1:]), popped, path

def bfs(grid, start, goal):
    validate_grid(grid, start, goal)
    queue = deque([start])
    parents = {start: None}
    popped = 0
    while queue:
        cell = queue.popleft()
        popped += 1
        if cell == goal:
            return result(grid, parents, goal, popped)
        for neighbor in neighbors(grid, cell):
            if neighbor not in parents:
                parents[neighbor] = cell
                queue.append(neighbor)
    return None, None, popped, []

def dijkstra(grid, start, goal):
    validate_grid(grid, start, goal)
    frontier = [(0, start)]
    costs = {start: 0}
    parents = {start: None}
    popped = 0
    while frontier:
        cost, cell = heappop(frontier)
        if cost != costs[cell]:
            continue
        popped += 1
        if cell == goal:
            return result(grid, parents, goal, popped)
        for neighbor in neighbors(grid, cell):
            candidate = cost + entry_cost(grid, neighbor)
            if candidate < costs.get(neighbor, float("inf")):
                costs[neighbor] = candidate
                parents[neighbor] = cell
                heappush(frontier, (candidate, neighbor))
    return None, None, popped, []


def check_path(grid, start, goal, answer):
    moves, cost, popped, path = answer
    if not path:
        assert moves is None and cost is None
        return
    assert path[0] == start and path[-1] == goal
    assert moves == len(path) - 1
    for a, b in zip(path, path[1:]):
        assert b in neighbors(grid, a)
    assert cost == sum(entry_cost(grid, cell) for cell in path[1:])


maps = [
    (('S999G', '.###.', '.....'), (0, 0), (0, 4)),
    (["." * 25] * 25, (12, 12), (12, 18)),
]

planners = [("BFS", bfs), ("Dijkstra", dijkstra)]

for grid, start, goal in maps:
    for name, planner in planners:
        def job():
            return planner(grid, start, goal)

        answer = job()
        check_path(grid, start, goal, answer)
        moves, cost, popped, path = answer
        print(name, "-> (moves, terrain cost, popped):", (moves, cost, popped))
        print("Path:", path)
        measure(name, job, repeats=30)

Three boundary cases to predict

On ('S#G',), the free goal is unreachable: (None, None, 1, []). On ('S',) with start=goal=(0,0), the result is (0, 0, 1, [(0,0)]). On ('S0G',), the route has two moves but costs only 1. Strict improvement prevents equal-cost zero cycles from repeatedly creating heap entries.

Compare a model answer

The top costs 3c + 1 and the bottom costs 8. Dijkstra uses the top for c = 1 or 2 and the bottom for c = 3 or 9. BFS keeps the four-move top route. If turn cost matters, model a state as cell plus heading and put a nonnegative turn cost on the corresponding transition.

Solve the switching point, then add turns

Compare 3c+1 with 8: the top is cheaper when c<7/3; the bottom is cheaper when c>7/3. They tie at c=7/3, which is not a single integer digit. Therefore the first integer that changes the optimal choice is c=3. Dijkstra promises minimum energy, not minimum moves among equal-energy routes.

Now suppose the robot initially faces east and each 90° turn costs t≥0. The top path needs no turns, so it still costs 3c+1. The lower path goes south, east, north: it makes three turns including the initial east-to-south turn, costing 8+3t. At c=3 and t=1, the top costs 10 and the bottom 11: including turns changes the choice back. We assume a turn in place is legal and charge it explicitly.

A state must now be (row, column, heading). Reaching the same cell facing north or east can give different future turn costs, so a dictionary keyed only by cell would merge different states incorrectly. Add turn actions at cost t and forward moves at the destination’s entry cost. All transition costs remain nonnegative, so Dijkstra still applies.
