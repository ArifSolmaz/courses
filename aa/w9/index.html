What route costs least over terrain?

15 min · Engineering question

The digits now give the energy cost of entering a cell. Dots and G cost one. S starts with cost zero. The cheapest route may take more moves.

Before you start

BFS minimized moves in Week 8. The min-heap from Week 7 lets us process the smallest known cost first.

Dijkstra keeps the cheapest known cost for each cell. To relax an edge, add the edge cost to the current cost and compare it with the saved cost at the neighbor. If the candidate is smaller, update the cost and parent and enqueue the improved entry.

The heap may still hold an older entry for that same cell. Skip it if its cost differs from the saved cost. With nonnegative edges, a current minimum pop settles that cell’s cost. Stop when the goal is popped with its current cost.

The fewer-move route S–A–G costs 8. The route through B uses three moves and costs 6. Comparing the final costs answers a different question from comparing step counts.

The top path uses four moves and costs 28. A min-heap processes the lower-cost candidates and settles the goal via the lower path, costing 8. That is safe here because every move has nonnegative cost.

Show the worked steps
  1. Popping S creates A at cost 4 and B at cost 1. Popping B improves A to 3 and discovers G at 9.
  2. Popping A at 3 improves G to 5. The older entry A at 4 stays in the heap but is stale.

Common mistakes

  • Stopping when the goal is first inserted.
  • Expanding stale entries.
  • Using the same stopping rule with negative edges.

45 min

Measure it

Compare BFS and Dijkstra on both maps. Record steps, terrain cost, expanded cells and time. Then make every traversable cell cost one and compare again.

Select Run or copy the code into Python 3. The two times are the median and largest of five batch averages, in milliseconds per call. The largest batch average does not bound an individual call. The pop count includes the goal and excludes stale heap entries.

from statistics import median
from timeit import repeat


def measure(label, job, repeats=200):
    samples = repeat(job, repeat=5, number=repeats)
    typical = median(samples) * 1000 / repeats
    longest = max(samples) * 1000 / repeats
    print(f"{label:18}  {typical:.6f} ms  {longest:.6f} ms")

from collections import deque
from heapq import heappop, heappush

DIRECTIONS = [(-1, 0), (0, 1), (1, 0), (0, -1)]


def neighbors(grid, cell):
    row, col = cell
    for dr, dc in DIRECTIONS:
        r, c = row + dr, col + dc
        if 0 <= r < len(grid) and 0 <= c < len(grid[r]) and grid[r][c] != "#":
            yield r, c


def entry_cost(grid, cell):
    row, col = cell
    symbol = grid[row][col]
    return int(symbol) if symbol.isdigit() else 1


def result(grid, parents, goal, popped):
    path = [goal]
    while parents[path[-1]] is not None:
        path.append(parents[path[-1]])
    path.reverse()
    return len(path) - 1, sum(entry_cost(grid, cell) for cell in path[1:]), popped, path

def bfs(grid, start, goal):
    queue = deque([start])
    parents = {start: None}
    popped = 0
    while queue:
        cell = queue.popleft()
        popped += 1
        if cell == goal:
            return result(grid, parents, goal, popped)
        for neighbor in neighbors(grid, cell):
            if neighbor not in parents:
                parents[neighbor] = cell
                queue.append(neighbor)
    return None, None, popped, []

def weighted(grid, start, goal, heuristic):
    frontier = [(heuristic(start, goal), start, 0)]
    costs = {start: 0}
    parents = {start: None}
    popped = 0
    while frontier:
        _, cell, cost = heappop(frontier)
        if cost != costs[cell]:
            continue
        popped += 1
        if cell == goal:
            return result(grid, parents, goal, popped)
        for neighbor in neighbors(grid, cell):
            candidate = cost + entry_cost(grid, neighbor)
            if candidate < costs.get(neighbor, float("inf")):
                costs[neighbor] = candidate
                parents[neighbor] = cell
                priority = candidate + heuristic(neighbor, goal)
                heappush(frontier, (priority, neighbor, candidate))
    return None, None, popped, []


def zero(cell, goal):
    return 0

maps = [
    (('S999G', '.###.', '.....'), (0, 0), (0, 4)),
    (["." * 25] * 25, (12, 12), (12, 18)),
]

planners = [("BFS", bfs), ("Dijkstra", lambda grid, s, g: weighted(grid, s, g, zero))]

for grid, start, goal in maps:
    for name, planner in planners:
        def job():
            return planner(grid, start, goal)

        moves, cost, popped, path = job()
        print(name, "-> (moves, terrain cost, popped):", (moves, cost, popped))
        print("Path:", path)
        measure(name, job, repeats=30)

45 min

Find when the energy-optimal route changes

Use the starter grid with the top three costs set to a common positive integer c. G costs 1 and the lower corridor still costs 8. Compare the two routes and include the extra turns on the lower route in your recommendation.

Start individually for 10 minutes. Work with a partner for 20. Spend the last 15 comparing with another pair and revising your recommendation.

  1. Write the cost of each route as a formula and compare c = 1, 2, 3 and 9.
  2. Choose the cheapest route for each input, then compare what BFS returns. Give the first integer c where the choices disagree.
  3. If a turn consumes extra energy, describe how the planner would need to represent heading. Explain why adding the same penalty to every cell is insufficient.
Compare a model answer

The top costs 3c + 1 and the bottom costs 8. Dijkstra uses the top for c = 1 or 2 and the bottom for c = 3 or 9. BFS keeps the four-move top route. If turn cost matters, model a state as cell plus heading and put a nonnegative turn cost on the corresponding transition.

5 min

Exit ticket

Why does first discovering the goal fail as a stopping rule for weighted search?

Write two or three sentences on your own. Support your answer with a count, a measurement or a step from today’s trace.

Compare a sample exit answer

Discovery gives a candidate, and a later path can improve it. In the example G is first seen at 10 and later improved to 6. Stop at a current minimum pop.
